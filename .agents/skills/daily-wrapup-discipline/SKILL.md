# 日终收敛与沉淀纪律

用户要求收尾沉淀时，按四步走，缺一不可：收敛、补录、对账、沉淀。

## 步骤
1. **下收敛令**：通知全员——在飞的干完当前阶段即停，成果归档销账，清理 worktree 残留，一句话回报平账；当晚不再派新单。逐一核回报，未平账的次日点名。
2. **补追溯缺口**：对照汇报和群聊，把仍在群聊里、未入三池台账的事项补录入池（含来源、现状、待拍板标记），确保台账无遗漏、信息可追溯。
3. **账实对账**：核对多处记录（如 TODO.md 与 pool.db）的一致性。发现编号冲突或漂移时，**编号不得复用**——新条目一律取新号，冲突条目派专人只对账不派工，回执确认后才算平。
4. **沉淀**：把当日台账、新机制、人员名单存入团队记忆；汇报文件放 docs/reports/ 固定目录。

## 生成汇报的硬规则
- 汇报里所有数字（完成数、剩余数、bug 数）必须取自三池台账真数据，不得凭印象填。
- 未完成事项须区分「在办」「挂起」并注明卡点（如等老板拍板、等真机验收）。

## 验收标准
- 全员回报平账，无在飞残留。
- 台账条数与实际事项一一对应，无群聊-only 事项。
- 记录间无编号/状态冲突，冲突项有对账回执。
