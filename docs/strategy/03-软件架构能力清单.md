# DevDesk 软件架构能力清单

> 截至 2026-10-21 · 以源码为准，spec 过期口径已标注

## 1 分层架构（4 层）

```
main → module_* (7 个 Router 页面) → core → platform → EUI-NEO
```

| 层 | 职责 | 关键文件 |
|---|---|---|
| main | 应用入口、装配层 | `main.cpp`、`app_registry.h`、`app_assembly.h` |
| module_* | 7 个 Router 页面模块（home/markdown/todo/claude_proxy/agent/settings/about） | 各 `src/module_*/` |
| core | 共享基础（Result / paths / sqlite_db / theme / logging / router / module_interface / tool / event_bus / llm_endpoint） | `src/core/` |
| platform | OS 能力抽象（http_client / http_server / keychain / credential_protection / json） | `src/platform/` |
| EUI-NEO | GUI 框架，同级目录源码依赖 | `../EUI-NEO/` |

### 依赖铁律

- `core` 不得依赖 `platform`；除 header-only 类型桥接外，不得调用 EUI-NEO 运行时
- `module_*` 之间不得互相依赖——工具调用走 `core::ToolRegistry` 按名间接触达，事件通信走 `core::EventBus`
- `platform` 可依赖 `core`（用 `Result<T>`）
- `module_*` 可依赖 `core` 和 `platform`

## 2 模块插拔机制

| 机制 | 实现位置 | 说明 |
|---|---|---|
| Router 门控 | `app_registry.h` 的 `kModuleRegistry`（7 行登记表）+ `app_assembly.cpp` 的 `buildGatedEntries` | gatingKey == nullptr = 恒注册（Home/Settings/About）；非空 = 由配置键控制 |
| 模块工厂 | 每模块一个 `extern "C" create_*_module()` | 编译期独立，模块间零链接依赖 |
| LiveToggle | 设置页模块开关即时生效 | `dispatchModuleToggle` → onStart/onStop 重入幂等 |
| Module 接口 | `core::module_interface.h` | compose / onStart / onStop / onPageEnter / onKeyEvent / shortName / iconGlyph |

**可被开关插拔的模块**：笔记 / 待办 / Claude / 智能体（Home / Settings / About 不可禁用）。

## 3 依赖反转点

| 抽象 | 定义层 | 实现层 | 作用 |
|---|---|---|---|
| `core::ITool` / `ToolRegistry` | core | 各 module_* 在 onStart 注册，module_agent 经 Registry 按名调用 | 工具调用中介——agent 与业务模块互不依赖 |
| `core::LlmEndpoint` | core | `module::agent::DirectLlmClient`（按激活 profile 直连上游） | LLM 请求抽象——agent loop 不依赖代理或具体传输层 |
| `core::event::EventBus` | core | 发布方（todo/md 写路径 emit）→ 订阅方（agent Scheduler onEvent 入队） | 进程内事件总线——发布方与订阅方只 include core 头，互不 include |
| `core::LlmProfileSource` | core | `module_claude_proxy`（ClaudeService 提供） | profile 配置来源——agent 与 claude_proxy 互不依赖 |

## 4 智能体执行架构

### AgentLoop（单次 run 执行器）

- 消息累积：逐轮追加 user/assistant/tool_result 消息到对话历史
- 工具循环：LLM 响应 → 解析 tool_use → `ToolRegistry::find` → 同步执行 → 回喂结果 → 再请求
- 护栏：`maxIterations` 迭代上限、`allowDestructive` 破坏性工具门控、`cancelToken` 协作式取消
- 落库：`agent_runs` / `agent_messages` 三表审计链（AgentStore）

### Scheduler（触发侧）

六种触发类型：

| 类型 | 触发源 | 说明 |
|---|---|---|
| manual | 用户在 UI 手动点"运行" | 同步 spawn，`startRunExclusive` 同 task 不并发闸 |
| schedule | cron 表达式 | tick 线程每分钟匹配，同分钟去重 |
| resident | 常驻队列 | `enqueueResident` 手动入队，pop 即 spawn |
| event | EventBus 事件 | event 线程消费队列，`cooldown_sec` 冷却，窗口内事件直接丢弃 |
| daily | 每天首次 | tick 线程当天首次触发（同分钟去重同款机制） |
| once | 一次性绝对时间（Unix 秒） | tick 线程匹配到点窗口，有且仅有一次，错过不补 |

共用闸：

- **同 task 不并发**：`startRunExclusive`（SELECT running … LIMIT 1 → 已有 → AlreadyExists 拒）
- **冷却**（仅 event 型）：`(taskId, 事件名)` 级，默认 300 秒，同任务不同事件互不压制
- **限次**：`max_runs` 达上限后 Scheduler 自动 `setTaskEnabled(false)`，拒绝后续派发

### 预算护栏体系

| 护栏 | 位置 | 说明 |
|---|---|---|
| 迭代上限 | `AgentTask::maxIterations`（默认 10） | 超限 → finishRun("limited")，含当前迭代计数 |
| 墙钟上限 | AgentLoop 内 `wallClockBudgetSec` | 超时 → 同理 limited |
| token 上限 | Anthropic usage 字段累计 | 超限 → 同理 limited |
| 单条工具结果截断 | AgentLoop 工具结果文本 32KB 硬上限 | 超限按 UTF-8 边界截断加 `[truncated]` 标记后回喂，不终止运行；消息历史本身不截断（靠迭代上限兜底） |
| 单闸 | `startRunExclusive` | 同 task 同时只允许一个 run |

### 三表审计

| 表 | 内容 |
|---|---|
| `agent_tasks` | 任务定义（name / goal / trigger_type / trigger_config / model_slot / enabled） |
| `agent_runs` | 运行实例（task_id / status / started_at / ended_at / iterations / input_tokens / output_tokens / error） |
| `agent_messages` | 消息审计（run_id / seq / role / content_json / tool_call_id / created_at） |

## 5 扩展点清单

### 加一个业务模块

1. 建 `src/module_xxx/` 目录，含 `xxx_module.cpp`（实现 `core::Module`）
2. `src/module_xxx/CMakeLists.txt` 建 `devdesk_module_xxx` 静态库
3. `CMakeLists.txt` 顶层 `add_subdirectory(src/module_xxx)` + `target_link_libraries(DevDesk PRIVATE devdesk_module_xxx)`
4. `src/core/module_interface.h` 的 `PageId` 枚举加一项（枚举序 = 侧边栏顺序）
5. `src/app_registry.h` 的 `kModuleRegistry` 加一行 + `extern "C"` 工厂声明
6. `src/main.cpp` 加 `#include` + `create_xxx_module` 调用
7. 如需可插拔：`settings_config.h` 加 `kModuleIdXxx` 常量，`app_registry.h` 的 `gatingKey` 填该常量

### 加一个工具

1. 在所属模块实现 `core::ITool`（name / schemaJson / execute / isDestructive）
2. 在模块 `onStart` 里 `ToolRegistry::instance().registerTool(shared_ptr)`
3. 在模块 `onStop` 里 `unregisterTool(name)`
4. 模块隔离守卫（`check-module-isolation.sh`）会自动检查 module_agent 与工具方互不 include

### 加一个事件

1. `src/core/event_bus.h` 的 `EventBus` 类中加 `inline constexpr const char* kXxx = "xxx";`
2. 在发布方的写路径末尾调 `core::event::bus().emit(kXxx)`
3. 在订阅方 `subscribe(kXxx, handler)` 并保存 token（析构即退订）

### 加一种触发类型

1. `trigger_config.h`：TriggerConfig 结构扩字段 + encode/decode 新分支
2. `scheduler.h`：Scheduler 加新路由方法 + 新线程（或扩 tickNow 判定）
3. `agent_module.cpp`：saveTaskDialog 的 triggerIdx 加新选项 + UI 配置行

### 已知约束（铁律禁止）

- **module_* 之间不得直接 include 或 link**——模块隔离守卫静态检查
- **core 不得依赖 platform、不得调用 EUI-NEO 运行时**——架构铁律
- **平台代码禁止 `#ifdef _WIN32` / `__APPLE__`**——必须接口隔离 + 分文件编译

## 6 已知架构债与限制

| 项 | 判定 | 出处 |
|---|---|---|
| CI 复验待确认 | Windows 编译红灯 + macOS probe 全红修复已合并进 dev，未 push、未复验 | CLAUDE.md 已知欠账表 |
| Windows DPAPI 运行时未验证 | `credential_protection_win.cpp` 只有 CI 编译门禁，无真机加密-解密回环测试 | 同上 |
| macOS 覆盖率工具 | `scripts/coverage.sh` 仅 AppleClang；Windows gcovr 为欠账；CI 未接覆盖率 | 同上 + CLAUDE.md 欠账 |
| `-wal`/`-shm` chmod 极端场景 | 空事务失败时不会被 chmod | 同上 |
| EUI-NEO macos Liquid Glass | 无法实现，实色+阴影替代 | EUI-NEO 能力上限 |
| EUI-NEO 托盘自定义菜单 | 硬编码 Show/Exit | 同上 |
| macOS 27 OpenGL 移除风险 | 无 Metal 后端；长期需 fork EUI-NEO 加 Metal | spec §15.1 |
| Core 覆盖率未达 90% 目标 | 79.5%（2026-10-03 基线） | `coverage-summary.txt` |
| 部署 | 源码构建为主，个人项目 YAGNI | spec §15.3 |

### YAGNI 决策（有意不做，来自 spec §15.3）

- UI 锦上添花（动画粒子、3D tilt）
- 企业功能（多账号、云同步）
- 复杂编辑器能力（语法高亮、括号匹配）
- 打包与分发（个人项目级别，已有 Inno Setup / DMG 满足基本需求）

---

**漂移点**（spec → 现状）：① spec 智能体经本地代理转发请求；现状智能体走 `DirectLlmClient` 直连上游（经 `core::LlmEndpoint` 抽象，与代理完全解耦）。② spec 写 `migrations.h` 版本化迁移链；实际 schema 是单份幂等 DDL + `addMissingAgentColumns` 补列迁移，不设 migration 表。③ spec 描写的 `DragController`（`src/core/drag_controller.h`）是早期设计产物，未曾落码——W8 Todo 拖拽用元素级 `onDrag`/`onRelease` 回调直接实现。④ spec 中 `ClaudeService` 承载代理启动/停止/转发全链，现状已拆分为 `claude_service.cpp`（780 行）+ 独立模块（CallLogStore / ProfileRepository / ProxyRuntime / SettingsTakeOver），且智能体不再经过代理。
