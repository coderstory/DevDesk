# DevDesk 智能中枢 D/E 期：文献与自主性设计调研

> 2026-10-21，17 篇论文，14 次有效抓取（6 次失败：Bing 全网屏蔽 + arxiv 长查询超时），来源均为 arxiv.org 直抓。

## 1. 验收自评的理论依据（D2：什么算做完）

### 文献结论

**Reflexion**（Shinn et al., 2023, 2303.11366）提出"口头强化学习"——agent 失败后生成一段自然语言反思存入 episodic memory，下次决策时检索读取。它不更新模型权重，而是把失败经验写成文字提示自己。缺点：自我宽纵——同一模型既干活又给自己打分，容易高估。HumanEval pass@1 从 80% 到 91%。

**Self-Refine**（Madaan et al., 2023, 2303.17651）更进一步：生成→自评→修改→再评，同模型分饰"作者"和"评论家"，迭代到满意或达到次数上限。跨 7 类任务平均提升 ~20%。问题与 Reflexion 一样：自我宽纵。

**LLM-as-a-Judge / MT-Bench**（Zheng et al., 2023, 2306.05685, NeurIPS 2023）：系统梳理 LLM 当裁判的三类偏见——位置偏见（排前面的回答得分高）、冗长偏见（长的显得更"用心"）、自我增强偏见（裁判偏好与自己风格相似的答案）。提出交换位置取平均、多证据校准来缓解。与人类裁判一致性 >80%。

**LLMs are not Fair Evaluators**（Wang et al., 2023, 2305.17926）：证实位置偏见极严重——仅调换两个答案的展示顺序，Vicuna-13B 能在 66/80 题上"赢"ChatGPT。提出三招校准：多证据校准（要求裁判先列出证据再打分）、平衡位置校准（多轮不同顺序取均分）、人类兜底（计算平衡位置多样性熵，高难度自动转人工）。

**RSEA**（Nguyen et al., 2026, 2606.28374）：核心发现——**不加 hold-out 验证的自我进化是高风险高方差的**。Dynamic Cheatsheet 在 ALFWorld 接近最优（70.7%）但在 WebShop 崩塌（0.14 vs 基线 0.43）。RSEA 用严格的 keep-better gate（在留出验证集上不退化才提交新策略），实现了单调安全的自进化——任何 benchmark 上都不显著差于基线。

### 对 D2 的设计建议

"什么算做完"不能由一个模型说了算。建议三层验证：(1) **结构化评分表**（rubric），把"做完"拆成 3-5 条可机械验证的条目（编译通过？测试增量通过？产物大小合理？），每条只有 pass/fail，不给模型打分空间；(2) **分离 reviewer**，验收模型与执行模型用不同 prompt/system message 甚至不同模型路由，避免自我宽纵；(3) **hold-out gate**，每次改完代码后跑一条与改动无关的回归用例集，退化了就回滚，不做"主观判断"。

## 2. 失败重试设计（D1：怎么重试不炸）

### 文献结论

**Voyager**（Wang et al., 2023, 2305.16291）：Minecraft agent 的自我纠错机制有三层——环境反馈（报错信息）、执行错误（运行时异常）、自我验证（执行后自问"任务完成了吗"）。关键设计：每次重试不是盲目重跑，而是带着上次的错误信息进入下一次 prompt。技能库存储成功方案，重试时优先检索。

**ExpeL**（Zhao et al., 2023, 2308.10144, AAAI-24）：提出"经验学习"——训练阶段收集成功和失败的完整轨迹，提取自然语言经验规则；推理阶段回忆相关经验辅助决策。核心洞察：失败不一定是策略问题，可能是环境噪声；**三连败同类错误 = 规则缺陷，单次失败 = 概率噪声**。这个区分很关键。

**Agent-Reflex**（Dong et al., 2026, 2610.17953）：训了一个专门的"反思模型"，分三阶段——先注入工具噪声收集成功-失败配对，再监督微调学会反思，最后在线强化学习巩固。在 5 个长程工具使用基准上达到 58.6 分。实用结论：反思能力可以专门训练而不依赖通用模型自己"觉得"错了。

**ANNEAL**（Hakim et al., 2026, 2605.16309）：对比了两种失败处理模式——ReAct/Reflexion 的"每次重新推理"（episodic recovery）只能单次恢复，相同故障复发率 72-100%；ANNEAL 的"持久符号修复"（把失败原因写入知识图谱）让复发率降到 0%。

### 对 D1 的设计建议

核心是**区分两类失败**：瞬时失败（API 超时、网络抖动、编译缓存脏）和逻辑失败（代码逻辑错、设计缺陷、需求理解偏）。瞬时失败用指数退避重试（1s→2s→4s→8s，上限 3 次），超过上限熔断降级为人工通知。逻辑失败不重试——重试同一策略不会产出不同结果——改为带着错误日志进反思链：定位错误归属（我的代码 vs 环境 vs 上游），若属我自己代码则写入"经验池"供后续任务检索。**熔断阈值按 10 分钟窗口计，同类错误 ≥3 次即熔断**，不设全局统一熔断器（不同任务独立计数）。

## 3. 自唤醒 / 自我调度（D3：怎么自己安排下一件事）

### 文献结论

**Generative Agents**（Park et al., 2023, 2304.03442）：提出 agent 架构三层——观察（记录经历）→ 反思（定期把零散记忆合成高层洞察）→ 规划（基于反思生成日程）。关键机制：反思不是实时的，而是定时触发（如每天结束时），把原始记忆提炼为高层次抽象再写入记忆流。这套"定时反思→计划生成→执行"的循环是自唤醒的原型。

**Auto-RecSys**（Li et al., 2026, 2609.10922）：工业级 agent 系统的双环自进化——Execution Evolution Loop 在每次失败后更新操作手册（playbook），Idea Evolution Loop 在实验完成后用结果启发下一轮假设。核心设计三点：(1) 认知-程序分离（自然语言管推理，确定脚本管执行，混用会炸）；(2) 集中式跨会话记忆（失败不丢进度、重启可续跑）；(3) 分布式异步执行（多个实验并行跑，不互相阻塞）。

**RSEA**（Nguyen et al., 2026, 2606.28374）：递归自进化——上一代的经验（策略+技能+流程）经 hold-out 验证通过后成为下一代的起点。验证失败则回退到上一代基线。这个"不退化才升级"的机制直接适用自唤醒的场景——醒来后先跑验证，验证通过才能继续安排新任务。

### 对 D3 的设计建议

自唤醒工具建议三条边界：(1) **次数硬上限**——单任务最多自唤醒 3 次，第 4 次转为人工通知并附前 3 次的完整轨迹。防止死循环；(2) **必须有取消机制**——每次自唤醒前检查一个"取消令牌"（本地文件标记或内存 flag），用户可随时置位取消；(3) **每次唤醒先验自检**——醒来第一件事不是干活，而是跑一条轻量自检（读系统时间 + 写一条心跳日志 + 检查上次任务是否真的完成了），自检不过不安排新任务，直接上报。

## 4. 多角色软件交付的 SOP 设计（E 期：从需求到 MR）

### 文献结论

**MetaGPT**（Hong et al., 2023, 2308.00352）：核心创新是把人类软件工程的标准作业程序（SOP）编码进 agent prompt 序列。角色分工——PM 产 Product Requirements Document → 架构师产 Design Document → 开发写代码 → QA 写测试。每个角色产出结构化文档作为阶段闸门，下游角色必须消费上游文档而不能跳过。文档格式标准化（统一用 Markdown 模版），减少了幻觉级联。

**SWE-agent**（Yang et al., 2024, 2405.15793, NeurIPS 2024）：提出 Agent-Computer Interface (ACI) 概念——给 agent 设计专用界面而非让它用人类 IDE。核心设计元素：自定义命令（如 `edit` 代替 `sed`）、文件查看器（只显示相关行号而非整文件）、简洁的状态提示。SWE-bench pass@1 = 12.5%。启示：交接物不应是自然语言文档，而应是**机器可解析的结构化记录**。

**FlowGen**（Lin et al., 2024, 2403.15852, ICSE 2025）：对比了三种软件开发流程——Waterfall、TDD、Scrum——用 agent 模拟。结果：Scrum（迭代+每日站会+回顾）在代码质量上显著优于其他流程，Pass@1 达 75.2（HumanEval）。设计和代码评审阶段对减少 code smell 和增加异常处理贡献最大。

**ANNEAL**（Hakim et al., 2026）：提供了"交接物需要带完整溯源"的论据——每次修改带 provenance（谁改的、基于什么证据、什么时间），出问题可以精确回滚到上一版本。

### 对 E 期的设计建议

交接物建议三层：(1) **PM→开发**：结构化需求卡片（不是自由文本），包含功能描述、输入/输出契约、边界条件清单，每条可独立验证；(2) **开发→QA**：除代码 diff 外附带一份"自测覆盖清单"——改了哪些文件/函数、每个改动对应的场景、哪些场景因环境限制未测。QA 拿着这份清单做补充测试而非从头猜测；(3) **统一阶段闸**：每个阶段产出一个 JSON/Markdown artifact 存入任务目录，下游必须在 prompt 中引用上游 artifact 的摘要才能开始工作，引用失败则闸止。artifact 带版本号和溯源（变更人 + 时间戳），回滚时按版本号逐级回退。

## D/E 期设计原则汇总

1. **自我评价必须结构化，禁止自由打分**：用 rubric 拆成 pass/fail 机械验证项，不用 LLM 给 1-5 分。
2. **反思者与执行者分离**：至少用不同的 system prompt；预算允许时用不同模型路由。
3. **失败分类是重试的前提**：瞬时错误退避重试、逻辑错误进反思链不重试、同类错误 3 次熔断。
4. **自唤醒必须带 kill switch 和硬上限**：最多 3 次、用户可随时取消、每次醒来先自检。
5. **交接物 = 结构化 artifact，不是聊天记录**：JSON/Markdown 模板，带版本号和溯源，下游工作必须先引用上游 artifact。
6. **阶段闸用 artifact 引用验证，不靠 agent 自觉**：缺少上游 artifact 摘要则系统层拦截，不进入推理。
7. **"不退化才升级"适用于所有自主能力**：新策略/新记忆提交前必须有 hold-out 验证，退化即回滚。
8. **痕迹可回滚优于痕迹完美**：每次变更带溯源，出错时按版本号精确回退到上一个已知好的状态。
