# DevDesk 技术能力清单

> 截至 2026-10-21 · 以源码与 CI 实测为准

## 1 语言与构建

| 项 | 内容 |
|---|---|
| 语言标准 | C++20（CLAUDE.md 口径；spec 旧记 C++17 已过期） |
| 构建系统 | CMake 4.3.3+，生成器固定 Ninja |
| 编译器 | macOS: AppleClang（Xcode CLT）；Windows: MSYS2 MinGW64 g++ 16.2.0 |
| 多平台 | macOS arm64（当前日常开发）· Windows 11（原生支持，非移植目标） |
| 编译缓存 | ccache 持久配置（平台专属路径），worktree 热命中 99.2% |
| 一体化脚本 | `scripts/build-test-run.sh`——构建 / 全量测试 / probe / 发布形态守卫 / 模块隔离守卫 / 静态守卫自检 全链一条命令 |

## 2 框架关系

| 项 | 内容 |
|---|---|
| 来源 | `../EUI-NEO/`，同级目录源码依赖，通过 `add_subdirectory` 集成 |
| 非 submodule | CI 每次 `git clone --depth 1 <fork>` 取框架，不锁版本 |

| 推送路径 | `origin`（上游 sudoevolve/EUI-NEO）永不 push；`fork`（coderstory/EUI-NEO）可推 |

## 3 UI 与渲染能力面

以下口径取自 `docs/EUI-NEO-CAPABILITIES.md` 源码审计（2026-09-20），分为可用的和不可用的。

### 可用的

- 基础容器：row / column / flow / stack / loader / rect / text / image / svg / polygon / shadertoy
- 表单控件：button / input（多行+IME+选区+撤销重做） / checkbox / radio / switch / slider / stepper / progress / segmented / tabs / dropdown / datePicker / timePicker / colorPicker
- 导航容器：navbar / sidebar / dialog（模态+遮罩） / toast（单实例无队列） / tooltip / contextMenu / carousel
- 数据展示：dataTable / lineChart / barChart / pieChart / markdown（md4c） / virtualList / virtualMasonry / scroll / scrollView
- 样式：任意 hex 颜色+透明度 / 单色边框+圆角 / 外阴影+内阴影 / 2 色渐变（仅水平/垂直） / transform 2D+3D
- 字体：FreeType 加载 TTF/OTF + 系统 fallback（macOS 苹方 / Windows 微软雅黑 / Linux Noto CJK）
- 图标：FontAwesome codepoint + Unicode Emoji + SVG 栅格化
- 交互：onTap / onPress / onDrag / onScroll / onContextMenu / onKeyEvent / onFocusChanged / clipboard / IME
- 多窗口：`app::openWindow`
- 动画：transition（8 种 easing + 位掩码属性）+ AnimatedValue + SmoothedValue
- 实验性：workshop::cardSlider / heartSwitch / neumorphicButton / tiltCard

### 不可用的（须绕开）

- **OS 文件拖入**——无 onFileDrop，"+"新建按钮 + openFileDialog 替代
- **drop target API**——跨元素拖放用 onDrag 回调自实现（W8 Todo 已落地）
- **macOS Liquid Glass / vibrancy**——用实色 + 阴影替代（Windows 磨砂已可用）
- **tree 组件**——用 virtualList + "▶/▼" 字符自实现
- **全局 OS hotkey**——窗口失焦收不到键盘事件
- **fontWeight 运行时真切换**——只打包 Bold 一份字重，SemiBold/Medium 无效
- **托盘自定义菜单**——硬编码 Show/Exit
- **Toast 队列**——单实例
- **Collapse / Accordion / skeleton loader / Tab 焦点循环**——均不支持
- **onResize / onMove 回调**——靠 screen 参数变化触发自适应

## 4 存储

| 项 | 内容 |
|---|---|
| 数据库 | SQLite3，单连接 + 全局递归锁 |
| 全文检索 | FTS5（tokenize=unicode61 remove_diacritics 2），Markdown 笔记全文搜索 |
| Schema 管理 | 单份幂等 DDL（`schema.h` 的 `kSql`），不设版本化迁移链 |
| 补列迁移 | `addMissingAgentColumns`：PRAGMA table_info 逐列补缺，老库不丢数据 |
| 配置入库 | 六类 JSON 配置全部迁入 `app_config` 表；唯一留在文件系统的是 `~/.claude/settings.json`（Claude Code 接管契约） |
| DB 启动备份 | `Database::open` 先备份库文件再 apply schema |
| 数据库门面 | `core::Database` 封装 open → migrate → db()；`appDatabase()` 进程级共享 |

## 5 网络

| 项 | 内容 |
|---|---|
| HTTP 客户端 | libcurl（同步 + 流式 chunk 读取 + 指数退避重试） |
| HTTP 服务端 | cpp-httplib（header-only，本地代理用） |
| 本地流式代理 | 三线程架构（cpp-httplib worker ← 队列 → libcurl connection），SSE chunk 透传 |
| 上游方言归一 | 按 base_url host 推断 + 显式 `dialect_override`（opencode_zen / anthropic_default） |
| failover | `fallback_profile_id`——0..1 单跳备用供应商，不换第三家 |
| 直连客户端 | `DirectLlmClient`——不经本地代理，按激活 profile 直发 `POST {baseUrl}/v1/messages`（智能体路径） |

## 6 安全

| 项 | 内容 |
|---|---|
| 凭据保护 | 平台拆分：macOS/POSIX = 明文列 + 库文件 `0600`；Windows = DPAPI 密文 hex 文本 |
| 钥匙串 | macOS Keychain / Windows DPAPI——仅作启动时一次性残余清理，不作为凭据主存储 |
| settings.json 接管 | DevDesk 是终局 owner，`ANTHROPIC_AUTH_TOKEN=PROXY_MANAGED` 标记归属；cc-switch 过渡期并存不做兼容 |
| 代理认证 | 启动时生成 32 字节 base64 随机 token，`Authorization: Bearer <token>` 校验 |
| API key 脱敏 | UI 侧只用 `api_key_hint`（前 6 + *** + 尾 4），全量 SHA256（`api_key_check` 判密钥变更） |

## 7 测试与质量

| 项 | 内容 |
|---|---|
| 测试框架 | 自制迷你框架（`REGISTER_TEST` 宏 + `DOCTEST_CHECK/REQUIRE` + fail-fast），非真 doctest |
| 真窗口探针 | 4 个 probe（home / screenshot / dropdown z / module toggle sidebar），ctest -L probe |
| 覆盖率工具 | macOS: llvm source-based coverage（`scripts/coverage.sh`，首批基线 DevDesk 合计 87.1%）；Windows gcovr 为欠账 |
| 模块隔离守卫 | `scripts/check-module-isolation.sh`——module_* 互不依赖的静态检查 |
| 静态守卫链 | 模块隔离 + 探针跳过登记 + Windows 交叉编译 + std include + ToolGuard 双层花括号 + 守卫自检 |
| CI | `.github/workflows/ci.yml`：push dev / PR → dev·master 触发；macOS xcode-27 + Windows windows-2025 双平台 |
| 覆盖率目标 | core ≥90% / Service ≥80% / Platform ≥70%（spec §12.3；core 79.5% 未达标） |
