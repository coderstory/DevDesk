# 正式 PDF 调研报告构建规格

> 2026-10-21 定稿 | 触发：用户要求"全部处理完毕后生成正式 PDF 报告，纯技术+结合本项目，传统风格、图文并茂、避免 AI 味、可读性第一；不清楚怎么写就看别人的报告和论文怎么写"
> 执行时点：08-12 全部融合进 05/00 之后

## 一、格式依据（不自行发明）

- **骨架**：国标《科学技术报告编写格式》（GB/T 7713 类）——封面、摘要（含 3-5 个关键词）、目次、引言、正文章节编号（1 / 1.1 / 1.1.1）、图表按章编号（图 2-1、表 3-2）、结论、参考文献、附录
- **白皮书实物参照**：阿里《AI Agent Handbook》的组织方式（分篇/章/图/表/贯穿案例）——结构已拆解于 12 号报告
- **论文行文参照**：arxiv 惯例（10 号报告中文献）——摘要给结论、正文给证据、每个数据结论带出处
- **参考文献著录**：编号列表 [1][2]…，正文引用处标号，条目含：作者/机构. 标题. URL（抓取日期）

## 二、报告结构

**总原则（2026-10-21 用户强调）：报告不是六份调研的拼接，是调研结论的整理重组——先输出整理好的结论，再与本项目计划相结合。** 按主题组织（不按报告罗列）；禁止「XX 报告说……」式流水账，结论融入正文、出处一律走引用编号 [n]；每章开头一段「本章要点」。

## 四、风格红线（逐条对表验收）

1. 黑白灰 + 深蓝线条，零渐变、零玻璃、零色块装饰、零动画
2. 无 emoji、无感叹号标题、无"赋能/抓手/亮点"式营销腔；通篇调研报告体
3. 段落行文为主，列表只用于真并列项；每图有编号+图注，每表有编号+表题
4. 每个数据结论正文标 [n] 引用，对应附录 A
5. 术语首现括号一句人话（与 GLOSSARY 一致）
6. A4 纵向、正文宋体系/标题黑体系、1.5 倍行距左右、页码页眉

## 五、技术管线

1. 内容素材：docs/strategy/ 全套（00-12）+ GLOSSARY.md + docs/adr/*
2. 构建方式：自包含打印版式 HTML（A4、分页控制）→ 无头 Edge `--print-to-pdf` 渲染 → 校验页数与体积
3. 交付：输出 `DevDesk智能中枢技术调研报告.pdf`，**必须复制到 D:\Data\desktop\**；HTML 源放 docs/strategy/report/（随基线一并定账）
4. 验收自查：图表齐全（以第三节图表清单为准）、**全部图整幅落在版心内无截断——每张 SVG 必须自适应页面宽度（CSS figure svg{max-width:100%;height:auto} + viewBox 缩放，用户实测 v1 曾有图超宽被裁，此为硬红线）**、引用编号闭环、术语零黑话、页数约 25-38 页、文件 ≤15MB

## 六、构建纪律

- 构建代理先读本规格 + 00-12 + GLOSSARY + ADR，再动笔；先写全文再排版
- 禁外部资源（字体/图/CDN 全零）；图全部内嵌 SVG 手绘（标准符号）
- 我方审计：结构对表（五章+附录齐全）、图表计数、引用抽查、桌面副本核对
- 用户验收：可读性肉眼把关（视觉类风险已知，规格已锁死传统版式以降险）
