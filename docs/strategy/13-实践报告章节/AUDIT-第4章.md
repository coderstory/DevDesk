## 二、Findings 清单

### 【必改】共 6 条

**F4-1 测试数字口径跨章不一致 + 缺日期（4.2 阶段4，L87）**
- 问题：成稿写"全量约 1630 多条测试"，第 1/2 章写"约 1600+ 条（截至 2026-10-19）"，数字与口径均不一致，且未按大纲铁律标注日期。
- 建议："全量约 1600+ 条测试（截至 2026-10-19）"。

**F4-2 阶段 3 判据收窄（4.2 阶段3，L71）**
- 问题：成稿写"关键维度（如被标记为回归面或静默失败的 finding 修复后）复查通过"。CLAUDE.md 原判据是"相关维度已由审计方（或另一个独立子任务）复查通过"——未限定"关键维度"。成稿将复查范围从"所有相关维度"收窄为"关键维度"。
- 建议：改为"所有相关 finding 的修复结果由审计方或另一个独立子任务复查通过"，不区分关键与否。

**F4-3 "编译器的配置阶段"表述不准（4.2 阶段5，L99）**
- 问题：f274f74 事故是 cmake configure 失败，cmake 是构建系统配置工具，不是编译器。写成"编译器"会误导读者以为 GCC/Clang 出了故障。
- 建议："集成分支当场无法通过构建系统的配置阶段（cmake configure 失败）"。

**F4-4 "索引损坏"属推测性添加（4.3 调度纪律，L97）**
- 问题："导致合并失败甚至索引损坏"——CLAUDE.md 只写"撞 index.lock 导致合并失败"，index.lock 是 git 的并发互斥锁，冲突只阻止同时合并，不损坏索引。成稿添加了源没有的后果。同类型反例：本报告写作铁律要求"每条原则必须有推演过程"，但不允许凭空添加未发生的后果。
- 建议：删除"甚至索引损坏"，改为"导致合并失败"。

**F4-5 图 4-1 中文字号大面积低于 12px（SVG）**
- 问题：菱形决策点文字 6px、活动标签 7-8px、泳道副标题 8-9px——均低于大纲"中文 ≥ 12px"的图规。此图是 print 关键图，小字在 A4 上不可读。
- 建议：将所有正文标签字号提升到至少 12px。如果 layout 空间不够，扩大 viewBox（如 500→700 宽）并等比例放大所有字号；或精简标签文字使更大字能放入。图注类文字可保持 9-10px。

**F4-6 图 4-2 中文字号大面积低于 12px（SVG）**
- 问题：与图 4-1 同——槽位副标题 7px、排队标签 8px、图注 8px。8 个并发槽的副标题（"笔记模块""设置页diff"等）7px 在 print 上不可读。
- 建议：与图 4-1 同步调整。可将 8 槽行高增加、字号升至 12px，排队行随同调整。

### 【建议】共 6 条

**F4-7 阶段 4 漏判据：实现者交付前截图自查（4.2 阶段4，判据段）**
- 问题：CLAUDE.md 阶段 4 判据含"凡改动涉及可见 UI 的，实现者必须交付前自己启动 app、打开窗口、截图看效果"。此条不等同于阶段 6 用户验收——它是实现者的交付前自查，防止交付"肉眼一看就错"的版本。成稿阶段 4 测试段未提及此条。
- 影响：中——实现者的自查环节被跳过，交付物视觉质量完全依赖阶段 6 用户发现。
- 建议：在阶段 4 末尾（交付前三问之后）补一句："涉及可见 UI 的改动，实现者还必须在交付前自己启动应用、截屏确认'看起来对'——数值断言能证明坐标对，证明不了'看起来对'。"

**F4-8 "修复合并 ≠ 交付"未标注日期（4.2 阶段5，L102-103）**
- 问题：成稿以自然语言表达了同义概念，但 CLAUDE.md 标注增补日期为 2026-10-19。本报告铁律要求数字/纪律带日期，以帮助读者理解纪律的演进时间线。
- 建议：在相关句末加"（2026-10-19 增补）"。

**F4-9 阶段 2 判据收束处漏"审计者非实现者"（4.2 阶段2，判据收束段落 L63-64）**
- 问题：正文判据收束段（"审计产出是一份结构化的发现清单……六个维度必须逐条给出结论……空着就是没审"）仅覆盖了"六维度全答"和"file:line"两条判据，漏了"审计者非实现者则审计无效"这一条。此条在表 4-1 的判据列有（"审计者非实现者"），在正文"谁做"段有（L43-44），但在"通过判据"收束处没有复述。读者只看正文判据段会漏掉这个硬条件。
- 建议：在 L64"空着就是没审"后补一句："如果审计者和实现者是同一个 AI 会话，则审计无效——不管六个维度答得多完整。"

**F4-10 "index.lock"未做白话解释（4.3，L97）**
- 问题："撞 git 的索引锁（index.lock）"——"索引锁"对非技术读者不够直白。index 在 git 里指什么？lock 是什么意思？与外行的直觉（"锁门锁车"）对应不起来。
- 建议：改为"撞 git 的并发锁（index.lock——git 用来防止两个人同时操作同一份数据的临时文件，同一时刻只允许一个人修改）"。

**F4-11 "configure"首现未按铁律解释（4.2 阶段5，L99）**
- 问题：非技术读者看到"配置阶段（configure）"不知道这步在做什么。configure 是 cmake 读取构建描述文件、检查编译器与依赖库是否就绪、生成构建计划的步骤——这些语义不是"配置"两个字能自然传达的。
- 建议：加一句解释："configure 是构建工具（cmake）的第一步——检查编译器和依赖库是否就绪、把'哪些文件要编译、按什么顺序'生成一份清单，这步不通过后面编译也无从谈起。"
