## 三、案例 4 事实核验

### 3.1 "装载时机"坑的文档落点（必改）

**成稿 L129-131 声称**："补上了部署步骤中的一条关键提示：'hook 配置变更后必须重启会话验证生效'"，以及"每一个环节都有对应文件的 git 历史可查"。

**实查结果**：
- CLAUDE.md 中搜"装载时机""重启会话.*生效"→ 0 命中。
- CLAUDE.md L299 唯一相关表述为"改 hook 配置须走子任务 + 管道实测（合成 stdin 喂脚本验证两条路径），不许只改不测"——这是"测试方法"，不是"装载时机需重启"的部署提示。
- "装载时机"这个术语与"重启会话验证生效"这条具体规则，仅存在于本报告的大纲和章节成稿自身，未在任何项目文件的规则正文中落盘。

**裁定**：成稿把"管道实测"（测试法）夸大为"'重启会话'部署提示已写入文件"——从"已验证出此坑"到"已写进规则文件"中间差了一步。建议改法：如实写"CLAUDE.md 的测试纪律要求 hook 变更必须走管道实测（间接覆盖了装载时机验证），但'重启生效'本身目前是经验认识、尚未作为独立规则条目落盘"。

### 3.2 git 历史覆盖度（必改）

**成稿 L131 声称**："每一个环节都有对应文件的 git 历史可查——…全都在同一天的提交中。"

**实查**：
- `git ls-files` 返回：`.claude/hooks/strategy-guard.sh`、`.claude/settings.json`、`docs/strategy/cumulative-markers.txt`、`scripts/check-cumulative-markers.sh` ——**全部为 untracked 文件**（未进 git）。
- `git log` 对这些文件返回空（无任何提交记录）。
- 唯一有 2026-10-21 提交记录的是 `CLAUDE.md`（commit `39340e75`，其中 L299 包含 hooks 段落）。

**裁定**：成稿说"全都在同一天的提交中"——对 5 个文件中的 4 个而言是假陈述。建议改法："CLAUDE.md 的 hooks 段落已在 2026-10-21 提交（commit `39340e75`）；其余文件作为配套基建存在于工作目录中，尚未独立进 git 历史。"
