## ④ 技术判断成立性

**(a) 协议适配缝约一天工作量** → **成立**。现有工具注册表（src/module_agent/）结构已定，追加一个 protocol 字段 + 新建 ProtocolAdapter 抽象类（初始仅 identity 适配器），在 C++ 侧不超过 3-4 个文件的 touch。一天工作量合理。

**(b) 十态升级的兼容成本** → **成立**。当前 agent_runs.status 是 `std::string`（值域：running/completed/failed/limited/cancelled，agent_store.h:25），非枚举。新增五态只需追加新字符串值、更新所有 switch/if 分支与 UI 渲染（runStatusText/statusDotColor），不涉及 schema 迁移。主要工作量在消费者端枚举，架构上无破坏性。

**(c) webhook 推本地 HTTP 服务** → **成立**。09 报告明确推荐此方案且 DevDesk 平台层已有 HttpClient/HttpServer 基建。桌面应用开本地端口监听有限（仅接收 GitLab POST）、HMAC-SHA256 验签标准化，技术上无梗阻。

**(d) 无进展检测可落地性** → **成立**。四条信号全部可在 agent loop 状态机内观测——工具调用历史（记录连续相同 tool+param）、错误计数（按 error type 分类累加）、plan 时间戳（比对距上次更新）、工作区文件变更（已有事件触发机制可复用）。C++ 实现无非确定性依赖（不涉及 LLM 推理、不涉及异步外部状态），纯状态计数+时间比对即可。

**(e) 预算租约"父停子停"** → **成立，附条件**。当前 Scheduler 在 agent_module.cpp 按任务调度，有 startRun/finishRun 生命周期管理。租约需在 task/run 记录上新增 parent_task_id（或 parent_run_id），父任务终止时级联失效子任务预算。现有基础设施（预算上限、限时、限次）足以支撑，新增字段 + 级联逻辑为可估量工作量（约 2-3 天含测试）。附：租约的"四维限定"（资源上限/操作范围/有效期/撤销方式）中后三者需要 info 层 schema 扩展，建议与 D 期委派体系一并设计、不全塞进 A 期。
