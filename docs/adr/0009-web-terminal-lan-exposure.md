# ADR 0009：网页终端默认关闭、开启后明文 HTTP + 扫码绑定与 TOTP 鉴权

终端模块新增网页访问：把 tab 列表、终端配置与终端主窗体搬到网页，供局域网访问、移动端适配，主要用途是在手机上跑 claude code。本 ADR 只讨论暴露面与鉴权。

## 决策

1. **默认关闭**：网页终端不随应用启动自动开启。
2. **监听范围**：开启后监听全部网卡（`0.0.0.0`），默认端口 `7878`，可配置修改。
3. **传输**：明文 HTTP，不启用 TLS。
4. **鉴权**：扫码绑定 + TOTP 六位码，不设口令。桌面端生成一次性二维码，扫码即完成设备绑定；此后每次登录输入验证器应用生成的六位码。
5. **本机访问**：来自本机回环地址的请求免验证，视同桌面端自身操作。
6. **单设备绑定**：同一时间只允许一台设备绑定，换设备须先在设置页解除绑定。
7. **登录节流**：登录失败 5 次后锁定 1 分钟。

## 理由

- **默认关闭 + 强制鉴权**：这是把本机 shell 暴露给局域网，风险极高，不能以「局域网可信」为前提默认开启。
- **扫码绑定作为第一因子**：二维码只显示在桌面屏幕上，扫码的前提是物理上能看到这台机器——这就是第一因子的证明。绑定令牌一次性、5 分钟有效，限制其被转发的价值。
- **TOTP 作为第二因子**：绑定后每次登录都要求验证器动态码，绑定凭证泄漏不足以接管终端。
- **口令方案被否**：手机上输入长口令不可行，实际必然越设越短，安全收益低于其带来的操作摩擦。
- **自签 TLS 被否**：手机浏览器对每台新设备都要手动信任自签证书，体验代价高于收益；风险由「默认关闭 + 鉴权」控制。

## 已知代价

局域网为明文传输：同网段可在网络层嗅探到会话 cookie 与终端内容。若使用环境不可信（公共 / 共享 Wi-Fi、不可控网段），须改用 TLS——协议形态不变，可在同一端口叠加 TLS，不影响本 ADR 的鉴权与暴露面决定。

## 范围

只讨论暴露面与鉴权。渲染形态、前后端协议细节不在本 ADR 内。
