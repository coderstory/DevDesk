# ADR 0010：网页终端应用层每会话加密（HTTP 层仍明文）

Status: accepted

Date: 2026-11-23

Supersedes: ADR 0009 第 3 条（明文 HTTP、不启用 TLS 的传输决策）；鉴权与暴露面仍以 ADR 0009 为准。

## 背景

网页终端把本机 shell 暴露到局域网。ADR 0009 原定明文 HTTP，独立审计（need#490，P0-1～P0-3）指出：明文下同网段被动嗅探可见终端内容、TOTP 码、TOTP 密钥、绑定令牌与会话 cookie，拿到 7 天 cookie 即可接管终端。老板 2026-11-23 裁决：HTTP 层保持明文，新增应用层每会话临时密钥协商与 AEAD 加密；目标是挡住同网段被动嗅探，明确不防主动 MITM；界面不得宣传「安全加密」。

## 决策

1. **每连接一次临时密钥协商**：客户端每次建立网页连接时生成一次性 X25519 密钥对，与服务端一次性 X25519 密钥对做 ECDH；服务端每个连接使用新的临时密钥。
2. **密钥派生**：HKDF-SHA256，盐由服务端在握手响应中给出，`info` 带方向标签（client→server / server→client），派生两条独立 256 位密钥。
3. **加密算法**：AES-256-GCM（OpenSSL 已在两平台链接）；每个方向独立 64 位计数器 nonce，连接建立时从 0 开始，禁止复用同一密钥+nonce。
4. **帧格式**：HTTP body 内承载加密帧（版本号、计数器、密文与认证标签，文本层以 base64 承载）；认证失败即丢帧并断开，不采用任何降级。
5. **凭据只在密文内**：TOTP 六位码、TOTP 密钥（`otpauth`）、绑定令牌、会话票据只出现在 AEAD 加密帧或 URL `#` 片段（片段浏览器不发送）中；不使用 Cookie / Authorization 头承载鉴权凭据。
6. **推送通道**：沿用 SSE（GET）。客户端先在加密通道内申请一次性「流票据」（60 秒有效、单次、只读），再以查询参数打开 SSE；流内所有事件均为 AEAD 密文。输入与普通请求走加密 POST。
7. **无明文回退、无版本降级**：握手失败或不支持加密版本时拒绝进入登录 / 绑定 / 终端界面，只给错误与重试入口。
8. **重连即重协商**：断线重连生成新的临时密钥并重新握手；跨连接不复用密钥。v1 不在长连接中途重协商。
9. **威胁模型边界**：
   - 防：同网段被动嗅探（抓包看不到 TOTP、密钥、令牌、票据、终端内容与输入）。
   - 不防：主动 MITM、ARP / DNS 欺骗、连接劫持、浏览器或本机被控、流量分析（帧大小与时序）、主动重放（含 60 秒内重放流票据——只能打开一条读不到明文的只读流）。
   - 明文可见：HTTP 请求行、静态资源、握手公钥、SSE 流票据查询参数。
   - 文案约束：界面只可写「会话加密（不防主动中间人）」，禁止「安全加密」「银行级」等宣传语。
10. **范围**：只决定传输层加密。暴露面、绑定与 TOTP 鉴权、默认关闭等仍按 ADR 0009。

## 被否决的备选

- **扫码下发长期密钥**：密钥可能被拍照 / 截屏捕获一次即永久冒用，且无前向保密；虽实现简单，但把一次性物理在场证明退化为长期秘密。
- **TLS / 自签证书**：手机对每台新设备手动信任证书，体验代价高于收益（ADR 0009 已否），且老板裁决明确不上 TLS。
- **维持明文**：审计 P0 阻塞，同网段可被动读取屏幕与凭据，不可接受。
- **口令 / PAKE**：无口令方案（ADR 0009），PAKE 不适用；引入口令会带来弱口令与找回问题。

## 已知代价

- **不防主动 MITM**：能劫持连接的攻击者仍可冒充服务端或注入；本决策只提高被动窃听门槛。
- **文本承载开销**：SSE 文本流以 base64 承载密文，体积约增加 1/3；最坏帧体积需技术卡按密文后重算，推送预算相应调整。
- **实现复杂度**：握手状态机、方向密钥与 nonce 管理、流票据、认证失败处理、测试缝均需新增；加密错误路径不能回显内容。
- **可调试性下降**：抓包不再可读，排障依赖不含秘密的结构化日志；不提供明文调试开关（避免误用）。
- **仍为 bearer 语义**：会话票据被主动窃取或重放不受本层保护，属于威胁模型外。

## 影响

- 前端与后端所有 API 请求 / 响应改为加密帧；静态资源仍明文。
- 技术卡需补：握手协议版本与错误码、nonce 与重放窗口、握手限流、流票据生命周期、密钥生命周期、加密测试向量与抓包验收。
- PRD v4 的 F-25（密钥协商与加密帧）、F-26（凭据保护）与 S-24～S-27 为验收口径。
