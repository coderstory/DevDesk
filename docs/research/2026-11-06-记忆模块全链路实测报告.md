## 3. 问题清单

### FIND-159-1（P2·易用性：镜像源只有环境变量一条路）
- 现象：从零安装在本机网络下，官方 PyPI 600s 超时必现（`01-install.log` t+597s Failed）；失败文案指引「可在环境变量 PIP_INDEX_URL 配置镜像源后重试」——透传缝本身验证有效（设 `PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple` 后 55s 装完，`01-install-mirror.log`），且 Failed 后重试正确复用已建 venv。
- 缺口：DevDesk 以 GUI 应用形态启动时，用户要吃到这个环境变量必须从终端带 env 拉起 app——UI 内无镜像源配置项，失败文案给的是普通用户走不通的出口（能达成但明显费力，P2 下限）。
- 建议：主控台安装失败卡片加「镜像源」输入框或预设镜像单选（写 settings，拼进 pip 安装 env），文案与 UI 出口对齐。

### FIND-159-2（记录·配置受限，非缺陷）
- S8 提炼真调（LLM 补标）在哑 key 下 4 断言红（401 类）——脚本约定 `E2E_LLM_KEY` 走真网关，本轮未拿到 key 未重跑。复现命令：`E2E_LLM_KEY=<真key> TELEMEM_PY=<venv> bash scripts/run-memory-e2e.sh`。提炼环节不在本轮 8 环节清单内，如实记「未验证」。

### OBS-159-1（P3·观察项，不立项）
- 真实 140KB 会话首轮只采出 ~175B（2 events）：分段器按水位增量起采属设计口径，但「采集覆盖度」对首装用户偏薄，后续增量轮会补齐。留观不改。
