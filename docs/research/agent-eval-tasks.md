# Agent 评测任务集（活文档）

> 用法：人工每发现一次 agent 产出问题（半成品 / 漏细节 / 注释超标 / 过度设计 / 派发不当），**当次**就转成一条任务追加到此处。任务全部来自真实失败，不接受想象任务。改过 agent 定义后，抽相关任务复测。
> 判分优先确定性手段（grep / git diff / 测试结果 / 文件存在性）；主观项用 rubric，标注「需人工校准」。
> 每条任务入库前自检：正确执行的 agent 能通过吗（有参考解）？两个懂行的人会得出同一结论吗？

## 任务来源

- v0（2026-10-28）：来自用户对开发流程的系统性批评（需求漏状态、UI 失守、凑覆盖率、闭门造车、过度设计、注释膨胀、成本失衡等），逐条转化 14 条；同日补充 B5 / D4（技术方案卡、POC 实证两条后续原则），共 16 条。

## 维护规则

1. 失败驱动入库：实战发现新失败模式 → 当次追加任务，附原始案例。
2. 双向平衡：每类角色至少一条「不该做」的反向任务。
3. 毕业机制：某任务连续 5 次全过 → 标记为回归任务（只防倒退，不再作为能力信号）。
4. rubric 校准：B2/C3 的主观判分首批与用户判断对齐后才可依赖。
