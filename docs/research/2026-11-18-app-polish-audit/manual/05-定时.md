# 05 定时（Schedule 模块）用户手册

> 依据源码实况编写（2026-11-18）：src/module_schedule/。cron 表达式为六种规则类型之一（「表达式」），编辑已有 cron 规则时表达式不回显（v1 已知限制，`schedule_ui_edit.cpp:393-395`）。

## 一句话

侧边栏「定时」管理定时规则（一次性/间隔/周期/表达式/事件/常驻六类）：触发后按动作仅提醒、提醒并打开、静默执行或仅投递到企业微信；运行历史可在抽屉查看状态、投递明细并重试/重跑；系统级规则只读。

## 入口与前置（模块开关/门控）

- 入口：侧边栏第 5 项「定时」（`src/app_registry.h:54`）。
- 门控：设置页模块开关 `kModuleIdSchedule`（`src/app_registry.h:40,54`）。
- 数据位置：schedule_rule / schedule_run / schedule_delivery 等表存 devdesk.db（`schedule_store.h:20`）。
- 通知渠道：toast=应用内提示、os=系统通知（macOS 通知中心 / Windows 托盘）、fullscreen=全屏提醒（总开关默认关）、silent=静默、wecom=企业微信 webhook（密钥在设置页配置，`channels/wecom.cpp:343-348`）。

## 主流程步骤（编号：操作→预期可见结果）

1. 点侧边栏「定时」→ 页首「定时」标题 +「运行历史」按钮 +「新建」按钮 + Tab「系统定时 / 用户定时」（各带「共 N 个」计数）（`schedule_ui_list.cpp:1094-1126`）。
2. 新建规则：点「新建」→ 弹窗「定时规则」（`schedule_ui_edit.cpp:491`）：
   - 「启用」开关；「名称」placeholder「规则名称」（`schedule_ui_edit.cpp:518-532`）。
   - 类型六选一：一次性 / 间隔 / 周期 / 表达式 / 事件 / 常驻（`schedule_ui_edit.cpp:497-502`）。
   - 按类型的字段：一次性=「触发时刻（YYYY-MM-DD HH:MM）」；间隔=「间隔秒数（≥1）」；周期=「周期单位」每天/每周/每月/每年 +「每 N 周（N≥1）」+ 周几勾选（周日至周六）+「锚定日期（其周几须在所选周几中）」+「第 N 天（1..31）」或「第 N 个周几」+「仅工作日（勾选 = 过滤周六日）」+「时刻 HH:MM」；表达式=「cron 表达式（分 时 日 月 周）」；事件=「事件名（逗号分隔）」（`schedule_ui_edit.cpp:544-700`）。
   - 「动作」：仅提醒 / 提醒并打开（参数「打开页面（页面标识[:参数]）」）/ 静默执行（「已注册任务」下拉；空时提示「暂无已注册任务（保存将被拦截）」，「提醒内容取规则名称，无附加参数」）/ 仅投递（`schedule_ui_edit.cpp:725-799`）。
   - 「错过策略」：补一次 / 跳过 / 全部补（`schedule_ui_edit.cpp:802-804`）。
   - 「通知渠道」多选；「接下来 5 次」触发预览（无解时「无下次触发时刻」，`schedule_ui_edit.cpp:817-856`）。
   - 底部按钮「删除 / 保存 / 取消」（`schedule_ui_edit.cpp:876-926`）。
3. 保存校验失败示例文案：「calendar.time 必须为 HH:MM 且小时 0-23、分钟 0-59」「锚定日期必须为真实存在的「YYYY-MM-DD」」「锚定日期 …（周X）不在所选周几中，请调整锚定日期或勾选周X」「每月规则必须选择「第 N 天」「第 N 个周几」「最后一个工作日」之一」「静默执行动作必须选择一个已注册任务」「仅投递动作必须勾选「企业微信」渠道」（`schedule_ui_edit.cpp:127-261,904`）。
4. 行卡信息：类型 chip（单次/间隔/周期/cron/事件/常驻）、调度摘要（如「每天 09:00」「每 30 分钟」「cron <表达式>」「今天 HH:MM」「每月 N 日 HH:MM」）、「下次」时刻、「来源」、「只读」（系统规则）、「上次」执行状态（无则「无记录」）、「已归档 / 已停用」chip（`schedule_ui_list.cpp:59-86,289-380,815,916-1011`）。点击行卡进入编辑（回填表单，`schedule_ui_list.cpp:615-620`）。
5. 启停：编辑弹窗「启用」开关控制；停用后行卡显「已停用」。
6. 运行历史：点「运行历史」→ 抽屉「运行历史」：汇总「共 N 条 · 成功 X · 失败 Y · 错过 Z」（`schedule_ui_history.cpp:456-459`）；每条 run 显示状态（成功/失败/已错过/运行中/待执行/已跳过/已抑制，`schedule_ui_history.cpp:89-109`）、「计划 <时刻>」「实际 <时刻>」「耗时 N ms」「尝试 N」「尚未开始」；投递明细状态（成功/失败/重试中/待投递/已丢弃，`schedule_ui_history.cpp:114-119`），渠道名「渠道 #N」或名称；失败 run 有「重试」按钮（`schedule_ui_history.cpp:195`）；「关闭」退出抽屉。
7. 重试/重跑：历史内失败 run 点「重试」；重跑入口校验失败时提示「重跑入口不可用 / 该运行记录无关联规则，无法重跑 / 重跑失败：<原因>」（`schedule_ui_list.cpp:711-726`）。

## 空态·错误态

- 列表加载失败：「定时列表加载失败：<原因>」；「渠道选项加载失败：<原因>」（`schedule_ui_list.cpp:524,588`）。
- 行卡状态：规则被删后刷新 → 「规则不存在或已删除：<原因>」（`schedule_ui_list.cpp:483,553`）。
- 历史抽屉：「暂无运行记录 / 规则触发后会在此处留下计划与实际执行记录」（`schedule_ui_history.cpp:509-510`）；「运行历史加载失败：<原因>」（`schedule_ui_list.cpp:664-681`）。
- 「上次」无执行：「无记录」。

## 设置项联动

- 模块开关门控；企业微信 webhook key 在设置页配置（keychain 存储，`channels/wecom.cpp:343-348`）；全屏弹窗总开关当前默认关且无设置入口（`channels/fullscreen_channel.cpp:42-46`）；渠道密钥缺失 → 本次投递放弃但不停用渠道（`action_runner.cpp:258-266`）；智能体工具 schedule.runs 查历史（`schedule_runs_tool.cpp:85`）。

## 演练卡壳点

1. 编辑已有「表达式」规则时 cron 表达式不回显、被清空（v1 限制，`schedule_ui_edit.cpp:393-395`）——走查编辑 cron 规则会卡，需重新输入或放弃编辑。
2. 编辑弹窗「删除」是否二次确认未见实现证据，需实操确认。
3. 「系统定时」Tab 规则的来源与「只读」边界（哪些系统规则、能否启用/停用）需实操确认。
4. 「停机错过，不补跑」与「错过策略」的适用关系（哪些规则类型不补跑）需实操核对（`schedule_engine.cpp:311`）。
5. 全屏提醒总开关当前无设置入口（默认关），「全屏提醒」渠道实际不可触发——走查时无法演练该渠道。
