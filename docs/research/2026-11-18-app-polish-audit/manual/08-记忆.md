# 08 记忆

> 手册走查底稿，以源码实况为准（核对基线 commit 64378979，2026-11-18）。记忆模块 = DevDesk 内置 telemem 记忆引擎（Python 子进程）+ 本机面板库；本章把「采集→提炼→审核→入库→检索召回」全链与「记忆审核（审计）TAB」逐项写透。

## 一句话

记忆模块在 Claude 对话时自动采集片段、经云端 LLM 提炼成「提案」，你在「记忆审核」TAB 逐张裁决入库，之后 Claude 对话自动注入检索到的记忆，外部客户端也可经 DevDesk 的 MCP `memory_search` 工具主动查询。

## 入口与前置（模块开关/门控）

- 设置页「模块」卡「记忆」开关**默认开启**（`src/module_settings/settings_config.cpp:122`：引擎未安装时页面只显引导态，零后台成本）；关闭需重启生效。
- 页面结构：页头「记忆」+ 三 TAB（`src/module_memory/memory_module.cpp:108-131`）：
  - `主控台`（kViewConsole）
  - `记忆审核 (N)`——标签实时带待审提案数 N（`memory_module.cpp:121-124`）
  - `配置`（kViewConfig）
- 全部数据落 `~/DevDesk/memory/`（随 `DEVDESK_DATA_ROOT` 隔离，`src/module_memory/engine/telemem_config.cpp:25-27`）。

## 主流程步骤（编号：操作→预期可见结果）

### A. 首次安装（向导全步骤）

1. 进入记忆页 → 主控台顶部「telemem 记忆引擎」状态带：状态点（灰 `未启动`/黄 `准备中`/绿 `运行中`/灰 `已停止`/红 `故障`）+ 右端按钮组（`memory_module.cpp:189-287`）：
   - 从未装过 Python：按钮组直出 `首次安装向导`（Idle + 未检出 Python 时内联直出，`memory_module.cpp:249-282`）。
   - 其余态：`启动引擎`（主操作，右缘对齐）+ `详情`。
2. 点 `首次安装向导` → 弹「首次安装向导」四步清单（`memory_module_modals.cpp:157-296`），底部按钮 `开始安装 / 重试`（安装中显 `安装中…` 且禁用；运行中显 `重新运行安装检查`）：
   - ① `Python 3.10~3.13`：绿 `已检测（<版本>）` / 红 `未检测到——安装后重试` / 黄 `检测中…`。
   - ② `venv + pip 安装`：黄 `进行中…`（显示引擎 detail）→ 绿 `完成`；telemem 依赖链（faiss+numpy+mem0ai）慢网按 10 分钟上限（`src/module_memory/engine/telemem_engine.cpp:34`）。
   - ③ `embedding 本机包`：五态文案（`memory_module_internal.h:237-256`）——`待开始` / `需下载（联网，首次约 26MB）` / `进行中…`（带进度 detail） / `已就位（随包）` / `已就位（数据根）` / `失败：<原因>（可重试）`。
   - ④ `引擎拉起与健康检查`：绿 `运行中（127.0.0.1:8421）` / 红 `失败（见下方说明）` / 黄 `进行中…`。
   - 完成态正文：「安装完成，记忆引擎已在后台运行。关掉本向导即可正常使用。」；失败态正文：「安装失败：<原因>（可点「开始安装 / 重试」再跑一轮）」。
   - 向导说明句：「本向导将检测 Python、创建虚拟环境并安装 telemem，检查 embedding 本机包（llama-server + 模型）就位，全程只写数据目录。」
3. 点 `关闭` 收向导；引擎 Running 后主控台状态带变绿。
4. embedding 模型下载：流式下载不看总墙钟，**空闲超时兜底**——低于 8KB/s 持续 30 秒判死，报「下载中断: <原因>」（`src/module_memory/engine/llama_host.cpp:25,188,230`）。

### B. 配置（提炼端点与 key、触发线、告警）

1. 切「配置」TAB → 四个折叠组（组头带实时摘要，点击整行展开/收起，`memory_module_panels.cpp:994-1050`）。
2. **组 0「提炼端点」**（未导入时组头黄字摘要「未导入——提炼不可用」）：
   - 点 `从 DevDesk 网关一键导入当前 profile` → 把 Claude 页当前激活 Profile 的端点绑定为提炼端点，toast「已导入：端点绑定已生效，引擎启动时写入 TELEMEM_CONFIG」；只回显端点/模型、**不回显任何密钥**（`memory_module_panels.cpp:1076-1126`）。Claude 页没有激活 Profile 时 toast「导入失败：网关 profile 服务未装配（请先在 Claude 页配置并激活 profile）」。
   - **提炼 API key（本机钥匙串）**：未配置 = 引导句「尚未配置——粘贴 API key，仅存本机钥匙串，不写配置与日志。」+ 输入框（占位 `sk-…（智谱 API key）`）+ `保存`；已配置 = 掩码回显 + `修改` / `清除`（清除 toast「已清除：提炼 API key 已从钥匙串删除」）。key 通道 = 钥匙串服务 `devdesk.memory`（`src/module_memory/engine/telemem_config.h:63`），引擎启动时经环境变量 `ANTHROPIC_API_KEY` 注入子进程（`telemem_config.h:25-27`），配置文件里 api_key 恒为空串（`telemem_config.cpp:29-34`）。
   - **向量化端点（本机）**：只读行 `llama-server · http://127.0.0.1:11435 · 模型 <kEmbedModel> · 1024 维（换档 = 全量重嵌）`（`telemem_config.h:14`，端口常量；模型/维数常量见 `telemem_config.h`）；警示条「记忆原文不出机：向量化全部落本机（零 API 费）。」
3. **组 1「触发线」**：`升级阈值` 滑条（60~95%，说明「Recall@5 低于此值时提醒（红线 85%）」）+ `两字词提炼基线 · 命中次数` 滑条（2~10 次）+ 基线磁贴「命中 5 次 → 候选 / 复现 3 轮 → 确认 / 11 天窗口内有效」（`memory_module_panels.cpp:1256-1403`）。
4. **组 2「用量告警」**：三条滑条——`日档阈值`（默认 50 万）、`月档 · 软档`、`月档 · 硬档`；说明「今日/本月 token 越线弹一条桌面提醒（每档每天最多一条）；月档软/硬即消耗带预算。」；口径警示「token 为码点估算（非引擎真值）；判定面 = 记忆消耗账本。」（`memory_module_panels.cpp:1405-1510`）。
5. **组 3「安全与隐私」（常显不折叠）**：
   - 脱敏开关（默认开）：开 → toast「脱敏已开启：出机前自动清除敏感信息」；**关 → 弹「确认关闭脱敏？」红色二次确认**（正文见弹窗清单），确认后 toast 警告「脱敏已关闭：内容将原样出机，用完请尽快重新开启」。
   - 数据行：路径盒显示 `~/DevDesk/memory  ·  <体积>`。
   - `导出全部记忆（JSON）` → 落盘数据目录（文件名 `devdesk-memory-<时间戳>…`），toast「已导出：<路径>」（`panel_state.h:119`、`panel_state.cpp:757`）。
   - `清除全部…`（红）→ 弹「清除全部记忆？」需输入「清除」二字武装确认钮；成功 toast 明示「面板库已清空（引擎侧记忆不在本操作范围）」（`memory_module_modals.cpp:98-155`）。
   - 页脚灰注：「引擎侧记忆清空需引擎列举接口（A 阶段未暴露），清除全部只清本机面板库。」（`memory_module_panels.cpp:1600-1607`）。

### C. 采集→提炼→审核→入库→召回全链

1. **采集**：引擎 `运行中` 期间，F1 背景采集循环自驱（引擎停则停，页不打开也随引擎停而停），把 Claude 对话片段写进采集库（`src/module_memory/panel/panel_state.h:127-133`）；未经提炼的片段会以「原始片段（未分类）」形态出现在审核 TAB（bug184 诚实降级口径）。
2. **提炼**：后台管线把片段送云端 LLM（组 0 配的端点 + 钥匙串 key，经脱敏闸）→ 产出四类**提案**：新增 / 遗忘 / 失效（标记过期）/ 合并；每条带置信度、来源（Claude 对话 / 整理 / 遗忘扫描）与证据链。
3. **审核（审计 TAB 到底显示什么）**——切「记忆审核 (N)」TAB：
   - **工具条**：`类型` 下拉（全部/合并/失效/遗忘/新增）+ `来源` 下拉（全部来源/Claude 对话/整理/遗忘扫描）+ 状态 chips `待审` / `已处理` + 右端 `批量处理` 按钮（窄窗 <860 时 chips 折第二行，`memory_module_panels.cpp:713-832`）。
   - **待审列表 = 提案卡流**（每张 176px 高，`memory_module_panels.cpp:385-609`），一张卡从上到下：
     - 类型徽章（`新增`/`遗忘`/`失效`/`合并`，语义色 pill）；
     - 标题行：`新增记忆：<正文>` / `遗忘过时记忆：<原文>` / `标记过期记忆：<原文>` / `合并重复记忆：<正文>`；未经 AI 提炼的 add 卡显 `原始片段（未分类）：<片段>`（`memory_module_panels.cpp:466-479`）；
     - 右端摘要：`置信度 高/中/低 · 来自 <来源>`（≥0.8 高 / ≥0.5 中，`memory_module_internal.h:104-108`），悬停出全口径（含观察时间）；
     - 正文 3 行（add=「将新增：…」，merge=「合并结果（将生成）：…」，forget=「拟遗忘（移出自动想起）：…」，invalidate=「拟标记为过期：…」；超长按码点截断加 …）；
     - 证据链行（蓝色单行）：`查看全文 ▸ 证据链：来自 <时间> · 会话 <会话id>｜「<原文摘录>」`；扫描类提案显「证据链：无（扫描类提案，无会话出处）」——点它弹「提案全文」只读弹窗（多行、可复制、改动不落状态）；
     - 底部操作：`拒绝`（文字钮）· `编辑后接受`（次级）· `接受`（主钮）。
   - **裁决动作**：`接受` → 提案执行，toast「已接受：提案已执行，可在「已处理」里撤销」；`拒绝` → toast「已拒绝：这条提案已留档，不再打扰你」；`编辑后接受` → 弹编辑框改正文后接受，toast「已接受：编辑后的记忆已执行」。裁决留档进审计表 `memory_proposal_audit`（`src/module_memory/proposals/proposal_store.cpp:44`）。
   - **批量模式**：点 `批量处理` 进/出；卡片左侧出现勾选框（**仅「遗忘/新增」可勾**，点不可批类型的框 toast「批量限制：批量接受仅对「遗忘 / 新增」开放，这张请逐张处理」）；批量条显 `已选 N 项` + `取消选择` + `批量接受`，完成 toast「批量接受完成：<成功>/<总数> 条已执行（失败项保持待审）」（`memory_module_panels.cpp:834-891`）。
   - **已处理视图**（切 `已处理` chip）：已裁决卡流（92px，含撤销标记），卡上 `撤销` 走撤销链——**为已接受提案生成一张新撤销卡回到待审列表再审一次**（`panel_state.h:110-111` `createUndoCard`，`memory_module_panels.cpp:612-687`）；空态「还没有处理记录」。
   - **降级口径**：引擎未运行时列表顶部黄条「记忆引擎未运行：以下为采集的原始片段，未经 AI 提炼分类；启动引擎后新提案将自动归纳类型。」（`memory_module_panels.cpp:697-711`）。
   - **渐进加载**：待审列表默认渲 50 条，尾部「已显示前 50 条 · 还有 N 条待审（也可用上方筛选缩小范围）」+ `再显示 50 条`（bug190/bug217 大库防冻结，`memory_module_panels.cpp:894-928`）。
4. **入库**：接受/批量接受即落本机提案库并执行引擎侧动作（A 阶段 accept 的 baseVersion 校验以提案快照放行，`panel_state.h:103-104`）。
5. **检索召回（两条出口）**：
   - **对话自动注入**：Claude 对话时 hook 自动检索并注入记忆——每次最多 **5 条、合计 500 字**（防喧宾夺主，健康格③口径，`memory_module.cpp:475-497`）；hook 检索超时 **800ms**（「不阻断用户提问」特例，`src/module_memory/mcp/search_tool.cpp:21-22` 注释）；注入按 UTF-8 码点安全截断（bug255，`src/module_memory/hook/inject.cpp:90-96,161-162`）；主控台「最近动态」蓝点显示注入事件。
   - **MCP 主动查询（外部如何调用）**：DevDesk 本机 MCP 服务（MCP 页启停，地址/端口见 MCP 页）是唯一对外入口，统一暴露 `memory_search` 工具——参数 `{query: "自然语言检索词", limit: 1..10 默认 5}`，超时 3000ms，输出硬顶 20000 字（`search_tool.cpp:22-30`）；工具描述「检索 DevDesk 本机长期记忆（构建约定、环境事实、项目结论等已沉淀条目），返回按相关度融合的记忆段落」（`search_tool.cpp:73-76`）。MCP 客户端（Claude Code 等）只需配置 hub 一个 server；设置页「开放记忆查询」开关控制 `memory_search` 是否出现在工具清单（USER_GUIDE §3.8 口径）。注意：记忆引擎内部另有 `127.0.0.1:8421` telemem MCP 端点，那是内部实现细节，**不作为接入方式**。
6. **健康自评**：主控台健康格② `触发线 · 记得牢不牢` 卡内 `跑评测` → 冻结 15 条查询转测本机检索（零 API 费），toast「评测已启动：冻结 15 查询转测引擎检索（本机 embedding，零 API 费）」；Recall@5 低于升级阈值时状态行转黄「当前 N% · 低于升级线」（`memory_module.cpp:436-472`）。

### D. 主控台日常监视

1. **引擎状态带**：状态点 + `启动引擎`/`停止引擎`（Danger 红）+ `详情`；故障/模型缺失时带上直接出警示短语「引擎故障 · 点「详情」看原因」/「本机模型文件缺失」（`memory_module.cpp:230-243`）。
2. **健康四格**（118px）：① `脱敏闸 0/110`（状态「强制开启 · 已锁定」；110 条红队攻击样本全拦口径）② `触发线 · 记得牢不牢`（评测分 + 阈值刻度仪表 + 跑评测）③ `注入预算 · 今日`（`N/5 条` + `<chars>/500 字`）④ `存储概览`（采集事件数 + 体积 + 会话数，悬停见「提案 N 待审 / M 已处理 · 记忆都存在你自己的电脑里，配置页可随时导出」）（`memory_module.cpp:290-521`）。
3. **消耗带** `token 消耗（今日 / 本月）`：12px 进度横带 + `今日 <n> tk · <金额> · 本月 <n> tk · <金额>`；右端档位字 `预算充足` / `逼近预算 · 软档提醒` / `已触发硬档 · 提炼暂停`；悬停 tooltip 给软/硬档数值与估算口径（`memory_module_panels.cpp:49-131`）。
4. **运行明细折叠组**（默认收起，组头摘要显最近一条账目）：展开后 = `最近调用记录` 表（时间/类型/条数字数/token·金额，cap 10 行；类型显示名：提炼·输入 / 提炼·产出 / 向量化 / 注入·条数 / 注入·字数 / hook 检索）+ 尾部 `查看全部（导出 JSON）` + `最近动态` 流（cap 8 行，彩点按类型：采集绿/拦截黄/注入蓝/合并灰/整理主色）+ 各自空态（`memory_module_panels.cpp:134-380`）。

## 演练卡壳点

1. **「整理成文」无手动按钮**：简报口径的「整理成文→审核→入库」链路里，「整理」在代码中是提案来源枚举（`dedupe`/`conflict` → 显示名「整理」，`memory_module_internal.h:110-115`），由引擎/管线自动产出，页面**没有**「手动整理成文」入口——若老板预期存在该按钮，属设计含糊点，走查时需现场确认预期形态。
2. **「接受」对引擎侧到底执行了什么**：A 阶段 accept 走「快照放行」（`panel_state.h:103-104` 注释明言版本校验形同旁路），接受后记忆是否真的进了引擎可检索库，走查时需用「跑评测」+ MCP `memory_search` 实测闭环（撤销卡机制可回滚，但回滚是否同步引擎侧同样需实测）。
3. **keychain 拒绝/系统弹窗**场景的用户文案未在代码中找到专门分支（保存失败路径未逐行核），实测 macOS 钥匙串拒绝授权时的表现。
4. **faiss 损坏恢复**：引擎侧损坏无专门用户入口，只能整体「故障」态兜底——走查时确认详情弹窗 detail 文案是否把「重建索引」出路讲清。
5. **「记忆审核 (N)」的 N 口径**：N = 全部 pending 数（不随筛选变化，`memory_module.cpp:121-124`），与列表内筛选计数的关系走查时向用户演示一遍。
6. **MCP 端到端演练**：hub 地址/端口在 MCP 页（不在记忆页），「开放记忆查询」开关位置在设置页——三个页面联动才能完成外部调用演练，走查时按「MCP 页启停 → 设置页开开关 → 客户端配 server → 调 memory_search」四步实测。
7. **向导② venv 安装 10 分钟上限**内用户只能看「进行中…」无限等待文案（无进度百分比），慢网下的体验需实测确认是否足以安心。
