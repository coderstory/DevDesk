# 窗口绿白间隔圆角虚框边框——能力与实现路径调研

> 需求：[pool:need:168] 老板 2026-11-03：「给应用加一个绿色的边框，边框是绿色和白色间隔的带圆角的长条子，间隔是白色且比较短，类似虚框的效果」
> 调研日期：2026-11-03 ｜ 工具调用 15/20 ｜ 证据等级标注：〔实跑〕=仓内实测结论，〔源码〕=仓内源码直读，〔官方〕=微软/苹果一手文档，〔二手〕=社区资料

## 一、结论先行

1. **推荐路径 = 方案 a（应用内绘制）**：在窗口客户区最外缘画一圈「白色实线底环 + 绿色短段覆盖」的双层 ring，纯 DSL 可实现（`ui.rect` 的 `.border(width,color)` 实线环打底 + 圆角，绿色短段用细长 rect 沿四边排布）。**Windows 上这不是"内描边"**——DevDesk 主窗口在 Windows 已是 undecorated 自绘壳（`src/main.cpp:967`），客户区 = 整窗，ring 就是真实窗框位置。
2. **备选路径 = 方案 c-lite（仅 Windows）**：`DWMWA_BORDER_COLOR`（Win11 22000+）把系统窗框染成绿色——一行 DwmSetWindowAttribute，但**只能实色**，虚线间隔做不到，只能当降级/叠加选项。
3. **明确不可行项**：① DWMWA_BORDER_COLOR 画虚线/间隔——API 只收 COLORREF 实色〔官方〕；② macOS 原生 API 画窗口边框——`NSWindow.setBorderColor/setBorderWidth` 已废弃且 Big Sur 后实际失效，`contentBorderThickness` 只画实色内容边框〔官方+二手〕；③ EUI-NEO `.border()` 直接出虚线——渲染层无 dash/stipple 支持〔源码，grep 零命中〕，要原生虚线需扩展 fork 渲染层（M 档）。
4. **双平台观感天然不对称**：Windows ring = 真窗框位置；macOS ring = 系统窗框内侧的内描边（系统标题栏必然在 ring 之外，框架明确 macOS 无自绘壳钩子、宿主应保系统标题栏）。要 macOS 整窗一致需给 fork 加 NSWindow overlay 层（M 档，非 borderless、保红绿灯）。
5. **静态绘制成本 S 档**（一个 ring 组合件 ~100–200 行，双平台一份代码）；动画（marching ants）可行但元素多时有组合开销，老板原话未要求动画，建议首版静态。

## 三、实现路径选型

### 方案 a：应用内绘制（推荐）

**做法**：compose 最外层叠一个非交互 ring——
- 底层：`ui.rect("ring.base")` 全窗铺满、`.radius(圆角)`、`.border(2, 白色)` → 得到带圆角的白色实线环；
- 上层：沿四边以固定间距排布绿色细长 rect（或用 `ui.polygon` capsule 线段，边段抗锯齿更顺）盖在白环上，间隔露出白底；
- 元素一律**非 interactive**（rect 默认非交互，不挡 EUI-NEO 层最外缘的八向 resize 热区与标题栏拖拽命中）。

| 平台 | 观感 | 额外工作 |
|---|---|---|
| Windows | ring 即真实窗框位置（F1），与系统圆角叠加 | S：ring 组合件 ~100–200 行，含最大化时隐藏等状态分支 |
| macOS | ring 画在 content 区边缘 = 系统窗框内侧内描边（F3），标题栏在 ring 外 | 同一份代码直接生效（S）；观感不一致要接受或走 fork 扩展（见下） |

**风险**：① ring radius 必须 ≥ 窗口系统圆角半径再内缩，否则四角被 DWM 圆角裁掉（Win11 圆角半径 app 不可调，只有三档偏好，F10）；② ring 若设置 `.interactive()` 会吃掉边缘 hit-test——纪律性禁止；③ 透明/半透档下 ring 随 clearColor alpha 一起半透，磨砂档无影响；④ 最大化时 ring 贴屏幕边，建议隐藏（设计决策）。

### 方案 b：无边框窗口 + 全自绘窗框（不推荐，Windows 已变相在做，macOS 不可做）

Windows 侧方案 a 能成立正是因为框架壳已把"无边框+自绘框"最难的拖拽/缩放/动画做完了（F1），无需再投入。macOS 侧 borderless = 丢红绿灯、无框架命中钩子（F3），已被框架明确否定。**此路径无增量价值。**

### 方案 c：平台原生边框着色（备选/降级）

- **Windows**：`DWMWA_BORDER_COLOR` 染绿（需在 fork `window_effect_win.cpp` 加该属性，仿 DWMWA_CAPTION_COLOR 现成写法，XS 档）。只能实色实线（F9），达不到"绿白间隔虚框"；可与方案 a 叠加（DWM 实线在最外 1px，ring 在内）或单独作为极简版交付。
- **macOS**：原生做不到虚框（F12）。整窗一致方案 = fork 加 NSWindow overlay view（content view 之上叠一层禁 hit 的自绘层，覆盖含标题栏的整窗 bounds，`NSBezierPath.setLineDash` 画虚线）——**非 borderless、保红绿灯**，ObjC++ + 主题/全屏生命周期联动，M 档；borderless 路线被 F3 否定。

### EUI-NEO 渲染层扩展（`​.border()` 加 dash 参数，可选长期项）

F6 确认渲染层无 dash 支持。扩展 = rect shader 加 dash 函数（或 polygon 线段批处理）+ DSL 参数 + GL/Vulkan 双后端验证，M 档，收益是"虚线边框"成为框架一等能力（任何元素可用）。符合"EUI-NEO 能力缺失优先在 fork 修"的仓规；单需求场景下先用方案 a 的 rect 排布达成目标，扩展留作池内后续项。

## 五、给 designer 的设计空间说明

**自由度（app 完全可控）**：
- 颜色：任意 hex+alpha（绿/白均如此，`core::Color` 8 位 hex）；
- 段几何：绿段长度、白间隔长度、环宽（建议 2–4px，太细则白底不可见）、四边相位对齐方式；
- 圆角：ring 自己的 radius 任意（受"≥ 窗口圆角+内缩"下限约束）；
- 状态分化：激活/失焦换色或降透明、最大化隐藏、按模块/窗口独立开关——焦点状态 app 内可读；
- 动画：可实现（onTimer 驱动段位移/相位滚动，"流水"效果），成本 O(段数)，首版建议静态。

**被平台锁死**：
- 环永远画在窗口像素**之内**：无任何 OS 级窗口虚框 API（Windows DWM 只实色 F9；macOS 边框 API 已死 F12）——环外沿 = 窗口外沿，不可能突出窗口矩形；
- Windows 系统圆角半径不可调（ROUND/ROUNDSMALL/DONOTROUND 三档偏好而已，F10），ring 四角弧度必须包络它；
- macOS 系统标题栏（红绿灯）必然在 content 区 ring 之外（F3/F12），除非 borderless（丢红绿灯，框架否定）；
- DWM 系统窗框（Win11 默认 1px 深色描边）与 ring 同时存在：不想要系统描边可设 `DWMWA_BORDER_COLOR=DWMWA_COLOR_NONE` 隐掉（F9），让 ring 独占窗沿——推荐随方案 a 一并做。
