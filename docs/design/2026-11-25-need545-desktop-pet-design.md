## 2. 决议点（结论 + 理由）

### 2.1 形象 = 纯矢量「小绿灵」，无 PNG / 无序列帧 / 无皮肤

身体 + 叶芽 + 五官全部由圆角矩形/圆形绘制，零素材文件。理由：① 用户要「不需要太复杂」——去掉素材管线与加载失败面；② 任意 DPI 清晰；③ 与 DevDesk 绿色体系同源；④ 比 6 套皮肤的小狗/小猫贴图更有一个应用自己的识别符号。

> 历史教训：旧模块 200+ 帧 PNG 占包体、逐帧切换增加状态面；本次不做。

### 2.2 两项状态动效 = 呼吸 + 眨眼（不做视线跟随）

任务书上限两项。选表现力/成本比最高的组合：呼吸让静态形象「活着」，眨眼是最低成本的拟人信号。视线跟随需要持续读光标并更新瞳孔位置，是第三项且会引入空闲采样，不做。

### 2.3 命中 = 整窗方形（含光晕带）

窗口 160×160，其中身体 80×80、光晕边距 40。整窗命中（含光晕带）：「点击桌宠」在感知上包括光晕；逐像素/区域命中是既有平台债务（旧设计 U11），本期不引入。代价：四角透明区在桌面上占一个 160×160 的点击遮挡面——通过可拖拽与体积小（约为一张图标两倍见方）接受；列入已知限制 §12.4。

### 2.4 点击 = 单一动作「唤起主窗口」

左键单击（按下到抬起位移 ≤4px）→ 调用应用级统一唤起路径（托盘 Show 同源），覆盖主窗可见但被遮挡 / 最小化 / 隐藏到托盘三种态。不做双击差异化、不做右键菜单。

### 2.5 位置 = 默认主屏右下角，可拖，持久化

首次启动（无记录）落主显示器工作区右下角：右边距 24、下边距 16（逻辑 px）。拖拽结束后按屏幕物理坐标持久化；下次启动若落点不在任何显示器工作区内 → 重置为默认位。

### 2.6 设置落点 = 设置 → 通用卡第 4 行「桌面宠物」，默认关

与「动态背景 / 留白动画」同款行几何（label 92 + 说明 + 右侧 44×24 开关）。默认关闭（不打扰未主动启用的用户）。开关即时生效：开 → 建窗；关 → 淡出关窗。**卡高不破零滚动预算**：卡高 222 → 228（推导见 §4.9），通用 tab 内容总高 228+8+164=400 ≤ 最小窗可用高 424。

### 2.7 桌宠独立于主窗

主窗最小化 / 隐藏到托盘 / 失焦 / 被其他窗口遮挡时，桌宠照常可见（既有平台行为，依据见 §11）；桌宠窗口始终置顶——包括位于主窗之上。遮挡主窗时可拖走；这是桌面宠物的常规形态（对照 Shimeji 类产品）。

## 3. 页面级构图（桌面级）

> 桌宠没有「页面滚动」，构图对象是屏幕层位 + 窗内分层。先定层位与分层，参数见 §4。

### 3.1 层位模型（屏幕坐标，自下而上）

| 层 | 内容 | 行为 |
|---|---|---|
| L0 | 桌面壁纸/图标/其他应用窗口 | 与桌宠无交互（桌宠整窗命中会遮挡其正下方 160×160 区域） |
| L1 | DevDesk 主窗口 | 常规窗口，可最小化/隐藏到托盘 |
| L2 | **桌宠窗口**（置顶、无边框、不进任务栏/Alt+Tab、不抢焦点） | 独立子窗口；主窗隐藏时存活；随进程退出销毁 |
| L3 | 下拉/对话框等临时弹层 | 不属于桌宠窗 |

滚动模型：桌宠窗内容固定 160×160，**无滚动容器、无内部滚动**；主窗的滚动模型完全不变。桌宠窗不随主窗尺寸变化，最小窗 1000×640 下不做任何降级（与主窗解耦）。

### 3.3 锚定与空间节奏

- **桌宠锚点**：主显示器工作区（不含任务栏/Dock）右下角；右 24、下 16。默认位在 100% DPI 下窗右下角距工作区右边 24px、下边 16px。
- **窗内节奏**：8px 网格 → 身体中心 (80,78)；身体半径 40；五官集中在身体纵向 62–94（视觉重心略偏上）；地面阴影与身体底沿留 4px；光晕边距 40 = 呼吸最大外扩（37.1）+ 余量 2.9。所有间距为构图值，不再套用主窗 40px 页边距（桌面级元素，空间尺度独立）。
- **视觉权重**：脸（眼睛 > 嘴/腮红）> 叶芽 > 光晕 > 地面阴影。信息密度低但单点强度高——桌宠是「余光可见」的装饰物，不做信息展示。

### 3.4 构图三问

1. **滚动模型对吗**：桌宠窗无滚动、无列表、无内容溢出可能（内容固定 160×160）；主窗滚动模型零变化。与全站「外壳不滚、内容区内滚」不冲突——桌宠不是页面。
2. **有无大段无效空白**：窗内四周 40px 透明不是空洞，是光晕与呼吸外扩的**功能预算**（外晕最大外扩 37.1px）；若压到 8px 边距，光晕会被窗口裁切出现硬边。四角无内容但被径向柔光填满，不产生空白感。
3. **密度与视觉权重平衡吗**：主体（80×80）占窗 25% 面积但占 90% 注意力；光晕/地面阴影只服务主体塑形。不存在「信息上下堆叠、定宽空列、弹性区稀疏」类缺陷；最小窗与宽窗下桌宠尺寸不变（与主窗解耦），不破版。

## 4. 逐区块规格

坐标一律为窗口内逻辑 px；颜色写作「token / 值」；alpha 为独立参数。

### 4.4 光晕参数（用户硬需求）

| 层 | 参数 | 待机 | 吸气峰值 | 按压闪光 |
|---|---|---|---|---|
| 外晕 | 阴影 blur | 22 | 26 | 24 |
| 外晕 | 阴影色 alpha | 0.42 | 0.34 | 0.55 |
| 外晕 | spread / offset | 3 / (0,0) | 3 / (0,0) | 3 / (0,0) |
| 内晕 | 填充 alpha | 0.10 | 0.13 | 0.16 |
| 最大外扩 | `blur×1.08×1.18 + spread + 1` | 29.0 | 37.1 | 32.9 |

边距 40 > 37.1 → 任何状态光晕不被窗口裁切。光晕是「呼吸的载体」：身体起落 1.5px，光晕软边同步张缩——这是本设计的**大胆单点**，其余参数克制。

```
        └── 设置开关=关 ◀── [S7 退场 180ms] ◀── [S6 回弹+单击] ◀── 抬起(≤4px)
```

| 状态 | 进入动作 | 可见表现 | 退出条件 |
|---|---|---|---|
| S0 未启用 | 无窗口 | 桌面零像素变化；设置行开关=关 | 开关开 |
| S1 入场 | 建窗 + 播放入场 | 各层 opacity 0→1（320ms OutCubic）+ 角色层 translateY +6→0（320ms OutBack）+ 光晕 α0.42 起 | 320ms 到 |
| S2 待机呼吸 | 循环呼吸 | 见 §5.2 呼吸行 | 眨眼计时/按下/开关关 |
| S3 眨眼 | 随机 4–7s；20% 双眨（第一次睁眼后 380ms 再眨） | 双眼 18→2.5 高度 | 睁眼完成回 S2 |
| S4 按压 | pointerdown（左键） | 按压几何表 + 光晕 0.55 | 抬起（→S6 或 S5）/ 拖动超阈值（→S5） |
| S5 拖拽 | 按下后位移 >4px | 窗口 1:1 跟随光标；角色保持待机几何；呼吸暂停、眨眼暂停 | 抬起 → 位置钳制 → S2 |
| S6 回弹+单击 | 抬起且位移 ≤4px | 回弹 160ms + 上跳 4px/110ms/回落 190ms + 光晕闪 0.55→0.42（300ms）；**同时唤起主窗口** | 动画完 → S2 |
| S7 退场 | 开关关 或 应用退出 | opacity 1→0（180ms OutQuad）→ 关窗 | 180ms 后窗口销毁 |

优先级：S4/S5 > S3 > S2；进入 S4 若正在眨眼，眼睛立即复位（不补完眨眼）。拖拽期间呼吸与随机眨眼暂停（省唤醒）。

**节拍预算**：呼吸以 12Hz（83ms/步）参数更新而非逐帧正弦（3.2s ≈ 38 步，幅度 1.5px 视觉平滑）；眨眼与按压用短过渡；拖拽期间零动画。目的：常驻窗口不因装饰动效把全局帧循环拖成持续 90fps 满载。

### 5.3 连点与中断

- 单击唤起主窗后 300ms 内的第二次单击忽略（主窗已在前面，requestShow 幂等但仍避免重复上跳）。
- 拖拽中松手 = 只移动，不唤起主窗（位移 >4px 一律抑制点击）。
- 拖拽中按 Esc/失焦：无特殊处理，松手即结束；窗口跟随光标，不跳变。
- 应用退出时若在拖拽中：不保存中途位置（保存上一次稳定位置）。

## 8. 自适应行为表

### 8.1 DPI

| 显示缩放 | 客户区物理尺寸 | 内容逻辑尺寸 | 描边视觉宽 |
|---|---|---|---|
| 100% | 160×160 | 160×160 | 1.5px |
| 125% | 200×200 | 160×160 | 1.9px |
| 150% | 240×240 | 160×160 | 2.25px |
| 200% | 320×320 | 160×160 | 3px |

创建物理尺寸由 `windowScaleForPoint(anchor)` 求得（非硬编码 1.25 等假设）；内容参数全部逻辑值，不因 DPI 改值。

### 8.2 多显示器

- 默认位取**主显示器**工作区；有持久化位置时按落点枚举工作区校验。
- 副屏负坐标合法（`getMonitorWorkAreas` 明确支持）。
- 换屏/拔屏导致位置落在所有工作区外 → 启动重置为主屏默认位（静默）。
- 运行中不监听显示器变更（平台无变更回调，见 §11）；拔屏后桌宠可能暂留在原坐标，下次启动自愈。

### 8.3 跨 DPI 屏拖拽（已知降级的闭环）

窗口物理尺寸创建后固定；拖到不同 DPI 屏时逻辑内容会被放大/缩小。设计闭环：**松手时**按落点显示器的 scale 重新设置客户区物理尺寸（`round(160×s_new)`），内容逻辑尺寸不变 → 视觉大小恒定。若重设失败（句柄失效）：保持原尺寸，记日志，下次启动修正（已知降级，不阻断交互）。

### 8.4 主窗尺寸无关性

桌宠窗尺寸与主窗 1000×640 / 1600×1000 两档无关；主窗任何尺寸下桌宠不重排、不缩放、不溢出。工作区小于 160×160（极端）→ 以左上角为锚、最小边距 8 放置（仍可能部分出屏，概率极低，不额外设计）。

### 12.2 两遍法记录（第一轮构图 → 第二遍自审）

- **第一轮**：桌面级层位（桌宠置顶独立窗）→ 窗内径向分层（光晕→地面→身体→五官）→ 参数。
- **第二遍自审（「给同类页出方案是否也会得到同样结果」）**：若默认发挥，桌宠会得到「通用卡通动物贴图 + 阴影 + 通用 emoji 脸」——那是默认不是选择。本设计的换向：
  1. 形象不是动物，是 **DevDesk 自己的绿色信号团子**（叶芽 = 应用识别点；圆身=最低造型成本、最高可爱度/复杂度比）；
  2. **光晕即呼吸**（把用户要求的光晕变成动效载体，而非静态描边）；
  3. 不做皮肤系统——单一形象是身份，不是可换素材。
- **大胆只花一处**：光晕呼吸（§4.4）。脸/叶芽/地面阴影全部收敛、无粒子、无星星、无描边特效。
- **拿掉一个不服务任务书的装饰**：初稿曾计划「悬停时叶芽轻摆」——悬停态在置顶小窗上高频误触且用户未要求，已删。

### 12.3 已知限制（明示，不藏）

1. 整窗命中：透明四角也吃点击，无法透传给桌面（逐像素命中不在本期）。
2. 无右键菜单：关闭桌宠只能去设置开关（用户明确「不需要太复杂」，不另造退出口）。
3. 运行中不响应显示器插拔/分辨率变更，下次启动自愈。
4. 跨 DPI 屏拖拽在松手时修正尺寸，拖拽过程中可能出现一次缩放跳变。
5. Windows 上点击桌宠的瞬间它可能短暂成为前台窗口（平台未启用「点击不激活」样式位），随即主窗唤起接管前台；不影响后续输入。
