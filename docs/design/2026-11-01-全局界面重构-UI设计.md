## 一、诊断：六条病灶

全部基于 2026-10-31 真机截图（`/tmp/desk-shots3/*.png`，1600×1000）与源码实测。

| # | 病灶 | 证据 | 后果 |
|---|---|---|---|
| **D1** | **玻璃质感从未成立** | 背景 halo 峰值 alpha `0.11`（`app_sidebar.cpp:621`），卡面 alpha `0.92`（`metrics.h:47`）。0.92 的白叠在「几乎白色的底」上 = 白 | 半透做了，但透出来的是「白透白」，视觉等同纯白。玻璃感需要底层有可透的内容 |
| **D2** | **底色色相分裂** | `background #FAFAF9`（暖白，偏黄）vs `sidebarBg #F0FDF7`（冷绿白）。侧栏与主区不同色温 | 页面接缝处显脏；「绿白」只存在于侧栏，主区是奶油色，整体不像一个体系 |
| **D3** | **统计卡五彩噪音** | 首页 5 张卡分别用绿/蓝/橙/紫/青底（`01-home` 截图）。这 5 色不承载状态语义，纯装饰。基高已是 96（`home_module.cpp:365`），但 `kHomeStatGrowRatio=0.18`（`:49`）让统计行吸走 18% 余高，实际可撑到 120+ | 5 个注意力焦点抢同一层级，反而没有一个能聚焦；卡被余高撑高后，纵向留白更多 |
| **D4** | **空态吃满整屏** | 图表卡空态仍占 220px + 全部余高（`01-home`），画面正中一行「今日暂无 API 调用」 | 空态是首屏第一印象，却呈现为「一大块死白」 |
| **D5** | **Todo 第四列被压成竖排** | `03-todo` 截图右端：「已归档」三字逐字竖排、数字 0 独占一行。根因在 `todo_ui_logic.h:77-81`：归档列折叠态宽度 = `normal × kArchiveCollapsedRatio`，**无最小宽度保底**，列头文字（3 字 + 6px 圆点 + 12px padding）放不下 | 布局缺陷，非视觉偏好。修复只需加下限，不必改列数模型 |
| **D6** | **侧栏无图标、选中不可见** | 侧栏 12 项纯文字；选中态是白胶囊压 `#F0FDF7` 淡绿底，对比约 1.05:1 | 导航靠读字不靠扫形，扫视成本高；当前位置几乎无指示 |

**一句话**：现在的问题不是「不够好看」，是**层级缺失**——背景、面板、卡片、文字全在同一个明度带上（都在 0.9~1.0 亮度区间），所以任何一层的边界都要靠 1px 浅边框去硬划，划出来还是浅的。

## 二、设计立场与决策

| 病灶 | 决策 |
|---|---|
| D1 玻璃不成立 | **玻璃三件套**：底有对比（halo 加强）+ 面有半透（0.72）+ **边有高光**（1px 白色内描边）。三者缺一，玻璃就退化成白卡。EUI-NEO 无 backdrop blur，靠这三件做「拟玻璃」而非「真玻璃」 |
| D2 色温分裂 | **底色归绿族**：`background #FAFAF9 → #F5FAF7`，与 `sidebarBg #F0FDF7` 同色相、差一档明度。全站色温统一到「绿白」 |
| D3 五彩噪音 | **统计卡去五彩**：5 张卡统一白半透底，语义色只保留给**真实语义**（逾期=红、进行中=绿）。指标身份靠图标 + 字色区分，不靠底色。同时 `kHomeStatGrowRatio 0.18 → 0`，余高全部给图表卡，统计卡恒 96 |
| D4 空态吃屏 | **空态降高**：图表卡空态高度压到 `min(220, 内容高)`，空态文案改为「引导 + 主操作」双行，而非陈述句 |
| D5 归档列被压 | **归档列加最小宽度保底**：折叠态 `max(96, normal × ratio)`，展开态 220。列数模型不动（见 §6.3） |
| D6 侧栏扫视 | **图标 + 双指示**：每项加 16px 图标；选中态 = 左侧 3px 绿色竖条 + 淡绿胶囊（`primarySoftBg`） |

### 视觉总调性

> **微信绿白 + 液体背景 + 磨砂玻璃卡**。
> 参照系：微信 PC 客户端的信息密度与克制，加上一层「有生命的底色」。
> 克制原则：一屏只允许出现**一个**饱和绿色（主操作按钮）；其余绿色一律降到软底 `#E6FBF2` 或文字档 `#157E4E`。

## 三、设计 token

### 3.1 色彩

现状值取自 `src/core/theme.cpp:69-100`（`lightTokens()`）。

#### 品牌色（**待拍板**）

| token | 现状 | 建议 | 理由 |
|---|---|---|---|
| `primary` | `#36D399` | **`#07C160`** | 现状是翠绿（偏青），与「微信绿」不是一个色相；`#07C160` 是微信标准绿，识别度直接到位 |
| `primaryHover` | `#2EC48F` | `#06AD56` | 同步加深一档 |
| `primaryPressed` | `#23B07F` | `#059048` | 再深一档 |
| `primarySoftBg` | `#E6FBF2` | `#E8F8EE` | 向新绿族对齐（原色偏青） |
| `primaryText` | `#157E4E` | 不变 | 4.87:1 on `#FAFAF9`，已达 AA。新绿更深，对比只会更好 |
| `onPrimary` | `#FFFFFF` | 不变 | 见 §7 的对比度例外说明 |

> **影响面**：`primary` 被主按钮填充、图标、进度条、选中态大量引用。换值会改变全站观感但**不破坏任何对比度**（新值比旧值更深，白字对比从约 1.9:1 提升到约 2.6:1）。不改也能跑，但「微信绿」的识别不成立。

### 3.2 字体

机制限制：EUI-NEO **只打包 Bold 一份字重**，`fontWeight()` 数值无效（`CAPABILITIES.md` §0 陷阱表）。**所以字重不能作为层级手段**——层级只能靠字号 + 色阶。

| token | 值 | 用途 |
|---|---|---|
| `fontSizeDisplay` | 48 | 仅留空态插画旁的大数字（几乎不用） |
| `fontSizeStat` | **30**（现状 28） | 统计卡数字 |
| `fontSizeTitle` / `fontSizePage` | 24 | 页面标题 |
| `fontSizeLarge` | **19**（现状 18） | 卡片标题、区块标题 |
| `fontSizeWeChat` | 16 | 正文（微信标准字号，信息密度舒适区） |
| `fontSizeBody` | 14 | 次级信息、表格单元 |
| `fontSizeSmall` | 12 | 元信息、标签、caveat |

**字阶关系**：30 / 24 / 19 / 16 / 14 / 12 —— 六级，比例约 1.16~1.25，紧凑但有区分。

⛔ **禁止**在业务代码里写字面量字号（`fontSize(15.0f)`）；一律走 token 或 `core::theme::scaled()`。

### 3.3 间距

8pt 基准（现状已如此，本次只收紧使用纪律）。

| token | 值 | 用途 |
|---|---|---|
| `spacingSmall` | 4 | 图标与文字间隙 |
| `spacing` | 8 | 行内元素间距 |
| `spacingLarge` | 16 | 卡片内边距（内容块之间） |
| `spacingXLarge` | 24 | 卡片内边距（卡内主区）、区块间距 |
| `spacingXXLarge` | 40 | 页面级大间距（慎用） |
| `spacingPage` | **20**（现状 12） | 页面外边距。12px 贴边太紧，气口不足 |

**卡片内边距统一**：`padding = 24`（现状各模块 16/20/32 混用，是"参差感"的来源之一）。

### 3.4 圆角

| token | 值 | 用途 |
|---|---|---|
| `radiusSmall` | 6 | chip、小标签、输入框内元素 |
| `radius` | **10**（现状 8） | 按钮、行卡、输入框 |
| `radiusLarge` | **14**（现状 12） | 内容卡片 |
| `radiusOverlay` | 16 | 大卡片（首页统计/图表）、模态框 |
| `radiusPill` | 999 | 胶囊 chip、头像 |

**为什么加大**：8px 圆角在 1600px 宽的窗口里显得"方"，撑不住玻璃质感；10/14/16 三档与 12px 边框粗细更匹配，也更接近微信 PC 的现代档位。

### 3.5 阴影与层级

| 层级 | 值 | 用途 |
|---|---|---|
| `shadowNone` | — | 平铺卡片（贴背景可直接无阴影，靠描边分层） |
| `shadowSm` | `0 1px 2px rgba(16,54,38,0.05)` | 行卡、chip |
| `shadowMd` | `0 1px 2px rgba(16,54,38,0.05), 0 4px 14px rgba(16,54,38,0.06)` | 内容卡片 |
| `shadowLg` | `0 8px 28px rgba(16,54,38,0.10)` | 浮层（弹窗/菜单/dropdown） |

⛔ 阴影一律用**冷绿黑**（`rgba(16,54,38,·)`）不用纯黑——纯黑阴影压在绿白底上会发灰发脏。

## 四、玻璃层级（核心规范）

这是本次重构唯一的新概念，也是 D1 的解药。

### 4.1 四层

```
L3 浮层   surface 0.97 + border 0.72 + shadowLg   ← 弹窗 / 菜单 / dropdown / toast
L2 卡片   surface 0.72 + border 0.72 + shadowMd   ← 内容卡 / 统计卡 / 列表行卡
L1 面板   surface 0.55 + border 0.40              ← 侧栏浮层 / 页面底板（大面积区域）
L0 背景   halo alpha 0.16~0.20（多色多重）         ← 全窗流体层
```

### 4.2 关键：底层必须先"有东西"

现状 halo 峰值 `0.11` + 单色（`primary` / `primaryHover` 两个近似绿）。要加强到：

| 参数 | 现状 | 建议 |
|---|---|---|
| halo 数量 | 7 | 7（不变） |
| 峰值 alpha | `0.11` | **`0.19`** |
| 色相变化 | 2 色（都是绿，`primary`/`primaryHover`） | **3 色轮替**：`#07C160`（主绿）/ `#34D399`（薄荷）/ `#A7F3D0`（浅绿）。同族不同明度，形成"液体深浅"而非"一块绿" |
| halo 半径 | 短边 0.20~0.37 | 不变 |
| 卫星墨点 | 每晕 2 个、alpha×0.55 | 改为每晕 3 个、alpha×0.45（更细碎，液体感更强） |

> **为什么不能只调卡面 alpha**：卡面从 0.92 降到 0.72，透出的是「alpha 0.11 的淡绿」——几乎是白。玻璃感 = 底层对比 × 上层透明度的乘积，**底层不够，上层怎么降都是在降白度而不是加质感**。

### 4.3 玻璃卡标准画法（EUI-NEO 落地）

一张玻璃卡 = 3 个元素，缺一不可：

```
① 主体 rect：.color(cardSurface(t))    ← surface @ 0.72 + kGlassTint 微绿染
               .radius(14)
② 高光边 rect：外层再套 1px 描边
               .color(transparent).border(kGlassBorder, 1px).radius(14)
③ 阴影       ：.shadow(kGlassShadow) 或走 panelShadow
```

EUI-NEO 无 `backdrop-filter`，**不要试图模拟模糊**。1px 白色高光边 + 0.72 半透，人眼会自己把「亮边 + 微透光」解读为玻璃。这是用设计原理绕过技术缺口的做法，不是妥协。

`cardSurface(t)` 现状 `metrics.h:47` 是 `0.92`，本次改 **`0.72`**；并新增 `ui_kit/glass.h` 导出 `glassFill / glassBorder / glassShadow` 三个 helper，避免每个模块各写一遍色值。

### 6.1 首页


### 6.3 Todo 看板（D5 的解）

**列宽公式**（修复归档列被压，改 `todo_ui_logic.h:77-81`）：

现状逻辑（有缺陷）：
```cpp
out.normal  = span / kColumns;
out.archive = out.normal;                 // 展开态与普通列等宽
out.archive = uiLerp(out.normal * kArchiveCollapsedRatio, out.normal, archiveT);  // ← 折叠态无下限
out.normal  = (span - out.archive) / (kColumns - 1.0f);
```

改为：
```
普通列 = (span - 归档列) / (kColumns - 1)      ← 不变
归档列展开态 = 220
归档列折叠态 = max(96, normal × kArchiveCollapsedRatio)   ← 新增下限 96
```

**96 的来历**：列头 = 12(pad) + 6(圆点) + 6(gap) + 「已归档」3字×15px ≈ 45 + 6(gap) + 18(计数 chip) + 12(pad) ≈ 105。
取 96 是**允许列头在折叠态省略计数 chip** 的下限；若要 chip 也留，取 112。
本方案取 **96 + 折叠态隐藏 chip**（chip 信息在归档页内可见，列头不必重复）。

窗口极窄（< 3×260 + 220 + 48）时触发横向滚动，不压缩任何列。

## 七、无障碍

### 7.1 对比度（WCAG AA）

| 组合 | 比值 | 结论 |
|---|---|---|
| `textPrimary #1F2937` on 玻璃卡（≈`#F8FBF9`） | 13.2:1 | ✅ AAA |
| `textSecondary #4B5563` on 玻璃卡 | 7.3:1 | ✅ AAA |
| `textTertiary #6B7280` on 玻璃卡 | 4.6:1 | ✅ AA（仅用于 ≤12px 元信息时需 600 字重补偿） |
| `primaryText #157E4E` on `#E8F8EE` 胶囊 | 5.4:1 | ✅ AA |
| 白字 on `#07C160` 主按钮 | 2.6:1 | ⚠️ **品牌例外**（见 7.2） |

### 7.2 主按钮的对比度例外

微信、支付宝的主按钮都是绿底白字，比值约 2.6:1，低于 AA 4.5:1。这是**品牌一致性 vs 无障碍标准**的既定冲突。

本方案的选择：**保留绿底白字**（否则失去微信识别），但强制三个补偿条件：
1. 字号 ≥16px 且 600 字重（大字号放宽到 3:1 的临界尽可能接近）
2. 按钮高度 40px，触达面积充足
3. **不把主按钮当唯一信息载体**——按钮文字本身就是操作名，不依赖颜色传达状态

若需严格 AA：主按钮改 `#0E7A4A` 填充（白字 5.1:1），但视觉上就是「深绿按钮」，不再是微信绿。**此项交由用户拍板**。

### 7.3 其他

- 焦点态：2px `#07C160` 外描边 + 2px offset，玻璃卡上需同时加 1px 白内描边保证可见
- 触达：所有可点区域 ≥32×32（桌面端从 44 放宽，鼠标精度高）
- 字号缩放：全部走 token，`setFontScale(0.5~2.0)` 下布局不得破裂——玻璃卡 padding 用 token 不写死
- 动效：背景 halo 是常驻动画，**必须**响应 `fluidBackgroundEnabled` 开关；开启 `prefers-reduced-motion` 等价设置时 halo 静止

### 8.3 原型与实现的差异（必须知道）

| 项 | 原型 | 真机实现 | 影响 |
|---|---|---|---|
| 背景光晕 | CSS `radial-gradient`，中心浓边缘渐隐 | 硬边正圆 `ui.rect().radius(r)` + `opacity` | 实现会比原型略「块状」。alpha 一致时观感接近，**不要为此加额外模糊** |
| 卡片模糊 | `backdrop-filter: blur(14px)` | **无**（EUI-NEO 无此能力） | 已实测：关闭模糊后与开启版几乎无差别，视觉差异来自「高光边 + 半透 + 冷阴影」，不来自模糊。**这条差异可忽略** |
| 字体 | 系统字体栈 | Inter + PingFang/YaHei 回退 | 字宽略有差异，布局按逻辑像素给值不受影响 |
| 字重 | 400/600 可用 | **只有 Bold 一份** | 原型里 400 的文字在真机上会略粗。层级靠字号+色阶承担，不靠字重 |

> 原型右下角有「玻璃模糊」开关，关掉即为真机可得效果——验收时以关掉后的样子为准。

### 风险提示（给开发）

1. **改尺寸必然踩翻探针**：`tests/probes/` 里的几何断言（首页统计行对称、列表 slot 数、关于页行高）对 px 敏感，改完必须同步；`ctest -L probe` 是硬门禁。
2. **S3 与 S6 有耦合**：背景加强后，如果统计卡还是纯白实底，会显得「背景花、卡片死」。两者要在同一批里完成。
3. **字重只有 Bold**：不要用 `fontWeight(400)` 试图做细字，引擎不切 face，只会得到「声明了 400 但渲染是 Bold」的假象。
4. **别加 `backdrop-filter`**：EUI-NEO 没有。实测关闭模糊后与原型开模糊的观感差异可忽略，玻璃感来自描边而非模糊。
