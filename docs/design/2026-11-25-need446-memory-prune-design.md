## 2. 能力前置（只读核对结论）

**结论：列举与单删缝已存在、可复用；无批量删除命令 → 客户端串行编排；来源筛选缺解析字段 → 列为开发前置；不需要新增引擎命令。**

| 能力 | 实证 | 结论 |

| 全量列举 | `IMemoryRetriever::listAll(limit,timeoutMs)`（`telemem_client.h:87-92`）→ `get_memories`（`telemem_client.cpp:790-804`）；头注释「limit 无上限（POC 定案）」；生产调用 `listAll(200,10000)`（`panel/panel_state.cpp:224-226`） | 有；**无 total/offset**，以 limit 一次拉取，命中上限需提示 |

| 创建时间 | 未解析 `created_at` | 缺；本期不做（「过时」以最后更新时间为准更贴近修剪语义） |

### 开发前置（实现任务书必须带）

- **P1 面板数据面**：`PanelState` 增后台任务——列表加载、删除队列、进度快照；compose 只读快照。禁止 UI 线程直连网关（listAll 超时档 10s，delete 单条约 10s）。
- **P2 删除编排**：串行逐条 `delete_memory`；每删 1 条回写进度；首条失败即停、保留成功计数与失败原因（§10.4）。
- **P3 来源筛选**：扩 `MemoryListItem` + `parseListResponse` 暴露来源字段，并与引擎实际字段对齐；未完成前该下拉隐藏（不留灰控件）。
- **P4 上限提示**：一次 `listAll(2000, 15000)`；返回数 == 请求上限时列表头显示「可能未显示全部」（§5.3）。
- **P5 引擎门**：仅 `State::Running` 允许列举/删除；否则错误态分流（§5.5）。

## 3. 四决议点（结论 + 理由）

### 3.1 ① 入口 = 第 4 个页面级 TAB「记忆修剪」（不是配置内子区）

| 方案 | 判断 |
|---|---|
| 配置内子区（追加折叠组/列表） | ❌ 配置视图内容已 1424px 高（`memory_module.cpp:213-220` 注释），列表再埋进去不可发现；且破坏性与配置动作混在一屏，误触代价高 |
| **第 4 个 TAB** | ✅ 任务型高频入口、可被页头直接看见；破坏性动作独立成面，进入即知语境；四 TAB 在最小窗可用宽 728 下总宽约 344，不换行（§9） |

TAB 顺序：主控台 / 记忆审核 (N) / 配置 / **记忆修剪**（追加在末位，既有 0/1/2 索引与探针不迁移；新枚举 `kViewPrune=3`）。

### 3.2 ② 列表形态 = 一次全量拉取 + 客户端筛选 + 50 条渐进渲染

- 拉取：进入视图自动加载（首次骨架），`limit=2000`、超时 15s；返回数达上限显示上限提示；切走再回来距上次 >5s 自动刷新（后台，不闪骨架），另有「刷新」文字钮。
- 排序：最后更新时间倒序；更新时间缺失（0）置底。
- 筛选三轴：
  - **关键词**：内容子串，大小写不敏感，输入即筛（≤2000 条客户端过滤，无网络）。
  - **时间**（主轴）：`全部` / `30 天未更新` / `90 天未更新` / `180 天未更新` = `updatedAt < now − N 天`；`updatedAt==0` 的条目只在「全部」出现，计数行如实报未纳入条数。
  - **来源**（P3 门控）：全部来源 / 自动采集 / 手动添加；未就绪时控件不渲染。
- 渲染：一次只画 50 行（沿用审核视图性能先例 `memory_module_panels.cpp:560`），尾部「再显示 50 条」；筛选变化重置为 50。
- 每行正文 2 行截断，行内「全文」一等入口（复用既有全文弹窗规格）。
- 理由：记忆总量在本机是百条级、删除是低频维护动作；无需分页器与虚拟列表，验收重点在「看得清、选得准、删得可控」。

### 3.3 ③ 选择与批量 = 显式勾选 + 当前筛选内全选 + 筛选变化即清空选择

- 行整行点击 = 切换勾选（复选框同步）；右侧「全文」「删除」文字钮为后建节点，优先命中，不触发整行勾选。
- 表头「全选」= 当前筛选下全部已加载条目（含未渲染的渐进部分）；再次点击取消。
- **切换筛选条件/关键词、离开本 TAB、刷新后条目消失** → 清空选择（防"隐藏的已选条目"被批量误删）；toast 不提示。
- 批量条仅在已选 ≥1 时出现（插入表头下方 44 高，不做高度动画）；批量删除需一次确认（§5.6 D2）。
- 理由：破坏性操作里「看不见的选中」最危险；宁可多一次重新勾选。

### 3.4 ④ 全清 = 输入「清空」二字武装 + 二次确认主钮（沿用既有强确认先例）

- 入口：工具卡右端「全部清空」文字级危险钮（低权重但不隐藏）。
- 弹窗：Standard 460 / 高 280 / 危险主钮 / 标题 errorText / 正文写明范围与不可恢复 / 输入框必须精确等于「清空」才武装；未武装主钮置灰。
- 执行语义：循环「清单→逐条删→再清单」直至返回 0（应对一次拉取上限与进行中新增），轮次上限 20；未清空则如实报「已删除 N 条，仍剩 M 条」。
- 理由：全清是唯一不可局部挽回的动作，成本应与风险成正比；复用项目既有强确认形态（`memory_module_modals.cpp:99-156`）不新造交互。

## 4. 页面级构图

### 4.1 滚动模型

外壳不滚：页头（32）+ TAB 行（40）固定；TAB 下方为唯一滚动容器（既有 `components::scrollView`，`memory_module.cpp:235-240`），视图内容整体内滚。工具卡随内容滚出（不吸顶）——本页筛选是进入后一次设定的动作，不是持续操作；列表卡内不二次滚动（总高交外层）。三个弹窗为页内模态层（scrim + 卡），自身内容区是唯一内滚区（全文弹窗）。与全站同类页一致。

锚定铁律：
- 工具卡/列表卡左缘 = 视图 x=0，宽 = contentW；卡内元素左右内缩 12（工具卡）/16（列表卡），与审核视图一致。
- 右置元素（来源下拉、全部清空、计数、刷新、批量钮、尾行钮）全部右缘锚定 `w−12` 或 `w−16`，不设固定左坐标。
- 列表行文本列 = 左起 46、右止于右侧动作组（40+8+40）+16；不设第三列（无空列）。

### 4.3 空间节奏与密度预算

- 行高 68（正文 2×20 + 元信息 16 + 上下 8/4）；列表卡表头 44；批量条 44；进度带 44；尾行 44；工具卡 90（内高 88 = 12+32+8+24+12，另加上下 1px 描边）；卡间距 8（`kCardGap`）。
- 字级只用记忆页既有三档：14 / 13 / 12（含 11.5 的 chip，沿用审核视图）；不引入第四档。
- **构图三问**：
  ① 滚动模型：外壳与 TAB 固定、内容整体内滚、弹窗单内滚，与全站同款（见 §4.1）。
  ② 无效空白：工具卡两行满宽利用；行文本列吃掉全部剩余宽；空/错/加载态用统一空态组件 150 高，不放大白卡、不留空列；无固定宽空列。
  ③ 密度与权重：最高权重 = 搜索与时间 chips（修剪主路径），列表行次之，单删/全清低权重（文字级/低视觉重量）；宽窗 1328 与最小窗 728 两档均无横向溢出、行文本可读宽 ≥ 542（§9）。
- 原则句（本页为何独特）：**把记忆当作可清理的库存——先按「多久没更新」筛出候选，再逐条或成批清掉；代价写在每个删除按钮旁边，选中的东西永远在眼前。**

## 10. 数据与行为细则

### 10.1 加载与刷新
- 首次进入（视图 3）→ 加载；上次成功加载距今 >5s 的再次进入 → 后台刷新（保留列表，计数前置「刷新中…」）；手动「刷新」5s 节流。
- 加载失败不丢上一次成功列表？**不保留**：错误态直接替换（避免展示可能已过期的可删条目）；重试成功后恢复。
- 排序：`updatedAt` 倒序；0 置底；同值按 id 字典序稳定排序。

### 10.2 筛选
- 过滤顺序：时间 → 来源 → 关键词；计数「共 N 条 · 筛选后 M 条」。
- 时间筛选排除 `updatedAt==0`，计数行如实报未纳入条数（§5.2）。
- 关键词只匹配正文（不含 id）；大小写不敏感；首尾空白 trim。

### 10.3 选择
- 选择集存 id；刷新/筛选后与当前筛选结果求交，消失的 id 静默移出。
- 全选只勾当前筛选（不是全部加载）；选择数 > 渲染数合法（批量作用于全部已选 id）。
- 任何筛选条件变化、离开 TAB、开始删除 → 清空选择。

### 10.4 删除编排（P1/P2）
- 单条：确认 → 关闭弹窗 → 逐条调 `delete_memory`（超时 10s）。
- 批量：按选择集顺序串行；每成功 1 条进度 +1；首条失败即停（不继续猜测性删除），保留成功计数并报失败原因。
- 全清：循环 `listAll(2000,15000)` → 逐条删 → 再清单；清单空即完成；20 轮仍未空则停止并如实报剩余；进行中新增条目也在后续轮次被清（语义 = 清空完成时刻的全部记忆）。
- 并发保护：同时只允许一个删除任务；任务期间所有入口禁用；应用退出/模块停 → 任务中止，下次进入以列表真值为准。
- 与提案链边界：被删 id 若仍被待审提案引用，提案后续执行可能回 NotFound——属提案层既有错误边界，本视图不改提案链、不主动清卡（在 toast/日志按既有通道透传）。

### 10.5 Toast 文案（单实例）
- 成功单删：「已删除」/「这条记忆已从本机记忆库移除」
- 成功批删：「已删除 N 条记忆」/「其余记忆不受影响」
- 部分失败：错误态「删除未全部完成」/「已删除 X / N 条，第 X+1 条失败：<原因>」
- 全清成功：「已清空全部记忆」/「共删除 N 条」
- 全清未净：错误态「清空未完成」/「已删除 N 条，仍剩 M 条：<原因>」
- 刷新节流：无提示（静默忽略）

### 10.6 生命周期
- 删除任务在面板层后台线程，切 TAB/切页不中断；返回本 TAB 若任务仍在跑，直接显示进度带。
- 模块停用/退出 → 任务中止（与采集循环同生命周期口径）；重启后进入按真值重拉。

## 11. 禁止项自查 + 品味自审

- 禁止项：无旧橙/陶土色；无渐变与装饰色块；红只用于删除与错误（`error`/`errorText`）；蓝未使用；无插画空态、无情绪化文案；无键盘快捷键；正文未落到代码层（本文件不含框架/库选型，HTML demo 为唯一载体例外）；未假设框架缺失能力（列表/下拉/输入/内滚/弹窗壳均为既有组件）。
- AI 五 tell：不命中——非暖米色+衬线、非暗夜霓虹、非报纸排版（行卡有 10px 圆角与 8px 间距）、非等尺寸卡片堆+统一灰影（列表行无卡无阴影，仅分隔线 + 选中底）、无全大写眉标/中点元信息串/破折号标签（元信息用括号）、无等宽数字标小数据、按钮无尾缀箭头。
- 大胆只在一处：**时间阶梯 chips（30/90/180 天未更新）+ 实时计数**作为本页视觉锚；其余（工具卡、行、批量条、进度带）全部安静克制。拿掉的装饰：行未加来源标签、未加卡片阴影、未加骨架动画、未给批量条加高度动画。
- 两遍法：第一轮构图 = 第 4 TAB + 两行工具卡 + 单列表卡 + 批量条/进度带（token 骨架：绿主色、白卡、10 圆角、8 网格、14/13/12 字级）；第二轮自审——给同类页出方案是否会得到「配置里塞一个列表 + 全选删除」？会，那是默认脸 → 换向为「以陈旧度为第一筛选轴、选中永远可见、代价写在按钮旁」的独立修剪台；为什么：老板原话「过时的、重复的记忆能修剪吗」，修剪的第一判据是时间，不是分类。
- demo 渲染自审：按 1000×640 与 1600×1000 两档对照参数表核对元素位置/字号/色值，并以脚本测量无横向溢出（详见交付说明；本机通道不支持看图时如实记录）。
