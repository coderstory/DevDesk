## 一、设计立场：四条病灶，四条 IA 决策

| 病灶（老板原话：硬堆控件、不现代、不合理、不人性） | 对症决策 |
|---|---|
| 页头一行堆 6 类元素，主动作在「提交/下一步」间漂移 | 页头三分区（身份区 / 反馈区 / 操作区），**每状态主动作唯一**且文案指名下一步（§四） |
| 前置 5 张 160px 大卡，「填单号」与「勾完成」混装 | 编辑态前置收为**单据式表单流**：一行一单据，label 定宽 + 输入 + 行尾勾（§五.2） |
| 步骤行 40px 挤 6 类控件 | 主行只留 **状态点 + 名称 + 状态 + 完成**；拖拽/排序/跳过收进行尾「···」菜单，查看收为行尾文字钮（§五.3） |
| 只读性无页面级声明，「现在该做什么」靠推断 | **模式徽标**第一眼回答「准备期还是发布日」（§四.3）；发布态整页切换为流程轨道形态（§六） |

## 二、信息架构总览（F-10）

同一页面两个形态，模式由任务状态唯一决定（无手动切换器进入产品）：

```
【编辑态 · Draft 配置中】                      【发布态 · Pending 待执行 / Running 执行中】
┌────────────────────────────────────────┐   ┌────────────────────────────────────────┐
│ ← 上线任务 10/31 周五  [○准备中][草稿]    │   │ ← 上线任务 10/31 周五  [●发布中][待执行]  │
│                     12/23▓▓░ [校验][提交发布][···] │  进度12/23 [撤回提交][下一步:确认提测单][···] │ 页头 56px
├────────────────────────────────────────┤   ├────────────────────────────────────────┤
│ (notice 反馈条，按需，3s 自动消失)          │   │ (notice 反馈条，按需)                    │
│ ┌ 发布准备 ─────────────────────────┐  │   │ ┌ 流程轨道 ─────────────────────────┐  │
│ │ 审批单据                           │  │   │ │ ◉ 任务前置 · 已完成 5/5        ▾ │  │
│ │ 提测单    [RM-20261031-007] □已完成│  │   │ ├ 生产环境 09:30–12:00  8/12 ──────┤  │
│ │ CAB 单   [CAB-2026-1031]   □已完成│  │   │ │ ●─ ✓ 提测单 RM-20261031-007 已完成│  │
│ │ nacos 工单 [MR-…]         □已审批 │  │   │ │ ●─ ◉ DB 脚本  ◀ 当前步   [确认] │  │
│ │ 数据库工单[…]            □已审批  │  │   │ │ ●─ ○ cron 配置  未完成   [确认]  │  │
│ │ 上线公告                           │  │   │ │ 🔒 部署  未解锁 · 已解锁可提前勾   │  │
│ │ [多行公告内容 textarea]      □已发  │  │   │ ├ 灰度环境 14:00–15:30  0/6 ───────┤  │
│ ├ 环境与服务 ──────────────────────┤  │   │ │ 🔒 全部步骤 14:00 解锁            │  │
│ │ ┌ 生产环境 09:30–12:00   3/8 ┐   │  │   │ └────────────────────────────────┘  │
│ │ │ order-service ·后端          │   │  │   │ ┌ 操作记录（折叠）──────────────────┐  │
│ │ │ 分支 release/20261031        │   │  │   │ │ 确认/撤回/提交/排序 全动作留痕      │  │
│ │ │ ○ 合并分支        [填写][···] │   │  │   │ └────────────────────────────────┘  │
│ │ │ ◉ nacos 配置 已填3项 [填写][···]│  │   │                                     │
│ │ └─────────────────────────┘   │  │   │                                     │
│ └────────────────────────────────┘  │   │                                     │
└────────────────────────────────────────┘   └────────────────────────────────────────┘
```

- **结构不变式**：外壳（页头 + 内容区）两态同构；差异只在内容区形态（表单流 vs 流程轨道）。内容区内滚动，外壳不滚、无分页器。
- 编辑态主动作 = 提交，**不放轨道引导**（轨道为发布态专属，2026-10-31 审计裁决）。
- 发布态内容域全部只读；编辑入口（填写/跳过/移除/排序/拖拽）一律**隐藏而非变灰**（F-03 二选一定稿：隐藏，保低干扰）；锁定步骤用「锁」语言表达不可操作（§六.2）。
- 兜底出路：Pending 页头常驻「撤回提交」次按钮（§十.1），发布态不开任何补填口子。

### 4.2 五状态 × 操作区矩阵（主动作唯一）

## 六、发布态流程轨道（F-14，须先出图定稿）

| 元素 | 规格 |

| 行 | 高 44，白底；行间 4 |

### 6.2 节点四态视觉语言（软引导的具体形态）

| 态 | 节点圆 | 行底 | 名称字色 | 行尾 | 可操作 |
|---|---|---|---|---|---|
| 当前步（下一步指向） | 14px 白底 2px #36D399 描边 + 内 6px #36D399 实点（1.6s 缓呼吸，尊重减弱动态） | **#E6FBF2 浅染 + 左缘 3px #36D399 竖条** | #1A1A1A | 「确认」绿文字钮 #157E4E（hover 底 rgba(54,211,153,.14)） | 可勾 |
| 已解锁未完成（可提前勾） | 空心 2px #999 描边 | 白 | #1A1A1A | 「确认」绿文字钮 | 可勾（软引导：允许提前，不硬锁） |
| 未解锁（锁定可见） | 空心 2px #E5E5E5 描边 | 白 | **#999999** + 行尾锁图标 14px + 解锁条件「14:00 解锁」12px #999 | 无按钮，整行不可点 | 不可操作；点击弹 notice 指名（「灰度环境 14:00 开始」） |
| 已完成 | #36D399 实底 + 白勾 | 白 | #1A1A1A | 「已完成」12px #999；整行可点 → 撤回确认弹层 | 可撤回（Done 前任意步，F-05） |

- **当前步 = 唯一绿染行**（同视口高亮唯一，操作高效原则）；其余未完成行保持白底，锁定行用字色 #999 表达，禁用大面积透明度叠层。
- 已跳过配置行（发布态只读展示）：划线灰名 + 「已跳过」12px #999，无确认钮（F-05）。
- 失败表达：不新增状态值——该步保持未完成态，通过「操作记录」补记备注；行尾不出现红色（红仅告警，未完成不是告警）。
- 超时：环境组头「已超时」chip（红染）；组内未完成步骤行尾加「已超时」12px 红字 #B91C1C，仍可勾（既有语义）。

### 6.3 已完成折叠（F-14）

| 规则 | 行为 |
|---|---|
| 组级折叠 | 「任务前置」组或某环境组**全部完成 → 默认收起**为一行摘要：「✓ 任务前置 · 已完成 5/5」14px #666 + 展开箭头；点击展开 200ms |
| 当前步所在组 | 永不折叠（含手动折叠后新当前步落入时自动展开） |
| 手动展开 | 记忆至会话内，状态变化（确认/撤回）后重算默认态 |
| 摘要行视觉 | 无节点圆，左侧绿勾 14px 替代；背景白，hover --border-2 |

### 6.4 页头提示与 F-23 锚点高亮

- Pending 未到时间：页头进度位旁显示「生产环境 09:30 开始」12px #999（来自最早未解锁环境）。
- 提醒窗「去处理」落点（F-23）：进入页面后滚动至当前步行顶部，随后当前步行做**一次**高亮脉冲（box-shadow 0 0 0 4px rgba(54,211,153,.25) → 0，800ms ease-out，仅一次）；滚动 240ms ease-out。

## 七、归档态（Done / Voided）

- Done：发布态轨道形态保留，全部绿勾；页头无主动作，徽标「已归档」；配置内容只读可查看。
- Voided：整页内容区 opacity 0.7 灰化 + 页头「恢复」次按钮；徽标「已作废」#999；配置内容仍可查看（既有语义）。

## 十、交互反馈形态（撤回提交 / 推进 / 回退 / 跳过 / 失败）

1. **撤回提交（F-02 兜底出路）**：Pending 页头次按钮 → 危险确认弹层（主按钮红）文案：「撤回后任务回到准备中（草稿），已确认的步骤与操作记录保留；修改后可重新提交。确定撤回？」→ 确认后整页切回编辑态（200ms 淡入），notice 成功「已撤回提交，可继续编辑」。Running 起按钮隐藏；已勾确认项与日志原样保留（不清理）。
2. **推进（勾选确认）**：点当前步/任意已解锁未完成行尾「确认」（或页头「下一步」）→ 状态点 150ms 弹入绿勾（scale .8→1 回弹）→ 当前步浅染底 150ms 平滑迁移至下一未完成且已解锁步骤（若在折叠组内自动展开）→ notice 成功「已确认「DB 脚本」」。
3. **回退（单步撤回）**：点已完成行 → 危险确认弹层「撤回后「nacos 配置」回到未完成，进度会重新计算。确定撤回？」→ 行 150ms 回到未完成态，notice 成功。
4. **跳过**：仅编辑态「···」菜单；发布态只读展示「已跳过」（§6.2）。
5. **失败/受阻**：不勾选 + 操作记录补记备注（F-22 既有）；门禁拒绝（缺单号/时间未到）→ notice 错误样式**指名缺项**，不弹确认层。
6. **提交（Draft→Pending）**：主按钮 → 校验（F-20 扩展：前置单号/公告内容齐备 + 分支/配置内容既有校验）→ 不过：清单弹层+行内标红；通过：切发布态（200ms），notice 成功「已提交，进入发布流程」。

## 十二、自适应

| 项 | 方案 |
|---|---|
| 基准档 | 1600×1000（设计基准）；**最小可用窗口 1000×640**（PRD UI 契约档位） |

## 十五、禁止项自查

- 色彩语义：绿=操作与当前步高亮（唯一鲜艳色）；红仅告警（超时/危险/缺项）；蓝仅链接（+既有状态 chip 信息蓝，已声明不扩面）；灰=中性/锁定/禁用。✔
- 无渐变、无装饰色块、无插画、无情绪化文案；常驻说明 ≤1 行。✔
- 圆角 6px 基准 + 内容大卡 16px 特例；8px 网格；字号三档。✔
- 主动作唯一：每状态页头至多一个绿填充主按钮。✔
- 弹层右下「取消（次）+确认（主）」；危险确认主按钮红。✔
- 自适应：1000×640 最小档无横向滚动、步骤行三要素不重叠、外壳不滚。✔
