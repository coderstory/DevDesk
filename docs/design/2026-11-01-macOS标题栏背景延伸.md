# macOS 标题栏背景延伸（方案 A 落地）

> 2026-11-01
> 用户反馈：标题栏目前是固定的白色，和窗体不协调；窗体的背景应该延伸到标题栏。

## 一、诊断

**现象定位（macOS 专属，Windows 无此问题）**

- macOS 走 **AppKit 系统标题栏**（`customWindowChromeSupported()` 只在 Windows 为 true），
  标题栏是**非客户区**，EUI 的逐帧绘制（动态光晕）进不去 → 标题栏只能是
  `applyWindowVisuals` 落的一块**静态底色** `TitleBarAppearance{customColor=theme.colors.background,
  colorAlpha=窗口效果档 α}`。off 档 α=1.0 → 不透明的 `#F5FAF7`，即用户看到的"固定白"。
- EUI 的 macOS 层**已经**做了 `titlebarAppearsTransparent=YES`，标题栏能透出窗口背景色——
  但那只是 clearColor 的纯色，没有光晕。
- Windows 走 EUI 自绘的 40px 标题栏，光晕画满全屏，**本来就连续**。

**EUI-NEO 的历史结论（本次推翻并解决）**

`core/platform/window_effect_macos.mm` 文件头记录：曾尝试 `NSWindowStyleMaskFullSizeContentView`，
真机实测 **"FSCV 会把 GL surface 整体下移一个标题栏高（32pt）"**（内容位移、底部裁切、
标题栏与内容间留透明空带），二分实测「容器重挂载本身不偏移 → 偏移由 FSCV 引入」，
故**主动放弃 FSCV**（几何零位移优先）。

**本次找到偏移的确切成因与解法**：

- 成因：FSCV 单独设置时，AppKit 只让 contentView「**可以**」延伸，**不会自动**把它和
  其下的 GL 视图放大 → GL 视图仍停在客户区矩形，相对窗口就偏了一个标题栏高。
- 解法：FSCV 之后**显式把 contentView 与 GL 视图的 frame 一并对齐到整窗**。
  GLFW 的 `_glfwGetWindowSizeCocoa` / `_glfwGetFramebufferSizeCocoa` 都读
  `[window->ns.view frame]`，故 GL 视图放大后**窗口逻辑尺寸与帧缓冲尺寸一并放大**，
  宿主的绘制坐标系随之覆盖标题栏 → 背景连续。

## 二、实现

### EUI-NEO（commit `a702a9d`，已推 origin/main）

- `TitleBarAppearance` 新增 `extendContentIntoTitleBar`（默认 false；Windows 忽略）。
- macOS 侧 `enableContentExtensionIntoTitleBar()`：
  ① `styleMask |= NSWindowStyleMaskFullSizeContentView` + `titlebarAppearsTransparent=YES`
  ② `alignContentToFullWindow()`：contentView 与 GL 视图一并对齐到整窗
  ③ `titleVisibility = NSWindowTitleHidden`（系统标题文字隐藏，宿主自绘品牌，避免同名重复）
- **两个坑**：
  - `alignContentToFullWindow` 里必须**只取 `nsWindow.frame` 的尺寸、origin 归零**。
    直接用 `nsWindow.frame` 会带上它在**屏幕上的位置**，把整个内容视图搬偏（真机实测错位）。
  - 挂/摘材质视图（`attachMaterialView`）会重排 contentView 子视图并改 GL 视图 frame →
    该函数收尾处按关联对象标记**重新对齐**，否则背景在标题栏处断掉。

### DevDesk

- `settings_config.cpp` 的 `applyWindowVisuals`：`appearance.extendContentIntoTitleBar = true`
  （`main.cpp` 的主题回调紧跟其后调 `applyWindowVisuals`，最终状态一致）。
- `app_sidebar.cpp`：macOS 上内容让出系统标题栏那一条（30px，红绿灯所在）；
  Windows 走自绘标题栏，自带 40px 占位，不受影响。
- 单测 `test_app_sidebar.cpp` 的几何断言按平台条件化（`kExpectedBodyTop`：macOS 30 / 其他 0）。

## 三、验收

- Release 全量单测 **2088 例 / 通过 2088 / 失败 0**
- Release 构建 + 签名 + 安装 `/Applications/DevDesk.app` 成功
- 真机取证（`screencapture`）：标题栏区已透明、内容延伸到窗口顶部，红绿灯浮在左上角

## 四、遗留 / 待复验

1. **最终取证实况未拍到**：屏幕在最后一次取证时进入休眠（`screencapture` 只拿到黑帧）。
   中间一版取证确认了「FSCV 生效 + 顶部出现光晕 + 红绿灯浮起」，但**内容偏移修正后的
   最终视觉需要复验一次**（屏幕保持唤醒、窗口在前台）。
2. **侧边栏品牌区与红绿灯的关系**：当前用「内容整体下移 30px」避让。更好的做法是只让
   侧边栏品牌块避让红绿灯（页面区不受影响）—— 需单独工单。
3. **窗口效果档的合成**：标题栏区现在由 GL 内容绘制，而窗口效果（半透/磨砂）走
   NSVisualEffectView 材质层，材质与 GL 内容的叠放次序需逐档复验（当前 off 档已验证）。
