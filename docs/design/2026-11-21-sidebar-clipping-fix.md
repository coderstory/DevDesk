# 侧边栏裁切修复设计（池 bug#368 · P0 设置/关于不可达）

日期：2026-11-21　角色：ui-ux-designer　载体：EUI-NEO（纯 DSL，无渐变 API）
关联 demo：`docs/design/2026-11-21-sidebar-clipping-fix-demo.html`

## 0. 结论摘要

- **推荐方案 C** = 方案 A（系统组锚底，不参与滚动）+ 方案 B2（边缘 chevron 提示 + 当前项自动滚入视口）。
- 关键取舍：**不用可见滚动条**。滚动条视觉被 bug188 老板裁决（2026-11-05）明确取消，B 的可视提示改为右侧 16px 栅边里的 12×12 chevron，不触碰该裁决；若老板愿意解除 bug188，可换 B1（4px 细滚动条），参数一并给出。
- 参数基线（展开 200px / availH≥712 正常档）：`topPad 32 / brandH 56 / brandNavGap 28 / itemH 40 / gap 4 / toggleZone 56 / footerZone 109`。

## 2. 页面级构图

### 2.1 构图三问

1. **滚动模型对吗**：错。当前是「品牌不动 + 其余全滚」，把规范要求锚底的系统组也卷进了滚动流。改为四段式：品牌（固定顶）→ 工作导航（内容区独立内滚）→ 系统组（固定底）→ 折叠钮预留区（固定底）。外壳不滚，只有工作导航区滚 —— 与全站「外壳不滚、内容区各自内滚」一致。
2. **有无大段无效空白**：无。系统组上方的弹性空白只在「工作项少 / 窗口高」时出现（1600×1000 档留白 165px），它是 flex spacer，服务「系统组贴底」这一分组语义，不是堆叠空洞。窗口变矮时弹性区被压缩到 0，空白自然消失。
3. **信息密度与权重平衡**：高频业务项（首页→终端）权重最高，占中段全部视觉带宽；系统组（设置/关于）是低频平权项，靠 1px 分隔线 + 底部锚定降权，不与业务项争视线。两档窗口下比例均成立：最小窗（1200×720）业务区 441px / 系统区 109px；宽窗（1600×1000）业务区 689px（其中 165 为空）/ 系统区 109px。

## 3. 候选方案

### 3.1 方案 A：系统组独立锚底

做法：`navPlan` 只规划业务行（含上线分组头/子页），系统组（Settings/About）从滚动流移出，作为独立底部块；原「业务→系统」的组间 divider 移作系统块上沿分隔线。

| 参数（正常档 availH≥712，展开 200） | 值 |
|---|---|
| footerZoneH | 109 = 8（呼吸）+1（分隔线）+8+40（设置）+4+40（关于）+8 |
| footer 顶 | availH − 56（toggleZone）− 109 = **availH − 165** |
| 分隔线 | x=16 / w=168 / h=1 / `borderDefault` #E5E7EB |
| 工作导航视口 | y=116, h=availH−281（1438×801 → **490**） |
| 工作区内容高（分组收起） | 12 行 ×44 −4 = **524** |

| 评估维度 | 结论 |
|---|---|
| 200px 可行性 | ✅ 分离线宽 168 与行宽 16..184 完全同心，无新开列 |
| 1438×801 表现 | ⚠️ 工作区 524 > 视口 490，**溢出 34px**：缺陷从「关于不可见」转移成「上线行只露出 6px、34px 被裁」 |
| 1600×1000 表现 | ✅ 视口 689 > 524，无溢出，规范意图完整达成 |
| 1200×720（紧凑档）表现 | ⚠️ 视口 441、内容 524，溢出 83px |
| 20 项时（工作区 18 行） | ⚠️ 视口不变、内容 788，溢出 298px；系统组始终可达，但约 6.8 行只能靠盲滚滚出 |
| 实现复杂度 | 中：改 `navPlan` 规划段、contentH、offset clamp 上界、footer 绘制块；`navContentKey` 需并入「是否含系统组」 |
| 折叠态 72px | ✅ 行 hit x=16/w=40，图标居中 22..50；分隔线 x=16/w=40；垂直几何不变（footerZone 仍 109） |

**单独用 A 不足**：在 1438×801 与 1200×720 两档都把「不可达」从系统组挪到工作区尾部，用户仍然看不见「还有更多」。

### 3.2 方案 B：可视提示 + 当前项自动滚入（保持单一滚动流）

B 拆两个子档，差异只在提示载体：

- **B1：恢复 4px 悬浮滚动条** —— `scrollbarWidth(0.0f) → 4.0f`，`scrollbarOverlay(true)` 保持（内容宽不被占，仍 200）。thumb 颜色 `textTertiary` #6B6D80，透明底无轨道。**需老板解除 bug188**。
- **B2：右侧栅边 chevron 提示**（推荐，不触碰 bug188）—— 不引入滚动条组件视觉，只加两个 12×12 的上下箭头，落在行右缘之外的 16px 栅边里。

共同的「当前项自动滚入」参数（两档一致）：

| 项 | 值 |
|---|---|
| 触发 | ① 路由切换后 ② 窗口高/档位/分组收展变化后（在既有 offset clamp 之后紧接执行） |
| 规则 | 若 rowTop − 4 < offset → offset = rowTop − 4；若 rowBottom + 4 > offset + viewportH → offset = rowBottom + 4 − viewportH |
| 缓冲 | 上/下各 **4px** |
| clamp | `[0, contentH − viewportH]` |
| 动画 | 无（瞬时，与 §11.2「无动画」一致） |

B2 chevron 参数（展开 200）：

| 项 | 值 |
|---|---|
| 字形 | 12 × 12，chevron-up / chevron-down（码点 0xF077 / 0xF078），字形盒内居中 |
| 命中盒 | 16 × 24，x = **184..200**（行右缘 184 之外，压进 16px 栅边）；展开态字形实占 186..198（右距 2px） |
| 上箭头 | 命中盒 y = navStart − 2 .. navStart + 22；下箭头 y = viewportBottom − 22 .. viewportBottom + 2 |
| 显示条件 | 上箭头：offset > 0.5；下箭头：offset < maxOffset − 0.5（隐藏时 pointer-events 关闭，不可误点） |
| 常态色 | `textTertiary` #6B6D80；hover `primaryHover` #06AD56 + 底 `primarySoftBg` #E8F8EE（圆角 6） |
| 按压 | scale 0.92，100ms ease-out；松开 200ms OutBack |
| 点击 | 滚动 0.8 × viewportH（1438×801 → 392px），clamp 到 [0, maxOffset] |
| 折叠态 72 | 命中盒 x = (72−16)/2 = **28..44**，字形居中；其余同上 |
| 层级 | 浮在滚动区之上（z 高于行），不参与滚动、不被行遮挡 |

| 评估维度 | 结论 |
|---|---|
| 200px 可行性 | ✅ chevron 落在栅边，不压任何文字（文字右界 184） |
| 1438×801 | ✅ 溢出由提示与自动滚入共同兜住；系统组仍在滚动流中（**与规范 §14.4「设置项独立在底部」冲突**） |
| 20 项 | ✅ 溢出 282px 全部可达，chevron 一次点击走 0.8 屏 |
| 实现复杂度 | 低-中：chevron 两个节点 + 可见性公式；自动滚入约 15 行；**不破 bug188** |
| B1 额外成本 | 改 1 个字面量 + 视觉走查；需裁决 |

|---|---|
| 200px | ✅ |
| 1438×801 | ✅ 上线组经 1 次 chevron 点击或滚轮可达；设置/关于常驻底部 |

## 4. 推荐：方案 C（A + B2）

理由按权重：
1. 只有 A 能让「设置/关于」回到规范 `docs/UI-UX-DESIGN.md:24-25` 与 macOS 惯例要求的位置——这是缺陷的**语义根因**，不是可达性问题；
2. A 单独会把不可达从系统组转移到工作区尾部（1438×801 溢出 34 / 1200×720 溢出 83），**必须有 B**；
3. B 选 B2 而非 B1：bug188 是老板 2026-11-05 的明确裁决，chevron 不产生滚动条视觉（无 thumb / 无 track），无需重新裁决；若老板愿意解除，B1 只是把 `scrollbarWidth(0.0f)` 改 `4.0f`，可随时切换；
4. C 在两档窗口都成立，且在宽窗自动退化为纯净的 A（chevron 因 maxOffset=0 隐藏）。

**唯一的不可逆代价**：A 无条件吃掉 109px 垂直空间，使 1438×801 档工作区视口从 599 降到 490。判定值实测：若某天导航项超过 24 个，需重新评估把「上线」也收进分组折叠或考虑二级抽屉（不在本次范围）。

| 导航项 | 左键单击 / 键盘 Enter | hover → 按压 0.98 → 选中胶囊 | `router->navigateTo(page)` + 自动滚入 | 连点：幂等（同页不再滚，`maxOffset=0` 时 offset 恒 0）；拖出：按压态立即复位，不触发点击；长按：无特殊行为 |
| 分组父项「上线」 | 单击 | hover 底；展开时 chevron 由 ▸ 转 ▾ | 只切展开，不导航 | 连点 = 反复收展，offset 每次按 clamp + 自动滚入重算；组内当前页时父项保持选中胶囊 |
| chevron 上/下 | 单击 | hover：`primaryHover` 图标 + `primarySoftBg` 圆角 6 底；按压 scale 0.92 | offset ±392（0.8×viewportH）后 clamp | 到顶/到底即隐藏（阈值 0.5px），不会出现可点但无效；长按不连续滚（保持单次） |
| 自动滚入 | 路由/窗口/收展变化 | 无视觉动画（瞬时） | 目标行完整入视口（±4px 缓冲） | 目标行高 > 视口（不可能：40 < 490）→ 兜底对齐顶 |
| 折叠钮 | 单击 | hover scale 1.09 / 按压 0.90 / 280ms OutBack | 宽 200↔72 瞬时切换 | 不变（引用 `app_sidebar.cpp:958-1008` 既有规格） |
| 侧栏滚动 | 滚轮 / 拖拽 | 原生跟手 | offset 变化后 chevron 可见性重算 | 到边界 clamp，不橡皮筋 |

## 9. 20 项时表现预估（availH 771 / 正常档 / 展开 200）

压力口径：20 行 = 工作区 18 行（17 顶层 + 上线分组头）+ 系统 2 行 + 1px 分隔线，内容高 = 20×44 − 4 + 5 = **881**。

| 方案 | 工作视口 | 内容高 | 溢出 | 可见行 | 可达性 |
|---|---|---|---|---|---|
| 当前 | 599 | 881 | **282** | ≈13.6 | ❌ 尾部约 6.4 行永久不可达 |
| A | 490 | 788（18 工作行） | **298** | ≈11.1 | ❌ 可达但盲滚，无任何提示 |
| B1/B2 | 599 | 881 | 282 | ≈13.6 | ✅ chevron 1 次到底 |
| C | 490 | 788 | 298 | ≈11.1 | ✅ chevron 1 次到底；系统组常驻 |

结论：项数增长只压缩工作区，系统组恒定 109px 不受影响；chevron 每次 392px，一片到底所需点击数 = 1（298 < 392）。

## 10. 禁止项自查 / 两遍法自审

- 未出现框架/库名（EUI-NEO 仅作为既有实现载体在「事实」节提及，规格表零技术绑定）；
- 无渐隐遮罩、无毛玻璃、无渐变、无装饰色块；
- 无「适当/视情况」类占位：全部参数为具体 px / token 名 / ms；
- 四色语义未越界：绿仅用于选中与可点反馈，灰承担中性，未用红/蓝；
- 同语义同值：系统组行与工作行共用同一套行几何（40/44/16/28/56/128）。

两遍法第二轮（「给同类页出方案会不会得到同样结果」）：
- 默认答案会是「加个滚动条或缩行高」——那是 AI 默认脸（SaaS 侧栏套件）。本设计把决策换成**结构分层**（系统组锚底）+ **非滚动条的滚动提示**（栅边 chevron），并把两者的分界处理成 1px 分隔线 + 16/8/8 的呼吸节奏。
- 大胆只花在一处：底部系统块的「独立成区」。其余全部沿用现有 token（行高 40、圆角 6、白卡胶囊），不做二次风格漂移。
- 交付前拿掉的装饰：原备选的「更多 ⌄」文字标签 pill（不服务任务书，chevron 已表达同一信息）。
