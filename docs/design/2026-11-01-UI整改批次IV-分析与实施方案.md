## 1. A 组：材质分层与果冻效果

### 1.1 现状事实

材质只有两个来源，定义在 `src/ui_kit/glass.h`：

| 函数 | 浅色 alpha | 深色 alpha | 用途 |
|---|---|---|---|
| `glassFill` (= `ui_kit::cardSurface`) | 0.72（+3% 绿染） | 0.92 | 卡片层 |
| `glassPanelFill` | 0.55 | 0.55 | 面板层（看板列 / 大底板） |

半透**只在这两个函数里存在**。任何直接写 `t.colors.surface` 的矩形都是**完全不透明**——这就是「部分卡片有半透、部分没有」的机制性根因，不是漏改某一处。

### 1.2 材质登记表（本次要建立的新规范）

| 层级 | 语义 | 填充 | 描边 | 阴影 | 圆角 |
|---|---|---|---|---|---|
| **L0 页面底** | 页面背景 | 不透明 | 无 | 无 | — |
| **L1 容器卡** | 装条目的面板（todo 列、agent 列表面板、schedule 分段容器） | `glassPanelFill` (α .55) | `borderDefault` 1px | 面板阴影 | 14px |
| **L2 业务卡** | 容器内的业务条目（todo 条目、agent 任务项、release 版本项） | `cardSurface` (α .72/.92) | `borderDefault` 1px | `panelShadow` | 12px + **果冻** |
| **L3 内嵌盒** | 输入框、值盒、代码块、弹窗内嵌容器 | `t.colors.surface`（不透明） | `borderDefault` 1px | 无 | 8–10px |

**关键判定规则**：L3 保持不透明是**对的**（输入框不透明才有可读性）；要改的只有**被误当成 L3 用的 L2 业务卡**。

### 1.4 果冻效果规格（新增，A2）

「果冻」= **软**（大圆角）+ **弹**（回弹缓动）+ **呼吸**（轻微形变）。EUI 无 backdrop-filter，质感靠几何与动效，不靠模糊。

EUI 可用能力（已核实）：

| 能力 | API | 位置 |
|---|---|---|
| 圆角动画 | `AnimatedValue<float> radius` | `runtime_instances.h` |
| 变换动画 | `AnimatedValue<Transform> transform` | 同上 |
| 回弹缓动 | `Ease::OutBack` | `EUI-NEO/core/animation.h:20` |
| hover/pressed 色 | `.states(normal, hover, pressed)` | `core/dsl.h:1016` |
| 按压缩放 | `.visualStateFrom(id, pressedScale)` | `core/dsl.h:798` |
| hover 缩放/位移 | `.runtimePointerTransformFrom(id, rotX, rotY, hoverScale, maxTx, maxTy)` | `core/dsl.h:800` |
| 显隐动画 | `.transition(...)` + `.animate(AnimProperty::...)` | 现有代码已在用 |

**果冻三段式（建议规格）**

| 状态 | 圆角 | 缩放 | 缓动 | 时长 |
|---|---|---|---|---|
| 常态 | 12px | 1.00 | — | — |
| hover | 16px | 1.02 | `OutCubic` | 180ms |
| 按下 | 8px | 0.97 | `OutBack`（回弹） | 120ms → 260ms 回弹 |

实现落点：新增 `src/ui_kit/jelly.h`（inline，零链接成本），对外一个

```
ui_kit::jellyCard(ui, id, x, y, w, h, t, onClick)
```

内部：`.rect` + `.radius()` + `.transition()` + `.animate(AnimProperty::Radius | AnimProperty::Transform)` + `.visualStateFrom(id + ".bg", 0.97f)`。
**注意**：`states()` 只能改颜色不能改圆角/缩放，圆角与缩放要用 `transition` + `animate` 显式声明属性，否则不会动。

### 1.5 容器卡 / 业务卡分层落地（A3）

- L1 容器卡统一走 `glassPanelFill`（todo 列已如此，`todo_ui_board.cpp:337`），agent 列表面板 `agent_module.cpp:575` 当前用 `cardSurface`（应降到 L1 档）。
- L2 业务卡统一走 `cardSurface` + `jellyCard`。
- **禁止**在 L2 出现 `t.colors.surface`。

## 2. B 组：智能体列表重设计

### 2.1 现状几何（`agent_module.cpp`）

```
kTaskRowH   = 44
kTaskCardPad= 12
kTaskCardH  = 44 + 24 = 68      ← 卡高固定
kTaskCardInset = 10
contentW    = screen.width - 64  ← 卡宽 = contentW - 20，无上限
kTaskActionW = 56
```

1600×1000 窗下：卡 **1516 × 68** ≈ 22:1，确实是细长条。

行内元素：`标题` + `配置异常?` + `限次?` + `已停用?` + `状态点` + `状态文字` + `详情` + `编辑` + `启停` + `删除` + `入队?` + `启动` = 最少 8 个子元素、最多 12 个。
标题宽度靠 `fixedW` 反算：`titleW = rowW − fixedW − rowGap×(childCount−1)`，宽屏下标题仍被 5 个 56px 按钮压到只剩几百 px。

### 2.2 改造方案

**(1) 改成多列网格**（不再是「单列 + 卡宽上限」）—— 抄 MCP 页的 `ui.flow` 网格
（`mcp_page_module.cpp:40`/`:80`/`:245`），它注释原话就是「**避免宽窗里卡片被拉成横条**」：

```
kCardMinW = 340   kCardMaxW = 420   kTaskCardH = 110
列数 = gridColumns(contentW, gap)   // 抄 mcp_page_module.cpp:80
```

单列怎么限宽都不行（详见 §10.4 的数字账推导）；
**只有多列才同时解决「不细长」和「不留大片空白」**。窄窗（内容宽 < 720）自动退化为 1 列。

**(2) 卡高与内容分三行**

```
kTaskCardH = 120  （三行：标题行 22 + 状态行 18 + 触发条件行 18 + 上下内边距 12×2 + 行间距 11）
```

- 标题行：`任务名`（占满卡宽 − 右侧状态药丸宽）+ 右侧状态药丸（`运行中/已完成/失败/一次性`）
- 状态行：状态点 + 状态文字 + 徽章（配置异常 / 限次 / 已停用）
- 触发条件行：cron 原文 / 「常驻」/ 「一次性」+ 最近一次运行时间

> 卡高 120 与 MCP 页的 `kCardH = 120` 对齐（`mcp_page_module.cpp:43`）→ 两页卡片观感统一。

**(3) 操作按钮组改 hover 才出现（B2+B3）**

| 操作 | 形态 | 位置 |
|---|---|---|
| 启动 | **常驻** 主按钮（Primary，56×32） | 卡右上 |
| 详情 | hover 才出（图标按钮 28×28，fa-circle-info） | 卡右下组 |
| 编辑 | hover 才出（fa-pen） | 同上 |
| 启用/禁用 | hover 才出（fa-power-off） | 同上 |
| 入队（常驻任务） | hover 才出（fa-list） | 同上 |
| 删除 | hover 才出（fa-trash，danger 色） | 同上 |

实现：

```cpp
// ⚠️ 不要用 hoverOpacityFrom 做这件事 —— 三个硬约束让它做不了（见 §10.0.1）。
// 正确范式 = MCP 页的「透明 hit rect + onHover 回调 + 每卡 hover 状态」（mcp_page_module.cpp:416）
//
// 1) 卡片铺一个透明命中面（铺满整卡，最后 build → 命中优先），吃 hover 与点击
inner.rect(id + ".hit")
    .size(cardW, kTaskCardH)
    .states(kTransparent, kTransparent, kTransparent)   // 三态同色 → 不能当 hoverOpacityFrom 源
    .onHover([this, id](bool h) { hoveredCards_[id] = h; })
    .onClick([this, taskId] { openTaskDetail(taskId); })
    .build();

// 2) 操作组：每帧按状态决定 opacity（不是 hoverOpacityFrom）
inner.stack(id + ".actions")
    .size(actionsW, 28.0f)
    .zIndex(2)
    .opacity(hoveredCards_[id] ? 1.0f : 0.0f)
    .content([&] { /* 5 个图标按钮 */ })
    .build();
```

EUI 侧已核实：
- `hoverOpacityFrom(sourceId, hiddenOpacity, visibleOpacity)` 在 `core/dsl.h:799`，`RectBuilder`/`TextBuilder`/`StackBuilder` 均继承 `BuilderBase` → **签名都可用**，但**语义上有三条硬约束**（§10.0.1），本场景用不了；
- `hoverBlend` 是 `SmoothedValue<float>`（`runtime_instances.h:64`）→ 连续渐变，能做淡入而非硬切；
- `components::tooltip` 在用同一机制（`components/tooltip.h:75`），但它的源是 **rect**（如 `md.help.icon.bg`）→ 合法；
- **项目内已验证的 hover 显隐范式是 MCP 页的 `onHover` + 状态集合**（`mcp_page_module.cpp:416-424`）→ **照抄它**。

**可访问性红线**：hover-only 对键盘用户不可达（EUI 目前**没有** focus 状态，`core/dsl.h` 搜不到 `focusBlend/hasFocus`）。
→ **已拍板（2026-11-01）**：不考虑无鼠标用户，**不做缓解**（常显开关 / 右键菜单均不做），hover-only 直接上。

## 3. C 组：定时页

### 3.1 列表缺卡片（C1）

`schedule_ui_list.cpp` 的 `drawUserRow` / `drawSystemRow` **完全没有 `cardPanel` 调用**（grep 命中数 = 0），行是裸 `rect` + 文本拼的；这与 todo / agent / release 的「条目 = 业务卡」规范不一致。

方案：
- 每行包一张 **L2 业务卡**：卡宽 = 内容宽 − 2×inset（**全宽，不限宽**——定时行信息量大，需要全宽），卡高 = 行高 + 2×pad（pad 12）。
- 系统定时段（L1 容器卡内的 L2 业务卡）与用户定时段同规格。
- 卡片走 `jellyCard`（与 B 组统一）。
- 系统行的锁图标语义保留在卡内右侧。

### 3.2 新建按钮重复（C2）

**实测结论：层级其实已经分开了，问题比预想的小。**

现有两处：

| 位置 | 节点 id | 按钮级别 | 源码 |
|---|---|---|---|
| 页头 | `schedule.new` | **Primary（填充绿钮）** | `schedule_ui_list.cpp:826` |
| 用户定时空态 | `schedule.list.user.empty.action` | **Secondary（非填充）** | `ui_kit/empty_state.cpp:122` |

⚠️ **原方案写「空态是 Primary、页头降级为 Secondary」是错的** ——
`ui_kit::emptyState` 的 action 按钮**默认就是 `ButtonLevel::Secondary`**
（`empty_state.cpp:122` 硬编码），页头那个才是 Primary 填充。

所以「两个绿钮同屏」的描述不成立：**空态那个本来就是非填充**。
真实观感问题是**两个按钮都在同一位置抢注意力**（页头右上角 vs 空态卡中央），
而不是两个同色同级的绿钮。

方案（推荐）：**只降页头**——
页头 `schedule.new` 在**有数据时**保持 Primary（这是高频入口，需要显眼），
**空态时降级为 Secondary**（此时空态中央已经有一个引导按钮了，页头不必再抢）。
判据：空态时页头是幽灵钮 + 空态卡中央一个次级引导钮；有数据时页头绿钮。

⚠️ 实现注意：`ui_kit::emptyState` 的 action 有独立 id `<id>.action`
（`empty_state.h:47` 注明「单测按此定位」），要单独调它的样式**不要改 emptyState 本身**，
否则影响全站所有空态。

备选（不推荐）：直接删掉页头按钮，仅靠空态引导 —— 但有数据时就没有新建入口了，不可取。

## 4. D 组：首页

### 4.1 最后 2 张卡文本缩短（D1）

**已查实的机制**（`home_module.cpp:123`）：

```cpp
std::string labelText = badge.empty() ? label : label + " · " + badge;
```

`kStatCards` 的 `title` 确实是短词，但卡片实际显示的是**标题 + 说明拼接**：

| 卡 | label | badge | 实际显示 |
|---|---|---|---|
| 今日笔记 | 今日笔记 | 今日修改过的笔记 | 今日笔记 · 今日修改过的笔记 |
| 待办任务 | 待办任务 | 待办+进行中未完成 | 待办任务 · 待办+进行中未完成 |
| **逾期任务** | 逾期任务 | 已过截止时间 | **逾期任务 · 已过截止时间** |
| **API 调用** | API 调用 | 今日代理调用 | **API 调用 · 今日代理调用** |

方案：**正常态不再拼 badge，只留 label**（即「逾期任务」「API 调用」）。
但 badge 同时承担**错误态**（`ok ? 说明 : "加载失败"`）—— 加载失败必须显形，不能一起去掉。

```cpp
// 正常态：只留指标名；错误态：保留「加载失败」
const std::string labelText = (!ok && !badge.empty())
    ? label + " · " + badge
    : label;
```

⚠️ **别把下面这段溢出测量保护一起删了**（`home_module.cpp:124-131`）：
合并文本量宽超过卡宽时**丢弃 badge 只留指标名** —— 注释明写这是防
「居中文本越出卡缘」（home_probes 的 6(a) 溢出判据守这条），
且量宽留了 12px 余量（measureTextSize 与最终排版有 1~2% 差）。

改后逻辑变成「正常态本来就只有 label」→ 测量保护**只在错误态生效**：
```cpp
std::string labelText = label;
if (!ok && !badge.empty()) {
    std::string merged = label + " · " + badge;
    core::TextStyle ms; ms.text = merged; ms.fontSize = core::theme::scaled(14.0f);
    if (core::TextPrimitive::measureTextSize(ms).x + 12.0f <= cw) labelText = merged;
}
```
→ 错误态在窄卡下仍可能放不下「逾期任务 · 加载失败」→ 保留溢出丢弃逻辑。

**连带的一致性提醒**：~~只改这 2 张会导致 5 张卡标签长短不一~~。
**已拍板（2026-11-01）：5 张统一短标签**——`drawSolidStatCard` 是 5 张卡共用路径，
统一改反而无需按卡 id 加条件分支，改动量更小；错误态保留「加载失败」不变。

### 4.2 今日 Token 分布卡折叠态太矮 + 文本只有上边距（D2）

**已查实的机制**（`home_module.cpp`）：

| 项 | 值 | 位置 |
|---|---|---|
| 折叠态卡高 | `kHomeChartCollapsedH = 56`（**固定，不随字号缩放**） | L42 |
| 卡内上边距 | `padding(spacingLarge)` = 16 | L644 |
| 标题 y | 16，行高 22，**顶对齐**（无 `verticalAlign`） | L650–658 |
| 折叠时内容 | `if (!chartCollapsed_)` 整块图表区不建 → **只剩标题** | L680 |
| 标题文案 | 「今日 Token 用量分布（每小时输出 token 合计）」 | L653 |

两个症状的成因：

1. **「高度太低」** —— 56px 里只有 16（上边距）+ 22（标题）+ 18（下方空）。
   标题又是长句，在窄窗口的 `contentW − 32` 盒里被截断。
2. **「文本只有上边距，没有下半句」** —— 折叠态**不渲染任何副标题/说明行**
   （`if (!chartCollapsed_)` 把整块内容跳过了），标题在 56px 卡里又是**顶对齐**，
   视觉上「上面有留白、下面没内容」。

方案：

| 项 | 改法 |
|---|---|
| 折叠态高度 | 56 → **64**，且改为 `core::theme::scaled(64.0f)`（跟字号档） |
| 折叠态标题 | 改短为「**今日 Token 分布**」；展开态才用全称「今日 Token 用量分布（每小时输出 token 合计）」 |
| 垂直居中 | 折叠态标题加 `.verticalAlign(eui::VerticalAlign::Center)`，行盒高 = 卡内高，文字真正居中 |
| 行高 | `.lineHeight()` 改 `core::theme::scaled(22.0f)`（现在写死 22，放大档字高 > 行盒 → 裁切） |
| 折叠箭头 | 位置 `y=16` 随卡内高联动，居中对齐到标题同一基线 |
| 展开态 | 保持现状，但 `chartWrapH = chartCardH − 48 − 16` 里的 48/16 也要确认随卡内边距一致 |

## 6. F 组：字号缩放健壮性（**本组是根因级，风险最高**）

### 6.1 现象与根因

用户反馈：不断调整字号缩放后，**部分文本不展示或展示不全**；设置-模块 tab 文本全乱。

根因是**两套尺寸口径混用**：

| 口径 | 写法 | 缩放后表现 |
|---|---|---|
| 缩放过的 | `.fontSize(core::theme::scaled(12.0f))` + `.lineHeight(core::theme::scaled(20.0f))` + `.size(w, scaled(h))` | 正常 |
| 没缩放的 | `.size(w, 20.0f)` / `.lineHeight(20.0f)` / 裸字号字面量 | **字变大了但行盒没变 → 被裁切 / 溢出重叠** |
| **半缩放（最恶劣）** | 同一张卡里标题走裸字号、描述走缩放 | **字号比例被打破 + 行盒没变 → 描述压标题、跨格撞车 → 「全乱」** |

EUI 的 `TextBuilder` 是「给定行盒 → 按 lineHeight 排 ink → 超出即裁」，所以**行盒高度不随字号缩放 = 文字被裁**（表现为「展示不全」）；而多个固定行高的行叠在一起（设置模块 tab 的多行网格）会互相压盖（表现为「全乱」）。

### 6.1.1 设置-模块 tab「全乱」的确切根因（已查实）

`settings_ui_cards.cpp:452–455`：

```cpp
cardTitle(ui, id, t, 16.0f, w - 56.0f - kMcpToggleBoxW, 22.0f, 22.0f, "模块");
//                    ↑ 裸 16.0f，不缩放      ↑ 22 固定      ↑ 22 固定
cardDesc (ui, id, t, 40.0f, w - 56.0f, roundFs(16.0f), "开关即时生效…");
//                     ↑ y 固定 40          ↑ 缩放后的字号
```

放大档下：标题字号**不变**、描述字号**变大**，描述起始 y 固定 40、行高变大 →
描述顶到标题、甚至压到下一格 → 「全乱」。
另：`kMcpToggleBoxW = 150` 注释明写「不随字号缩放」，标题可用宽度被固定吃掉 150，
字号一放大标题先被挤掉。
格内每个模块的 name/desc 也有同样问题（注释已承认「窄列必然超宽 → 省略号兜底」）。

### 6.2 方案（分三步，建议一次做完）

**第 1 步：建立单一缩放入口**

```cpp
// src/core/theme.h 新增（紧邻现有 scaled()，两者共用 fontScale()）
struct ScaledText { float fontSize; float lineHeight; };
inline ScaledText scaledText(float baseFont, float baseLineHeight) {
    const float s = fontScale();
    return {baseFont * s, baseLineHeight * s};
}
```
所有文本的 `fontSize`/`lineHeight` **必须**来自同一个 `scaledText` 调用，杜绝「只缩字号不缩行高」。
⚠️ 双乘红线见 §10.7（第 1 步），**`scaledText()` 的两个参数都必须是未缩放的字面量基准**。

**第 2 步：审计「行盒未缩放」清单**

用脚本扫全仓，找出所有 `.size(..., <数字>)` / `.lineHeight(<数字>)` / `.height(<数字>)` 里数字**未**经过 `scaled()` 且该元素含 `.text()` 的调用点。已知高危区（字号被缩、容器没缩）：

- `agent_module.cpp` 任务行内所有 `.size(x, 20.0f)` / `.size(x, 18.0f)`
- `schedule_ui_list.cpp` 列表行与页头
- `settings_ui_cards.cpp` 模块 tab 的多行网格（**用户报「全乱」的那一处**）
- `home_module.cpp` 统计卡内文本
- `md_module_*` 预览区

**第 3 步：设置-模块 tab 专项**（F2）

| 元素 | 现状 | 改法 |
|---|---|---|
| 卡标题字号 | 裸 `16.0f` | `roundFs(16.0f)`（与描述同口径） |
| 卡标题 y / 高 | 固定 22 / 22 | `roundFs(22.0f)`，y 随描述字号联动 |
| 描述 y | 固定 `40.0f` | `roundFs(40.0f)` |
| MCP 开关盒宽 | 固定 `150.0f` | 改 `roundFs(150.0f)`（注释写死「不缩放」是当时为了塞下 130% 档，但代价是标题被挤——改为缩放后需实测 130% 是否放得下，放不下就把开关移到第二行右侧） |
| 格内 name/desc | 固定两列、固定高 | 高度改为**内容派生**（按 `scaled` 后的行高 × 行数），字号放大到 >1.15 时两列自动降级为单列 |
| 整卡高 | 注册表写死（如 310） | 改为 `scaled` 后的常量，或按格数派生 |

补一句：`cardTitle` / `cardDesc` 是设置页**全卡共用**的 helper（不只是模块 tab），
修这两个 helper 能一次性修掉设置页所有卡的缩放问题——**优先改 helper 而不是改单个调用点**。

### 6.3 验收方式（后续实施阶段）

离屏探针已支持 `--font-scale`，扫 80% / 100% / 130% / 150% 四档 × 关键页，出图后**逐页人工看有没有裁切/重叠**。注意：**像素 diff 对文字放大不敏感，不能用 diff 当判据**（此前已踩过），必须人眼看图。

## 7. G 组：侧边栏（两处均已查实）

**G1｜有子项的组右侧箭头加右边距**

现状（`app_sidebar.cpp:452`）：一级组有子项时右侧画 chevron，盒宽 `kChevronW = 20`，
位置 `x = kWidth − padX − kChevronW` —— **贴着侧栏右内边距**，视觉上像被切掉。

方案：chevron 盒整体左移 `6px`（`kWidth − padX − kChevronW − 6`），让字形与右缘留出呼吸；
同时 `horizontalAlign` 由 Center 改 Left（字形 F077/F078 本身窄，居中在 20px 盒里会偏左，
改左对齐 + 缩窄盒宽到 14 更贴合）。

**G2｜选中二级菜单后，一级菜单不再显示选中条**

现状（`app_sidebar.cpp:398–416`）：

```cpp
// holdsCurrent = 当前页是本分组的子页
if (holdsCurrent) {
    ui_kit::selectionBar(ui, id + ".sel", std::string{}, padX, y, ...);  // ← 无条件画
}
```

**子项在 `active` 时也画自己的 selectionBar**（`app_sidebar.cpp:494`）→
父项一条 + 子项一条 = 「一级和二级同时亮」。
`holdsCurrent` 只影响图标/文字**颜色**（`primary` vs `textSecondary`，409–449 行），
**selectionBar 选中条照画不误**。

方案：`holdsCurrent` 为真时**跳过 selectionBar**，只保留「图标 + 文字变主色」作为
「当前页在本组内」的轻提示（这是父项该有的表达——它不是当前页本身）。

```cpp
// ⚠️ 判定要加 !collapsed（见下方副作用检查）
if (holdsCurrent && !collapsed) {
    ui_kit::selectionBar(ui, id + ".sel", std::string{}, padX, y,
                         kWidth - padX * 2.0f, itemH, t);
}
```

判据：
- 展开态：选中二级 → **一级无选中条**、二级有选中条；一级图标/文字仍为主色（轻提示）；
- 折叠态：选中组内任一子页 → **父项仍画选中条**（不能丢指示）；
- 一级与二级**不同时**出现选中条。

⚠️ 副作用检查：折叠态下父项是唯一入口，跳过 selectionBar 后父项不再有选中标识，
但折叠态父项本身就是当前页的图标入口（`holdsCurrent` 在折叠态仍为真），
此时**不应跳过** —— 判定需加 `!collapsed`。

## 9. 风险与拍板结论

1. ~~**卡宽上限**~~ —— **已定案**：不再纠结「单列 + 上限」，直接抄 MCP 页 `ui.flow` 多列网格（340–420 × 120 ≈ 3.5:1）。网格是项目内既有做法，不算破契约。**若你更想要别的比例，告诉我目标长宽比即可**（按 340–420 的卡宽推，2:1 需要卡高 170–210，两行内容撑不满；现实区间是 3~4 列）。
2. **hover-only 的键盘可达性** —— **已拍板（2026-11-01）**：不考虑无鼠标用户，不做缓解（无常显开关、无右键菜单），hover-only 直接上。
3. **果冻与「性能敏感设计」冲突** —— **已拍板（2026-11-01）**：性能顾虑不成立——果冻是 **hover 驱动**（非 hover 即静态），不是持续动画；且只有**选择项、按钮这类 L2 交互控件**才有果冻，L1 容器卡没有。列表数量无关，**全量上，无降级策略**。
4. **速度 ×2 的观感** —— **已拍板（2026-11-01）**：提速 ×2 **同时**降振幅（0.16/0.13 → 0.13/0.10），一步到位；真机再复核观感。
5. **首页 5 张统计卡的标签长度** —— **已拍板（2026-11-01）**：**5 张统一短标签**（正常态只留指标名，错误态保留「加载失败」）。
6. **此前遗留未做**（本轮未展开，登记在此）：首页「今日 Token 用量分布」图表区大片空白（有数据也不画图）、首页「切换 Claude Profile」按钮图标渲染成绿色方块（字体缺字形）。

### 10.0.1 ⚠️ EUI hover 模型的三个硬约束（**照抄 MCP 页，别自创**）

这三条是逐条读 EUI-NEO 源码核出来的，**任何一条不满足都会静默失效**（不报错、不崩、就是没效果）：

**约束 1：`hoverOpacityFrom` 的源必须是 rect 或 polygon。**
`instances_.hoverBlend(id)`（`runtime_instances.h:313`）只查 `rects` 和 `polygons` 两张表；
`TextInstance` / `StackInstance` **没有 `hoverBlend` 字段**（`runtime_instances.h:74-94`）。
→ 源传 text id：`hoverBlend()` 返回 false → 走 `state.opacity *= element.hoverHiddenOpacity`
（`runtime_update.h:170`）→ **永久隐藏**。tooltip 的源都是 rect（`md.help.icon.bg` 等）所以合法。

**约束 2：源必须「三态异色」。**
`runtime_update.h:790`：
```cpp
const bool stateColorsVisible = element.hasStateColors &&
    (!closeEnough(element.color, element.hoverColor) ||
     !closeEnough(element.color, element.pressedColor));
```
→ 三态全同色时 `stateColorsVisible=false` → `hoverBlend` **永远不更新** → 永久隐藏。
MCP 的透明 hit rect 正是三态同色（`kTransparent` ×3），所以它**不能**当 hoverOpacityFrom 的源。

**约束 3：hover 全局唯一 —— 只有 topmost interactive 元素拿得到 hover。**
`runtime_input.h:386`：`const bool topmostHover = enabled && element.id == hoverTargetId;`
`hoverTargetId` 来自 `hitTestInteractive`（`runtime_input.h:49`），命中测试**逆序遍历兄弟**
（`runtime_input.h:167`，兄弟按 `subtreeMaxZIndex` 升序 → **zIndex 高者先命中**）。
→ 「整卡 hover 显隐操作组」+「操作组里有可点按钮」**不能靠单一 hover 源实现**：
指针移到按钮上时 topmost 变成按钮，卡的 hover 就丢了（按钮不会继承卡的 hover）。

**✅ 正解：照抄 MCP 页的范式**（`mcp_page_module.cpp:390-424`，已上线可用）

```cpp
// 透明命中面：铺满整卡 + 三态同色 + 最后 build（命中优先）
ui.rect(id + ".hit")
    .size(cardWidth, kCardH)
    .states(kTransparent, kTransparent, kTransparent)
    .onHover([this, name](bool h) {
        if (h) hoveredCards_.insert(name);
        else   hoveredCards_.erase(name);
    })
    .onClick([this, name] { openDetail(name); })
    .build();

// 显隐元素：每帧按状态决定 opacity（不是 hoverOpacityFrom）
ui.row(id + ".cta")
    .opacity(hovered ? 1.0f : 0.0f)
    ...
```

要点：
- hover 状态存**模块级集合**（`hoveredCards_`），每帧 compose 时读；
- `onHover` 回调里改状态 → `composeRequested_=true`（`runtime_input.h:397`）→ 下帧自动重画；
- **父先于子**（`runtime_update.h:667` 父 → `:713` 子）→ 指针从卡移到按钮的那一帧，
  父的 `onHover(false)` 先触发、子的 `onHover(true)` 后触发 →
  **用「集合 insert/erase」而不是单个 bool**，才能保证移出后仍然正确。

**⚠️ 命中优先级要显式设计**：命中面（hit）要 **zIndex 高于**卡内容，否则点不到；
操作组按钮要 **zIndex 高于 hit**，否则按钮被 hit 吃掉点击。
两者都靠 `.zIndex()`（`dsl.h:522`）控制；`components::button` **没有 zIndex**
（独立类不继承 BuilderBase，见上表）→ 按钮组要包在 `ui.stack` 里、由 stack 的 zIndex 抬层级。

namespace ui_kit {
// 列数算法：先取「放得下多少列最小宽」的列数，再用剩余空间把列宽撑开；
// 撑过上限就减列重算，避免宽窗里卡片被拉成横条。
inline std::pair<int, float> gridColumns(float contentW, float gap,
                                          float minW, float maxW, int maxCols) {
    if (contentW <= 0.0f) return {1, minW};
    int cols = 1;
    for (int n = 1; n <= maxCols; ++n) {
        if (contentW >= n * minW + (n - 1) * gap) cols = n;
    }
    float cardW = (contentW - gap * (cols - 1)) / cols;
    if (cardW > maxW) {
        cols = std::max(1, static_cast<int>((contentW + gap) / (maxW + gap)));
        cardW = (contentW - gap * (cols - 1)) / cols;
    }
    return {cols, cardW};
}
}  // namespace ui_kit

### 10.7 批次 B6：字号缩放健壮性（F1+F2）—— **优先级最高**

**改动**

1. **单一缩放入口**（`src/core/theme.h`）：

⚠️ **注意：`core::theme::scaled()` 已经存在**（`theme.h:103`），
它就是「字面量 × fontScale」。**不要另起一个 `scaledText()` 造第二个入口** ——
两个入口迟早会出现一个缩了另一个没缩的漏网之鱼。
**正确做法：在 `scaled()` 旁边加一个「字号+行高成对」的兄弟函数**，
两者共用同一个 `fontScale()`，语义互补而非重复：

```cpp
// src/core/theme.h（theme.h:103 现有 scaled() 旁边新增）
inline float scaled(float px) { return px * fontScale(); }   // 已有

// 新增：字号与行高成对缩放（避免只缩字号不缩行盒 → 文字被裁）
struct ScaledText { float fontSize; float lineHeight; };

// ⚠️⚠️ 硬契约：baseFont / baseLineHeight 必须都是「未缩放的字面量基准」
//   ✅ scaledText(12.0f, 20.0f)
//   ❌ scaledText(t.sizes.fontSizeBody, 20.0f)   ← 双乘！
inline ScaledText scaledText(float baseFont, float baseLineHeight) {
    const float s = fontScale();   // core::theme::fontScale()，theme.h:99
    return {baseFont * s, baseLineHeight * s};
}
```

**用法**：
```cpp
const auto st = core::theme::scaledText(12.0f, 18.0f);
ui.text(id).size(w, st.lineHeight).fontSize(st.fontSize).lineHeight(st.lineHeight).build();
```

**双乘红线（`core/theme.h:102` 原文已警告）**：

> 令牌（`t.sizes.fontSize*`）在 token 重建时已乘 fontScale，勿再包一层（会双乘）

| 写法 | 结果 |
|---|---|
| `core::theme::scaled(12.0f)` | ✅ 字面量走这条 |
| `t.sizes.fontSizeBody` | ✅ 已是缩放后的值，**直接用** |
| `core::theme::scaled(t.sizes.fontSizeBody)` | ❌ 双乘 |
| `scaledText(t.sizes.fontSizeBody, ...)` | ❌ 双乘 |

**推论：行盒高度也必须用字面量基准去缩放**。
若某处行盒高度是跟着 token 字号走的（如 `rowH = fontSizeBody + 6`），
则应改成 `rowH = scaledText(14.0f, 14.0f).fontSize + 6`（用基准 14 走 scaled），
