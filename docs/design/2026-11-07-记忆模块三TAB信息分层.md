# 记忆模块三 TAB 信息分层重设计（低频收纳 · 高频突出）

- 池条目：need 181（[pool:need:181]）｜日期：2026-11-07｜角色：ui-ux-designer
- 老板口径（2026-11-06）：不反对高密度本身，要求**按用户关注频次分层**——最常看的突出，很少看的收进次级交互（折叠区 / 详情弹窗 / hover 悬浮），禁止「叠积木」式等权重平铺。
- 事实基线（本任务新查证，源码实测）：三 TAB = 主控台 / 记忆审核(N) / 配置（memory_module.cpp:95）；主控台 = 引擎卡 196 + 健康四格 236 + 消耗卡 150 + 调用记录表 + 动态卡（memory_module.cpp:122-127、memory_module_panels.cpp:97-321）；审核 = 工具条 + 232px 提案卡流 + 92px 已裁决卡（memory_module_panels.cpp:325-855）；配置 = 六张卡竖排（memory_module_panels.cpp:859-1311）。
- 关联：need 189（主控台一屏不滚动——本设计 L1 常驻层高度预算使其可行，收口归该条目）；卡片形态对齐《2026-11-07-全站卡片设计基准.md》（#195）；弹窗对齐《2026-11-07-dialog-standard-design.md》（#156）。

## 1. 页面级构图（先整体后参数）

### 1.1 构图三问

| 问 | 答 |
|---|---|
| ① 滚动模型对吗 | 保持现状：页头标题 32px + TAB 行 40px 固定不滚，三视图各套独立内滚容器（memory_module.cpp:104-145）。分层不改变滚动归属，只减少需要滚动的概率——L1 常驻层预算 ≤ 一屏（§1.5）。 |
| ② 有无大段无效空白 | 现状病灶：主控台堆 5 张大卡（≥1200px 高），重点信息被均质卡片推到需要滚动才能看见；引擎卡 196px 中说明文案占 2 行、python/embed 行常驻（低频）。本设计：低频内容收进 L3（折叠/弹窗/悬浮），被释放的高度还给 L1 常驻层，各卡内不出现无主空列（对齐卡片基准 R2）。 |
| ③ 密度与权重 | 三 TAB 共用同一分层模型（§1.3）：L1 常驻层用最大字号与实色承载高频项；L2 悬浮层用 12px 辅助色承载口径/说明；L3 收纳层用折叠区与弹窗承载低频项。最小窗 1200×720 下：主控台 L1 总高 ≈ 372px + 折叠组头 44px，一屏可见（可视高 608px，见 §1.5）；审核/配置内容区内滚兜底。 |

### 1.2 三 TAB 共同壳（不变项）


### 1.3 分层模型（三 TAB 统一口径）

| 层 | 定义 | 载体 | 视觉 |
|---|---|---|---|
| **L1 常驻** | 高频必看：每次开页都要扫一眼 | 状态带 / 健康格 / 卡片主体 | 字级 L1-L3 档（卡片基准 §4.2），实色可点 |
| **L2 悬浮** | 低频佐证：口径、说明、来源细节 | hover 浮层（透明命中区 + 悬停显隐范式） | 12px textSecondary，深底浮层 radius 8，120ms 淡入 |
| **L3 收纳** | 很少看：排障、审计、一次性安装/设置 | 折叠区（默认收起）/ 详情弹窗 | 组头 44px 或弹窗（#156 规范），不占 L1 视觉权重 |

判定规则：一个信息项只能属于一层；从 L1 移出的项必须在 L2/L3 有**明确出口**（hover 有浮层、折叠有组头摘要、弹窗有入口文字），不许「删了就没了」。

### 1.5 空间节奏与密度预算（最小窗 1200×720）

可视内容区高 = 720 − 104（壳）− 12（底边距）= **604px**。

| TAB | L1 常驻层预算 | 一屏结论 |
|---|---|---|
| 主控台 | 状态带 64 + 16 + 健康格 132 + 16 + 消耗带 104 + 16 + 折叠组头 44 = **392px** | ✓ 剩 212px；展开运行明细后内滚（低频可接受） |
| 审核 | 工具条 52 + 10 + N×(176+12) | 卡流内滚（决策对象逐张看，符合任务性质） |
| 配置 | 常显组 ~200 + 16 + 4×(44+8) = **424px** | ✓ 四组全收起时一屏；展开任意一组内滚 |

间距选档只用 4/8/16/24（theme spacing 档，theme.cpp:52-56）；卡间距 kCardGap=16 沿用（memory_module_internal.h:49）。

### 2.2 引擎状态带（原 196px 引擎卡 → 64px 一行）

大胆单点：**引擎卡降维成状态带**——与 release 行卡同语言（行=状态的最小承载，#195 基准），其余区块保持安静档。

| 参数 | 值 |
|---|---|
| 带高 | 64px；底 surface、radius 14（radiusLarge）、1px borderDefault（cardPanel 同款，状态带是卡不是行——它承载主操作按钮） |
| 状态点 | 10×10 圆，x=16 垂直居中；Running=success / Preparing=warning / Failed=errorText / 其余=textDisabled（engineStateColor 映射沿用，memory_module_internal.h:68-76） |
| 名称 | 「telemem 记忆引擎」fontSizeBody 14/600 textPrimary，x=34 |
| 状态词 | 12/600 状态色，紧跟名称 gap 8；Running 文案「运行中」，Failed「故障」等（engineStateText 沿用） |
| 版本 | 11 textTertiary「v1.10.1」——hover 状态词时与详情一并浮出（L2） |
| 右端按钮组 | 右锚 gap 8、高 36：① Running→[停止引擎 Danger]；② Idle/Stopped→[启动引擎 Primary]；③ Preparing→[启动中… 禁用]；④ Failed→[查看失败原因=详情 Primary]；⑤ 未安装引导态（Idle+pythonFound=false）→ 追加 [首次安装向导 Secondary] |
| 「详情」入口 | 文字钮（textSecondary，hover textPrimary），Running/Idle 常驻右端最左；点击开引擎详情弹窗（§2.6） |
| 异常前置 | Failed 或 llamaMissing 时：状态词旁加 11/600 warning 短语（「本机模型文件缺失」），细节进弹窗——警示词必须能从 L1 看见，细节不占 L1 |
| 果冻 | 按钮 hover scale 1.02 / 按下 0.96（基线三段式） |

## 5. 交互流程

1. 主控台开页 → L1 三段常驻可见（状态带/四格/消耗带）→ 看细节：hover 格/数字出浮层；排障：点「详情」开引擎弹窗、点「运行明细」展开折叠区。
2. 启停引擎：状态带按钮直操作（异步，Preparing 中禁用）；失败 → 状态词变「故障」+ 警示短语，弹窗看原因。
3. 审核：逐张裁断（接受→toast「已接受」；拒绝→toast；编辑后接受→弹窗）→ 争议时点「查看全文」；量大时用筛选 chips 缩小范围；批量裁断走「批量处理」次级入口。
4. 配置：首次安装走引擎详情弹窗内向导；日常不打开；要改阈值 → 展开对应折叠组（组头摘要即当前值，不开组也能看）。
5. 高危操作（脱敏关闭/清除全部）一律二次确认弹窗（现状保留）。
