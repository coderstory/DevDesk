### 2.2 滚动模型

- **外壳不滚**（全站纪律）：标题栏、侧栏、TAB 栏带均固定。
- **侧栏导航区内滚**：滚轮可滚、惯性/拖拽保留，滚动条视觉完全隐藏（§9，bug188 硬约束）。
- **终端网格区唯一内滚**：滚轮 = 回滚 scrollback（既有机制不变）；无滚动条视觉（终端惯例，滚轮回底即贴底）。
- **TAB 区内横滚**：TAB 超宽时 TAB 区内部横向滚动，滚轮横滚触发；两端 16px 渐隐遮罩提示；同样无滚动条视觉。
- 页面级不存在任何滚动条 UI。

### 2.3 空间节奏与信息密度预算

- TAB 栏 44px = 会话管理高频带：TAB 一次可达、新建主按钮唯一鲜艳色（四原则·操作高效）。
- 网格区 100% 余高让给终端输出，零常驻装饰；「运行中」徽标取消后运行态只由 TAB 圆点承载（四原则·低干扰：状态按需出现）。
- 无效空白检查：TAB 区空隙 = 4px 间距（服务分组）；空态时网格区居中极简引导（服务功能，非空洞）；其余空间恒被网格填满。
- 权重平衡：网格（最大面积）> 新建（唯一主按钮）> TAB（中频）> 设置/全屏（低频图标钮）。最小窗 1200×720 与宽窗 1920×1080 两档均成立（§8 收缩规则）。

### 2.4 构图三问

1. **滚动模型**：外壳不滚 + 侧栏/网格各自内滚 + TAB 区横滚，与全站同类页一致；终端区滚轮语义 = 回滚（终端惯例）。✅
2. **无效空白**：无大段空白；留白仅 TAB 间距与空态居中引导，均服务分组。✅
3. **密度与权重**：主体（网格）/辅助（TAB 栏）= 余高:44；高频操作（新建）视觉权重最高（唯一主按钮）。✅

## 3. 三层材质（老板裁决对齐，浅/暗两套）

**结构原则：一张卡、两段式，拒绝三层套娃**——终端容器卡是唯一卡面，TAB 栏带与网格区是同一张卡的上下两段（中间 1px 分割线），不出现「卡里嵌卡再嵌网格框」。

| 层 | 浅色值 | 暗色值 | 取值依据 |
|---|---|---|---|
| 层0 页面底（卡外，全站统一） | `background` #F5FAF7 | #1A1816 | 全站页面底 token；终端卡满铺页面区，此层仅主题切换瞬间可见 |
| 层1 外容器卡（TAB 栏带 + 网格区共同背板） | 统一卡材质 glassFill：#FFFFFF 系微绿染 **α0.94** | #232120 **α0.95** | 项目统一材质裁决（池127 已上调「接近实体，留少量呼吸感」）——替代现状不透纯白平板；单一来源 `ui_kit glassFill`，与全站卡片同源 |
| 层2a TAB 栏带 | = 容器卡面同材质（不另起层） | 同 | 拒绝套娃：TAB 栏即卡的上段 |
| 分割线（TAB 栏带/网格区界） | 1px `borderDefault` #E5E7EB | #3A3735 | 分割线一档 token |
| 层2b 网格底（文字区） | `surface` #FFFFFF **α1.0 实色** | `background` #1A1816 **α1.0 实色** | 文字区可「更实/更深」但须实色：玻璃微透会让动态背景/下层内容透出干扰字符可读性（可读性优先）。暗色 = 现状值延续（比卡面 #232120 深半档，突出文字区）；浅色 = 白实色与卡面几乎无缝，分界只靠 1px 分割线，一张卡浑然一体 |

**细黑边应用面（收敛，防到处勾边）**：
- 全局窗框：window ring 1px 纯黑（池168 既有，`window_ring.cpp` α1.0），承担整窗外缘。
- 浮层卡（覆盖卡）：1px 细黑边 浅 `rgba(0,0,0,0.35)` / 暗 `borderDefault` #3A3735（暗色纯黑边在深底不可见，降为既有 border 档——主题差异写死于此）。退出全屏钮为透明图标钮（§4.2 图标钮统一态），不属浮层卡，不勾边。
- 终端容器卡本体**不再加描边**：外缘已被 ring + 侧栏 divider（1px borderDefault）承担，再加即重边/套娃。

**字体栈方案（需求 7）**：

| 层 | 方案 |
|---|---|
| 主字体（半角度量源） | 等宽族，两案：**A（推荐）打包开源等宽 TTF**（OFL 许可，JetBrains Mono / Cascadia Mono 类）以路径式 fontFamily 加载——advance 构建期固化、双平台零漂移；**B 沿用 "monospace" 别名**（Win→Cascadia Mono/Consolas 回落、macOS→Menlo）——零打包但 advance 随系统版本漂移，度量必须运行时实测。两案都必须真实度量（下条），A 案只是让度量值可预期 |
| CJK 回退 | 框架系统 fallback 兜底（Windows 微软雅黑 / macOS 苹方），终端不设第二主字体 |
| 图标 | Font Awesome（TAB/动作组/覆盖卡），终端文字区字符照常由 ANSI 前景控制，禁 emoji |

**真实度量方案（目标行为，弃估算）**：

| 项 | 目标 |
|---|---|
| cellW | = 主字体半角 advance @13px（取整）；来源 = 框架等宽文本度量查询或首帧实测（能力项见 §10），**弃 fontSize×0.6** |
| cellH | = 主字体实际行高（取整，建议 clamp 到 1.20–1.35×fontSize），**弃 ×1.25 系数** |
| 列/行数 | floor(availW/cellW) / floor(availH/cellH)；窗口 resize 走既有量化→resize 会话链路 |
| 预期 | 若主字体 advance ≈ 7.8px（13×0.6 恰好命中的字体），视觉零跳变；偏差字体 → 列数修正（现状中文「间距过大」根因即估算偏大） |

**TUI 场景 CJK 宽字（占 2 格）预期表现**：

- 占位：CJK 恒占 2 cell（会话层 width=2 语义）；选区/IME 锚点/光标列换算按 width 折算（现状 terminal_page.cpp:196 cellX/cellSpan 已按 width，保留）。
- 绘制：每行 run 从列起点画。CJK 回退字形 advance ≠ 2×cellW 时，**只产生字形间隙观感差，不产生列漂移**——后续字符起点仍由 cell 网格决定，TUI 表格线/进度条/对齐不破版。
- 验收判据（开发前钉住）：`状态|正常|OK` 混排行：光标列 = 字符列 1:1；全 CJK 行与等列数 ASCII 行右端差 ≤1 cell；拖选框宽 = CJK 字符 2 倍于半角。

## 5. 交互流程

1. **新建**：点「+ 新建」→ TAB 插入序列尾并激活（200ms 滑入淡入）→ 网格区切新会话（Idle 空网格 + 光标闪烁 → prompt 出现即成功）。
2. **切换**：点非激活 TAB → 激活态迁移（120ms）→ 网格区换该会话帧；scrollback 偏移按会话各自记忆。
3. **关闭**：点 × → TAB 淡出收窄 150ms → **右邻 TAB 优先激活**（无右邻则左邻）；关闭最后一个 → 空态（§4.5）。关闭运行中会话 = 终止进程，无确认弹窗。
4. **失败**：会话 Failed → 该 TAB 圆点变红；若为当前 TAB，覆盖卡出现；切走再切回覆盖卡仍在（状态跟 TAB 走）。
5. **全屏进**：点 ⛶ → 侧栏 0 宽全隐（瞬时切换，`sidebarWidth()` return 0）→ 同槽图标 expand 切 compress（直切）。
6. **全屏退**：点同槽 compress → 侧栏恢复进屏前折叠/展开态 → 图标切回 expand（直切）。
7. **TAB 键盘快捷键：不设**。终端页键盘事件优先级属于会话（TUI 如 Claude Code 需要全部按键），Ctrl+T/W 类快捷键必然与 TUI 冲突；会话管理仅鼠标路径。（若未来支持，须走「非焦点态/修饰键前缀」方案另立需求。）
8. 双击 TAB 栏空白区 = 新建（WT 惯例，建议项，非本期验收必需）。

### 9.1 滚动条隐藏（bug188，老板硬约束：滚动保留、视觉全无）

### 9.3 logo 尺寸随窗口自适应（bug165）

现状：写死按窗高三档 48/44/40（app_sidebar.cpp:405-422），窗宽拉大不变。v2 规则 = **高度档与宽度档取小，再钳上限**：

| 维度 | 阶梯 |
|---|---|
| 高度档（既有，按侧栏可用高 H） | H≥712→48；680≤H<712→44；H<680→40 |
| 宽度档（新增，按窗口逻辑宽 W） | W<1440→48；1440≤W<1728→56；W≥1728→64 |
| logoSize | **min(高度档, 宽度档)**，钳 [40, 64] |
| 手动折叠态（72px） | 追加上限 **48**（72 带 − 2×12 边距；任何窗宽不放大）→ logoSize = min(上式, 48)；**全屏态无 logo 面（0 宽全隐，§4.6）** |
| 居中判据 | 四边完整落在侧栏带内：展开态 x=(220−size)/2，折叠态 x=(72−size)/2；垂直在品牌块 56px 内居中不溢出 |

- 上限 64 依据：品牌块高 56 恒定（锚点不塌），64 > 56 会溢出品牌块——**修正：logo 超过 56 时品牌块随档加高至 size+16**（正常档 topPad/brandNavGap 相应 −4 补偿，导航起点偏移 ≤8px，侧栏断言面同步）。若实现侧判品牌块不可动，则上限回落 56；两档任选其一，**优先前者**（大屏 logo 诉求是 bug165 本意）。
- 采纳上限 64 时折叠态仍恒 ≤48，两态不冲突。
