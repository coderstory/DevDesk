# 运行历史抽屉 UI 重整（2026-11-01）

## 一、问题（用户反馈 + 代码实况）

用户反馈：**「运行历史的弹窗没设计 UI 啊，按钮没都对齐的」**。

走查 `src/module_schedule/schedule_ui_history.cpp` 后确认两类问题：

### 1.1 没有设计（裸控件堆砌）

旧实现是四条 `ui.text` + 一个 `ui.rect` 手工拼的行：

- 行容器用 `t.colors.background` 底 + `t.sizes.radius` 圆角，**不走统一卡片材质**（无玻璃面、无统一阴影），在白弹窗底上几乎不可辨；
- 状态直接渲染英文原始值（`success` / `failed` / `missed`），与列表页 `runStatusZh()` 的中文口径不一致；
- 渠道行渲染成 `#3 failed(2 次/重试 1)`——`channelId` 是 `schedule_channel.id`（自增数字），对用户毫无意义；
- 无空态：`items` 为空时抽屉只剩一块空白面板；
- 高度写死 560，内容超出时靠 `y < h - 70` 截断——第 4 条以后的记录**永远看不到**；
- 字号全部裸字面量（`fontSizeSmall - 1.0f`），不进 `scaled()`，字号设置档位下不缩放。

### 1.2 按钮没对齐

三个按钮各写各的 `x`，没有统一右基准：

| 元素 | 旧坐标 | 旧右边界相对内容列右基准 |
|---|---|---|
| 行内「重试」钮 | `x0 + innerW - 76`（宽 60） | **差 16px**（卡内边距是 12） |
| 底部「关闭」钮 | `x0`（**左**对齐） | 差 96px |
| 右上关闭 | — | 不存在 |

行内文本左内缩 12px，按钮右内缩 16px，卡片左右边距不对称。

### 1.3 附带发现：重试按钮从不出现

`HistoryDrawerHost::retryRun` 宿主侧从未赋值（`schedule_ui_list.cpp` 只接了 `close`），
所以「重试」按钮在 UI 层有绘制逻辑、在产品里**永远不显示**——用户看到的抽屉根本没有可点按钮。

## 二、方案

### 2.1 栅格：单一右基准

内容列沿用全站弹窗栅格：左 `x0 = kDialogInsetX(24)`，宽 `w − kDialogBodyInsetX(48)`，
**右基准 `contentRight = x0 + contentW`**。所有右对齐元素一律贴 `contentRight`：

- 右上「×」图标钮（32×32）：`x = contentRight − 32`
- 行内「重试」钮（64×26）：`x = cardRight − 14`（卡内边距 14）
- 底部「关闭」钮（96×40）：`x = contentRight − 96`

探针 `schedule_ui_probe` 加了**几何门禁**：三个按钮右边界与基准的偏差 > 1.5px 即失败。

### 2.2 结构

```
┌ 运行历史                              [×] ┐  标题 20/700 + 右上 ×
│ 共 12 条 · 成功 9 · 失败 2 · 错过 1        │  统计条 12px
│ ────────────────────────────────────────  │  分隔线
│ ┌ 已错过                    [重试] ──────┐ │  卡片（统一材质 + 描边 + 阴影）
│ │ ● 计划 2026-11-01 15:28:21            │ │  状态点 + 状态文案
│ │   实际 … · 耗时 2140 ms · 尝试 1       │ │
│ │   企业微信 失败 · 重试 1               │ │  渠道 chip（药丸描边）
│ │   企业微信接口返回 93000               │ │  详情行（失败红字）
│ └───────────────────────────────────────┘ │
│ ────────────────────────────────────────  │  分隔线
│                                  [关闭]    │  右对齐
└────────────────────────────────────────────┘
```

- 卡片底板走 `ui_kit::cardPanelColored`（描边 / 阴影全站统一）；
  **底色按主题分档**：弹窗底本身是 `surface`（浅色 = 纯白），白玻璃卡压在白底上会「融」，
  故浅色取页面底 `#F5FAF7`、深色取比弹窗底亮一档的 `surfaceElevated`。
- 状态点 + 状态文案（中文）：成功 / 失败 / 已错过 / 运行中 / 待执行 / 已跳过 / 已抑制。
- 渠道 chip：药丸描边式，文案 = **宿主注入的可读渠道名** + 投递状态 + 重试次数，
  最多 3 个，超出折成「+N」。
- 空态接入 `ui_kit::emptyState`（图标 + 主句 + 引导句）。
- 列表走 `components::scrollView`（覆盖式滚动条），**不再截断**。
- 抽屉高度**随内容自适应**：`listTop + 内容高 + 底部带`，clamp 到 [440, 680]。

### 2.3 补齐功能缺口：手动重跑

为了让「重试」按钮真的能点，补齐三段链路（此前整段缺失）：

| 层 | 新增 |
|---|---|
| 存储 | `ScheduleStore::getRun(id)` —— 按主键读 run（重跑按 run 反查规则） |
| 引擎 | `ScheduleEngine::rerunNow(ruleId, now)` —— 走与自动触发**同一路径** `fireRule`（唯一索引 / 同规则串行 / 全局投递桶口径一致）；规则不存在或已停用 → fail |
| UI | `ScheduleListUi::retryHistoryRun(runId)` —— 反查 rule → `rerunNow` → 重新装载历史；失败标 `error_` 不静默 |

`ScheduleListUi` 构造新增 `ScheduleEngine* engine` 参数；引擎在位才接 `historyHost_.retryRun`，
无引擎时抽屉隐藏重试按钮（测试缝构造走的就是这条）。

## 四、验证

- 单测：`2091 例 / 通过 2085 / 失败 0 / 跳过 6`（新增 3 条：`getRun` 契约、
  `rerunNow` 契约、UI↔引擎重试接线）。
- 探针：`schedule_ui_probe` PASS（含几何门禁）；离屏截图三态：
  - 深色有数据态 / 浅色有数据态 / 深色空态。
- 其余 `ctest` 探针 25/25 通过；`agent_e2e_probe`（上游 CodingPlan 订阅过期）与

  与本次改动无关。

## 五、遗留

- 「重试」对 `missed`（已错过）行也开放：引擎按「现在」补跑一次，与规则自身的
  `missed_policy`（once/skip/all）口径独立——若产品希望「已错过」不提供手动补跑，
  改 `drawRunCard` 的 `retryable` 判定即可。
- 手动重跑与自动触发的并发：同规则串行由引擎 `runningRuleIds_` 保证，
  但「手动重跑的 run 行」与「自动触发的 run 行」在列表里无法区分来源（`origin` 同为 `user`）。
