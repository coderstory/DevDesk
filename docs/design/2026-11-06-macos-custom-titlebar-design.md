## 1. 页面级构图（先整体后参数）

### 1.1 区块划分与锚定关系

```
┌──────────────────────────────────────────────────────────────────┐
│ [左钮组 0~138] [品牌区 154~314]  ·········· 自由拖拽区 ·········· │ ← 40px 标题条（全宽）
├────────────┬─────────────────────────────────────────────────────┤
│  侧栏 220  │                页面内容区                            │
│  (72 折叠) │        （各页自管，本设计不触及）                     │
└────────────┴─────────────────────────────────────────────────────┘
   ↑ 侧栏与内容区均从 y=40 起（bodyTop=40，compose 统一扣除）
```

- **标题条**：全宽 40px 单区块，内部按 x 轴三段——左钮组（0~138，三颗 46×40 热区无缝连排）、品牌文本（x=154 起，定宽 160）、自由拖拽区（其余全部）。
- **锚定关系**：标题条左缘锚定窗口左缘、顶部锚定窗口顶缘、宽度跟随窗口全宽；侧栏（220/72）与内容区顶缘锚定 y=40。条区不铺底色——三档材质的 clearColor / backdrop 直透条区（Windows 现状同构，`app_sidebar.cpp:284-285` 注释一手）。
- **条与内容间不设分隔线**：FSCV 内容从 y=0 起 + 条区透明 = 融合本身就是「无边无界」；加线反而制造第三条横贯线。Windows 端现状亦无分隔线，两端一致。

### 1.2 滚动模型

外壳不滚：标题条固定 40px 恒在窗口顶部、不参与任何滚动；侧栏与内容区各自内滚（既有行为，本设计零改动）。标题条自身无滚动、无折叠、无收缩态。

### 1.3 空间节奏与信息密度预算

40px 高度预算：三钮热区占满条高（46×40×3=138px 宽），品牌文本 14px 字号垂直居中——条区常驻信息元素仅「品牌」一项 + 三颗钮，密度即全部，无留白空洞问题（条区剩余宽度全部是拖拽热区，功能性占位）。最小窗 1200×720 下：左钮组 138 + 间距 16 + 品牌区 160 = 314px，右缘余 886px 拖拽区，构图成立无挤压。

**构图三问**：① 滚动模型——条固定不滚、内容区各自内滚，与全站外壳不滚一致；② 无效空白——条区无弹性空列，剩余宽度全是拖拽热区（功能占位）；③ 密度权重——三钮是本区唯一高频交互元素、权重最高（46px 热区满高），品牌文本为低频识别元素（14px 灰阶次级存在）。

## 2. 核心裁决

### 裁决一：钮位置 = macOS 左缘（不与 Windows 右缘对齐）

**结论：三钮放左缘（x 0~138），Windows 端右缘双钮保持现状不动。** 理由四条：

1. **PRD 已锁定**：UI 契约原文「**左缘三钮**热区与 Windows 自绘钮同构」、用户流程步 1「左上三颗自绘钮」——同构指热区几何（46×40、钮命中优先于拖拽），不指屏幕位置。
2. **与 D3 同一裁决逻辑**：D3 已定第三钮=全屏（对齐 macOS 用户预期而非 Windows 最大化语义）；钮位置是同一逻辑的另一面——「语义/位置对齐平台预期、几何对齐跨端一致」。若位置也抄 Windows 右缘，macOS 用户窗口控制预期双重落空（位置不像 mac、语义又已选 mac），两头不靠。
3. **两端一致性的真正标的**是 G1：bodyTop 同 40px、同窗高同侧栏档位——已达成；钮的屏幕位置不在 G1 内，PRD 平台差异节亦明写「第三钮语义两端不同」，产品已接受平台差异表达。
4. **改 Windows 右缘为零收益高风险**：F-09 门禁要求 Windows 零行为变化，移动 Windows 钮位直接违约。

**热区同构细节**：每钮命中热区 46×40（=Windows kWindowButtonW 46 × titlebarHeight 40，`app_sidebar.cpp:267,250-252`），三热区无缝连排占 x 0~138；圆点视觉在各自热区内居中（圆心 x=23/69/115，心距 46——比原生 20 稀疏，换取热区与 Windows 完全同构 + 更大命中容错）。

### 裁决二：视觉方案 = 方案 A「红绿灯彩点」推荐，方案 B「DevDesk 统一线性钮」备选

**结论：推荐方案 A，但色值全部走 DevDesk theme token（非照抄系统色）。** 对比见 §3，逐态参数见 §5。

## 3. 两套视觉方案对比

| 维度 | 方案 A：红绿灯彩点（推荐） | 方案 B：DevDesk 统一线性钮 |
|---|---|---|
| 形态 | 12px 实心圆点 ×3，hover 浮现符号 | 46×40 矩形热区 + 线性图标（× − 全屏符），与 Windows 钮完全同构 |
| 颜色 | error 红 / warning 黄 / primary 绿（全 token） | normal 透明 / hover `colors.hover` / pressed `primarySoftBg`，图标 `textSecondary` |
| macOS 用户预期 | 与 30 年原生心智一致，零学习成本 | Windows 化观感，预期落空（位置虽在左缘、形状陌生） |
| 失焦灰显心智 | 原生同款（非 key 窗变灰），用户秒懂 | 需自建认知（灰图标=失焦） |
| 品牌一致性 | 与 DevDesk 线性语言异质——但彩点是全窗唯一彩色常驻元素，异质即识别点 | 两端品牌完全统一 |
| 语义色纪律 | 红=error（关闭是破坏性动作=告警语义 ✓）/ 绿=primary（全屏切换=操作 ✓）/ 黄=warning（窗口离场提醒，可接受） | 灰=中性，零越界 |
| 与基线四原则 | 信息优先：色即语义 ✓；低干扰：12px 小点 ✓；专业感：克制 ✓ | 全 ✓ |
| 实现增量 | 需自绘圆点+符号（覆盖层绘制，成本同级） | 复用 Windows 钮绘制逻辑左移（增量最小） |

**推荐理由**：本需求的灵魂是 G2「语义对齐 macOS 用户预期」——位置（裁决一）、第三钮语义（D3 全屏）、视觉形态（红绿灯）三者一致才构成完整的「macOS 原生感」；方案 B 只满足几何一致，把最显性的平台预期丢掉了。方案 A 的「大胆单点」恰在此处：**左缘三颗彩点是全窗口唯一的常驻彩色元素**，其余（品牌文本、条区）全部安静——符合「大胆只花在一处」。Windows 端不受任何影响（F-09）。

Demo 提供两套切换，验收以方案 A 为准，方案 B 保留为回退视觉（若 POC 阶段覆盖层绘制成本超预期，B 可即时顶上且零 token 变更）。

## 5. 状态表（normal / hover / pressed / 失焦 × 三钮 × 深/浅）

方案 A 圆点三态色值（全部锚定既有 token，`theme.cpp:12-115` 实读；红黄 hover/pressed 档与另一主题档/常用加深档重合，绿钮三态恰为 primary 三档 token）：

| 钮 | 语义 token | normal | hover（+符号） | pressed | 失焦（非 key 窗） |
|---|---|---|---|---|---|
| 关闭 | `colors.error` | 深主题 #F87171 / 浅主题 #EF4444 | 深主题 #EF4444 / 浅主题 #DC2626，白 × 8px（onPrimary #FFFFFF，对比 ≥3.6:1） | 深主题 #DC2626 / 浅主题 #B91C1C（=errorText token），白 × | 全部 #908A82（dark textDisabled）/ #6B7280（light textDisabled），符号隐藏 |
| 最小化 | `colors.warning` | 深主题 #FBBF24 / 浅主题 #F59E0B | 深主题 #F59E0B / 浅主题 #D97706，符号=主题底色挖空 −（dark #1A1816 / light #F5FAF7，对比 ≥3.9:1） | 深主题 #D97706 / 浅主题 #B45309，同符号 | 同上灰点 |
| 全屏 | `colors.primary` | 深主题 #36D399 / 浅主题 #07C160 | 深主题 #2EC48F（=primaryHover）/ 浅主题 #06AD56（=primaryHover），符号=底色挖空双三角（同上底色 token，对比 ≥3.8:1） | 深主题 #23B07F（=primaryPressed）/ 浅主题 #059048（=primaryPressed） | 同上灰点 |

- 1px 描边（常驻）= 各自 hover 档色；失焦态去描边。
- **首次点击非激活窗口 = 仅激活窗口，不触发钮动作**（macOS 原生语义，声明为实现契约；归覆盖层天然处理）。
- disabled 态（钮功能不可用场景，如关闭被策略禁止）：本需求无此场景，PRD F-08 已明「disabled 态可后置」——预留 token= textDisabled 同失焦灰。

方案 B（备选，与 Windows `app_sidebar.cpp:292-323` 完全同构，仅位置左移）：

| 态 | 底色 | 图标 |
|---|---|---|
| normal | 透明 | textSecondary（dark #C9C5BD / light #4B5563），12px 线性符：× / − / 全屏双三角 |
| hover | `colors.hover`（dark #353231 / light #EEF6F1）；关闭钮= `colors.error` | 关闭钮 hover 图标转白 #FFFFFF，其余 textSecondary |
| pressed | `primarySoftBg`（dark #0D3326 / light #E8F8EE）；关闭钮= error | 同 hover |
| 失焦 | 透明（不响应 hover） | textDisabled |

图标形状定义（两方案通用，码点归实现按 EUI 图标表选型，Windows 端 ×=0xF00D、−=0xF2D1 同族沿用）：关闭=×双斜线叉；最小化=水平横线；全屏=双三角向外箭头（macOS 绿灯符）。

## 6. 边界状态

| 边界 | 行为 |
|---|---|
| 窗口失焦（非 key） | 三点全灰（textDisabled）、描边消失、符号隐藏、hover 不响应；首次点击仅激活窗口。Windows 端失焦无此概念（现状不动） |
| 全屏中 | 标题条+三钮整体退场（隐藏，F-05/A7），无残留无占位；内容区顶到 y=0。demo 提供「全屏态」预览 |
| 退出全屏 | 条与钮完整回归 40px 构图（重挂钩子归技术卡，设计只锁回归后视觉=与常态逐像素一致） |
| 极窄窗（趋近最小宽） | 三钮热区 x∈[0,138) 左缘锚定：不挤压、不换行、不溢出（A14）；品牌文本宽=窗宽−154−16，溢出截断；窗宽<240 隐藏品牌文本。1200 最小宽下右缘余 886px 无任何挤压 |

| 深/浅主题切换 | 色值按 §5 表随 token 即时切换，无过渡闪烁（150ms 内平滑过渡） |

## 7. 材质联动（F-08/A12：三档 × 深/浅 = 6 组合）

| 材质档 | 条区底 | 彩点可辨性处理 |
|---|---|---|
| 关闭 | 透明 → 透出 `colors.background`（不透明确底） | 彩点原色直接可辨；1px 描边保留（统一行为） |
| 半透 | 透明 → 透出半透 background + 壁纸混色 | 彩点为不透明小面积纯色，1px hover 深档描边保证与任意壁纸混色可辨 |
| 磨砂 | 透明 → 透出磨砂 backdrop | 同半透；失焦灰点（textDisabled 5.18:1 on dark background）在磨砂降对比场景依赖描边兜底，失焦态灰点+灰感可接受弱化（失焦本意即弱化） |

- 关闭钮红底白叉对比：A12 要求「红底对比清晰」——hover 态白 × on #EF4444/#DC2626 ≥3.6:1，normal 态红点本身即高辨识元素，6 组合均达标。
- 不为材质档增加钮级底衬/背板——彩点+描边已足够；加背板反而破坏「条区与 app 顶区融合」验收（A12 验融合不验背板）。

## 8. 交互流程（语义声明，实现归技术卡）

1. 单击关闭钮 → 关闭确认链（可 veto，PRD 回传链锚定）；取消则窗口保持、钮无状态残留。
2. 单击最小化钮 → 窗口入 Dock；恢复后钮位/隐藏态不变（A11）。
3. 单击全屏钮 → 进原生全屏，条与钮退场；退出后完整回归（A2/A7）。
4. 按下拖拽区 → 窗口跟随移动；结束立即点侧栏命中正常（A5）。
5. 双击拖拽区 → 按系统偏好缩放/最小化（A6）；全屏中整条不存，无此交互。
6. 失焦窗点击钮 → 仅激活窗口（§5 契约）。
7. VoiceOver：三钮可达并朗读「关闭/最小化/全屏」（F-07，标签文案即此三者）。

## 11. Windows 端对照声明（F-09）

零改动清单：右缘双钮 46×40 位置/三态色/图标/交互全不变；titlebarHeight()=40 不变；拖拽热区规则不变；bodyTop=40 不变。本设计全部增量仅存在于 macOS chrome 生效分支（`customTitlebarActive()` gate 之后）。

## 12. 禁止项自查

- **不自造 z 序**：钮为窗口内容上的覆盖层（系统视图层级），不引入窗口级 z 操作；全屏退场走隐藏不走层叠 hack。
- **不硬编码色值**：§5 全部色值锚定 `theme.cpp` 既有 token（error/warning/primary/hover/primaryPressed/textDisabled/onPrimary/background/errorText）；红黄 hover/pressed 加深档在文档内钉死推导值，实现时随 token 槽位落库，不在业务代码裸写。
- **不破坏 40px 几何契约**：条高 40、热区 46×40、bodyTop=40 全部沿用现值，无新造数值。
- 正文无框架/库名绑定；交互回传语义引自 PRD 契约，实现归技术卡。
- 无「大气美观」类不可执行描述；全部参数可对照验收。
