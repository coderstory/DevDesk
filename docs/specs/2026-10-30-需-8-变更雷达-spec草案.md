上游：`docs/superpowers/research/2026-10-30-需求场景支撑.md` 场景 A2 / 缺口 G-3；表结构参考 `docs/specs/2026-10-29-三池mcp业务方案.md`。

## 1. 一句话需求

新增第四个出厂任务模板「变更雷达晨报」：cron 早间触发，对模板里配置的多仓库清单逐仓跑 `git.status` + `git.log`，把「昨夜以来的提交 + 未提交/未推送状态」汇总成晨报写入笔记目录——用户开工前打开笔记即见一圈仓库的变更全貌。

本质 = `kTaskTemplates`（`src/module_agent/agent_task_templates.h`）加一行常量，与需-6 已交付的三个出厂模板（日报 / 发版 Changelog / 测试环境巡检，`465baf2b`）完全同模式：零新工具、零新调度、零新 UI。

## 3. 需求定义

### 3.1 触发（cron）

- 默认 `30 8 * * 1-5`（工作日 8:30），模板文案「变更雷达晨报」。
- 取 8:30 的理由：开工前晨报已落盘；与既有「每天 9:00 巡检」错开触发分钟，避免同一分钟起两个 run。
- cron 在套用模板后可改（与三个既有模板同口径，弹窗内随意编辑）。

### 3.2 扫描范围（多仓库清单来源）

- **清单 = 任务提示词（goal）里手写的仓库路径列表**，相对工作目录，一行一个；套用模板后用户自行改成自己的一组仓库。
- 沿用需-6 已拍板边界「模板不自动探测仓库布局」——不做仓库自动发现、不做清单配置页、不持久化清单结构（任务本身就是持久化，goal 改了下一轮就生效）。
- 每仓两查：
  1. `git.status`（repo=该仓）——分支、领先/落后远端、未提交与未跟踪文件数；
  2. `git.log`（repo=该仓，n=20，oneline）——筛出**自上一工作日 18:00 以来**的提交（与日报模板 18:00 口径首尾相接，覆盖夜间免费窗口批次产出的提交）。
- 仓库路径无效 / 非 git 目录：该仓计为「扫描失败」条目写进晨报，不中断其余仓库（巡检模板「正常带过、异常置顶」同款分层）。

### 3.3 晨报落点（笔记目录）

- `fs.write` 写入 `notes/radar/雷达晨报-当天日期.md`（自动建父目录）——与 notes/daily、notes/changelog、notes/inspect 同族口径。
- 晨报结构（提示词约定，非代码逻辑）：
  1. **差异置顶**：有「领先远端未推送 / 落后远端未拉 / 存在未提交变更 / 昨夜有新提交」的仓库排前面，各附一句话现象；
  2. **按仓分节**：每仓「分支与领先落后 → 昨夜提交列表（每条首行摘要）→ 未提交/未跟踪概况」；
  3. **尾注**：扫描仓数、正常/异常/失败计数，最终回复给出文件路径与两三句总结（日报模板同款收尾）。

### 3.4 异常提醒（可选增强，零新能力）

- 存在「落后远端未拉」或「扫描失败」条目时，模板提示词约定用 `app.notify` 发一条系统提醒（标题「变更雷达异常」，正文列仓名与现象）——巡检模板同款先例，不构成新能力。
- 仅提醒、不动手：模板不含 git.pull / git.commit 等写动作（见 §4 非目标）。

## 4. 非目标

- 不做仓库清单配置页 / 自动发现 / 子模块递归扫描（清单就在任务 goal 里，所见即所得）。
- 不做变更内容深读与 AI 分析（是否 fs.read / git.diff 追查某个异常仓，由模型当轮自主决定，模板不强制步骤）。
- 不做任何写仓库动作：不 pull、不 push、不 commit——雷达只看不动（git.pull/commit 工具在库是既有事实，模板提示词明确不使用）。
- 不改 agent 代码结构与 UI：不加新弹窗、不动 kCronTemplates、不新建工具。
- 不做跨机器/远端仓库扫描（清单里的路径必须本机可访问）。

## 6. 依赖与风险

- 依赖：无前置阻塞项（零件全部在库）。
- 风险 1：仓库路径手填易错 → 提示词里给路径示例与「扫描失败不中断」出口文案（F-04 兜底）。
- 风险 2：仓库数多时晨报过长 → 提示词约定未提交文件只计数不逐条列（差异置顶段逐仓一句话）。
- 风险 3：cron 错过不补跑（既有语义，`agent_module.h` 闹钟预览行「需应用运行；错过不补」同口径）——8:30 机器没开机则当天无晨报，接受为既有口径，不在本需求扩大。
