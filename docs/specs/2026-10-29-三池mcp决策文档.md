日期：2026-10-29 ｜ 业务主笔：惨品 ｜ 技术主笔：老学究 ｜ 状态：合稿草案，批准前零代码
前序：业务方案 `docs/specs/2026-10-29-三池mcp业务方案.md`（已批），本稿为其技术定稿，冲突处以本稿为准。

## 0. 结论先行

1. 独立 Python 进程 MCP server（官方 `mcp` SDK），不进 DevDesk app——app 是开发对象频繁重启，池状态不能随它丢。
2. 存储为独立 SQLite 文件 + FTS5；**不引用** DevDesk `core/sqlite_db`（那是 app 内基建，独立进程用不上）；engram 降为 schema 参照。
3. 五表：`needs` 主表 + `dev_progress`/`bugs`/`acceptance` 三子表（`need_id` 外键）+ `status_log` 溯源表。
4. 四工具面：入池 / 捞取 / 更新 / 检索；全员可读，写走单写者纪律。
5. HTML 报告（F-06）由池更新脚本自动重生成，浏览器直开；POOL.md 退役。

## 1. 运行形态

| 项 | 定 |
|---|---|
| 进程 | 独立 Python 3 进程（MCP stdio server），随开发群常驻，与 DevDesk app 生命周期无关 |
| 实现 | 单文件 `pool_mcp.py`：MCP server + SQLite 访问 + HTML 报告生成三合一 |
| 依赖 | 官方 `mcp` Python SDK + 标准库 `sqlite3`；**实测本机 Python sqlite3 = 3.54.0，FTS5 原生可用，零额外依赖**（2026-10-29 实测） |
| 数据文件 | `docs/pool/pool.db`（独立于 app，git 管理）；HTML 报告 `docs/pool/pool-report.html` |
| 挂接 | 各 Bot 会话配置一条 MCP stdio server 即接入 |

## 2. 表结构（DDL 级）

```sql
CREATE TABLE needs (
  id INTEGER PRIMARY KEY,            -- 需-N/BUG-N/债-N 的数字部分
  pool TEXT CHECK(pool IN ('need','bug','debt')),
  title TEXT NOT NULL,
  priority TEXT CHECK(priority IN ('P0','P1','P2','P3')),
  status TEXT CHECK(status IN ('在池','排产','进行中','待验收','关闭','挂起','拒绝')),
  blocker TEXT,                      -- 挂起必填：等授权/等环境/条件未触发/登记不派工
  owner TEXT,                        -- Bot 名，一条目一 owner
  detail TEXT,                       -- 指针（docs/ 路径），长文不入库
  created TEXT, updated TEXT
);
CREATE TABLE dev_progress (id INTEGER PRIMARY KEY, need_id REFERENCES needs(id), time TEXT, note TEXT);
CREATE TABLE bugs        (id INTEGER PRIMARY KEY, need_id REFERENCES needs(id), time TEXT, note TEXT);
CREATE TABLE acceptance  (id INTEGER PRIMARY KEY, need_id REFERENCES needs(id), time TEXT, evidence TEXT);
CREATE TABLE status_log  (id INTEGER PRIMARY KEY, need_id REFERENCES needs(id), time TEXT,
                          from_status TEXT, to_status TEXT, reason TEXT);   -- 溯源链
CREATE VIRTUAL TABLE needs_fts USING fts5(title, body, content='');
```

溯源链查询：`SELECT * FROM status_log WHERE need_id=? ORDER BY time`——一条需求摸到全部进度/BUG/验收/状态变更。

## 3. MCP 工具面（四工具签名）

1. `pool_add(pool, title, priority, owner, detail?) → id`：入池；写 `needs` + `status_log`(→在池) + FTS 索引 + 重生成报告。
2. `pool_fetch(priority?, status?, pool?) → rows`：捞取；按 P 级/状态/池过滤。
3. `pool_update(id, status?, priority?, owner?, blocker?, note?) → ok`：状态机校验（§4）+ `status_log` 一行 + 可选子表记录 + 报告重生成。
4. `pool_search(keyword) → rows`：FTS5 命中标题/正文，查重铁律与开工前检索走它。

权限：四工具全员可读；写操作按单写者纪律由排产 Bot 执行，server 侧不加锁（SQLite 单写原子性 + 纪律兜底）。

## 4. 状态机（承接业务稿 §3，程序化校验点）

合法迁移表（server 在 `pool_update` 内强制，非法迁移拒返回错误）：

```
在池 → 排产 | 挂起 | 拒绝
排产 → 进行中 | 挂起
进行中 → 待验收 | 挂起
待验收 → 关闭 | 进行中(打回)
挂起 → 在池(解除，记原因链)
```

- 关闭前置：`acceptance` 至少一行（F-03/04）；拒绝必填 reason（入 status_log）。
- 挂起必填 blocker；解除时 status_log 记原因链。
- P0 即时插队属排产决策，程序层不管；P1-P3 按 `priority, id` 排序捞取。

## 5. HTML 报告（F-06）

- 每次写操作尾部同步重生成（条目 < 百，纯 Python 字符串拼 HTML，无模板引擎）。
- 内容三块：三池状态总览（按 P 级分组）、在产条目排产视图、点开条目的溯源链（status_log + 子表全展）。
- 浏览器直开（`open docs/pool/pool-report.html`），零服务零构建。
