## 段1 范围(本草案,已实现)

单一脚本 `tools/session_archive.py`,三模式:

1. `ingest`(hook handler):stdin 读 SessionEnd payload → 解析 transcript jsonl(抽取 user/assistant 文本,tool 噪音剔除)→ 入库,reason 做分类维度。
2. `sync`(对账补漏):扫 `~/.claude/projects/*/*.jsonl`(单层=主会话),增量收录(强杀漏采兜底,调研建议#3)。
3. `search "关键词"`:FTS5 检索,可带 `--project` / `--since` / `--limit`。

存储:SQLite + FTS5,落 **`~/DevDesk/session-assets/session-assets.db`**(DevDesk 数据根口径,仓外;`SESSION_ASSETS_DB` 环境变量可覆盖,测试用)。

### 表结构(§6.5 口径:审计四件套)

- `assets`:session_id PK / project / title / started / ended / turns / size_bytes / mtime / reason / archived_at / created_by / updated_by / deleted(软删)
- `assets_fts`:FTS5(title, body),`session_id UNINDEXED` 关联

## 接线

## 验收标准

- F-1 ingest:模拟 SessionEnd payload(stdin)喂样例 jsonl → 库中出 1 条,标题/项目/文本可 search 命中。
- F-2 sync:对真实 `~/.claude/projects` 全量跑 → 收录数≈现存 jsonl 数;**幂等**(重跑零新增)。
- F-3 search:真实数据上按本仓库关键词检索,返回可读行(标题/项目/时间)。
- F-4 hook 接线后不阻塞会话退出(async),失败静默不骚扰。
- F-5 软删纪律:删除走软删标记,读路径过滤。

## 已知取舍

- transcript 全文入库会使 DB 体量可观(1840 会话全量约数百 MB 级)——接受,单机私有资产;只存抽取文本,不存原始 jsonl 副本(原文仍在 ~/.claude 不动)。
- `sync` 首跑全量耗时一次性成本,之后增量。
