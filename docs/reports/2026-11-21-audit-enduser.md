## 6. 四条主任务流走查

### 流 1：记笔记 → 保存 → 搜索找回
| 步骤 | 可达成 | 依据 / 断点 |
|---|---|---|
| 进入笔记页 | ✅ | 侧边栏「Markdown」；空态「还没有笔记 点右上角 + 开始」（方位词问题见 P2） |
| 新建 | ✅ 3 条路 | 页头「新建笔记」`markdown_module.cpp:475-485`、列表头「+」`md_module_tree.cpp:263-276`、⌘/Ctrl+N（macOS 上 Ctrl 不生效，P1-3） |
| 写内容 + 保存 | ✅ | 停止输入 400ms 自动落盘；底栏 `● 未保存 / ✓ 已保存 HH:MM / ✕ 保存失败，自动重试中`（`md_module_editor.cpp:268-278`） |
| 搜索找回 | ✅ | 左栏搜索框，中文子串兜底；无命中「没有匹配的笔记」 |
| 步数 | **3 步**（点新建 → 起名回车 → 写） | 断点：无 |

失败路径提示：磁盘满/只读 → `保存失败「路径」<原因>，已自动重试`（`md_module_editor.cpp:536-540`，说清了「发生了什么 + 会自动重试」）；文件名非法 → 弹窗内红字「笔记名不合法：不支持绝对路径、盘符（如 C:）或 ..」；Windows 保留名 → 预检红字；笔记目录丢了 → 列表错误行「列表加载失败：…」+ toast（`md_module_tree.cpp:364-370,604-610`）。
**判断：这条流最扎实**——状态可见、错误可理解、退出有保护。

### 流 2：建待办 → 改状态 → 完成 / 归档
| 步骤 | 可达成 | 依据 / 断点 |
|---|---|---|
| 新建 | ✅ | 页头「新建任务」唯一入口（`todo_ui_board.cpp:217-230`），弹窗直接写明「将创建在「待办」列」（`todo_ui_dialogs.cpp:223-227`） |
| 改状态 | ✅ 4 条路 | 拖卡跨列 / 右键「移动到「某列」」/ ⌘↑↓ / 详情弹窗 |
| 完成 | ✅ | 详情「标记完成」chip 或拖入已完成列 |
| 归档 | ✅ 2 条路 | 拖入归档列；详情「归档」chip（`todo_ui_dialogs.cpp:873-885`）。指南 `:116` 写「归档列不可拖出」，实际服务端口径矩阵允许 归档→非 done 列（`todo_service.cpp:723`），即**可恢复但文档没说** |
| 步数 | **4 步**（新建 → 拖 → 拖 → 完成） | 断点：得先知道「拖」这件事——页头副标题有写（旧截图 `app-todo.png` 可见「拖动卡片跨列移动」） |

失败路径提示：`任务标题不能为空`（输入框内）；写操作失败走页头状态条「移动失败 / 删除失败 / 保存失败：<原因>」；`归档任务按归档时间排序，不支持手动移动`。
**判断：顺畅，但「归档」有两处认知缺口**：①自动归档（P1-2）用户不知道 ②归档可拖回但文档反着说。

### 流 3：切 Claude 模型 / Provider → 验证能用
| 步骤 | 可达成 | 依据 / 断点 |
|---|---|---|
| 新建 Profile | ✅ | 左栏列表头「+」（`claude_ui_list.cpp:627-637`）或「导入」（读 `~/.claude/settings.json`） |
| 填参数 | ⚠️ | Base URL / API Key / 模型映射 / 环境变量 —— 术语门槛（P2） |
| 保存 | ✅ | 首个 Profile 提交前做「正在验证可用性…最长 5 秒」预检，失败原因写表单红字（`claude_ui_form.cpp:212-220`） |
| 验证 | ✅ | 「测试连通」→「连通成功 / 上游返回 HTTP N，API 可用」；失败分 401/403、404、其他三类并给处置（`claude_service.cpp:279-286`、`claude_module.cpp:613-640`） |
| 真正用起来 | ⚠️ | 必须回页头点「启动代理」（默认不启动）；指南 `:145` 有写，页面顶部引导条也写 |
| 步数 | **5 步以上** | 断点：术语 + 「代理」概念 |

失败路径提示：`该 Profile 未保存 API Key，请先填写`（本地事实优先，`claude_module.cpp:618-621`）；`连不上——<底层原因>`；`接口不存在——HTTP 404（…检查是否为 Anthropic 兼容网关地址）`；`启动代理失败：<原因>`（多为端口占用）；`503 no_active_profile`。**这些提示质量很高**，问题只在「名词前置」——用户要先懂词才读得懂。
**判断：门槛最高的一条。技术用户 OK，普通用户卡在理解而非操作。**

### 流 4：换壁纸 → 导入素材 → 删除素材
| 步骤 | 可达成 | 依据 / 断点 |
|---|---|---|
| 开启模块 | ✅ | 设置 →「模块」→ 壁纸格（默认关）；指南 `:199` 误写「并重启后出现」（P2） |
| 选文件夹 | ✅ | 片库页「选择…」+「重新扫描」（`wallpaper_ui.cpp:1000-1035`） |
| 导入 | ✅（macOS） | 「从花見导入…」，同名同大小跳过；需装花見 + 完全磁盘访问，失败有专词弹窗 |
| 看素材清单 | ❌ | 片库页只有「文件夹卡 + 视频格式卡 / 分辨率 + 适配」，**没有任何文件列表**（`wallpaper_ui.cpp:1225-1253`）；用户只能看到「参与轮播 N」这类计数 |
| 删除素材 | ⏳ 开发中 | 当前 HEAD 无入口（need#356 在途：托盘「删除当前壁纸」+ 废纸篓），按任务要求不作为已上线功能评价 |
| 步数 | 开→选→导 = **3 步**；删除不可达 | 断点：想删某个不要的视频，界面上找不到它 |

失败路径提示：路径行「目录不见了」；`无法读取花見` 弹窗（可直达系统设置）；`参与轮播 0 / 低于档位 N`（素材全被过滤）；格式不支持在提示行明写「MKV / AVI / WEBM 不会被扫描，需自行转成 mp4」。
**判断：能用但「好用」不足**——片库叫「片库」却看不到片子，删除只能等 need#356。

## 7. USER_GUIDE 质量评估

| 栏 | 内容 |
|---|---|
| **覆盖（好）** | 14 个模块各一节，「能做什么 / 怎么操作 / 出错了看哪」三段式；数据位置与备份成体系（§4）；FAQ 覆盖代理、端口、模块开关、主题、搜索、丢稿等高频疑问。模块级「出错了看哪」表格把错误提示当产品文档写，是同类个人项目里少见的做法。 |

## 9. 做对了的部分

1. **「出错了看哪」写进了用户文档**：每个模块都有「提示 → 含义 → 处置」三行，用户遇到错能自助。这是把错误处理当产品做。
2. **自动保存 + 三态状态栏 + 退出拦截**：`● 未保存 / ✓ 已保存 HH:MM / ✕ 保存失败，自动重试中`，退出前弹「有未保存修改」。普通用户最怕的丢稿被三重堵住（screenshot `app-markdown.png` 底部状态栏可见）。
3. **危险操作说清后果再说「不可恢复」**：删除笔记「及其磁盘文件，不可恢复」、删除 Profile「及其保存的 API Key，不可恢复」、删除被引用服务「被 N 个环境引用；删除后将自动从这些环境摘除」。用户是在知情下点确认的。
4. **空态基本有「为什么空 + 下一步」**（10/13 模块）：待办「归档的任务在这里」、壁纸空态卡带主次按钮、定时「暂无运行记录」统一空态组件。
5. **失败提示不是死胡同**：端口占用、Key 被拒、404 网关不对、目录不见了、笔记目录丢了，每条都给了「看看哪儿」。「连通异常」还按 401/403/404/其他分了四类处置。
6. **本地优先是真的**：数据全在 `~/DevDesk`、笔记是普通 `.md`、凭据分级保护（mac 0600 / Win DPAPI）、明确「不上传任何内容」。对「东西必须在我自己电脑上」的用户，这点是决定性的。
