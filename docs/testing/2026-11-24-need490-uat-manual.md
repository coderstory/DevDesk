# DevDesk 网页终端 真机 UAT 手册

- 日期：2026-11-24；对应功能：need#490「网页终端」；代码基线 dev `ab1531a4`（含并发上限 / 错误口径 / 端口持久化变更）
- 读者：产品负责人 / 验收人。按顺序做，每步都有「预期」和「不对时先看什么」。
- 一句话说明：手机和电脑连同一个 WiFi，用手机浏览器打开电脑上的终端，看到同一块屏幕、能输入。

---

## 0. 开始前准备

### 0.1 三件必备

| 项 | 要求 |
|---|---|
| 电脑 | DevDesk 已启动，终端模块可用（左侧能进「终端」页） |
| 手机 | 与电脑连**同一个 WiFi / 同一局域网**（手机开流量、连不同 WiFi 都不行） |
| 手机浏览器 | Safari / Chrome / Edge 等现代浏览器；手机上装一个「验证器」App（iOS 可用系统自带「密码」App；Android 用 Google Authenticator、Microsoft Authenticator 等） |

「验证器」= 每 30 秒生成 6 位数字的 App，用来给登录加一道锁。

### 0.2 怎么拿到访问地址、怎么看到二维码

1. 电脑打开 DevDesk → 左侧「设置」。
2. 设置页顶部有 5 个 tab：**通用 / 模块 / 日志 / 同步 / 网页访问**，点**第 5 个「网页访问」**。
3. 打开「启用网页访问」开关。
4. 这个卡片里会同时出现三样东西：
   - **访问地址**：形如 `http://192.168.x.x:7878`（第一行是局域网地址，第二行带「本机」标记的 `http://127.0.0.1:7878` 只能电脑自己访问，手机不要用这条）。
   - **验证器绑定**：一张**二维码** + 倒计时「剩余 mm:ss」+「刷新」按钮。
   - **自诊信息**：`监听地址：0.0.0.0:7878（局域网可见）`、在线设备数、最近登录时间、「打开日志目录」按钮。

默认端口 **7878**。端口可在服务关闭时改（1024–65535），服务运行中只读；改完点「应用」会**持久化**，下次启动 DevDesk 仍用该端口，不需要重填。

> **演示模式**：只在网址末尾手动加 `?demo=1` 时，页面才进入内置 mock（假数据，用于看布局）。正常验收**不要加**，加了你看到的不是真实终端。

### 0.3 日志在哪（出问题先看这里）

| 平台 | 日志文件 |
|---|---|
| macOS | `~/DevDesk/logs/devdesk.log`（`~` 是你的用户主目录） |
| Windows | `%USERPROFILE%\DevDesk\logs\devdesk.log`（例如 `C:\Users\你的名字\DevDesk\logs\devdesk.log`） |

最省事：网页访问卡底部点「**打开日志目录**」，直接弹出文件夹。

## 1. 主流程（M1–M11）

### M1 开启服务

- 操作：设置 → 网页访问 → 打开「启用网页访问」。
- 预期：
  - 开关停在「开」，短暂显示「正在开启…」后消失。
  - 访问地址出现 `http://192.168.x.x:7878`；验证器绑定区出现**可扫的二维码**，倒计时从约 5 分钟开始。
  - 自诊区显示 `监听地址：0.0.0.0:7878（局域网可见）`。
- 不对时先看什么：
  - 开关**自动弹回** + 红字「端口被占用或无法监听」：说明 7878 被别的程序占了。先关掉服务，把端口改成 7879 之类，点「应用」，再开。
  - 红字「网页服务未装配」：网页终端模块被关掉了，去「模块」tab 重新启用终端模块。
  - Windows 首次启动弹防火墙提示：必须允许「专用网络」，否则手机连不上（卡片自诊区也会给出这句提示）。
  - 详情看日志 `devdesk.log` 里 `网页终端服务启动失败` 一行。

### M2 手机扫码

- 操作：手机相机或微信/浏览器「扫一扫」，扫电脑上的二维码。
- 预期：
  - 手机浏览器打开形如 `http://192.168.x.x:7878/#b=...` 的地址。
  - 第一次绑定：几秒握手后显示「**绑定验证器**」页。
  - 这台手机以前绑定过、票据还在：直接进终端页，不再要码（票据保留 7 天）。
  - 已经用别的手机绑定过验证器：显示「**登录网页终端**」输入 6 位码的页面，而不是绑定页。
- 不对时先看什么：
  - 页面打不开 / 一直转圈：确认手机和电脑是同一 WiFi；地址必须是 `192.168` 开头那条，不要用 `127.0.0.1`；关掉手机 VPN；公司/酒店 WiFi 可能禁止设备互访（AP 隔离），换手机热点让电脑连热点再试。
  - 二维码显示「已过期」（红色）：点旁边的「刷新」，重新扫。
  - 扫码后显示「链接已过期 / 请在桌面端刷新二维码后重新扫码」：同上，刷新二维码重扫。
  - 日志查 `handshake_rate_limited`（试太多次被限流，等 1 分钟）。

### M3 添加到验证器

- 操作：在手机「绑定验证器」页点「**添加到验证器**」。
- 预期：
  - iOS 直接跳到系统「密码」App；Android 弹出应用选择（选你的验证器 App）。
  - 验证器里新增一条名为 `DevDesk` 的条目；返回浏览器，页面等着你输 6 位码。
- 不对时先看什么：
  - 按钮灰、点了没反应：二维码/链接已过期，回电脑点「刷新」再扫。
  - 手机没有验证器 App：先装一个（Google Authenticator / Microsoft Authenticator；iOS 也可用自带「密码」）。
  - 验证器里没出现条目：手动在验证器里选「添加账户 → 扫描二维码」，再扫电脑上的二维码。

### M4 输入 6 位码

- 操作：看验证器里 `DevDesk` 当前的 6 位数字，在手机页面输入。
- 预期：输满 6 位自动提交（或点「完成绑定」），**直接进入终端页**，顶部出现标签页，底部显示「已连接」。
- 不对时先看什么：
  - 「验证码错误，请重试」：6 位码 30 秒换一次，等下一轮再输；确认手机时间自动同步。
  - 「尝试次数过多，绑定已失效，请在桌面端刷新二维码」：**绑定环节错 5 次，这张二维码作废**。回电脑点「刷新」，用新二维码重来（M2 起）。
  - 提示「登录设备数已达上限」：先退出不用的手机（终端页菜单 → 退出登录）。

### M5 看到桌面同一个终端

- 操作：对比手机和电脑「终端」页。
- 预期：两边是**同一个会话**：同样的提示符、同样的历史输出；电脑端切 tab，手机 1 秒内跟着切；手机切 tab，电脑也跟着切。
- 不对时先看什么：
  - 手机显示「暂无终端」+「新建终端」：电脑端当前没有终端会话，点手机上「新建终端」或顶栏「+」。
  - 手机一直是骨架屏（灰条）：检查桌面「终端」模块是否启用、日志里有无会话创建失败。
  - 内容相同但排版/字号不同：正常，手机按自己的屏幕重排，内容一致即可。

### M6 输入 `echo hi`

- 操作：点一下手机终端画布（弹出软键盘），输入 `echo hi`，按键盘上的「换行/发送」。
- 预期：手机和电脑同时出现一行 `hi`。
- 不对时先看什么：
  - 点了没弹键盘：再点画布空白处；或点一次终端再点底栏。
  - 输入了但没反应：底部是否「已连接」；底栏出现过「待发送」标记说明在排队，等于网络恢复后补发。
  - 中文输入法候选框错位：换英文键盘先验证链路，再记下机型/输入法反馈。
  - 复制：直接用浏览器原生选择（长按文字拖动选择）；粘贴：点底栏「粘贴」，在弹出的框里粘贴，确认后原文插入（不会逐行执行）。

### M7 切 tab / 新建终端

- 操作：手机顶栏点「+」新建一个终端；点 tab 名切换；再在新 tab 里跑一条命令；**双击 tab 名可改名**。
- 预期：
  - 两端都多出一个标签页；切换后两端同步显示同一个会话。
  - 改 tab 名：上限 **32 个字符**（按字符计，中文也算 1 个），超长自动截断；改名后约 1 秒内同步到电脑端。
  - 关闭最后一个 tab 后显示「暂无终端」+「新建终端」；运行 `exit` 退出进程后显示「终端已退出（退出码 0）」+「重新开始 / 关闭标签」。
- 不对时先看什么：
  - 「会话数已达上限」：同时开太多会话，关掉几个不用的。
  - 「终端启动失败：…」：按卡上的原因处理；常见是默认 shell 或启动目录配置不对，去手机菜单 → 配置，或电脑终端设置里检查。

### M8 改字号

- 操作：手机终端页右上「⋮」→「配置」→ 拖「字号」滑块（10–24）；可顺带改字体、配色、默认 shell、启动目录。
- 预期：
  - 保存后立刻生效，电脑端同一会话的字号/画面同步变化（1 秒内）。
  - 页面底部出现「保存失败，请重试」横幅 = 有值非法（如启动目录不存在），改回合法值再存。
- 不对时先看什么：
  - 改了没同步：确认只开着一个配置页；返回终端后看底部连接状态。
  - 启动目录填了不存在的路径：确认后会被拒绝，检查路径是否在电脑上真实存在。

### M9 按 Esc 中断（跑 claude code 场景）

- 操作：电脑或手机终端里运行 `claude`（Claude Code）；等它开始输出时，点手机底部键带的「**Esc**」。
- 预期：Claude Code 立刻停止当前输出/操作；焦点保持；继续输入或点「Tab」补全仍有效。
- 不对时先看什么：
  - 看不到键带：点键带右侧的小箭头展开；键带只在终端页出现。
  - Esc 没反应：先点一下终端画布再按；确认底栏「已连接」。
  - 手机只有 Esc / Tab 两个特殊键，方向键、Ctrl 组合键不提供；需要时改用电脑操作。

### M10 断网 10 秒再恢复

- 操作：手机开飞行模式（或关 WiFi）约 10 秒，再恢复。
- 预期：
  - 断网约 1 秒内，终端顶部出现细条「连接中断，正在重连（第 N 次）」，底栏状态点变「重连中」。
  - 断网超过约 2–3 秒，会盖上全屏提示「桌面端已关闭网页服务」+「重新连接」（这是同一套重连逻辑，不代表电脑真关了）。
  - 恢复网络后**自动**重连（重试间隔 1/2/4/8/10 秒，最长等 10 秒左右），回到终端画面，滚动位置保留，断网期间排队的输入按序补发。
  - 补发队列总容量 **4 KB**（按字节计）。断网期间输入过多、超出上限时，**最旧的输入先被丢弃**，恢复连接后页面弹出「**部分输入未送达**」提示——看到它说明有几行你打的字没送过去，重新输入即可。
- 不对时先看什么：
  - 一直不恢复：点全屏提示上的「重新连接」；确认手机真的回到原 WiFi（没连到别的网络）。
  - 回到「登录网页终端」并提示「登录已过期，请重新验证」：票据失效（被撤销绑定，或超过 7 天），重新输验证器 6 位码。
  - 恢复后画面错位/花屏：退出重进页面（会重新拉取完整画面）；需要的话记录日志时间点。

### M11 关桌面服务看提示

- 操作：电脑设置 → 网页访问 → 关闭「启用网页访问」。
- 预期：
  - 手机约 2–3 秒内盖上全屏「**桌面端已关闭网页服务**」+「重新连接」。
  - 电脑重新打开服务后，手机**自动**恢复，回到原终端画面（会话还在）。
- 不对时先看什么：
  - 手机没提示：确认电脑开关确实已关；手机可能已经断网（见 M10）。
  - 重开服务后不恢复：点「重新连接」；确认端口没变（改了端口要用新地址重新打开）。
  - 若电脑是**重启了 DevDesk**（不是只关服务）：会话全部结束，手机重连后显示空态「桌面端已重启，会话已全部结束」+「新建终端」，见 E5。

## 2. 边界场景（E1–E5）

### E1 二维码过期

- 操作：开启服务后不扫，等倒计时走完（5 分钟）；或扫一张已过期的旧二维码截图。
- 预期：
  - 电脑卡片：倒计时变成红色「已过期」，「刷新」按钮变为高亮主按钮。
  - 手机扫过期链接：绑定页显示「**链接已过期** / 请在桌面端刷新二维码后重新扫码」，验证码框隐藏。
  - 点「刷新」后：新二维码出现、倒计时重置；旧链接/旧二维码永久失效。
- 不对时先看什么：刷新后手机仍显示过期 → 刷新页面再扫新码；日志看 `bind_expired`。

### E2 连续 5 次错码

- 绑定环节（M4）：
  - 操作：故意连输 5 次错误 6 位码。
  - 预期：出现横幅「**尝试次数过多，绑定已失效，请在桌面端刷新二维码**」，输入框和按钮变灰；必须回电脑「刷新」二维码后重新绑定。
  - 不对时先看什么：日志 `bind_terminal` / `bind_invalid`；确认是否真的错了 5 次（每输错一次计数器加一，输对即成功）。
- 登录环节（已绑定的手机）：
  - 操作：在「登录网页终端」页连输 5 次错码。
  - 预期：提示「**尝试次数过多，请 N 秒后再试**」并倒计时（60 秒窗口，按手机 IP 计）；倒计时结束可重试。此处**不会作废绑定**，只是临时锁定。
  - 不对时先看什么：等倒计时结束；换网络会换 IP，可能立即解锁（这是限流按 IP 的正常表现）。

### E3 撤销绑定后手机表现

- 操作：电脑网页访问卡 →「删除绑定」→「确认删除」。
- 预期：
  - 所有已登录手机在约 5 秒内盖上全屏「**绑定已撤销** / 请在桌面端重新扫码绑定，完成后刷新本页」。
  - 旧票据立即失效；电脑卡片回到「未绑定」态，出现新二维码。
  - 手机按提示回电脑重新扫码、重新添加验证器、输 6 位码后可再次使用。
- 不对时先看什么：手机没反应 → 手机是否在线（断网时会在恢复后才收到）；刷新手机页面应回登录/绑定页。日志看 `revoke` 广播与 `tickets_.revokeAll`。

### E4 换网络后地址变化

- 操作：电脑切换 WiFi（或路由器重新分配 IP），再看网页访问卡与手机。
- 预期：
  - 电脑访问地址**自动更新**为新的 `http://192.168.x.x:7878`；未绑定时二维码自动用新地址重生成。
  - 手机上旧地址打不开（旧 IP 已不存在）；需要用新地址重新打开。
  - 已登录的手机页面会一直显示重连，直到你打开新地址；票据仍在时打开新地址可免码进入（≤7 天）。
- 不对时先看什么：地址没变 → 等 1–2 秒刷新界面；电脑没拿到局域网 IP 时卡片会提示「未检测到局域网连接，手机暂无法访问」。改过端口的话地址里的端口也会变。

### E5 桌面重启后提示

- 操作：关闭并重新启动 DevDesk，重新开启网页服务；手机页面保持打开或重新打开原地址。
- 预期：
  - 手机凭已保存的票据**自动重连，不再输码**（票据在电脑上有文件持久化）。
  - 因为旧会话已全部结束，终端区显示「**桌面端已重启，会话已全部结束**」+「新建终端」。
  - 若票据文件丢失/被清（例如手动删了数据目录），手机回「登录网页终端」，需输 6 位码。
- 不对时先看什么：手机一直转圈 → 桌面服务是否已重新开启、端口是否变了；回登录页属正常（票据失效）。日志看启动时 `网页终端服务启动失败` 或票据加载失败。

## 3. 上限与错误提示

系统有一组硬上限，到顶不会卡死，而是给出明确提示。看到提示按右列处理即可。

| 场景 | 触发条件 | 你在页面上看到什么 | 怎么办 |
|---|---|---|---|
| 同时查看连接数满 | 同一套服务已有 **8 个** 正在查看的页面（含电脑、手机、其它浏览器） | 全屏「**连接数已达上限** / 已在线端不受影响，请稍后重试。」（服务端返回文案为「同时查看的连接数已达上限」，HTTP 503） | 先关掉不用的浏览器页面，点「重试」；已在线的不受影响 |
| 会话数满 | 终端会话开太多 | 「会话数已达上限 / 请关闭一个不用的会话后再试。」 | 点「关闭一个会话」或复用现有 tab |
| 登录设备数满 | 已登录手机数到上限 | 「登录设备数已达上限 / 请先退出不用的设备」 | 在旧手机终端菜单「退出登录」 |
| 登录验证码输错锁定 | 同一手机 IP 60 秒内错 5 次 | 「尝试次数过多，请 N 秒后再试」并倒计时 | 等倒计时结束；**不会作废绑定** |
| 握手 / 登录请求过频 | 短时间内反复连接 | 全屏「连接请求过于频繁，请稍后再试」+「N 秒后可重试」 | 等待倒计时结束再点「重试」（限流按 IP 计，换网络会换 IP） |
| 单次输入过快 | 命令队列积压到上限 | 「发送失败，请重试」 | 稍等再发；确认终端在跑、没有卡死 |

补充说明：
- 「同时查看连接数」上限是 **8**，到顶时第 9 个页面会被拒绝，提示文案里的「同时查看的连接数已达上限」就是本文这条，不是网络故障。
- 会话数、登录设备数、验证码锁定的具体数值以页面提示为准；提示出现时按表中「怎么办」操作，不要反复刷新。

## 4. 怎么判断是业务错误还是连接错误

判断口诀：**看页面有没有正常显示 DevDesk 界面**。

| 你看到的 | 属于 | 含义 | 处理 |
|---|---|---|---|
| 页面正常，出现**横幅 / 弹窗 / 底部提示 / 全屏提示卡**（如「会话数已达上限」「部分输入未送达」「绑定已失效」） | **业务错误** | 网页和服务端连上了，是应用层的规则或状态限制（服务端把这类结果放在加密内容里返回，HTTP 层仍是正常响应） | 按提示文字处理；提示条上的按钮优先 |
| 页面还在，底栏写「重连中 / 已断开」，顶部细条「连接中断，正在重连（第 N 次）」 | **连接错误（可自愈）** | 网络断了、电脑服务关了或电脑重启 | 恢复同一 WiFi 后自动重连；一直不恢复点「重新连接」 |
| 浏览器自己报错页（「无法访问此网站」「连接超时」「ERR_CONNECTION_REFUSED」等），或一直转圈 / 白屏 / 骨架屏不动 | **连接错误（到不了服务）** | 地址错、端口错、不在同一网络、服务没开、防火墙拦截 | 查地址是否为 `192.168` 那条、端口是否改过、服务是否开启、防火墙是否放行 |

要点：
- 业务错误**不会**变成浏览器的错误页——能看到 DevDesk 的界面和中文提示，就说明连接是通的，问题在规则/状态，别去查网络。
- 连接错误**不会**弹出业务提示卡——看不到应用界面时，先解决网络/地址/服务，业务提示要等服务连通后才会出现。
- 例外：第 9 个「同时查看」连接会直接显示全屏「连接数已达上限」卡片，它是业务上限但由连接环节触发，按第 3 节处理。

## 5. 自诊速查

| 现象 | 先看哪 |
|---|---|
| 开关弹回、红字 | 网页访问卡红字原因 → 换端口 / 查占用 → 日志 `网页终端服务启动失败` |
| 手机打不开页面 | 是否同一 WiFi、是否用 `192.168` 地址、防火墙是否放行、是否开了 VPN、WiFi 是否禁止互访 |
| 扫码后提示过期 | 电脑端「刷新」二维码，重新扫 |
| 输 6 位码总错 | 手机时间是否自动同步；绑定页错 5 次需刷新二维码，登录页错 5 次等 60 秒 |
| 画面不同步 | 底栏连接状态；是否同一会话；日志有无会话/帧错误 |
| 页面上的中文提示 | 属业务错误，按提示文字处理；不用查网络（见第 4 节） |
| 浏览器报错页 / 白屏 | 属连接错误，查地址、端口、同网、服务开关、防火墙（见第 4 节） |
| 断网恢复异常 | 点「重新连接」；确认回到原 WiFi；必要时刷新页面 |
| 端口相关 | 默认 7878；运行中不可改；关服务后改并「应用」会持久化，重启 DevDesk 仍生效；改了端口手机要用新地址 |

**自诊区字段含义**（网页访问卡底部）：
- 监听地址：`0.0.0.0:端口` = 监听本机所有网卡，同一局域网都能访问（不是只监听 127.0.0.1）。
- 在线设备：当前已登录的手机/浏览器数量（未完成登录的不计）。
- 最近登录：最后一次成功输码登录的时间；「从未登录」= 还没有设备登录过。

## 6. 安全提示（请完整阅读）

1. 手机和电脑之间走的是 **HTTP 明文传输**，没有 HTTPS 证书。业务数据在应用层额外做了加密（握手协商密钥后加密传输），被动抓包一般看不到终端内容；但这**不能替代 HTTPS**。
2. 加密**只防被动偷看，不防主动中间人**：同一局域网内有人伪造服务器/劫持流量时，无法通过证书识别真假。不要把端口映射到公网、不要在不可信 WiFi（咖啡厅、酒店、公司访客网）上开启服务。
3. 服务开启后监听 `0.0.0.0`，**同一网段内任何设备都能尝试连接**；安全性依赖 6 位验证码 + 限流（登录 5 次/60 秒按 IP 锁定、全站握手限流）。看到「在线设备」出现陌生数量、或「最近登录」时间不对，立即「删除绑定」并关闭服务。
4. 二维码里带一次性绑定令牌（5 分钟有效、绑定成功即作废）；截图/转发二维码等于把绑定入口给别人，用完请刷新。
5. 登录票据在手机浏览器本地保存 7 天，电脑端也落盘保存；共用手机或怀疑泄露时，用手机菜单「退出登录」，或在电脑端「删除绑定」让所有设备立即失效。
6. 不用时关闭「启用网页访问」；离开座位/换网络后重新确认地址与在线设备。
