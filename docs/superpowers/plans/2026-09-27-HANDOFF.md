## 0. 工作方式铁律（用户已定，不得违反）
1. **主会话禁止直接修改项目文件**（源码/配置/文档）；写入一律派子任务。commit 属仓库记账，主会话可自己做（用户 2026-09-27 明确"commit 又不修改文件"）。
2. **并发子任务上限 7**；空槽即补。**build 目录是单点资源**：同一时刻只一个 agent 编译/测试，撞 `cannot open output file ...: Permission denied` 就 `sleep 20` 重试 ≤5 次。
3. **每个任务完成 → 主会话审计（读 diff + 复跑验收）→ 立刻原子 commit → 立刻合 master**，不攒批。前提：**同一文件同一时刻只有一个写者**（派单按文件排他）。
4. 实现类任务优先走 **git worktree 并行**（各自独立 build 目录 + `-DEUI_NEO_DIR=D:/project/gui/EUI-NEO`），产物审计后合回。
5. 子代理报结论先证伪：读原文行核实（禁窄 grep 一行定论），只修 CONFIRMED。
6. **worktree 用完即清**：任务合并后**立即** `git worktree remove <path>` + `git worktree prune`，禁留残留。
7. **子任务只跑定向测试，禁全量**（用户："进度太慢了"）：只编译受影响目标 + 测试二进制子串过滤（如 `./tests/devdesk_tests.exe markdown`）；全量只在里程碑/提交关口由主会话跑一次。
8. **涉及编译/测试的子任务必须走 worktree**，禁止在主工作树里跑构建。收尾三步：① agent 在自己分支原子 commit 并报 sha；② **合并进 master 由主会话串行执行**（并发 merge 撞 `index.lock`）；③ `git worktree remove` + `prune`。
