## 1. 同步 01 · 401 定向引导（票：`.scratch/sync-product-gaps/issues/01-401-no-targeted-guidance.md`）

| 步骤 | 看什么 |
|---|---|
| 设置页 → GitHub 同步 → 把 Token 改成一个**错的**（如 `ghp_xxx`） | 点「测试连接」 |
| 弹出的错误详情 | 是否**指名 Token 失效**并告诉你去哪重做（GitHub → Settings → Developer settings → 生成新 Token），而不是「请求失败 / HTTP 401」这类要自己猜的话 |
| 把 Token 改回正确的 → 再点「测试连接」 | 错误行是否**立即让位**（不能留在屏幕上） |
| 输入一个**公开仓** URL → 测试连接 | 黄字提醒是否出现（口径见第 4 步） |

判据（我这边无法注入级验证的诚实边界）：模块接线（失败路径是否真调了那个纯函数、`updateToken`
实际动作）**无 UI 注入级测试**，只能靠你这一眼。

## 3. 智能体 04 · 执行记录呈现够不够用（票：`04-run-trace-presentation-needs-review.md`，**可能直接撤销**）

跑一个会**调工具**的任务（例如让它记一条待办），然后打开运行详情，逐条看：

1. 工具调用块（ToolUse / ToolResult）**默认是否可见**？要不要点开才能看到？
2. 工具**参数**（input 原文）有没有被摘要/截断到**看不出关键参数**（文件路径、命令、URL 这类）？
3. 历史 run 是否只能看到**最近若干条**（代码里 `kRunListLimit` 截断）？更早的还能不能翻到？
4. 角色徽章能否一眼区分「工具」与「用户」（代码里 tool_result 落库 role 是 user）。

**这条的裁决方式**：若你认为「够用」→ 我把票**撤销**并在产品矩阵里把 C2 改判 ✅（注明原口径过期）；
若不够用 → 收敛成一条具体缺口（例如「工具块默认折叠 → 应默认展开」，带复现步骤）另开票。
静态复核已确认渲染分支与落库链路**都在**（`agent_module.cpp:1145`/`:1157` 渲染、`agent_store.cpp:306` 落
`tool_call_id`），所以原口径「UI 不呈现」在字面上不成立——现在要判的是**呈现得够不够用**。

## 4. 同步 02/03 · 披露口径 + 大文件边界

| 步骤 | 看什么 |
|---|---|
| 设置页 → GitHub 同步卡片描述行 | 是否明说同步的是**整库数据库快照**（不只「笔记和待办」）、并列出**不上传**的表（调用日志 / 运行设置 / Token 与同步状态） |
| 同一卡片，公开仓提醒行 | 是否同步改成「整库快照与其中的密钥将公开可见」（不能只说笔记、待办） |

## 已由我静态/真网结案、**不必**你现场试的条目

- **cron 周域实际支持？** → **支持**。5 字段「分 时 日 月 周」，周域 `0-6`（0=周日），日/周同时受限走
  vixie「或」语义（`src/module_agent/cron.h:1-2`、`:11-18`、`:25`）；非法形态（L/W/#、英文名、步长 0…）
  在保存时即被拦（`cron.h:20-21`）。
- **远端文件树过大（分页上限）会静默漏同步吗？** → **不会静默**。真网实测 torvalds/linux 全树
  21.7 MB / 71638 条 → GitHub 返回 `truncated: true`；我方客户端**大声失败**（`github_api.cpp:574-578`
  「远端文件树过大被截断…暂不支持分页补取」）→ 引擎转成用户可见的「读取远端笔记树失败：…」
  （`github_sync_engine.cpp:336-339`），平台层有用例（`test_github_api.cpp:856`）。
