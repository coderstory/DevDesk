## 1. 状态机落地（F-01~F-06）

### 1.1 三模式映射（F-01）

`release_detail_logic.cpp` 现有 `isReadOnly`（Done/Voided）与 `isConfigPhase`（Draft+Pending）是「只有编辑态」的病根：Pending 仍在配置阶段。落地：

- 新增 `bool isEditMode(TaskStatus)`（= Draft）、`bool isPublishMode(TaskStatus)`（= Pending || Running）；`isReadOnly` 保留。**删除 `isConfigPhase`**，改其全部调用点（`composeReleaseDetailPage` 的 `configurable`、`finishServiceDrag:842`、`finishConfigDrag:890` 等 3~4 处）——`configurable` 只在 Draft 为真，Pending 自动失去编辑域。
- 模式是**推导**不是新状态：库中仍是五值文本编码（`release_types.h:19`），`displayStatus` 推导链（`computeDisplayStatus:954`）不动。Draft 进详情=编辑态、Pending/Running=发布态、Done/Voided=归档态，纯函数 `detailMode(TaskStatus)` 供 UI 分叉。

### 1.2 撤回提交（F-02）

- 新函数 `applyWithdrawSubmission(store, state)`（release_detail_logic.cpp，紧邻 `submitTask:688`）：
  1. 守卫：`displayStatus == Pending` 才放行；Running / Done / Voided → notice 拒绝（Running 拒绝是验收断言）。
  2. 写库：`Task next = state.task; next.status = Draft; store.updateTask(next)`——**只回退 status，不动任何确认字段**（pretestOk/cabOk/ticketNacosOk/ticketDbOk/announceSentAt/steps/configs.doneAt 原样），这正是 PRD「保留勾选项」裁决的零成本实现：数据本来就在这些字段里，不清理即保留。
  3. 日志：复用白名单 action=`revoke`（`release_store.cpp:31` 白名单不动），scope=「任务」、step=「提交」、note=「Pending→Draft 撤回提交」——F-02 验收的「日志新增一条撤回提交记录」由 note 区分语义，**不加白名单词、不改 schema**。
  4. `state.dirty = true` 重读 + notice「已撤回提交，可继续编辑」。
- 与 F-21 的衔接：撤回回 Draft 后用户改内容 → 既有 `applyContentRevocations`（release_detail_ui.cpp:42）自动撤旧确认——F-21「收敛为仅编辑态触发」天然成立（发布态内容只读，无变更可对账），补测试钉住即可，无代码改动。
- 与恢复链的自洽：`applyRestore:1041` 以「日志存在 action=submit」判已提交过；撤回不删 submit 日志，故撤回→再作废→恢复会正确回到 Pending/Running 而非 Draft。

### 1.3 发布态只读执行域（F-03）

- UI 隐藏（设计文档 §二已定稿「隐藏而非变灰」）：发布态不渲染单号输入框/配置「填写」/跳过菜单/移除/排序/拖拽手柄。
- 越权写路径 logic 层拒（防「变灰但可聚焦」歧义的兜底）：`applyRemoveService:1291` / `applyRemoveEnv:1308` / `applyEditorSave` / 跳过切换 / `moveService` / `moveConfig` 等编辑域写函数的守卫从 `isReadOnly` 收紧为 `!isEditMode`，拒绝时 notice 指名「发布中任务不能修改内容，请撤回提交或作废后操作」。确认域（markPrereqCompleted / markStepCompleted / markConfigCompleted / markAnnouncementSent / applyRevoke）保持只拒 Done/Voided——发布态推进是主交互。

### 1.4 流程轨道模型（F-04）

- 轨道序 = `performNextStep:1325` 既有固定序，不新造：新增纯函数 `collectTrackRows(const ReleaseDetailUiState&, int nowMinute) -> std::vector<TrackRowView>`（release_detail_logic.cpp），把「前置 5 项→各环境（合并分支→配置→部署→验证）」铺成行视图，每行带 {节点态：当前步/已解锁未完成/未解锁/已完成, 可勾, y 偏移}。`performNextStep` 改为消费同一份行序（消除两套遍历），「下一步」定位 = 轨道第一个未完成且已解锁行。
- 未解锁判定沿用既有门禁：时间窗（`markStepCompleted:509` 的 env.startMinute 比较）、单号（`deployGateMissing:310`）；`mergeBranch` 与前置项不受时间窗限制（既有语义）。
- **发布态专属守卫**：`performNextStep` 入口加 `isPublishMode` 判定，Draft 下调用 → notice 拒绝（编辑态主动作是提交，不放轨道引导——审计裁决的 logic 侧落实）。
- 验收断言修正（顺手修）：F-04 验收「缺单号时定位缺项」→ 改为「时间窗未到时点击锁定行 notice 指名环境与开始时间」——入口防呆（F-20）后「缺单号还能推进到下一步」不可达，原断言是死场景。PRD §十一同步改文本。

### 1.5 语义收敛与回归红线（F-05/F-06）

- F-05：不新增状态值；撤回（步骤级）走既有 `applyRevoke:1067`；已跳过配置发布态只读展示「已跳过」（TrackRowView 衍生态）。**F-05 措辞顺手修**：PRD §十一「撤回后步骤/前置回到未完成」限定为「步骤撤回」——前置勾选的撤回在发布态经单步撤回弹层（保留勾选项是 F-02 裁决，仅内容变更才对账撤确认，两条不冲突，措辞收准即可），实现不受阻。
- F-06 保既有回归红线：`advanceTaskStatus:971`（Pending→Running 时间基准自动、Done 自动）、`applyVoid/applyRestore`（唯一约束拒绝）、`restoredStatus` 重启重推——全部不动，既有用例必须持续绿。

## 3. F-23 锚点机制（跨 release_module / release_detail）

EUI-NEO 能力核对（`docs/EUI-NEO-CAPABILITIES.md` §0/§8）：

- `ui.setScrollOffset(id, offset)`（`EUI-NEO/core/dsl.h:1556`）：帧末取件、同帧去重、本帧元素不在则丢弃——**瞬时跳转**，无内建程序化缓动；但逐帧调用即可形成动画（md_module_preview 已有 9 处调用先例）。
- 无 imperative keyframes/spring；有 Transition + `onFrame`/`onTimer`。脉冲用「叠加 rect + 逐帧 alpha」自绘，不依赖框架动画。

落地（不造框架 workaround，全走公开 API）：

1. **入口锚点**：`ReleaseDetailUiState` 新增 `std::string pendingAnchor;`（空 = 无请求）。`release_module.cpp` 提醒回调（:183「去处理」）按任务状态分流：Pending/Running → `pendingAnchor = "publish.current"`；Draft → 保持现状（打开详情即编辑态，无锚点）。回调处读状态需要 store 查询（`findTaskByDate` 不适用，新增一次 `store.task(id)` 读取——store 已有单任务读取口，若无需补一个只读 getter）。
2. **滚动目标计算**：发布态轨道由 `collectTrackRows` 产出带 y 偏移的行清单（绘制与锚点同源，禁止两套布局算术）；`composeReleaseDetailPage` 消费 `pendingAnchor` 时取当前步行 y，写入滚动动画状态 `{fromOffset, toOffset, startTickMs}`。
3. **240ms 滚动**：滚动动画期间每帧 `ui.setScrollOffset("release.detail.scroll", easedOffset)`（ease-out 三次插值，~15 行），到点清除。`setScrollOffset` 是 pending 队列语义，逐帧驱动安全（`runtime_update.h:507` take-and-clear）。
4. **800ms 脉冲**：当前步行上叠加 `ui.rect(pulse)`（`.ignoreLayout()`），颜色 = primary@α，α = (1 − elapsed/800ms) × 0.25，elapsed 超 800ms 停画。一次性由状态字段保证（`anchorPulseDone`）。
5. 校验清单弹层「清单项点击 → 定位缺项」（F-15）复用同一滚动动画原语（编辑态定位到缺项表单行 y）。
6. 取舍：设计稿「尊重系统减弱动态」——EUI-NEO 未暴露减弱动态查询（能力文档未列），本页动效均为 120~800ms 短过渡，与既有页面 transition 用法一致，维持常开；此为已知取舍，非遗漏。

## 7. 失败路径

| 路径 | 行为 |
|---|---|
| 撤回提交时已 Running | 入口隐藏（页头无次按钮）+ logic 拒绝 notice（双保险，验收断言） |
| 提交校验失败 | 清单弹层 + 表单行标红；清单项点击滚动定位到缺项行；缺单号时按钮不放行（F-20 入口防呆） |
| 门禁拒绝（时间窗/单号） | notice 错误样式指名缺项（「灰度环境 14:00 开始」「请先填写：提测单号」），不弹确认层 |
| 轨道空态（无环境/无服务） | 编辑态：「环境与服务」卡内空态 +「去基础配置」链接；发布态：轨道区空态说明（无环境任务不可提交——validateTaskSubmission 分支全空时前置仍可过，提交后轨道只有前置组，属合法形态） |
| 撤回/作废/恢复写库失败 | Result 透传 notice（既有）；statusWriteFailed 一次提示语义保留 |
| F-23 锚点元素不在帧树 | setScrollOffset 本帧丢弃语义（dsl.h:1556 注释）天然兜底：下一帧 compose 重算，不排队跨帧 |
