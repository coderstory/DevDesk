## 0. 一页结论

**推荐：C 混合（telemem 做抽取/向量化/存储引擎，检索通道自研补短板，卡片人审叠加）**。理由一句话：它完整保留你已拍板的「telemem 管理面板」形态，只在你最硬的需求（2 字中文/标识符检索）上补一条已实测满分的自家通道，且日后任何换路线的退路都最宽——A 是它的省钱起步版（少 3~5 人日，但检索短板没堵），D 是它失去引擎后的归宿（自家库已是 D 的检索核心）。

三路线一句话画像：

- **A. telemem 面板**：引擎能力全用第三方，DevDesk 只做治理层（脱敏强制、卡片人审、注入预算）。最省事，但 2 字中文/标识符检索押在未验证的向量方案上，卡片只能代理第三方工具、拿不到完整撤销链。
- **C. 混合**：telemem 管记忆的「生产」（抽取、向量化、存储），检索走自家 SQLite 全文通道（2 字中文已实测命中），卡片打在自家库上（撤销链/版本校验全套可用）。
- **D. 自研 P0**：按已终审规格书全链路自建。包体最小、无上游风险，但 LLM 抽取这一格要自己从零补（本地抽取模型一次没测过），周期 8~12.5 人周起。
- **B. mem0-mcp**：出局。三种存储后端全部要求联网与 API key，「本地模式」存内存里、重启即丢（源码级复验坐实，`2026-10-27-memcpp-mem0-mcp-reference.md:10`），与「本地离线」轴正面相撞，无参选资格；其能力上报、日志静默等机制借鉴已被 P0 规格吸收。

## 1. 先穷举两全解（路线不是非此即彼）

| # | 组合 | 是否成立 | 条件与代价 |
|---|---|---|---|
| 1 | **A 起步 → 短板暴露后升级 C** | **成立，推荐作为 A 的默认预期结局而非事后救火** | 前提：A 的治理壳从第一天就留两条缝——「写入拦截点」（调 telemem 入库前先过脱敏）与「检索接口」（hook 壳不直连 telemem 而走一层内部接口）。这两缝本就是 A 设计的一部分，零额外成本。**触发条件**：真机试用评测中，2 字中文/标识符查询命中率不达标（口径：用已冻结评测资产转测 telemem 检索，Recall@5 <85%，或 2 字词「端口/配置/模块」命中低于自研基线 5/3/11——见 feasibility §5 门槛 2 与 §10.1）。**代价（非零，要如实告知）**：治理层大头（脱敏/预算/hook 壳）零返工，但卡片代理层要重接（A 的卡片操作打在 telemem 的改/删工具上，C 的卡片打在自家库上），且已入 telemem 库的记忆要导出回填到自研全文库（telemem 有列表接口和操作历史库，可导，属体力活）。反过来，若实测全绿（向量方案意外扛住 2 字中文），A 可继续独跑，不必升级。 |
| 2 | **C 起步（推荐）** | 成立 | 等于把组合 1 的两条缝直接建满，增量成本 3~5 人日（全文通道）+ 半天~1 天镜像接缝验证。省掉组合 1 的卡片重接与数据回填。 |
| 3 | A + 轻量兜底（不建全文索引，对 telemem 记忆全量列表做模糊扫描兜底） | 成立，仅当过渡态 | 能救 2 字查询，但每次兜底要全量拉取再线性扫，记忆量上万后会拖慢注入路径；不单列推荐，只作组合 1 升级前的临时止痛。 |
| 4 | C 的反面（自研抽取+自研全文，telemem 只当向量备胎） | 成立但无新增价值 | 这已经是 D 换了个壳，不展开。 |
| 5 | D 与 A/C 互转 | 隐性两全 | D 规格书的存储层（SQLite+FTS5）就是 C 的镜像库；若 telemem 引擎日后失效（上游风险兑现），C 自动滑向 D——这正是 C 退出成本最低的机制。 |

## 2. 比选总表（六维，分制 0~2）

「需求满足度」拆六个子项，每子项 0~2 分，满分 14（6 子项 12 分 + 抽取质量并入计 2 分权重）。

### 2.1 需求满足度

| 子项 | A telemem 面板 | C 混合 | D 自研 P0 |
|---|---|---|---|
| 本地离线 | **2** — 官方全本机配置现成（本机跑大模型抽取 + 本机向量化 + 本机存储，无遥测默认关；telemem 拆解 §1/§4） | **2** — 同 A，全文通道也是纯本机 SQLite | **2** — 全链路本机，单 exe（规格书 §1.3） |
| 2 字中文 + 标识符检索 | **0.5** — telemem 检索纯向量、无全文通道（拆解 :81），对 2 字中文/标识符未验证（:105 保留意见明说）；其默认向量模型以英文为主，中文短词精确匹配处机制劣势（**推测**，验证方法=组合 1 的触发线实测） | **2** — 自家 FTS5 双字分词 + 模糊兜底：冻结集 Recall@5 1.00、「端口/配置/模块」命中 5/3/11（feasibility §3.4/:345 实测） | **2** — 同 C（同一套方案，规格书 §2.3/§2.4） |
| LLM 抽取质量（把对话读成一条条记忆的能力） | **1** — 现成中文抽取管线，官方自测中文基准 86.33% 但无第三方复现，本机档质量未由我们验证（拆解 :103/:131） | **1** — 同 A（引擎同一个） | **0.5** — 规格书 P0 无抽取器（段级原文起步）；本地抽取模型零实测、云端抽取要走脱敏+网关（feasibility §7.1） |

## 3. 推荐 C 的理由（四条，按权重排）

1. **与你已拍板的两件事零冲突**：「可内置第三方 + DevDesk 托管」与「做成 telemem 管理面板」在 C 里原样保留——面板照做，telemem 照装照管，只是检索多走一条自家通道，用户感知不到内部分工。
2. **把最硬、且已实测的需求钉死**：2 字中文/标识符检索是此前 P0 的硬出口条件，也是 telemem 路线唯一未验证的保留意见。C 用实测满分（Recall@5 1.00）的全文通道兜住这一格，同时让注入热路径不再依赖 telemem 的未实测延迟——A 路线的最大风险在 C 里结构性消失，而不是等 UAT 揭盅。
3. **卡片人审只有打在自家库上才完整**：B4 设计的状态机、撤销链、防覆盖版本校验三件套需要行级版本号与标记翻转语义，telemem 只提供事后改/删工具。A 的卡片是「降级版人审」，C 的卡片是你已审过的原设计。
4. **退路最宽**：telemem 上游若出问题（钉死旧版依赖、单人维护），C 降级为「全文通道独跑」不丢数据；若彻底换 D，自家库直接复用。C 是三条路里唯一「进可攻退可守」的。

**推荐附带条件（开工前必须钉死的一步）**：先花半天~1 天做 UAT 验证 spike，两件事：① telemem 抽取结果怎么取回（镜像接缝）——候选机制是盯它的操作历史库或接住写入接口返回值（**推测**可行，需实测钉死；做不出则 C 降级 A 或升 D，见拍板问题 C-3）；② 顺手把冻结评测集打一遍 telemem 检索——既验证 A 路线的保留意见，也给「是否需要全文通道」留下数字。若 ② 意外全绿且你更想省 3~5 人日，可退回组合 1（A 起步、留触发线）。

## 4. 拍板问题清单（共 14 问：A 5 / C 5 / D 4）

**选 A 需回答（5 问）**
- A-1 Python 运行时分发：安装包捆绑独立环境（包体 +150MB 左右），还是首次运行时在线安装（要求用户机联网且有 Python）？还是 DevDesk 内嵌一份精简解释器？
- A-2 脱敏闸：默认开死不可关，还是面板可关？本机抽取档（数据不出机）是否豁免脱敏？
- A-3 卡片人审的代理形态：接受/拒绝卡直接调 telemem 的改/删工具（无撤销链，可接受吗），还是在 DevDesk 侧另记一本账补撤销链（多一套要维护的状态）？
- A-4 本机抽取用的大模型从哪来：随包带 Ollama+约 5GB 模型、面板引导用户自装、还是注入 DevDesk 已有网关配置（后者走云端、脱敏闸变硬性）？
- A-5 检索短板的触发线：2 字中文/标识符 miss 率到多少你拍板升级 C？（建议沿用 §1 组合 1 的口径，预先写死避免临场扯皮）

**选 C 需回答（5 问；C-1/C-2/C-4/C-5 与 A-1/A-2/A-4/A-5 同题，此处列差异项）**
- C-1（同 A-1）Python 运行时分发方式。
- C-2（同 A-2）脱敏闸默认开死还是可关。
- C-3 镜像接缝：抽取结果回填自家全文库的机制（盯 telemem 历史库 / 接写入返回值 / 双写代理），由 UAT spike 实测定，你只需拍板「接受实测出的那种」并授权 spike 先行。
- C-4 所有权划分确认：提案/状态机/撤销链全部落自家 SQLite，telemem 的变更由卡片代理执行——确认这个「自家库是唯一真相」的划分（与规格书 §1.1 单一注册源红线同源）。
- C-5 telemem 故障降级线：引擎挂时全文通道独跑、只停新抽取——可接受吗？

**选 D 需回答（4 问；另有规格书 §7 既有三问：包体上限、bundled 还是首跑下载、分发形态）**
- D-1 抽取器空缺：首版先上「段级原文入库、无语义抽取」，LLM 抽取等后续——接受首版没有「自动提炼成一条条记忆」吗？
- D-2 时间预算：接受 8~12.5 人周（至 P3）vs A/C 的 1~2 周量级？若只做 P0（10~15 人日）则接受无抽取、无向量注入的最小可用版？
- D-3 无人值守：P0 手动启动可接受吗，还是自启托管（计划任务/注册表）必须进首版？
- D-4 规格书即施工依据：已过终审的规格书是否原样开工（含吸收 mem0-mcp 调研建议的两条日志静默修订）？
