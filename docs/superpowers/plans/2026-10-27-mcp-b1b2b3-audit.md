## 二、Findings（blocker 0 / major 2 / minor 3）

### F1 [major·正确性/安全面] web_fetch_markdown 的 SSRF 字面校验可被 URL 解析分歧绕过
- 证据：
  - `src/module_mcp/mcp_tools_builtin.cpp:163-171`（parseUrl 对非方括号 authority 取 rfind(':')，host 段含 `@` 时整体当作 host）；`:341-372`（ssrfRejectReason：host 含 `@` 使 parseIpv4 失败 → 放行）；`:343-345`（v6 解析失败一律返回空串 = 放行，如 `[fe80::1%25eth0]` 的 zone-id）。
  - `src/platform/http_client.cpp:62`（CURLOPT_URL 原样透传；libcurl 按 RFC 3986 取**最后一个** `@` 之后为 host → `http://a@127.0.0.1:8931/mcp` 工具侧判"非字面 IP"放行，curl 实连 127.0.0.1）。
  - `src/module_mcp/mcp_tools_builtin.cpp:234-254`（parseIpv4 只认规范点分十进制：`127.1`、`0177.0.0.1`（八进制）、`2130706433`（整数）、`0x7f000001` 均 parse 失败放行，而 getaddrinfo/inet_addr 语义接受这些拼写到同一地址）。每跳 Location 归一后复检机制本身真实（loop 重解析 :497-506），但复检用同一解析器，绕过同样适用于每一跳。
- 影响：工具的"拒绝本机/内网地址"防线对上述拼写形同虚设；被注入的 URL 可读本机服务（含本 MCP 服务自身端口）与内网 HTTP 服务并把响应回灌进模型上下文。重定向每跳校验是后续可复用的安全机制——其"真实可靠性"被高估，后续加网段的人会在错误地基上加码（维护代价高，故 major；不定 blocker：本机信任模型 §14.2-6 已接受无鉴权，且 DNS rebinding 同类风险已被 spec 接受）。
- 建议：取 host 后 fail-closed——authority 含 `@` / `%` 直接拒绝；v6 解析失败拒绝而非放行；IPv4 解析失败但 host 呈"疑似 IP 形态"（纯数字点段/0x 前缀/段数<4）拒绝；或改用 libcurl curl_url 提取 host 后复检，与实际连接目标同源。
- 关联 F6：`tests/test_modules/test_mcp_fetch_tool.cpp:213-232` 的 SSRF 表只覆盖规范拼写，修 F1 必须同步补 `http://a@127.0.0.1/`、`http://127.1/`、`[fe80::1%25eth0]` 用例（当前测试挡不住绕过）。

### F3 [minor·正确性口径] 非 2xx 错误文本"前 200 字符"实为前 200 字节
- 证据：`src/module_mcp/mcp_tools_builtin.cpp:423-428`（utf8SafePrefix 按字节截断到 maxBytes=200）、`:539-540`（调用点）。spec §6.1-5 写"响应体前 200 字符（UTF-8 边界安全）"。
- 影响：CJK 页面错误信息仅约 66 个汉字，诊断信息量口径漂移；注释自称"200 字符"与实现不符，误导后续维护者。
- 建议：按码点截（复用 truncateByChars 思路）或 spec/注释统一改口径为"200 字节"。

### F4 [minor·已知取舍登记] 服务端排他绑定后同端口快速重启存在 WSAEACCES 窗口
- 证据：`src/platform/http_server.cpp:195-210`（a028fb1e，注释已声明 TIME_WAIT 代价）；模块开关快速关→开、或 restart 失败重试时可能落在窗口内：start fail → 设置卡红字"启动失败：端口 X 被占用或无法监听"。
- 影响：已声明的取舍（换占用如实报错），失败可见、重试可恢复；仅文案未提示"刚关闭请稍候"。登记备忘，不强制改。
- 建议（可选）：McpService 失败文案或设置卡反馈对此场景补一句提示。

### F5 [minor·容错备忘] 裸 `<title>`（无 `<head>` 包裹）不参与标题兜底
- 证据：`src/module_mcp/html_to_markdown.cpp:402-404`（仅 Head 模式收 title）、`:528-534`（Head 模式退出）；HTML 片段/不规范页面无 `<head>` 时 title 被透明处理进正文，`# title` 兜底失效。
- 影响：部分页面缺标题兜底，其余转换不受影响；spec §7"head（仅保留 title）"未禁止该容错。骨架可接受，登记备忘。
