## 2. 五问作答

### 2.1 infer=true 触发语义（spec 口径优先）

spec 能确定的：控耗 1「水位之后的内容才调云端」＋控耗 2「提炼**批处理**…桶数」＋风险注记「**后台常驻**提炼」（integration-spec:36/37/42）→ spec 意图 = **自动后台批处理**，消费对象是新采集内容，不是卡片接受流（卡片链 = 人审原文直存，overview:63 定案不变；需-3 spec:58 addDirect 零侵入）。需-3 spec:158 明确把「infer 节流/预算软硬档接线」划给需-4（已并池 3）＝本卡。

本卡推荐触发：**挂 `collectLoopMain`（panel_state.cpp:183）采集轮后置 `runInferRound`**——同线程、同生命周期（引擎 Running 才跑）、继承 30s 节拍，不新建线程不新建循环。

**OQ-1（开放问题 → 已裁决留痕）**：infer 批处理与卡片链的关系——全部过闸段「双通道并存」（原文卡 + 云端提炼结论，同段内容可能双份入库）还是部分覆盖？「每小时云端调用/桶数上限」取调用数还是桶数量纲？spec 未写。
**裁决（2026-10-31，主会话授权保守自决）**：覆盖范围取 spec 控耗 1 字面口径（水位之后的内容 = 全部过闸新采集段，双通道并存）；量纲取**云端调用次数**（llm_attempt 行计数）；「宁少提炼」由保守默认上限 4 次/小时承载（节流闸常态生效，实际消耗远低于轮次供给）。

### 2.2 硬档暂停闸落点

- **闸 = `runInferRound` 内逐次判定，先于任何云端出机**：`UsageLedger::monthTokens`（与 panel_state.cpp:291 同库同源，账面口径不出现第二份）＋ `settings.usageHardBudgetTokens` → 构造 `TokenUsageMeter` 调 `phase()`（**复用 F-05 判定函数，不写第二份阈值逻辑**）→ `Hard` = 暂停：不调云端、队列不推进、不报错。面板既有文案（memory_module.cpp:843）此时由空承诺变为事实。
- **直存路径零改动**：`executeProposal → addDirect`（curator.cpp:65）与 `search`（telemem_client.cpp:314）均不设闸 = spec:38「检索不受影响」＋任务口径「直存 infer=false 不受影响」。
- **「新采集入队暂存」的落点 = infer 队列本身**：新采集段过脱敏闸后入队（enqueue 在 `collector.commit` **之前**，崩溃重放靠 (session_id, start_seq) 唯一键 INSERT OR IGNORE 去重）；硬档 = 队列滞留，解除（跨月滚动 monthStart / 用户上调阈值）后自动续跑 = spec:38/127「入队暂存、恢复后自动补跑」。队列存在即「未提炼水位」＝控耗 1 去重口径（collector 事件幂等防重复摄取 → 云端调用 0）。

### 2.3 节流上限（计数器放哪、超限语义）

- **计数器 = usage_ledger.db 新 kind `llm_attempt` 行**：每次云端尝试（无论成败）记 1 行，tokens 恒 0；`hourAttempts = COUNT(ts ≥ hourStart)`（本地自然小时，同 dayStart/monthStart 惯例）。放账本的理由：重启不丢、零新存储、token/金额聚合天然不受影响（tokens=0；`estimateCostMilliYuan` 未知 kind 单价 0，usage_ledger.cpp:68）。
- **超限 = 排队顺延，不丢弃**（spec:37 判据原文「排队顺延到下一窗口，不报错、不丢采集数据」）：队列不动、本轮结束，下一小时窗口自动续。
- **失败也计数（attempts 口径）**：429/502 的自动重试天然受同一小时预算约束，防重试风暴，不需要额外退避策略。
- 上限可配置：panel_settings 新键 `inferHourlyLimit`（≤0 = 关闭节流；**OQ-2 裁决留痕：默认 4 次/小时**——月硬档 3M token ≈ 全月约 375 次提炼的量级约束下的保守值，settings 可调）。

## 4. 取舍（放弃 · 推迟及理由）

- **放弃**独立限速器/令牌桶组件、独立提炼水位表：账本行计数即计数器、队列即水位（代码负资产，最小 90%）。
- **放弃**429 专用指数退避：attempts 计数 + 30s 轮次已把重试压进小时上限，spec 未要求。
- **推迟**：面板队列深度展示、inferHourlyLimit 滑条 UI（键落盘已满足判据）。
- **llm_output 记账口径**（OQ-3 → 已裁决留痕）：add 响应无 usage/id 回传（live 定案 {"status":"stored"}），输出 token 拿不到真实值——**裁决：按输入等额估算**（输出单价 2.8 > 输入 0.8，宁高勿低，估算口径与账本既有语义一致）。
- **实现期偏离留痕（2026-10-31 实现段）**：`runInferRound` 改为 `runInferStep` 单步形态（每步至多 1 条）——宿主 30s 节拍下小时上限自然达满（吞吐无损），且引擎停止时 join 最坏只等一次在途调用（30s），不放大 UI 阻塞；失败停轮/节流顺延语义单步天然成立。成功路径不刷 note（动态流由 llm_input/output 账面行承载），llm_attempt 行在流中隐藏（与 inject_chars 成对隐藏先例同款）。
