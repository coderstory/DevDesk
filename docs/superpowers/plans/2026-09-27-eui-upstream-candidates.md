## 1. 判据与归类口径

入选必须**同时**满足：① 任意 App 通用——不是 DevDesk 的产品设计（配色/页面结构/交互取舍），而是"谁用 EUI-NEO 都会撞"的框架能力问题；② DevDesk 侧有**被迫绕行的证据**（自造 workaround、探针反推、重复实现、HANDOFF/KNOWN_LIMITATIONS 条目、能力表 ❌ 项）。三条归属线不混：**上游** = 满足①②的框架能力；**`ui_kit`** = 多个 `module_*` 各抄一份的 DevDesk 组合（设计 token + 组件装配，重构 spec §4.1 已裁决）；**业务** = 模块自己的数据/交互语义。宁缺毋滥：证据不足的进 §3 而非 §2。

## 3. 明确不建议上游（属业务 / 设计 token / `ui_kit`，或证据不足）

1. **设计 token 与尺寸字面量**（28px 内边距、460px 标准弹窗宽、64px 表头高、chip 配色）→ `ui_kit`：这是 DevDesk 方案 B 的组合，重构 spec §4.1 已裁决，不是框架概念。
2. **chip 宽度估算 3 套启发式**（`markdown_module.cpp` 的 `estimateTextWidth`、`todo_module.cpp` 的 `chipWidth`、claude 无估算器）→ `ui_kit`，**且不是上游缺口**：上游 `core/render/text.h` 已公开 `TextPrimitive::measureTextWidth`，`measureTextMetrics` 与渲染共用 `resolveFontPath`（同源），粗估可直接换掉。
3. **Toast 状态机 ×4 / dialog 表单脚手架 ×13**（重构 spec §3.3 的 D1/D2）→ `ui_kit`；只有"队列"这一项归上游（U10）。
4. **拖放落点算法**（`dragDropTarget`、`hitDropColumn`）→ 业务：上游已给元素级 `onDrag`/`onRelease`，跨列语义是 DevDesk 自己的。
5. **页面原点 `Router::pageOriginX`** → App 布局的产物（侧边栏 + 页面区），不是框架概念；框架侧要保证的是 U1 的"指针空间统一"，两者别混。
6. **Markdown 键盘流**（Tab 缩进/表格跳格、列表续行、Ctrl+B/I/K）→ 业务：Tab 在编辑器里是缩进语义，不是框架焦点循环。
7. **macOS 27 Liquid Glass / vibrancy** → 平台栈未定 + XL 工作量，PR plan 已裁决不选（Windows 侧磨砂已由上游 windowEffect 解决）。
8. **无 `onResize`/`onMove` 窗口回调** → 证据不足：DevDesk 全仓无因此产生的 workaround，`compose(ui, screen)` 的 `screen` 参数已够用（grep `onResize` 零命中）。
9. **Tab 焦点循环未实现** → 证据不足：DevDesk 未做表单 Tab 导航，无被迫绕行（spike 用例里 Tab 是文本缩进）。
10. **主窗最小化时子窗泵暂停**（`glfw_app_main.cpp` iconified 分支）→ 上游行为，但属**已知取舍 + 暂态**（用户还原即恢复），DevDesk 未绕行；登记在 `KNOWN_LIMITATIONS.md` Windows #4，暂不提。

## 4. 执行顺序建议

1. **先做 U8**（构建/打包三件）：零风险、互不依赖，立刻消掉 DevDesk 的摘 `-Os` workaround 与手写 JSON 序列化——顺带把"能提上游"的信用建立起来。
2. **U1 的第一版（纯增量）**：只加 `app::contentScale()` + `Screen.scale` + 指针事件 `scale/space` 字段，**不动现有回调语义**；DevDesk 改吃新 API、探针降级为断言。破坏性统一留第二版（依赖第 1 版先被上游接受）。
3. **U2 的 ① 单独先提**（容量 8 → ≥64，一行常量、极低风险）：立刻给在飞的 Markdown Phase 3 增量收益；②③④ 等 Phase 3 落地后按实测缺口再提（② 是 L，需先开 issue）。
4. **U3 + U5 合成一批**（都是 input/dialog 交互契约，同一次评审能少走一轮）：U3 ①② 与 U5 的 `onEscape` 增量、可立即落地；U3 的 DevDesk 侧 4 处 `requestFocus` 修法**不依赖上游**，可先按 HANDOFF C1 独立修。
5. **U4 与 U7 各自独立排期**：U4 优先（数据安全，有真实丢失风险的补偿代码）；U7 必须先开 issue 定 API 形状（PR plan 已如此要求）。U6/U9/U10/U12 随所在主题顺手带上；U11/U13 备档不提。
