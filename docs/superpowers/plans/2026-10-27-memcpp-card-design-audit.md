## 4. 静默失败面

### F2（中）撤销链路缺两条语义
- file: docs/superpowers/plans/2026-10-27-memcpp-proposal-card-design.md:88,110,133
- 问题：(a) 同一原提案可生成多张不同 id 的 pending undo 提案——id 幂等键（59 行）挡不住，baseVersion 只在落库时兜底，卡片层会出现重复撤销卡；(b) 原提案撤销后停留 accepted、无「已撤销」可视状态，已接受卡常驻撤销入口，用户可反复撤销。
- 影响：并发/重复操作下卡片语义各自发挥，C4/C7 实现无统一口径，审计链难对账。
- 建议：规定「同一 undoOf 仅允许一张未决 undo 提案，重复生成则复用」；已接受卡在存在未决/已生效 undo 时显示撤销态。

### F3（低）id 撞号静默丢弃
- file: docs/superpowers/plans/2026-10-27-memcpp-proposal-card-design.md:59
- 问题：「同号只算一条」未定义「同 id 不同内容」分支：不同提案撞号时第二条静默消失、无留痕。
- 影响：整理器 id 生成有缺陷时，丢提案无任何信号。
- 建议：落库时校验同 id 内容一致，不一致报错而非静默去重。

### F4（低）批量部分失败无界面回显规格
- file: docs/superpowers/plans/2026-10-27-memcpp-proposal-card-design.md:97,139-142
- 问题：逐条独立成败只有逻辑语义；§2.3 只写了确认弹窗，未写批量后逐条成败如何回显。
- 影响：部分失败时用户无从知道哪几条未落库。
- 建议：C2/C7 任务卡补「批量结果逐条回显」一条。
