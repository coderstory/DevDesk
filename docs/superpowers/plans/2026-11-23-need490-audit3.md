## 新 findings

[P1][约束] 技术卡 §4 行135-139（另见行22/435） — 4 项硬上限中「并发会话 64」「票据表 64」无 PRD 授权；409 不在 §3.1 行104 的 HTTP 码集合，且新增「登录设备数已达上限」文案未裁决 — 为什么：PRD P-15 只裁 SSE 64 + 握手 32/min，额外设备数上限等于静默加产品限制，触碰「不做设备清单/不自动踢设备」禁区 — 建议：回 PRD 裁决并补 409/文案，或删两上限只留 64/32 — If we skip it：实现出 PRD 未授权的设备数上限，验收无依据、与 P-15 冲突。
[P1][约束] UI 设计 行319/430 — 设置页仍写「停留期间不自动刷新；离开再进即刷新」，违 PRD P-24 与技术卡 §3.2/§9.6「广播即刷新并覆盖草稿」 — 为什么：前端按 UI 稿实现会把已裁决的并发覆盖语义做反 — 建议：改为「收到广播刷新控件、未提交草稿被覆盖」 — If we skip it：P1-2 在实现侧复发，S-15 必红。
[P1][约束] ADR 0009 行10/20/27 — 仍写「扫码即完成设备绑定」「绑定令牌一次性」「明文可嗅探会话 cookie」；PRD v5 P-22 为有效期内可重复 claim，ADR 0010 已取代传输条款 — 为什么：ADR 优先级高于 PRD，实现者按 ADR 会做单次 claim、明文 cookie 假设 — 建议：ADR 0009 加 2026-11-23 取代注记（两步绑定、可重复声明、无 Cookie） — If we skip it：幂等 claim 与无明文凭据的验收依据不稳。
[P1][工程] 技术卡 行1/3/4/398/474 — 仍标「PRD v4」「S-01～S-30」；PRD v5 已加 S-31 并在 §543 写明 S-24～S-31 转技术卡 — 为什么：测试矩阵漏 S-31（在线数上限） — 建议：全改 PRD v5 / S-01～S-31 — If we skip it：在线数上限验收漏项。
[P2][工程] UI 行317/429 — 目录错误仅「目录不存在」，缺「非目录/不可进入」（PRD E-18/S-30） — 建议：三态文案或统一「目录不可用」 — If we skip it：无权限目录报错误导。
[P2][工程] 技术卡 行244 — 票据表 64 条「约 2KB」实算约 5KB（每条 ~80B JSON） — 建议：改 ~5KB — If we skip it：预算数字失真。
[P2][工程] 技术卡 行138/139 — 「票据表非连接」与「连接类统一 64（含票据表）」自相矛盾 — 建议：分列「连接类 / 凭证类」 — If we skip it：计数口径歧义。
