## 1. F-ID → 技术方案（逐条对齐拍板卡 §7）

### F-01 陈旧检测 / 重组判据（核心）

- **实现**：`build-test-run.sh` 构建成功段（L396 之后、发布形态守卫 L398 之前）插「bundle 维护」段：`DEVDESK_OS=darwin` 且非 `--install` 且 **`-d $BUILD_DIR_ABS/DevDesk.app`**（存在性门 = 「存在才维护」判据）→ 调 `platform/macos/build-app.sh`，传 `DEVDESK_BUILD_DIR="$BUILD_DIR_ABS"`、`DEVDESK_SKIP_LSREGISTER=1`，**默认签名（照签，见 D1）**。bundle 的「新鲜」由结构保证：build-app.sh 在同一次运行内从刚编出的裸二进制 cp 组装，不存在陈旧来源。
- **判据修正（D1，拍板卡 F-01 字面判据不可达）**：拍板卡 F-01 写「bundle 内二进制 sha256 == 裸二进制」，但拍板卡 §8.2 同时推荐照签——签名改写 Mach-O，两条不可兼得（POC4/POC6/POC7 实证）。修正经**方案独立审计确认成立**（2026-10-31,审计复核 POC6/7+仓内三处佐证,并补强: S1 只活在测试层——hook 运行时无条件重组不做任何比对,判据修正零运行时风险）：**照签 + 判据改为 S1 确定性基线比对**（POC5 实证签名确定性）。等价性说明：S1 = 「当前裸二进制经 build-app.sh 确定性重组」的输出指纹；篡改/陈旧 bundle 的 sha 必 ≠ S1，判据无假绿空间。
- **验证（先红后绿）**：
  - 先红（现状已给出真实红）：POC1 活体陈旧 bundle 与裸二进制 sha 不一致且存续 15+ 小时——改动前，「陈旧 bundle 跑构建后纹丝不动」就是默认行为；
  - 后绿：跑构建得新鲜 bundle → 记 S1 → 篡改 bundle 内二进制（`printf '\0' >> …/Contents/MacOS/DevDesk`）→ sha ≠ S1（红态制造成功）→ 再跑构建（增量、秒级）→ bundle 内 sha == S1 且 `codesign --verify --strict` 通过（build-app.sh 内部已断言）→ 判据绿。

### F-02 无 bundle 空态（核心）

- **实现**：存在性门不命中（`[ -d ]` 假）→ 整段静默跳过，零命令、零输出、不创建 bundle（D4）。
- **验证（回归型，改动前现状即满足，无先红）**：`mv build/DevDesk.app /tmp/…` 移走 → 跑 `bash scripts/build-test-run.sh --no-test --no-run` → 断言：① `build/DevDesk.app` 仍不存在（不产生）；② 输出无「bundle 维护」行；③ 耗时仅参考观测（同 T2 降参考口径，不设断言）。移回。

### F-03 新鲜 bundle 幂等（核心）

- **实现**：build-app.sh 是 `rm -rf` 全量重建、无「已新鲜跳过」分支、无内部状态（build-app.sh L38 注释自述「.app 内不会残留上次的文件」）→ 幂等结构性成立。
- **验证**：POC5 已在 build-app.sh 层实证（同输入两次连跑 sha 全等）。经 hook 再验一次：新鲜 bundle 状态下连跑两次构建，两次的 bundle 内 sha 相同、无假红、每次增时 ≈0.4s（≤10s 预算，拍板卡 §8.3）。

### F-04 副作用隔离（核心）

- **实现**：hook 固定传 `DEVDESK_SKIP_LSREGISTER=1`（lsregister 会写用户 LaunchServices 库且注册的是构建目录临时路径，build-app.sh L160-163 自己就是这么主张的）；写操作范围 = `$BUILD_DIR_ABS/DevDesk.app` 单目录；不写 /Applications、不写源树。
- **验证**：① ⏭ 行不在常规构建输出里（hook 成功路径把 build-app.sh 输出吞进 BUNDLE_OUT，仅失败时 tail -30）——验证 = 手动复跑同款命令（`DEVDESK_BUILD_DIR=<构建目录> DEVDESK_SKIP_LSREGISTER=1 bash platform/macos/build-app.sh`）可见「⏭️ 跳过 LaunchServices 注册（DEVDESK_SKIP_LSREGISTER=1）」行；② 跑构建前后 `/Applications/DevDesk.app` mtime 不变；③ `git status` 干净（源树零写入）。

|---|---|---|
| D1 | **照签**（hook 不传 `DEVDESK_SKIP_SIGN`）+ F-01 判据改为 S1 确定性基线 | 遵拍板 §8.2 推荐（bundle 级身份供 Gatekeeper / 通知等能力用，且与 --install / package 产出形态同构）；POC4 实证签名成本含在 0.423s 内。放弃 SKIP_SIGN=1 形态——它能让字面 sha 相等判据成立，但产出无 bundle 签名的异构形态，且被拍板材料推荐否决。拍板卡 F-01 字面判据与 §8.2 的内部张力由本卡 POC 裁决收口 |

## 3. 改动清单（精确到文件与插入点）

### 3.1 `scripts/build-test-run.sh`（唯一行为改动）

**插入点：L396（构建成功 if/else 块收尾 `fi`）之后、L398（`# 发布形态守卫。`注释块）之前**，插以下一段（含注释约 26 行）：

```bash
# bundle 维护（债-19，A'「存在才维护」）：build/DevDesk.app 存在 = 有人用过它
# （打包 / --install 留下的快照），维护义务随之成立——重组装，使 bundle 与本次构建的
# 裸二进制一致，杜绝「裸二进制新、bundle 壳旧」的双产物假象。bundle 从未打过的纯开发树
# 不进这段，零开销零输出。--install 流程在下方 3c 段自带重组（含防陈旧断言链），这里
# 跳过避免同一次运行重组两遍。bundle 是 macOS 形态，其余平台整段不进。
BUNDLE_APP="$BUILD_DIR_ABS/DevDesk.app"
if [ "$DEVDESK_OS" = "darwin" ]; then
  if [ "$INSTALL" = "1" ]; then
    if [ -d "$BUNDLE_APP" ]; then
      echo "⏭ bundle 维护跳过（--install 流程稍后自行重组，避免同一次运行重组两遍）"
    fi
  elif [ -d "$BUNDLE_APP" ]; then
    echo "── bundle 维护（检测到既有 DevDesk.app，重组装）──"
    BUNDLE_OUT=$(DEVDESK_BUILD_DIR="$BUILD_DIR_ABS" DEVDESK_SKIP_LSREGISTER=1 \
      bash platform/macos/build-app.sh 2>&1) || {
      echo "$BUNDLE_OUT" | tail -30
      BARE_SHA="$(shasum -a 256 "$BUILD_DIR_ABS/DevDesk" 2>/dev/null | awk '{print $1}' || true)"
      BUNDLE_SHA="$(shasum -a 256 "$BUNDLE_APP/Contents/MacOS/DevDesk" 2>/dev/null | awk '{print $1}' || true)"
      echo "❌ bundle 重组失败——$BUNDLE_APP 可能停在半组装态，验收勿拿它当最新产物" >&2
      echo "   诊断：裸二进制 sha=${BARE_SHA:-<读不到>} / bundle 内二进制 sha=${BUNDLE_SHA:-<不存在>}" >&2
      echo "   → 处置：查磁盘空间与权限；rm -rf $BUNDLE_APP 后重跑构建（bundle 缺席 = 纯开发树安全态，需要时 --install 重建）" >&2
      exit 1
    }
    echo "✅ bundle 已与本次构建同步（$BUNDLE_APP）"
  fi
fi
```

实现注意（set -e / pipefail 三个坑，照脚本既有规避惯例）：
- `BUNDLE_OUT=$(…) || { … }` 形态豁免 set -e，失败摘要与 ❌ 得以在 exit 前打印（同 L391-395 构建失败块同款）；
- `if [ -d … ]; then echo ⏭; fi` 必须用完整 if——`[ -d … ] && echo …` 在条件假时整句返回非零，set -e 会杀脚本；
- 失败诊断里的 shasum 在文件可能不存在时跑，管道尾必须 `|| true`（pipefail 下 shasum 失败会污染命令替换退出码，赋值语句失败即触发 set -e）。不能复用 3c 段的 `file_sha256`——那是在 L799 才定义的，此处不可见。

**头注释同步（F-07）**：L41-53 安装段背景注释中「而它只被 scripts/package-macos.sh 调用 —— 常规构建路径根本不碰 bundle」处补一句：「2026-10-31 起（债-19）常规构建对**已存在**的 bundle 自动重组（构建成功段 bundle 维护段），本段断言继续保护安装路径。」

## 4. 失败路径（硬失败语义，按拍板决策）

- **退出码语义**：build-app.sh 非零退出 → hook `exit 1` → build-test-run.sh 以非零退出。该次运行的测试 / 守卫链 / --install / 启动段不再执行（bundle 齐备性是构建命令的交付承诺，齐备不了就该红，不静默绿）。
- **错误输出形态**（对齐守卫链中文诊断风格）：build-app.sh 自身错误（cp / mkdir / plutil / 签名脚本 ❌ 行）经捕获后 `tail -30` 打出（它内部 set -e，首个失败即停，错误在尾部）→ hook 补两行诊断（裸 / bundle 两侧 sha 或「不存在」，即拍板卡 §6.4 说的「B 作为 A' 内部组件保留在失败诊断」）→ 一行处置指引 → `❌` 行走 stderr（同 L339/L497 惯例）→ exit 1。
- **恢复语义**（两种态，都安全）：
  - 失败发生在 rm -rf 之后 → bundle 目录缺席或半成品。半成品（目录存在）→ 下次构建 hook 自动重组**自愈**；全缺席 → 停留在纯开发树安全态（F-02 形态），需要 bundle 时 `--install` 或 `package-macos.sh` 现组；
  - 逃逸阀：手动 `rm -rf build/DevDesk.app` 即回到零开销纯开发树——这也是**回滚**手段。
- **build-app.sh 内部软失败不动**：图标生成失败 / 版本号读取失败仍是其自身的 ⚠️ 降级（外观项，不拦部署，三调用方同语义），hook 不加码——A' 的硬失败边界 = build-app.sh 的退出码，不另立判据。
