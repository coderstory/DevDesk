# S0 · 真实 EUI API 映射表（架构意图 → 可实现路径）

> 落地方案示例中的 API 名（`Theme::Create` / `SetWidgetStyle` / `Button.Filled` 等）为示意形态——本表映射到 EUI-NEO 真实主题系统。EUI 缺的能力标注「Fork 扩展」，一并进 W1 批实现。

| # | 示例 API（方案示意） | 真实 EUI API | Fork 扩展 | 说明 |
|---|---------------------|-------------|-----------|------|
| 1 | `Theme::Create("devdesk")` | `components::theme::ThemeColorTokens{}` 结构体 + `components::theme::ThemeMetricTokens` | 否 | EUI 无工厂类，主题是 POD 值类型；`theme.h:88-98` 定义字段 |
| 2 | `theme->SetColors(...)` | 直接字段赋值 `tokens.primary = color(0x36/255,...)` | 否 | `theme.h:88` ThemeColorTokens 全部公开字段 |
| 3 | `theme->SetRadius(...)` | `tokens.metrics.radius.small = 6.0f` | 否 | `theme.h:50-63` RadiusTokens 字段直接设值 |
| 4 | `theme->SetShadows(...)` | `components::theme::shadow(tokens, blur, offsetY, darkAlpha, lightAlpha)` | 否 | `theme.h:248-259` 四种 shadow 工厂函数 |
| 5 | `theme->SetTypography(...)` | `tokens.metrics.typography.body = 14.0f` 等 | 否 | `theme.h:9-32` TypographyTokens 字段直接设值 |

# S4 · 弹性规则

## S4.1 布局锚点：1000×640 为最小档

所有布局值 = 最小档锚点（1000×640 窗口下的实测像素） + 伸缩公式。往上不做上限（`-Wall -Wextra -Werror` 已经保证无 overflow），往下最小 1000×640。

## S4.2 页面全局框架

```
|← 左侧导航栏 208px(固定，H20 §4/实现口径回写 2026-10-25) →|← 主内容区 flex(剩余宽度) →|
```

- 主内容区内边距：左 32px, 右 32px, 上 32px
- 最小档下主内容区宽 = 1000 - 200 - 64 = 736px

## S4.3 弹窗高度上限公式

> 审计 B#15：原公式用「窗口高 640」而非「客户区高」——640 是窗口最小尺寸（含非客户区外框），直接减 48 会在较小的工作区溢出（macOS 592 > 实际可用 564）。

```
弹窗最大高度 = min(窗口客户区实际高度 - 48, 内容自然高度)
```

- **客户区高度** = 窗口逻辑高 - 非客户区外框高（平台值取 `window_layout_*.cpp`）：
  - macOS 外框 = `{0, 28}`pt → 最小档客户区高 = 640 - 28 = **612pt** → 弹窗上限 = 612 - 48 = **564pt**
  - Windows 外框 = `{14.4, 37.6}@96dpi` → 最小档客户区高 = 640 - 37.6 = **602.4 逻辑 px** → 弹窗上限 = 602.4 - 48 ≈ **554px**
- 往上：弹窗随窗口客户区增长，最大到 `(客户区高 - 48)` 但不超内容自然高
- wizard 弹窗：内容超限时内部滚动——`ScrollView` 包内容区

# S5 · macOS 口径

## S5.1 逻辑单位声明

- macOS 一切布局值 = **点（point）**，不是物理像素
- `core::window::windowScaleForPoint` 在 macOS 恒返 1.0——Retina 的 2.0 是 contentScale，不是窗口单位换算
- **不要对设计规格值乘任何缩放系数**——24px 就是 24pt
