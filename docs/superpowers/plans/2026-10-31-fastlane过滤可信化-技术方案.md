## 根因（已核实，非转述）

1. **脚本层**：`scripts/build-test-run.sh:166` 把 `--filter` 值存入 `FILTER`，`:521` `TEST_OUT=$("$TEST_BIN" $FILTER 2>&1)` 以位置参数透传给 devdesk_tests。脚本对 filter 内容零感知。
2. **runner 层（关键）**：devdesk_tests **不用 doctest 原生 main 与选择器**。`tests/test_main.cpp:217` 自研 runner，`:237` `t.first.find(filter)` 对注册名（= REGISTER_TEST 第二参 description）做单子串匹配。任务简报中「doctest 支持 --tc/--ts/-sf」线索**不成立**——doctest 的选择器机器在这条路径上不存在；REGISTER_TEST 是 DevDesk 自研宏（`tests/doctest.h:220`，vendored doctest.h 本就带 DevDesk 专属改动，registry 定义在 `:80`）。
3. **命名分布实测**（/tmp/qa-matrix/all-cases.txt，2056 例）：markdown 家族按**源文件**圈定 = 257 例 / 15 文件（test_markdown* ×3 + test_md_* ×12），名字含 "markdown" 的仅 151，**106 例漏跑**（md_block_model_* / md_live_* / md_scanner_* / md_kbd_* 等；最恶劣 test_md_folder_tree.cpp 4 例名字连 "md" 都不含：folder_note_count_recursive 等）。与报告实测 114 命中同数量级（口径差异：114 为当时计数）。

## A 方案设计

### 1. tests/doctest.h（registry 携带源文件）

- `:80` registry 载体 `std::vector<std::pair<std::string, TestFunc>>` → `std::vector<TestEntry>`，`TestEntry{ std::string name; const char* file; TestFunc func; }`（file 存 `__FILE__` 字面量指针，零拷贝）。
- `:85` `register_test(name, f)` → `register_test(name, file, f)`。
- `:220` REGISTER_TEST 宏内调用改为 `register_test(description, __FILE__, unique_name)`。唯一改动点，所有 REGISTER_TEST 调用点签名不变。

### 2. tests/test_main.cpp（main() 过滤段重写）

- 位置参数收集：每个非 `--log` 非空 arg 都是一个 term（旧「last arg wins」行为废弃——该行为未文档化、无调用方依赖，见兼容性一节）；term 内按逗号拆分。
- 每个 term 剥 `--filter=` 前缀（F-2；`evidence/2026-10-31-debt20-audit/process_runner-filter-run.txt` 显示该形态已实际踩坑：被当过滤词 → 0 命中 → 退出码 2）。
- 匹配语义：
  - term 以 `file:` 开头 → 去前缀，对注册时记录的 `__FILE__` 做**归一化后全路径子串匹配**：`fs::path(file).lexically_normal().generic_string()`（统一正斜杠；`doctest.h:181` 已证实 ninja 可能传相对形态 `..\tests\...`，词法归一后含 `test_core/` 的形态两平台一致）。
  - 其余 term → 描述串 **或** unique_name 子串匹配（id 纳入为实现段新增，见偏离 1）。
  - 任一 term 命中即运行该用例（OR）。
- F-3 命中数可见：filter 非空时 Summary 邻行打 `Filter: <terms> → N 例`；total==0 的 `[ERROR]`（`:329`）附各 term 命中数（如 `各词命中: file:test_md_=0, markdown=0`）。退出码语义不变（0 全绿 / 1 有失败 / 2 零命中）。

### 3. scripts/build-test-run.sh（仅注释，逻辑零改动）

- `:14` `--filter` 用法注释更新：补 `file:<源文件子串>` 语法、逗号 OR、示例（`--filter file:test_md_,file:test_markdown`）；注明 0 命中仍退出码 2。
- `:529` 0 命中错误文案补一句「可按源文件过滤：--filter file:<文件名子串>」。
- FILTER 透传机制天然兼容，无逻辑改动。

### 4. 涉及文件

| 文件 | 改动 |
|---|---|
| `tests/doctest.h` | TestEntry 结构 + register_test 签名 + 宏传 `__FILE__` |
| `tests/test_main.cpp` | main() 过滤段：term 收集 / 逗号拆分 / file: 匹配 / 命中数输出 |
| `scripts/build-test-run.sh` | 仅 :14 与 :529 文案 |

测试侧（tests/）其余 198 文件零改动；src/ 零改动；两平台均走同一份 runner 代码，平台差异仅在 `__FILE__` 形态（设计已归一化覆盖，见反例验证的 Windows 专项）。

## 失败路径 / 兼容性

- **裸词过滤**：匹配域扩为「描述串 ∨ unique_name」——命中集合是旧语义的严格超集（实测 markdown 114→117），既有调用（脚本透传、zcode-dispatch SKILL.md 的 `--filter gate`、测试文件里「描述含 ASCII wallpaper」类注释约定）全部照旧且更可信。
- **「last arg wins」→ 多词 OR**：唯一语义变化点。grep 全仓确认无依赖旧行为的调用方：脚本只透传单个 FILTER 值；CI（.github）无 --filter 引用；scripts/ 内其它 filter 字样（check-eui-neo-version.sh 的 `filter_platform`、clang-tidy `--header-filter`）与 doctest filter 无涉。
- **`--filter=X` 形态**：经脚本 `:166` 落入裸词分支原样透传，F-2 在 runner 兜住（修前 0 命中退出码 2，修后正常）。
- **probe 段** `:551`「--filter 非空跳过」判定不变。
- **守卫链**：5 道守卫 + 自检全部与 doctest filter 无涉，平台守卫自检链不受影响。
- **Windows**：MSYS2/Ninja 下 `__FILE__` 可能是正斜杠绝对路径或相对路径，词法归一化覆盖两形态；实现时以反例验证组的 Windows 复跑收口。

## 偏离记录（实现段相对方案卡）

1. **F-1b 新增（必要延伸）**：裸词匹配域从「描述串」扩为「描述串 ∨ unique_name」。实现中发现更深一层洞：全仓 2049 条 REGISTER_TEST 仅 2 条描述串含自身 unique_name（python 全仓统计），测试文件注释承诺的「用例名前缀 agent_task_tpl_（--filter agent_task_tpl 可定向跑）」实测 0 命中——不扩则「过滤可信化」只做了一半。改动：TestEntry 加 id 字段 + 宏字符串化 `#unique_name` + 匹配函数多一子串，仍在原 2 文件内。
2. **反例 4 期望修正**：md_scanner_scan_fences 的描述串是 "md_line_scanner: …"（不含 md_scanner），按卡内原期望「命中 ≥1」建立在快照把 unique_name 当匹配域的误解上；id 纳入后命中 9，语义正确。
3. **快照口径差异**：/tmp/qa-matrix/all-cases.txt 2056 行与实测 2049 有 7 例出入（快照过期）；所有期望值以「当前源码 grep 独立计数 ∨ 二进制 Filter 行逐词命中数」互证为准，不依赖快照。
4. **doctest.h 宏行漏改一次**（编译期即红：register_test 期望 3 参实给 2 参），补改后构建绿——静态门禁兜住，无隐性问题。
5. **Windows 真机复跑未做**（本机 mac）：按卡内计划以「本机 POC（7 种路径形态全过）+ check-windows-cross-compile.sh（393 文件全过）」覆盖 Windows `__FILE__` 形态风险；真机复跑反例 1/3/4 留待 Windows 机，如实标未验证。
