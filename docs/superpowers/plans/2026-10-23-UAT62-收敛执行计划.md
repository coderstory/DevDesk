# UAT6.2 收敛执行计划（2026-10-23）

> 目的：消除「每个功能点重复分析 + 重复构建/测试/审计」的放大效应。任务多不等于节点多。

## 一、统一节点（每个波次只做一次）

| 节点 | 频率 | 执行者 | 说明 |
|---|---|---|---|
| 任务卡下发 | 每任务 | 主会话 | 固定文件白名单 + 精确公式 + 验收阈值；不给开放式"自行分析" |
| 代码编辑 | 每任务 | 子任务 | **不编译、不跑测试、不 commit** |
| diff 核对 | 每任务 | 主会话 | 只核对白名单与关键公式，不做二次全量分析 |
| 构建 | **每波次 1 次** | 主会话 | 所有编辑批落盘后串行构建（构建槽 1） |
| 定向测试 | **每波次 1 次** | 主会话 | 只跑受影响模块 ASCII 子串；全量仅里程碑 |
| 双独立审计 | **每波次 1 次** | 2 个只读 agent | 审合并后的总 diff，不按任务重复 |
| 红件修复 | **每波次 1 次** | 1 个 fixer 批 | findings 去重合并，统一修 |
| 全量测试 | **仅里程碑 1 次** | 主会话 | W5/出包前 |
| 出包 + 用户 UAT | **仅里程碑** | 主会话 | 0.5.0 → D:/Data/desktop |

## 二、任务卡模板（减少重复分析）

每张卡只含 6 项，子任务不再自行读全量文档：
1. 目标（一句话）
2. 文件白名单（精确路径）
3. 共享接口契约（新增字段/删除字段）
4. 精确公式/阈值（已算好，直接落码）
5. 验收断言（测试名 + 期望值）
6. 禁区（其它文件、构建、commit）

背景文档只给**章节行号**，不给整篇让子任务重读。

## 三·五、并行写策略（2026-10-23 用户定）

- **按文件重叠度分组**：
  - 文件完全不重叠 → 共用集成工作树 `D:\wt-uat62`，零合并成本。
  - 同一文件、不同代码行 → 每个 agent 独立 worktree + 临时分支（从 `feat/uat62-design-system` 切出），各自只改分配到的行并 commit；一个 merger 批按顺序合回 feat（不同行自动合并，同行冲突即分组错误）。
- 构建 / 测试只在集成树做一次，不在每个 worktree 各跑一遍。
- 合并后 `git worktree remove`，只清自己派发的。
- 任务卡必须写明精确行范围/区块，禁止跨出分配行改同一文件。

## 四、停止条件（硬时限）

- **单任务预期 ≤20 分钟；30 分钟必须回部分结果；45 分钟未回 = 立即 TaskStop 并按窄范围重派；绝不允许跑满 1 小时。**
- 监控方式：每次收到任务通知或用户消息时用 `ListAgents` 看 `started Xm ago`；≥30 分钟先 SendMessage 要求 5 分钟内回单，≥45 分钟直接停。
- 任务卡末尾固定写：「限时 30 分钟；到点先交已完成部分 + 剩余清单，禁止挂起。」
- 同一波次审计连续 2 轮无新 findings → 停止审计，进入出包。
- 同一文件同一时刻只有一个写者；编辑批不重复读设计文档全文。

## 四·五、最小代码量（2026-10-23 用户新增）

**三条硬禁**：
1. **不过度设计**：固定四列就不写 n 列通用路径；不预留"以后可能用"的字段/开关；helper 只服务当前验收。
2. **不重复造轮子**：先 grep 仓库与 EUI-NEO；复用 `findColumnByKind`、主题令牌、components、`core::platform::requestUiUpdate` 等。新增工具函数仅当同文件已用 ≥2 次。
3. **不过度防御**：内部不变量（四列固定、kind 已迁移、宽度 >0）不再套 null/空/负值/越界兜底；不静默纠正错误状态；**错了就让它错**——日志/断言/Result 直接暴露，不写掩盖分支。

**具体清理项（收口简化审计逐条核）**：
- `boardColumnWidths` 的 n≠4 通用推广 → 只保留固定四列。
- `openNewTaskForTodoColumn` 找不到 `kind='todo'` 时回落 `columns_.front()` → 改为日志报错并中止（不静默落错列）。
- 拖拽命中的「逐列向量为空则回落均匀 colW」→ 删除回落，测试显式设置逐列几何。
- `onPageEnter`/拖拽中断的防御性复位：只保留有真实场景依据的，其余删除。
- 对设计保证为正的值不再 `max(0, …)` 钳制（除非外部输入）。

**测试纪律**：断言必须能真实失败；禁止为了变绿放宽断言或传失真页高。

**其余**：不新增抽象（除非 ≥2 处复用）、不改名、不顺手重构；任务卡写改动行数上限；测试每条验收点一个用例、复用 fixture；收口删除重复实现/未使用字段/死代码/过度封装；验收看净增行数 + 构建/定向测试全绿。

## 五、最后环节：注释治理（2026-10-23 用户新增）

- **触发点**：功能与验证全部收敛后、出包前（W5 末/W6 前）。不与功能改动混批。
- **保留**：公共 API 契约、不变量、平台坑、非显然的「为什么」（1-2 行）、必要的 TODO/FIXME。
- **删除**：历史叙述（UAT 轮次/批次编号/规格条款号/commit hash）、逐行复述代码、设计推导长文、临时任务 ID、file:line 引用、装饰性 ASCII、与代码无关的决策记录。
- **上限**：普通注释块 ≤3 行；公共 API 头注释 ≤8 行；同一事实只说一次。
- **做法**：先清本波次改动过的文件，再全 `src/` 扫描；每文件 1 个 agent 出删改清单、另 1 个复核；**只动注释，不改代码**。
- **验收**：`git diff` 仅注释行变化；构建通过；抽查 10 个文件确认无行为差异。
