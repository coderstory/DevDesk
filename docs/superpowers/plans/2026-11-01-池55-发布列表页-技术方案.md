## 2. 「下一步」装配数据源方案（性能核心）

**不做逐行 collectTrackRows**（需 ReleaseDetailUiState + 全行展开 + 文案装配，过重）。方案：

- `release_logic.{h,cpp}` 新增纯函数：

```cpp
// 列表行「下一步 · {步名}」：与详情页页头主动作同一信息源（池53 §4.2 / 设计 §5.4）。
// 固定序 = performNextStep：提测单→CAB 单→nacos 工单(按需)→数据库工单(按需)→上线公告
// →逐环境(库序) 逐服务(库序) 合并分支→配置 n 项→部署→验证完成。
// 返回首个「未完成且已解锁」条目名；时间窗未开 / 单号门禁缺失 / skipped(槽位关闭)
// 均不算；无（全完成 / 全锁定）返回空串。D3 取舍：不复算 reorder 拖拽序，用库序。
std::string releaseNextStepLabel(const Task& task,
                                 const std::vector<TaskEnv>& envs,
                                 const std::vector<TaskService>& services,
                                 const std::vector<TaskConfig>& configs,
                                 const std::vector<TaskStep>& steps,
                                 int nowMinute);
```

- **零新增 SQL**：`releaseLoadTaskCards`（release_list_ui.cpp:771）每任务本就批量取 envs/services/configs/steps 四组向量在内存，`nextStepLabel` 直接消费；walk **首中即停**（停在第一个未完成项，期望 O(1)，最坏 O(任务条目数)——与同处既有的 `taskProgress` 全量 walk 同阶，增量成本可忽略）。`nowMinute` 用已导出的 `planDateElapsedMinutes`（release_logic.h:33）按页共用 nowUnix 快照换算。
- 门禁上移：`configGateMissing` / `deployGateMissing`（release_detail_logic.cpp 内部）语义上移 release_logic 公共，detail 改调公共版（消两份实现）；标签文案（前置 5 名 + 合并分支/部署/验证完成）在函数内列常量，注释钉与 detail `stepLabel:118` / `prereqTitle:183` 的文案契约（改一处必改两处）；配置名复用 `configItemLabels`（release_config_ui.h:26）。
- Tab 组计数：store 增 1 条 `countTasksByStatuses(vector<TaskStatus>)`（COUNT + status IN，复用 `taskStatusText` 编码 release_store.cpp:98）；随既有 1s 陈旧刷新与弹层关闭路径同步，库值分组（Pending+Running/Draft/Done+Voided）无需派生读环境。

## 5. 测试计划（三问 + 会红；logic 先行）

过滤口径：`bash scripts/build-test-run.sh --filter <子串>`，研发阶段只跑 release 域定向用例，全量归收口 qa。

## 6. 取舍与风险 / 未验证项

- **放弃**：瀑布流几何与 `summary` 摘要行（新设计无消费方，代码负资产即删）；SQL 侧筛选（改 store 分页契约 + 每 Tab 缓存复杂度，内存过滤已满足）；nextStepLabel 复算拖拽序（D3）。
- **文案契约**：release_reminder.cpp:115 的「配置中」是提醒域措辞非状态 chip，本卡不动（最小 90%）。
- **未验证项**（实现期首帧验证，证据物回填）：① rect `.states` hover 与行内竖条/分割线的叠层顺序；② contentKey 追加 tab 后滚动重锚与追加泵的同帧竞争；③ 1000×640 与 1600×1000 两档实测截图；④ Windows 侧字体渲染下 11px 环境 chip +N 收纳（双机按硬约束执行）。
- **风险**：D1/D2 与既有页面家族的视觉一致性由停等核对裁决，实现不先斩后奏。
