## 1. 判定口径

### 1.1 什么算“G 链全链通过”

一条链通过必须同时满足：

| 条件 | 要求 |
|---|---|
| 前置状态可复现 | 使用 scratch 数据库/临时笔记目录/独立端口，不依赖“上一条测试留下的状态”；生产数据只读或显式隔离 |
| 操作真实 | 走真实 UI 元素/真实服务/真实调度/真实指针（不能只调 mock 客户端的纯函数） |
| 末端结果可核对 | 核对**持久化结果**（DB 行、磁盘文件、HTTP 状态/响应、日志行、统计数字），不是只断言“按钮存在” |
| 失败会红 | 任一前置缺失（无凭据/无显示）必须显式记为未跑并让门禁红，或由门禁书面批准跳过；不得静默 PASS |

### 1.2 运行层级

| 层级 | 含义 | 本仓库对应物 |
|---|---|---|
| H | headless 单测（UI 树 compose，无真窗口） | `devdesk_tests`（doctest，`REGISTER_TEST`） |
| W | 真窗口 probe（真 GLFW 窗口 + 真模块/真指针） | `tests/probes/*`，`ctest -L probe` |
| N | 真网 live（真凭据/真上游/真 GitHub） | `tests/live/*`，`ctest -L live`，默认 OFF |
| M | 真机（打包 exe，人工操作） | `scripts/package-windows.sh` 产物 + 用户 UAT |

> 环境事实（本次审计实测）：当前工作树为 **Windows 11 + MinGW**，`build/CMakeCache.txt` 中 `DEVDESK_BUILD_PROBES=ON`、`DEVDESK_BUILD_LIVE_TOOLS=OFF`；`build/tests` 下 probe 可执行已存在，`tests/live` 两个驱动不存在。`tests/CMakeLists.txt` 把两个 live 目标整体包在 `if(DEVDESK_BUILD_LIVE_TOOLS AND UNIX)` 里，Windows 上即使打开开关也不会生成。

### 1.3 证据约定

- 单测名 = `REGISTER_TEST` 第一参数（可用 `devdesk_tests --filter <ASCII 子串>` 定向跑；中文描述经 Git Bash 传参有编码风险）。
- probe 名 = `build/tests/<name>.exe` 或 `ctest -L probe -R <name>`。
- “实跑”证据必须落盘：命令、退出码、关键断言输出、产物路径（截图/DB 行/文件内容）。

**缺口与证据**

- **W 探针与向导漂移**：`tests/probes/agent_e2e_probe.cpp:552-585` 只点 `agent.page.newTask`→`goal`→`trigger.item.5`→`save` 一次；而 `src/module_agent/agent_module.cpp:2265-2266` 是 4 步，`:2769-2793` 非末步 `save` 只前进不创建。静态推导该探针的 F4 创建必失败。需实跑复核后修 probe（不得改产品迁就旧 probe）。
- **试运行零覆盖**：全仓测试对 `agent.dialog.task.test` 只有“非末步不渲染”的存在性断言（`tests/test_modules/test_agent_ui.cpp:411`），无一次点击执行；`testRunDialog`（`agent_module.cpp:958-1055`）的临时任务创建/删除/结果回填无链式断言。
- **假绿语义**：`tests/probes/agent_e2e_probe.cpp:604-614` 在无生产凭据时把五流程记「未跑」，但 `passed` 不置 false；`:915-940` 仍打印 PASS。W5 若只读退出码，会在“完全没跑链”的情况下通过。
- **live 平台门**：`tests/CMakeLists.txt:422` 的 `if(DEVDESK_BUILD_LIVE_TOOLS AND UNIX)`；Windows 上 `agent_live` 不生成。
- **真机**：无书面记录；STATUS 的“用户真机目检”仅针对 H1–H19 视觉项。

**建议执行方式**

1. 先修 probe 的 4 步导航：每步点 `agent.dialog.task.step.<i>` 或点「下一步」并断言 `step.<i+1>` 高亮，最后再点 `save`；把「未跑」改为 `passed=false`。
