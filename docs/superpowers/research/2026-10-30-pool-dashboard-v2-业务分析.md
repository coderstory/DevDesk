# 团队看板 v2 业务分析（老板四缺口逐条方案）

日期：2026-10-30 深夜 ｜ 主笔：惨品 ｜ 状态：报老板娘审后按池 36 排产实现

## 缺口①：数据静态
**方案：三选一按成本递进，推荐 B**
- A（最省）：保留纯静态+生成器，但挂进 hook——每次 pool_update 写操作成功后自动重跑生成器（小萝莉已在做快照出口挂接，顺手把生成器挂同一出口）。零新服务，页面永远是最新快照。
- B（推荐）：加一个 ~50 行的只读 HTTP 端点挂 8940 服务（已挂着），`/api/pool.json` 直读池库吐 JSON，页面 JS 拉取渲染，30 秒轮询。数据永远实时，生成器只留作离线备份。
- C（不做）：WebSocket 实时推送——实时性收益配不上复杂度，否。
**验收**：池库变更后 ≤30 秒页面可见；池库不可达时页面显示「数据时间戳」而非装作最新。

## 缺口②：无筛选
**方案**：顶部筛选条三个维度：状态（挂起/进行中/关闭/拒绝）、阶段（已分析/已调研/开发中/测试中/已验收）、处理人（owner 下拉）。纯前端 JS 过滤已加载 JSON，零后端成本。默认视图=进行中+挂起（老板最关心的），一键「全部」。
**验收**：任一维度筛选结果与池库查询一致；筛选态下汇总卡数字同步重算。

## 缺口③：平铺布局
**方案**：三层信息架构——
- 顶：汇总卡（未完结/各阶段计数/最近变更时间戳）
- 中：「谁在干什么」横条（personal_todo 9 格，有内容的实色、空置灰——空格保留是为督促喂数）
- 主区：需求列表按**阶段分组**（开发中组在最上，其次测试中/挂起），行内展开式——默认一行一条（编号+标题+阶段+处理人），点击展开 detail/溯源链摘要，不再一屏全量平铺。
**验收**：一屏内能看到「在干什么+卡在哪」；默认视图不需要滚动超过两屏。

## 缺口④：只有需求池
**方案**：bug 池/待办池条目同表不同 pool 值，加一个池切换 tab（需求/BUG/待办/全部），数据层零改动，纯展示拆分。「没人在干活」根因=personal_todo 未喂数，老板娘已抓纪律，页面侧加空态文案「该成员未登记当前工作」而非显示为空白，避免误读为系统坏了。
**验收**：三池条目数与池库一致；空 todo 有明确空态文案。

## 非目标
不做编辑功能（看板只读，写操作永远走池 MCP 工具）；不做移动端适配；不做历史趋势图（后置路线图）。
