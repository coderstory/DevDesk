# 池 31/32 telemem 缝评估（decay 遗忘清单 × baseVersion 真值）

- 日期：2026-10-31 ｜ 角色：调研 ｜ 对象：telemem 1.10.1（PyPI wheel 精读 + 本机只读 POC 实跑）
- 结论一句话：**两个池项的挂起前提（「引擎无列举缝 / 无版本缝」）都已过时，缺口全部在 DevDesk 侧接口层，不等引擎升级即可闭环。**

## 结论先行

1. **池 31 无引擎侧缺口**：telemem 1.10.1 MCP 工具 `get_memories` 本身就是记忆列举缝，参数（scope + limit，上限无界）与返回字段（id/memory/hash/metadata/created_at/updated_at/user_id/role）足够支撑遗忘清单扫描。缺口 = DevDesk `IMemoryRetriever` 只有 3 方法、无 list；`panel_state.cpp:197` 注释「telemem 未暴露 list」与事实不符（DevDesk 自己的 `findMemoryIdByText` 就在调它）。
2. **池 31 唯一真缺口是「最近被想起时间」**：引擎无 recall/usage 追踪，`MemorySummary.lastUsedAt`（curator.h:32 注释「engine 侧清单提供」）拿不到。两条路：updated_at 作闲置代理（零新增），或 DevDesk 在 search 命中路径本地记使用时间（更贴 spec 语义）。需产品口径拍板。
3. **池 32 全局版本缝确不存在**（8 个 MCP 工具 + mem0 2.0.20 Memory 类均无 version/snapshot/count API），但**逐条目版本真值存在**：`get_memory(memory_id)` 返回 `updated_at`，且 update 必刷 updated_at（mem0 main.py:2066，连 metadata-only 也刷）、delete 后 get 返回 not_found——足够替代全局版本号做 baseVersion 前置校验。
4. **池 32 可 DevDesk 侧闭环**：以 updated_at（epoch 秒）作版本 token，`trustSnapshotVersion`（panel_state.cpp:40）换成真查询闭包即可；契约位（TargetVersionFn / MemorySummary.version / baseVersion 字段）全部现成，零 schema 变更。
5. 附带发现：spec 回填注「telemem 存量无列举/**全清**缝」（integration-spec.md:138 ③）中全清缝也过时——`delete_all_memories` 工具存在（需显式 scope，拒绝默认用户，安全性可接受）。

**缺口定位：DevDesk 侧接口/调用层（引擎侧无缺口）**

| 哪些记忆（正文可读） | `get_memories` → memory 字段 | ✅ |

## 池 32：baseVersion live 真值

**缺口定位：DevDesk 侧（引擎无全局版本缝——该口径本身正确；但「引擎升级后接真值」的等待不必要，逐条目真值现在就有）**

- 无全局版本/快照/计数 API：8 个 MCP 工具无一暴露；mem0 Memory 类无 version/snapshot/count；`memory_history` 是**逐条目**变更日志（ADD/UPDATE/DELETE + 时间戳），可作未来审计增强但不是全局版本。
- 逐条目版本真值：`get_memory(memory_id)` → updated_at；update 必刷（mem0 main.py:2066）；delete 后条目消失（MCP 回 not_found）。granularity = ISO 秒级（同秒内改两次不可区分，审核门控流程下风险可忽略）。

**最小改动面（接口级）**

1. `telemem_client.h/.cpp`：增 `getMemoryVersion(memoryId)` → `Result<std::int64_t>`（实现 = `callTool("get_memory", {memory_id})` + updated_at ISO → epoch；not_found 返回明确错误码）。
2. `src/module_memory/panel/panel_state.cpp:40-42`：`trustSnapshotVersion` 快照放行闭包 → 换成调上述方法的真闭包；`proposal_store.cpp:419` 的 baseVersion 前置校验链零改动（「≠ → expired」语义天然适配：条目被改/删 → 版本变/查无 → 自动过期重提）。
3. `curator.cpp` 建 forget 卡处：baseVersion = 扫描时该条 updated_at epoch（经 MemorySummary.version，curator.h:33 契约位现成）；add 类恒 -1 不动。
4. 零 DB schema 变更、零引擎升级依赖。可选增强：给 target 记 deleted-not_found 的错误码分支，让「已删除」与「网络失败」区分（当前同走 fail 保持 pending，亦安全）。
