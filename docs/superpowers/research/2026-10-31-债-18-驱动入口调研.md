## 0. 结论先行（≤5 条）

1. **场景格式推荐 JSON**：仓内 `platform::json`（yyjson 薄封装，`src/platform/json.h`）现成解析 + `Result` 错误链零新依赖；AI 误写率维度未找到可靠的跨格式对比数据（首版引用的 LEAN 基准数字原始出处无法定位，v2 已降格不作为依据），而 JSON 的确定性解析报错与 schema 校验面更适合门禁工作流；Maestro 选 YAML 的动机（非程序员手写可读）在「AI 写、审计读」流程里不成立。Gherkin 类 DSL 与代码型（Playwright/Flutter/GUT）均被先例排除。
2. **wait-for-condition 成熟参数面**：Playwright = 条件轮询直到满足或超时（expect 默认 **5000ms**、动作默认无超时、超时抛 TimeoutError）；Cypress = `defaultCommandTimeout` **4000ms**，重试只作用于查询+断言（动作不重试，但动作前同样自动等 actionability）。两家「动作前先等」是共识；本仓首版不做动作前自动等待是**确定性取舍**（少魔法、失败显式化），非先例跟随。本仓帧驱动天然 1 帧/轮（≈16ms@60fps），粒度优于 web 的重试粒度；建议默认超时 5000ms、场景级可覆写。
3. **命中回读：机制在框架里存在，但不可调**（v2 反转，已核实）：Playwright hit-target check 的语义（点击点实际接收指针事件的元素必须是目标）在 EUI-NEO 有同机制机器——`hitTestInteractive` / `resolveHoverTarget`（实现 `runtime_input.h:49` / `:73`），但二者是 **Runtime private**（声明在 `EUI-NEO/core/dsl_runtime.h:141` / `:147`，private 段自 :69 起，无 friend），DevDesk src/+tests/ 全仓 grep 零调用，唯一 caller 是框架自身 `runtime_lifecycle.h:130`（每帧内部消费）。首版命中回读是**技术方案显式二选一**：EUI-NEO 小步暴露（方案 C 子项前移，扩大改动面并新增跨仓提交顺序义务）vs 降级为 `assertNoEqualZOverlap` 静态近似（零框架改动）——见 §3.3 / §6.3。
4. **报告/退出码**：JUnit XML 是 CI 通用报告格式，但 driver 不必自产——ctest 自带 `--output-junit`（CMake 3.21+，⚠ 仓内 `cmake_minimum_required` 为 3.14，需确认 CI 工具链版本）一行接线；driver 本体 = stdout 中文逐步明细（人读，对齐 probe 惯例）+ 可选 `--report-json`（机器读）；退出码沿用仓内 0/1/2 口径 + 77 诚实跳过；TAP 消费面窄、无增量价值，不推荐。
5. **仓内基建大体现成**：五类动作原语、截图、canary 诚实跳过、ctest 注册、app 级组装链接样例全部现成（详见 §5 file:line）；命中回读**不在其中**（private 无通道，见 §0.3）。driver 新增工程面 = 「场景解析 + 步骤解释器 + wait 轮询 + id dump + 报告输出」五个纯组装件 + 命中回读二选一（暴露或降级）。规模注记：选小步暴露路径则改动面伸入 EUI-NEO 公开测试 API（与方案 C 全量正式化尚有距离），M 档判断需随之重注。

## 1. 场景文件格式选型（JSON / YAML / DSL）

### 1.1 业界先例盘点

| 系统 | 场景/用例载体 | 形态 | 对本仓的启示 |
|---|---|---|---|
| **Selenium IDE** | `.side` 文件 = **纯 JSON**，commands 数组每项 `{command, target, value}` 三元组 | 数据文件 | 最接近本需求形态（动作列表驱动）；JSON 承载动作序列先例成立 [S1] |
| **Maestro**（移动端 E2E） | `flow.yml` = **YAML**，`- launchApp` / `- tapOn: {id: ...}` 步骤序列 | 数据文件 | 明确以「非程序员也能读写」为设计目标；动态等待、可复用子流 [S2] |
| **Playwright MCP**（AI 驱动浏览器） | 页面快照序列化为 **YAML 形文本** + 短 `ref` id，agent 用 ref 调 `browser_click` 等 | 运行时交换格式 | 「元素树 dump → AI 读 → 引用 id 回传」的 AI 工作流先例，与 F-05 id dump 子命令同构 [S3] |
| **Playwright Test** | **代码**（TS）+ fixture；用例逻辑在代码里 | 代码 | 强表达力但要求编程环境——qa-tester 子代理无 IDE 写不了 C++，等价物即回到现状 [S4] |
| **Flutter integration_test** | **Dart 代码**（`testWidgets` + `tester.tap(find.byIcon(...))`） | 代码 | 同上；注意其 `pumpAndSettle()` = 帧驱动的 wait-for-idle 原生先例 [S5] |
| **Godot GUT** | **GDScript**（`extends GutTest` + `test_` 前缀方法） | 代码 | 同上 [S6] |
| **Cucumber/Gherkin** | `.feature` 自然语言 DSL + 步骤定义胶水层 | DSL | 社区长期批评：indirection 成本高、feature 文件与步骤定义双份维护、非技术干系人实际不读 [S7] |

### 1.2 AI 写场景下的误写率证据（二手，两源）

- **tokenization 伪影（二手，有定位符）**：Lightning-AI litgpt 弃 JSON 配置改 YAML，理由是 JSON 的**引号/转义 tokenization 伪影**令 LLM 更易错（litgpt issue #1021）[S8]。
- **反面（推理）**：YAML 的**缩进敏感**是另一类静默错误源（错误确定性差）；JSON 解析错误由解析器确定性暴露，「错得明显、报错精确」在门禁场景反而优于「错得微妙」。
- **数据缺口声明（v2）**：首版引用的「LEAN 基准省 ~44% token / 准确率 87.9% vs 86.2%」在检索结果中无 URL、**原始出处无法定位，降格不作为依据**；格式限制类研究（JSON/XML/YAML 约束生成对复杂任务推理影响有限、任务类型才是主因）同为转述、原文未定位 [S8]。本报告因此不在「AI 误写率」上做定量断言，格式推荐的依据转向 §1.3 的依赖成本与确定性校验。

### 1.3 格式对比与落地建议

| 维度 | JSON | YAML | Gherkin 类 DSL | 代码型（TS/GDScript/Dart） |
|---|---|---|---|---|
| 先例（同类场景） | Selenium IDE `.side` [S1] | Maestro [S2] | Cucumber [S7] | Playwright/Flutter/GUT [S4-6] |
| AI 误写风险 | 转义/逗号类错，但**解析器确定性报错** | 缩进类错，可静默；token 更省 | 歧义自然语言，步骤定义失配 | 需编译/沙箱，AI 可写但本仓无执行面 |
| diff 友好 | 每步一项一行即可，纯结构噪音少 | 无逗号括号噪音，diff 最干净 | 步骤串改动 diff 大 | 无关 |
| 注释 | ❌ 无（硬伤，需 `_comment` 字段约定补偿） | ✅ `#` 注释 | ✅ | ✅ |
| 仓内解析成本 | **零**：`platform::json`（yyjson）现成，`parse → Result<JsonValue>`（`src/platform/json.h:90`）；错误信息现状见下条 | 新依赖 yaml-cpp 或自写解析器（双平台静态链义务） | 自写 tokenizer | 需嵌脚本引擎（不可行） |
| 评审可读性 | 结构清晰，AI/人均可读 | 最好 | 表面最好、实为双份维护 | 差（用户不懂 C++） |

**建议（已确认级）**：**JSON**。决定性因素是仓内解析设施现成（`platform::json` 已被生产模块使用）与双平台零新依赖，而非误写率本身——误写率维度两格式差距小且互有攻守。补偿措施：
- 每步骤对象允许 `_comment` 字段（自定 schema 内合法键），弥补 JSON 无注释；
- 场景 schema 文档化（顶层 `{version, settings, steps[]}`），非法键/缺键在加载期报错并给相近候选（对齐 AC-2 的 id 候选机制）;
- 解析错误带行号：**现封装未透出 yyjson 错误详情**——parse 失败路径（`json.cpp:293-307`）返回固定文案「JSON 解析失败（yyjson_read 失败）」，`yyjson_read` 未传 `yyjson_read_err` 出参；`:334` 的 err.msg 属 **stringify** 路径，与解析无关。带行号 = 二选一：改 parse 封装透出 err.byte/msg（yyjson 原生支持），或 driver 侧自算行号——留技术方案定。

## 2. wait-for-condition 先例（轮询/超时/失败语义）

### 2.1 Playwright（精读官方文档 [S9][S10]）

- **auto-waiting**：每个动作（click/double-click 等）执行前自动跑 actionability 检查（Visible / Stable / Receives Events / Enabled；Editable 仅 fill 类），**轮询直到全部通过或超时**，超时抛 `TimeoutError`。
- **参数面**：`expect` 断言默认 **5000ms**（config `expect.timeout` 全局改 / 单断言 `{timeout}` 覆写）；**动作默认无超时**（`actionTimeout: 0`，靠 test runner 全局兜底）；test 整体默认 30000ms。
- **语义要点**：条件满足**立即通过**（不等待满额超时）；失败是「检查未在超时内全部通过」。

### 2.2 Cypress（扫描官方 retry-ability 页 + issue 佐证 [S11]）

- `defaultCommandTimeout` 默认 **4000ms**：命令在此窗口内**反复重试**直到断言通过。
- **重试只作用于查询与断言**（`cy.get` / `.should()`），**不作用于动作**（`.click()` 不重试）；链尾非查询命令（如 `.then()` 返回 void）会使重试失效（issue #30230）。
- 重试 = time-slice：整个 timeout 窗口被切成反复重跑「最后一个查询 + 断言」。

### 2.3 对本仓的落地建议

| 参数 | 业界面 | 本仓建议 | 依据 |
|---|---|---|---|
| 轮询粒度 | web 侧 ~几 ms~100ms（内部实现细节，未承诺） | **每帧一轮**（`pollOnce` 天然 tick，60fps ≈ 16ms） | driver 本就是帧驱动，轮询免费 [R1] |
| 默认超时 | Playwright expect 5s / Cypress 4s | **5000ms**，场景 `settings.defaultWaitTimeoutMs` 可覆写、单步骤可覆写 | 与 Playwright 对齐，取整 [S10] |
| 条件类型 | 元素出现/消失/可见/文本 | F-02 范围内：元素存在/不存在 + 文本含（复用 `ui.find` / `walkElements`） | 需求分析 F-02 |
| 失败语义 | TimeoutError，步骤终止 | 步骤 fail + 中文超时原因 + **现场截图**，场景按失败策略处理（见 §4.3） | 需求分析 §9「不挂死」 |
| 动作是否自动等 | **两家都等**：Playwright 动作前跑 actionability 检查并整套重试 [S9]；Cypress 动作不重试、但同样自动等 actionability（retry-ability 只覆盖查询+断言）[S11] | **首版不做动作前自动等待**——这是确定性取舍（少魔法、失败显式落在 wait 步骤上），**非先例跟随**；「点前先等」交给显式 wait 步骤；后续可加 `--strict-actionability` 开关再议 | 先例证明「动作前等待」是行业共识，故首版偏离共识属有意裁剪，须在报告中如实注明 |

## 3. 命中回读先例（「实际命中 == 目标元素」断言）

### 3.1 Playwright hit-target check（精读 [S9]）

- click 的第 4 项 actionability 检查「**Receives Events**」= hit target check：在**动作点**验证指针事件的实际 hit target 是目标元素（或其后代）；被 overlay（弹层、z 序悬浮元素）截胡 → 检查失败 → 重试直到超时。
- `force: true` 跳过这类检查（「禁用非必要 actionability 检查」）——即 force 点击**可能点偏**仍执行，Playwright 用它换确定性穿透能力。
- double-click 的第二击用 **deferred hit target check**（第一击完成后补验）。

### 3.2 EUI-NEO 同机制机器：存在，但 **Runtime private、无可调通道**（v2 反转，仓内已核实）

全仓 grep（`src/` + `tests/`，*.h/*.cpp）：`resolveHoverTarget` / `hitTestInteractive` 在 **DevDesk 侧零调用**；唯一 caller = 框架自身 `EUI-NEO/core/runtime/runtime_lifecycle.h:130`（`Runtime::update` 每帧一次，内部消费）。二者声明在 `EUI-NEO/core/dsl_runtime.h:141`（`hitTestInteractive`）/ `:147`（`resolveHoverTarget`），位于类 **private** 段（`private:` 自 :69 起，全文件无 `friend`）——C++ 语义上 tests/driver **不可调**。（首版调研依据 codegraph「tested via callers 含 probe_harness」判断可达，该判定有误，此处更正。）

机制本身（实现位置，供理解语义）：

| 能力 | 位置 | 说明 |
|---|---|---|
| 命中解析 | `EUI-NEO/core/runtime/runtime_input.h:73` `Runtime::resolveHoverTarget(event, dpiScale, inputEnabled)` | 捕获链优先（`capturedInteractionId` :5），否则 `hitTestInteractive`；结果带 hover 缓存（`canReuseHoverTarget` :92，动画/树变/坐标变即失效） |
| hit-test 核心 | `runtime_input.h:111` `hitTest<Predicate>` + `:124` `hitTestElement` | **orderedRoots 逆序 + 子级逆序**遍历（= z 序最顶层优先）、clip 裁剪（:139-153）、变换命中（`hitMatrixForElement` :562）、谓词 `interactive && !disabled`（:49-53） |
| 元素查找 | `EUI-NEO/core/dsl.h:1507` `Ui::find(id)` | `index_` 哈希 O(1)，返回 `Element*`（含 `frame` LayoutRect 逻辑坐标） |
| 元素树遍历 | `tests/probes/probe_harness.h:699` `detail::walkElements` | 产出 `parentOf` / `byId` / `leaves` 三张表；`assertNoEqualZOverlap`（:729）已在其上实现 z 序悬浮截胡检测——命中回读的**静态版**先例 |
| 可达性判定 | `EUI-NEO/core/dsl_runtime.h:141` / `:147`（声明）vs `private:` :69、无 friend | **不可调**：driver 要消费这套机器必须先由框架暴露（选项见 §3.3 二选一） |

### 3.3 落地建议（v2：写成技术方案的显式二选一）

命中回读在当前 EUI-NEO 上不可直接实现（§3.2），技术方案卡必须先二选一，该选择**直接改变改动范围与双仓提交顺序义务**：

- **选项 A——EUI-NEO 小步暴露（方案 C 子项前移）**：框架新增公开只读查询（如把 `hitTestInteractive` 提升到公开测试 API 头文件，或暴露每帧已算出的 hover target 只读接口，即 `runtime_lifecycle.h:130` 已消费的同一结果）。DevDesk 侧随后实现完整「click → 回读断言」：`ui.find(id)` → 取 `frame` 中心（左上 + width/2、height/2；事件坐标语义按框架 Physical 约定换算，见 `runtime_input.h:397-409` 的 dpiScale 除法注释）→ `click()` 注入（press+release 同帧，`probe_harness.h:623`）→ 断言 `实际命中 id == 目标 id`；不等则步骤 fail，stderr 给双方 id + frame + 截胡元素（诊断 = 「谁截胡了」，复用 `assertNoEqualZOverlap` 的报告风格）。成本：EUI-NEO 公开头文件 + 文档 + **先推 fork 再推 DevDesk** 跨仓纪律（AGENTS.md §一）；规模介于「零框架改动」与方案 C 全量正式化之间。
- **选项 B——降级静态近似（零框架改动）**：用在库的 `assertNoEqualZOverlap`（z 序截胡类）+ 结果侧断言（点击后预期元素出现/文本/几何）间接覆盖；动态命中截胡不在覆盖面内——报告在未验证处按 AGENTS.md §八精神如实标注「命中回读未实现」，不静默绿。
- **共同项**：对齐 Playwright `force` 豁免口——步骤可加 `"force": true` 跳过命中断言（场景作者显式声明「我知道会被截胡」），默认开启（无论选哪条）。
- **取舍依据建议**：若审计侧优先「防 toast/弹层 z 序截胡假绿灯」（需求分析 F-05 审计 P2 补的动机），选项 A 覆盖更完整；若优先守 M 档与零 src/ 改动前提，选项 B 可先行、A 作为方案 C 的第一个子项跟进。最终由技术方案卡裁决。

## 4. exit code / 报告格式（CI 门禁接入）

### 4.1 通行做法（扫描 [S12][S13][S14][S15]）

| 格式 | 定位 | CI 消费面 | 判断 |
|---|---|---|---|
| **JUnit XML** | 测试结果 XML 事实标准 | Jenkins / GitLab / GitHub Actions（dorny/test-reporter 等）原生解析 | **推荐接入层** |
| **TAP**（Test Anything Protocol） | 流式文本协议（TAP13 定稿、TAP14 subtests 草案） | `prove` / tap4j / node-tap 等；CI 原生支持弱于 JUnit XML | 不推荐：无增量价值 |
| **自定义 JSON** | 人读 + 自定义消费 | 无原生消费面 | 推荐作**机读明细层**（逐步诊断/截图路径），CI 层交给 JUnit XML |
| Playwright 先例 | 退出码 **0 过 / 1 败**；reporter 多路：`list`（人读）+ `junit`/`json`/`html`（机器读）并行 | CI 以退出码判门禁、以报告文件做展示 | 「**stdout 人读 + 文件机读双通道**」即行业形态 [S13] |

### 4.2 ctest 并存（扫描 [S12]）

- `ctest --output-junit <file>`（**CMake 3.21+**，`ctest_test(OUTPUT_JUNIT ...)` 同版本）：一行拿到 JUnit XML。⚠ **仓内 `cmake_minimum_required(VERSION 3.14)`**（`CMakeLists.txt:1`）——本机/CI 实际 CMake 版本待技术方案确认；≥3.21 则门禁段加一个 flag 即可，<3.21 则 driver 自产 JUnit XML（骨架小，非阻塞项）。
- ctest 对失败测试以非零码退出（现行门禁已消费该语义，`scripts/build-test-run.sh:533` `ctest -L probe --output-on-failure`）。
- 失败时 JUnit XML 曾有「全败才写出」的 bug（gitlab.kitware.com issue #23424，已修）——接入时用近期 CMake 或自产兜底。

### 4.3 对本仓的落地建议

1. **报告双通道**：stdout = 逐步中文明细 `[3/7] PASS click todo.board.new (命中回读: todo.board.new)` / `[5/7] FAIL 等待元素 'todo.item.缴费' 超时 5000ms`（对齐 probe 中文诊断惯例）；`--report-json <path>` = 结构化明细（步骤号/类型/状态/耗时/命中回读/截图路径/错误原因）。
2. **截图策略**：失败步骤强制留证 + 可选 `"screenshot": true` 步骤级开关（对齐需求分析 §9「失败现场截图价值最高」）。
3. **退出码**（对齐仓内口径，**已确认**为现行惯例）：`0` 全过 ｜ `1` 有步骤失败 ｜ `2` 用法/场景文件非法（含 0 步防假绿，需求分析 §9 已定）｜ `77` 无显示环境诚实跳过（`kSkipExitCode`，`probe_harness.h:67`，ctest `SKIP_RETURN_CODE 77`，`tests/CMakeLists.txt:458`）。
4. **失败策略**：默认 **fail-fast**（交互链后续步骤依赖前置状态，继续跑只产生级联误导）+ `--keep-going` 收集全部失败。业界对照：Playwright test 内断言败即终止该 test（fail-fast），Cypress 默认继续——两者各有生态，本仓选 fail-fast 因场景文件是**单链**而非独立用例集。
5. **门禁接线**：driver 以独立可执行注册 `add_test`（LABELS 建议 `"ui-drive"` 与 `"probe"` 并列或复用 probe 段——技术方案定）；`ctest --output-on-failure --output-junit` 一行并入现有 probe 门禁段（`scripts/build-test-run.sh:504-530`），Skipped 单独计数惯例照旧。

## 6. 给技术方案卡的输入清单

1. **场景格式定稿建议**：JSON（`platform::json` 解析）；顶层 `{version, settings{defaultWaitTimeoutMs, failureStrategy, dataRoot}, steps[]}`；步骤通用字段 `_comment` / `id 引用`；schema 作为长期契约随 driver 文档化并过独立审计（开放问题 1 的回答输入）。
2. **wait 语义**：条件=元素存在/不存在/文本含；每帧轮询；默认超时 5000ms（场景级/步骤级可覆写）；超时=步骤 fail + 中文原因 + 现场截图。
3. **命中回读（显式二选一，v2）**：(A) EUI-NEO 小步暴露——新增公开只读 hit 查询，driver 实现完整「click → 回读断言」（失败诊断输出截胡者 id+frame），等价 Playwright hit-target check 的框架内实现、可作对审计的先行例证，代价是改动面扩至 EUI-NEO + 跨仓提交顺序义务；(B) 降级 `assertNoEqualZOverlap` 静态近似 + 结果侧断言覆盖，零框架改动但动态命中截胡不覆盖、未验证处如实标注。两案均保留 `force:true` 豁免。技术方案须明示选择及其 M 档影响（详见 §3.3）。
4. **报告/退出码**：stdout 中文逐步明细 + `--report-json`；退出码 0/1/2/77 四态；失败策略默认 fail-fast + `--keep-going`。
5. **CI 接线**：driver 注册进 ctest（LABELS 定夺 `"probe"` 内 or 新 `"ui-drive"`）；`--output-junit` 接入前提=确认 CI/本机 CMake ≥ 3.21（仓内声明 3.14）；Skipped 计数惯例不变；`build-test-run.sh` 门禁段落位置（probe 段内 or 新段）待定。
6. **driver 链接集**：照抄 `tests/CMakeLists.txt:389-402` 整块——七源 = `app_assembly.cpp + app_sidebar.cpp + module_toggle_bridge.cpp + mcp_service_bridge.cpp + memory_mcp_bridge.cpp + toast_notice_bridge.cpp + module_mcp/mcp_page_module.cpp`（多出的缝源因模块库引用桥符号必须单独编入，见该块上方 :378-388 注释）；F-06 真点侧边栏导航正是 module_toggle_sidebar_probe 同款链接集——直接回应开放问题 3（组装深度）。
7. **键码契约**：场景文件用语义键名（`"Enter"`/`"Escape"`/`"Ctrl+S"`），driver 内映射到 GLFW 键码再走 `glfwKeyToInputKey`；双平台同表。
8. **方案 C 触发条件（v2 修订）**：命中回读若选 §6.3 选项 A，即以「小步暴露」形态**提前触发部分**方案 C 义务（公开测试 API 头文件 + 先推 EUI-NEO fork 再推 DevDesk，§一跨仓纪律）；方案 C 全量正式化仍以其完整目录为准（公开 API 面 + 框架文档 + `glfwKeyToInputKey` 双份消除，`probe_harness.h:534-536` 自警）。选 B 则 EUI-NEO 零改动、无跨仓义务。
9. **遗留待验证**：(a) 行号获取二选一——现 `parse` 封装未透出 yyjson 错误详情（固定文案，`json.cpp:293-307`；err.msg 在 :334 属 stringify 路径）：改封装透出 err.byte/msg 或 driver 自算；(b) 本机/CI CMake 实际版本；(c) 事件坐标空间换算（Physical vs Logical，`runtime_input.h:397-409` 的 dpiScale 注释）在 driver 封装里的统一处理；(d) **已核实事实**（非遗留，v2 全仓 grep + 头文件实读证实）：`hitTestInteractive` / `resolveHoverTarget` = Runtime **private**（`dsl_runtime.h:141`/`:147`，private: 自 :69 起，无 friend），DevDesk src/+tests/ 零调用、唯一 caller 为框架内部 `runtime_lifecycle.h:130`——即「无公开通道」，是 §6.3 二选一的决定性输入。
10. **元素可见性边界（新事实，v2）**：clip 外元素点击**必 miss**——`hitTestElement` 对 clip 区域外的命中直接提前返回 false（`EUI-NEO/core/runtime/runtime_input.h:139-153`），无论元素 frame 中心是否在 DOM 坐标内，命中判定均被 clip 检查拦截。此条**显式否证**上游需求分析 §9 的假设「视口外元素 = frame 中心仍在 DOM 坐标内可点」：滚动容器视口外的元素不可直接点。技术方案须直面开放问题 4——「滚动到位」动作原语从「待确认是否需要」升级为**必答**（或首版明确限定「仅支持可见元素」并在文档与报告中如实声明该边界）。
