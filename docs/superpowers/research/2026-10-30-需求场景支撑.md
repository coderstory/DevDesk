## 一、记忆线（module_memory / memcpp，4 场景）

上游事实基线：功能与界面代码全部落地，端到端验收「可交付」（2026-10-28，至 `9ee92079`）；真机 UAT（S5）未开始。总入口 `docs/superpowers/specs/2026-10-28-memcpp-overview.md`。

### 场景 M1：会话经验自动沉淀（采集 → 脱敏 → 提案卡人审 → 入库）

- 现状可用：全链已接线——引擎 Running 期背景循环（30 秒）跑「jsonl 增量采集 → 脱敏闸（六类敏感信息、红队 110 条零泄漏）→ 提案卡待审」，新增必审、不静默入库；采集幂等（重复读零入库）。证据：e2e-verify 报告 + `test_memory_{collector,sanitize,proposals}.cpp`。
- 差哪块：**G-1（infer 真调）**——接受提案时按原文直存（infer=false），提炼模型（glm-5.3-flash）从未真调，记忆是「原文段」不是「结论」（如「构建走 build-test-run.sh」这类可复用结论需人工读原文段）；提炼批处理节流上限也约定随 infer=true 启用时再接。另：S5 真机 UAT 未开始。

### 场景 M2：提问自动带上相关记忆（hook 注入）

- 现状可用：`devdesk memory hook` 子命令 + UserPromptSubmit 预载，至多 5 条、合计 500 字，任何失败只丢注入不打断提问（61 项契约单测，含「绝不 exit 2」）；检索走接口缝 IMemoryRetriever，升级检索通道调用方零改动。
- 差哪块：注入质量受两头上限约束——记忆本身未提炼（G-1，原文段召回后仍要模型自己消化）+ 检索对短词/间接表达的命中（当前 bge-small 难集 Recall@5 = 0.9，触发线口径已预写死）；真机注入采纳率 ≥30% 的验收留 S5。

### 场景 M3：记忆人审与遗忘治理（卡片四操作 / 撤销链 / 遗忘扫描）

- 现状可用：提案卡四操作（接受/拒绝/编辑后接受/撤销）+ 批量 + 过滤 + undoOf 撤销链 + baseVersion 防覆盖校验（105 项单测）；审核页三视图截图在案。
- 差哪块：引擎无列举缝 → decay 遗忘扫描已周期触发但 fail-closed 零卡（「哪些记忆该遗忘」实际空转，待引擎列举缝补齐）；baseVersion 防覆盖 live 空转（同为版本查询缝缺失，名义防线）；审核页窄窗标签重叠（UI 瑕疵待修）。这三条是 memcpp 已登记限制 #1/#7/#3，不新开缺口，随引擎开缝批次收口。

### 场景 M4：消耗可控（预算软/硬档 + 消耗卡）

- 现状可用：token/金额账本（今日/本月、估算口径）+ 月度预算软/硬档判定（软档黄条、硬档「暂停提炼·检索不受影响」）+ 面板消耗卡直读账本。
- 差哪块：到档动作只有「面板变色 + 暂停提炼」，没有主动通知——用户不看面板就不知道已经到档。通知出口缺失正是 **需-9 用量告警**（S 级，搭 M3 通知便车，见 `docs/specs/2026-10-30-需-9-用量告警-spec草案.md`）。

## 二、MCP 线（module_mcp + 各模块工具面，3 场景）

上游事实基线：MCP server 骨架 B1+B2+B3 实现复审通过（协议面 MUST 对齐、SSRF 防线除尾点外闭合）；菜单页 UI 终验可交付（6/6 场景、37 断言 0 FAIL）。骨架 spec `docs/superpowers/specs/2026-10-26-mcp-server-skeleton-design.md`。

### 场景 C1：外部资料取回（web_fetch → Markdown）

- 现状可用：`web_fetch` 内置工具（HTML 转 Markdown、SSRF 防线、Streamable HTTP、超时截断），实现复审两轮结论「站得住不打回」；MCP 页「试一下」可直验。
- 差哪块：正文主干提取（去导航/广告 boilerplate）仍是「全页转」，最小规则集（R1+R1b+R2 必做）有调研结论未实装，随骨架收口批（3 个 major：IP 编码绕过、无会话头请求、markdown 转义）一并处理——已排期的既有欠账，不新开缺口。

### 场景 C2：记忆开放给外部 agent（memory_search）

- 现状可用：`memory_search` MCP 工具 F-01~F-07 已实现全绿（工具本体 + 注册/注销 + MCP 页「记忆」模块行开关 + 持久化 + 降级文案 + 单测 11 用例）；关 = 运行时下线，开 = 立即恢复，重启态保持。矩阵见 `docs/superpowers/specs/2026-10-29-memcpp-mcp-integration.md`。
- 差哪块：真连 E2E（Claude Code 实调，F-08）后置、与 S5 UAT 同场；`listChanged=false` 已连接客户端需重拉 tools/list 才见工具消失（协议既有边界，已登记非缺陷）。

### 场景 C3：业务数据开放（笔记 / 待办经 MCP 读写）

- 现状可用：MCP server 基建就绪——扩展指南定死「新能力 = 任意 module_* 实现 IMcpTool 注册进 globalMcpTools()，不碰 module_mcp」；memory_search 已跑通此模式（先例含 app 层桥、模块行 UI）。
- 差哪块：**G-2（笔记 MCP）**——工具面只有 server_info / web_fetch / memory_search 三件，笔记、待办等业务数据零暴露：外部 agent（Claude Code）查得到记忆、查不到「我记过什么笔记、有哪些待办」，更不能把结论按业务规则写回。写入类工具需先定人审/授权闸口径（ADR 0002：业务数据只走业务工具，绕开直写是自造缺陷源）。

## 三、智能体线（module_agent，4 场景）

上游事实基线：M1 核心链路 + M2 调度/工具补全已合入；M3 可用性收口四项已实施（run 终态通知 / cron 模板下拉 / 一键复制 / 错误直达）；14 件内置工具（fs.* ×5 / bash.run / git.* ×8）+ app.now / app.stats / app.notify；出厂任务模板 ×3（需-6，`465baf2b`）。决策记录 `docs/superpowers/specs/2026-10-agent-roadmap-decisions.md`。

### 场景 A1：定时自动化（日报 / 巡检出厂模板）

- 现状可用：「新建任务」弹窗一键套用 ×3——日报草稿（工作日 18:00，git.log 汇总当日提交 → notes/daily/）、发版 Changelog（手动，tag 区间 git log/diff → notes/changelog/）、测试环境巡检（每天 9:00，curl 探测 + 异常 app.notify → notes/inspect/）。模板契约有单测钉死（禁臆造工具名）。
- 差哪块：日报是**单仓、只看已提交**口径——不扫未提交/未推送变更、不覆盖多仓；这层「开工前先看一圈仓库状态」的需求由场景 A2 承接。

### 场景 A2：变更雷达晨报（多仓状态巡检 → 晨报落笔记）

- 现状可用：全部零件在库——git.status 自带 `repo` 参数（分支/领先落后/porcelain 未跟踪）、git.log 自带 `repo`/`n`、fs.write 自动建父目录、cron 调度与模板常量表（加条目只改 `kTaskTemplates` 一处）。
- 差哪块：**G-3（cron 模板缺第四个）**——没有「变更雷达」出厂模板，用户要自己从零拼提示词。收口 = **需-8**（S 级、零新能力，本质第四个出厂模板，spec 草案 `docs/specs/2026-10-30-需-8-变更雷达-spec草案.md`）。

### 场景 A3：用量预警（额度 / 消耗将尽提前知道）

- 现状可用：数据面——记忆消耗账本/预算档在库（场景 M4：今日/本月 token + 月度软/硬档判定）；通知出口基建齐——M3 run 终态通知（failed/limited 必响的应用级 toast）+ platform::notify 系统通知层（macOS/Windows 双端）。⚠ 供应商余量数据面**不在库**：曾按 `2026-10-02-provider-quota-and-storage-design.md`（rev.2）实施、后摘除（schema 启动即清理 `profile_quota_*` 遗留表，`src/core/schema.cpp` dropRemovedTables）——需-9 v1 因此只做 token 两档。
- 差哪块：判定与出口之间没人接线——「自己去看卡片」而不是「越线来提醒我」。收口 = **需-9**（S 级、日/月两档 token 阈值判定 + 通知出口搭 M3 便车，spec 草案 `docs/specs/2026-10-30-需-9-用量告警-spec草案.md`；供应商余量百分比档待该功能回迁后另开小迭代，不重新立项）。

### 场景 A4：事件触发与任务记忆（M4 路线）

- 现状可用：决策已定稿未实施——纯进程内 EventBus、首批三动作事件（todo.created / todo.completed / md.saved）、冷却窗口防抖（默认 5 分钟）、任务级 context note（4KB 滚动）；M3 已实施完毕，真机使用验证进行中。
- 差哪块：M4 要动 core 与 migration（EventBus、agent_tasks 新列），排产前置 = 用户真机使用一段时间的明示开工信号；本批不动。关联：会话结束 hook（需-10）摸底已完成入库（SessionEnd 事件/payload/超时约束，`docs/research/2026-10-30-session-end-hook-recon.md`），实现未排。
