## 0. 门控与硬边界

- 门控结论：**必经**（整页三栏布局设计，非微调/文案级）。
- 硬边界（PRD §6 契约 + 决策，直接采信）：顶栏=仓库名+完整路径｜「切换仓库」｜「刷新」（含节流自动刷新指示位），**无搜索框**（决策①）；左栏=目录树+顶部「全部文件｜仅修改」二选一；中栏=独立变更列表，两组「变更/未跟踪」，重命名显 旧名→新名（决策⑤保留独立中栏）；右栏=路径条+「内容｜diff」视图切换（diff 仅变更文件出现）；diff=unified 单栏（决策③）；高亮语言集 md/java/js/ts/sql/json（决策②）；状态着色四态可区分=新增/修改/删除/重命名（PRD §6）。

## 1. 页面级构图（先整体后参数）

### 1.1 布局概念一句话

一台「仓库显微镜」：左栏回答「仓库里有什么」，中栏回答「现在改了什么」，右栏回答「具体怎么改的」——三栏等高、各自内滚，注意力权重从左到右递增，右栏占剩余全部宽度。

本页独特性原则句：**全部彩色只用于 git 状态与 diff 行编码，界面 chrome（顶栏/栏框/按钮）一律中性灰+绿色操作**——色彩密度本身就是本页的信息密度。

### 1.4 滚动模型（基线明文：外壳不滚、内容区各自内滚）

- Git 模块整体作为 app 外壳内容区的一个固定面，**页面级零滚动**，无分页器。
- 左栏树、中栏列表、右栏代码/diff 三区**各自独立内滚**（实现均为 virtualList，见 §11）。
- diff 超长行**横向滚动不换行**（PRD §5 diff 边界），行号列随行内容一体横滚（单栏 unified 天然对齐，规避 clue#14 双滚动联动时序问题）。
- 顶栏、左栏模式切换条、中栏组头、右栏路径条为各自栏内的固定头，不随内容滚动。

### 1.5 空间节奏与信息密度预算

- 定位=工具型高密度页（IDEA 对位）：行高统一 28px（树/列表）、代码行 22px、组头/路径条 32/36px，无卡中卡、无装饰留白。
- 密度预算：1280×720 档可见行数≈左栏 24 行 / 中栏 22 行 / 右栏 diff 28 行；留白只出现在三处服务分组——组头上下 4px、栏间 1px 分割线、右栏空态/占位居中弹性区（该弹性区仅在空/加载/错误/占位态出现，有内容即被行填满，不构成无效空白）。
- 权重：右栏（内容/diff）> 中栏（变更）> 左栏（树），与主路径 N7→N8 的注意力一致；变更状态色是唯一的高频彩色信号。

### 1.6 构图三问

1. **滚动模型对吗**：对——三栏各自内滚+固定头，与全站同类工作区页（外壳不滚、内容内滚）一致；diff 单栏横滚规避框架滚动时序陷阱（clue#14）。
2. **有无大段无效空白**：无——三栏行式布局由数据填满；唯一弹性区是右栏状态占位（空/加载/错误/二进制/超大），属状态画面不是构图空洞。
3. **密度与权重平衡吗**：平衡——最小档 800px 下三栏 200/240/≈330 仍成立（右栏 diff 横滚兜底），宽档右栏拿到 ≥560px 主权重。

### 1.7 两遍法第二轮自审记录

对照简报自问「给任意 git 工具页出方案是否也会得到同样结果」：①顶栏按钮排右侧+仓名排左=工具页通用，但仓名+完整路径双行排版是本页对「仓库上下文常驻可见」的选择；②git 状态色惯例 vs 基线四色纪律的调和是本页特有问题——新增/删除直接落基线绿/红语义（基线红明文含「删除」），修改/重命名落领域扩展组（§4.2 有依据声明），不是随手抄 IDEA 的多色彩虹；③大胆单点只花在一处=**unified diff 行级三色+双行号沟槽**（本页记忆点），其余全部安静。已核对 AI 五 tell：无暖米衬线/暗夜霓虹/报纸排版/SaaS 卡片套件/模板镀铬。
