## 一、评审概述

### 1.1 评审背景
本次评审覆盖 DevDesk 客户端全部核心功能页面，从视觉规范、信息架构、交互效率、用户认知四个维度，全面梳理当前产品存在的 UI 一致性问题与 UX 体验断点，输出可落地的整改方案，为后续产品迭代提供设计基线。

### 1.2 评审维度
- **视觉一致性**：组件样式、色彩体系、间距规范、字体层级
- **信息架构**：信息优先级、内容分组、导航逻辑、空状态引导
- **交互效率**：操作路径长度、反馈清晰度、快捷操作、容错性
- **用户认知**：语义清晰度、状态区分度、专业术语可理解性

### 1.3 整体评价
DevDesk 功能覆盖完整，核心能力（笔记、任务、代理切换）均已落地，符合开发者工具的基础定位。但产品目前缺少统一的设计系统支撑，各页面组件规范不统一、色彩语义混乱、说明文本过载，导致用户学习成本上升、操作易出错、专业感不足。

整体整改思路：**先统一基线，再优化体验，最后增强功能**。优先落地全局设计规范，解决跨页面不一致问题；再逐步优化各页面的信息层级与交互细节；最终形成统一、高效、低干扰的开发者工具体验。

## 二、全局共性问题与整改方案（按优先级）

### 2.1 P0 级：核心设计规范缺失（必须整改）
> 影响范围：全产品所有页面；风险：用户认知混乱、操作出错、产品专业感弱

#### 2.1.1 组件体系不统一，视觉语言不一致
**问题描述**
1. **Tab 组件无统一规范**
   - Markdown 笔记本页：使用实心橙色填充按钮作为 Tab 激活态
   - Claude 切换器页：使用纯橙色文字作为 Tab 激活态
   - 设置页：使用底部橙色下划线作为 Tab 激活态
   - 同一产品内三种 Tab 样式，用户无法形成稳定认知，且实心按钮 Tab 极易与主操作按钮混淆。

2. **选中态无统一规范**
   - 左侧导航：小对勾标记 + 浅背景
   - Todo 卡片：粗红色外边框
   - Profile 卡片：粗橙色外边框
   - 文件树条目：纯背景高亮
   - 全产品至少 4 种选中样式，且红/橙色粗边框与「告警/错误」视觉语义冲突，用户易误认为出现异常。

3. **按钮体系无层级区分**
   - 主操作、次操作、辅助操作视觉区分度不足
   - 不同层级的操作（如「新建任务」和「新增看板列」）混排，用户易误操作
   - 不同页面按钮圆角、内边距、字号不统一

**整改方案**
1. **统一 Tab 组件规范**
   - 未激活态：灰色文字（#666666），无背景
   - 激活态：橙色文字（#E67E45） + 底部 2px 橙色下划线
   - 禁用场景：**禁止使用实心填充按钮作为 Tab 切换**，避免与主操作按钮语义冲突

2. **统一全局选中态规范**
   - 通用选中样式：浅米色背景（#F8F4EF） + 左侧 2px 橙色竖线
   - 适用范围：导航条目、列表条目、卡片选中、文件树选中
   - 禁用场景：**禁止使用红色/橙色粗外边框作为普通选中态**，红色仅保留给异常、逾期、报错场景

3. **建立三级按钮体系**
   | 按钮层级 | 视觉样式 | 使用场景 | 示例 |
   | ---- | ---- | ---- | ---- |
   | 主按钮 | 橙色填充 + 白色文字 | 核心新增、确认、启用操作 | 新建笔记、新建任务、启用配置 |
   | 次按钮 | 白色填充 + 灰色描边 + 深灰文字 | 次要操作、取消、返回 | 测试连通、编辑、取消 |
   | 文字按钮 | 纯文字（橙色/灰色），无背景 | 辅助操作、链接类操作 | 查看详情、复制、更多 |

#### 2.1.2 色彩语义混乱，误导用户认知
**问题描述**
1. **橙色语义过载**：同时承载主按钮、Tab 激活、选中高亮、标签、普通文字高亮等 5 种以上含义，视觉重点分散，用户无法快速判断操作优先级。
2. **红色语义误用**：Todo 选中卡片、Profile 选中卡片使用红/橙色粗边框，与逾期、报错的告警语义冲突，用户易误判为异常状态。
3. **中性色体系缺失**：次要文字、边框、分割线、背景色没有统一的灰度阶梯，页面层次感弱。

**整改方案**
1. **收敛橙色语义**（仅保留 2 类场景）
   - 操作语义：主按钮填充色
   - 高亮语义：选中左侧线、Tab 下划线、可复制文本高亮
2. **收敛红色语义**（仅保留 1 类场景）
   - 告警语义：错误提示、逾期任务、危险操作确认
   - 禁止用于普通选中态、普通信息高亮
3. **建立灰度体系**
   - 一级文字：#333333（标题、核心内容）
   - 二级文字：#666666（次要信息、说明）
   - 三级文字：#999999（辅助信息、时间戳）
   - 分割线：#EEEEEE
   - 卡片背景：#FFFFFF
   - 页面背景：#FAF7F3

#### 2.1.3 表单与列表基线不统一，阅读效率低
**问题描述**
1. 各页面的两列信息列表（标签 + 值）均未固定标签宽度，内容不对齐，阅读视线来回跳动。
2. 开关、输入框、按钮等控件基线不统一，同一行控件高低错落。
3. 全局间距无规范，页面留白不均，拥挤与空旷并存。

**整改方案**
1. **两列列表统一规范**：固定左侧标签宽度（如 120px），右侧内容左对齐，形成整齐阅读基线。
2. **控件基线统一**：所有行内控件统一高度与垂直居中对齐。
3. **建立间距规范**：使用 8px 基础网格，模块间距 24px，组内间距 16px，条目间距 12px。

### 2.2 P1 级：核心体验问题（建议整改）
> 影响范围：全页面；风险：操作效率低、学习成本高、用户流失

#### 2.2.1 常驻说明文本过载，页面视觉噪音大
**问题描述**
- 所有页面顶部均常驻长段快捷键说明、功能解释文字
- 专业术语（迭代上限、模型槽位、system prompt、1M tokens）无解释
- 大量用户不需要持续查看的信息占用核心视觉空间，干扰内容阅读

**整改方案**
1. 全局统一增加「帮助」入口（问号图标），将快捷键、功能说明、专业术语解释统一收纳至悬浮弹窗，默认隐藏。
2. 页面仅保留一句话核心提示，长文本全部收拢到 tooltip 或帮助面板。
3. 专业术语统一增加问号图标，hover 显示通俗解释。

#### 2.2.2 左侧导航层级扁平，无分组与权重区分
**问题描述**
- 首页、笔记本、Todo、切换器、智能体、设置、关于全部平级展示
- 高频工作功能与低频系统功能无区分，用户扫描成本高
- 选中态辨识度低，当前所在页面感知弱

**整改方案**
1. **导航分组**
   - 工作区：首页、Markdown 笔记本、Todo 看板、Claude 切换器、智能体
   - 系统：设置、关于
   - 两组之间用细分割线区隔
2. **选中态统一**：采用「浅米色背景 + 左侧 2px 橙色竖线」，移除小对勾图标
3. **图标统一**：所有导航条目使用线性图标，选中时图标变为橙色

#### 2.2.3 空状态缺少引导，操作路径断裂
**问题描述**
- 看板空列、配置片段空列表、无搜索结果等场景，仅展示「暂无数据」纯文字
- 没有配套快捷操作按钮，用户需要自行寻找新建入口，操作路径断裂
- 空状态无情感化设计，页面空旷生硬

**整改方案**
1. 所有空状态统一格式：图标 + 提示文案 + 快捷操作按钮
2. 按钮就近原则：空状态按钮直接触发对应场景的新建操作
3. 示例：
   > 暂无任务
   > [ + 添加任务 ]

#### 2.2.4 可复制信息缺少快捷操作，效率不足
**问题描述**
- Git commit 号、文件路径、配置地址、API 地址等开发高频复制内容，仅纯文本展示
- 用户需要手动选中复制，操作繁琐，且容易选不全

**整改方案**
1. 所有代码类、路径类、哈希类文本，hover 时显示复制图标
2. 点击一键复制，复制成功后给出轻量 toast 提示
3. 关于页增加「复制全部环境信息」按钮，一键复制所有版本与依赖信息

---

### 2.3 P2 级：细节体验优化（远期优化）
#### 2.3.1 hover 与反馈状态缺失
**问题描述**
- 卡片、列表行、按钮多数缺少 hover 反馈
- 拖拽操作无占位提示与视觉反馈
- 操作成功/失败缺少轻量提示

**整改方案**
1. 可点击元素统一增加 hover 状态（背景加深、轻微上浮阴影）
2. 拖拽卡片时增加目标位置占位条
3. 关键操作（保存、复制、启用）增加 1.5s 自动消失的 toast 反馈

#### 2.3.2 Tooltip 体系缺失
**问题描述**
- 图标按钮无文字提示，用户需要猜测含义
- 专业术语、缩写无解释
- 截断文字无悬浮展示完整内容

**整改方案**
1. 纯图标按钮必须带 tooltip 说明功能
2. 文字超出省略号时，hover 展示完整内容
3. 专业术语、缩写增加 tooltip 解释

## 三、分页面详细整改方案

### 3.1 首页（工作台概览页）
#### 3.1.1 布局与结构问题
1. **数据卡片信息密度低**：5 个指标卡片横向平铺，单卡片仅展示数字+一行说明，空间利用率低
2. **图表区域占比过大**：「今日 Token 用量分布」图表高度占页面近 1/2，无数据时大面积空白，页面空旷
3. **操作按钮权重均分**：底部三个操作按钮宽度均分，视觉权重相同，无法体现「新建笔记」的高频优先级
4. **功能入口重复**：右上角「设置」按钮与左侧导航「设置」入口功能完全重复

#### 3.1.2 信息层级问题
1. 欢迎语「欢迎回来～」偏生活化，与开发工具的专业定位匹配度一般
2. 指标卡片缺少趋势或对比信息，数据价值弱
3. 无数据状态仅纯文字提示，缺少引导

#### 3.1.3 整改方案
| 问题点 | 整改建议 |
| ---- | ---- |
| 数据卡片布局 | 保持 5 列布局，优化卡片内信息密度；增加微小趋势标识（↑↓） |
| 图表区域 | 无数据时展示骨架屏或示例趋势线，避免大面积空白；降低图表默认高度 |
| 操作按钮 | 区分主次：「+新建笔记」为橙色主按钮且宽度最大；「+新建任务」为次按钮；「切换 Claude Profile」为文字按钮 |
| 入口重复 | 移除右上角「设置」按钮，仅保留「刷新」按钮 |
| 标题优化 | 标题改为「工作台」，保留日期信息，风格更贴合工具定位 |
| 空状态 | 图表空状态增加引导文案：「今日暂无 API 调用，启动 Claude 代理后将展示用量统计」 |

### 3.2 Markdown 笔记本页面
#### 3.2.1 顶部区域问题
1. **视图切换误用按钮样式**：「编辑/实时/双栏/预览」使用实心橙色按钮作为 Tab，与「新建笔记」主按钮语义冲突
2. **快捷键说明常驻**：标题下方长串快捷键提示持续展示，视觉噪音大
3. **标签添加入口隐蔽**：标签输入框右上角悬浮红点加号按钮，用户难以发现

#### 3.2.2 文件树面板问题
1. **缺少类型区分**：文件夹与 md 文件均为纯文字，无图标区分，识别成本高
2. **新建按钮位置不合理**：「+笔记」「+文件夹」放在面板最底部，不符合从上到下的浏览流
3. **选中态样式弱**：仅背景色变化，辨识度不足
4. **搜索功能简单**：无清空按钮，无搜索结果高亮

#### 3.2.3 编辑器区域问题
1. 底部状态栏信息含义不明确（「1.1」指代不明）
2. 缺少面包屑导航，当前笔记路径感知弱
3. 自动保存状态反馈不足

#### 3.2.4 整改方案
| 问题点 | 整改建议 |
| ---- | ---- |
| 视图切换 | 改为标准 Tab 样式（下划线激活），与全局规范统一 |
| 快捷键说明 | 移入右上角帮助图标，默认隐藏；hover 弹出快捷键面板 |
| 标签组件 | 标签输入框内置「添加标签」按钮，操作入口直观化 |
| 文件树 | 增加文件夹/文件图标；新建按钮上移至搜索框右侧；选中态统一为左侧竖线+浅背景 |
| 搜索框 | 增加清空按钮；搜索命中时在树中高亮关键词 |
| 编辑器 | 增加面包屑导航展示当前路径；底部状态栏增加 tooltip 解释；保存状态给出轻量提示 |

### 3.3 Todo 看板页面
#### 3.3.1 顶部工具栏问题
1. **「逾期 0」语义不明**：用户无法区分是统计展示还是可点击筛选按钮
2. **操作层级混淆**：「+列」（修改看板结构）与「+新建任务」（业务操作）两个不同层级操作并排摆放
3. **筛选能力缺失**：仅支持全局文本搜索，无法按优先级、负责人、截止日期筛选

#### 3.3.2 看板列问题
1. **列头控件拥挤**：编辑图标 + 添加卡片按钮紧挨着，hover 容易误触
2. **空状态无引导**：「已完成」列仅显示「暂无任务」纯文字，无快捷操作
3. **列宽不可调**：固定宽度，长标题挤压换行

#### 3.3.3 任务卡片问题
1. **选中态样式错误**：粗红色边框，与逾期告警语义冲突
2. **卡片信息单薄**：仅展示序号+标题，缺少优先级、截止时间、标签等关键信息
3. **序号含义模糊**：左上角圆形数字，用户无法判断是任务 ID 还是排序号
4. **已归档卡片无区分**：与活跃任务卡片视觉完全一致，干扰性强
5. **缺少 hover 反馈**：无拖拽感知，无快捷操作入口

#### 3.3.4 整改方案
| 问题点 | 整改建议 |
| ---- | ---- |
| 顶部工具栏 | 从左到右分为三组：搜索框、筛选统计区、操作按钮区；逾期标签支持点击筛选；区分「看板操作」与「任务操作」视觉权重 |
| 列头控件 | 增加按钮间距；扩大点击热区；hover 显示按钮功能提示 |
| 空状态 | 空列增加「+ 添加任务」快捷按钮，引导用户直接在当前列新建 |
| 卡片选中态 | 改为左侧橙色竖线 + 浅背景；红色边框仅用于逾期任务 |
| 卡片信息 | 增加优先级标记、截止时间预览；序号增加 tooltip 说明 |
| 归档卡片 | 降低透明度、文字灰度化，与活跃任务视觉区分 |
| 交互增强 | 卡片 hover 轻微上浮阴影；支持拖拽调整顺序与列；hover 展示快捷操作按钮 |
| 筛选能力 | 补充优先级、负责人、截止日期筛选下拉 |

### 3.4 Claude 切换器页面
#### 3.4.1 状态认知问题
1. **两套状态混淆**：「全局代理运行状态」与「Profile 选中状态」概念混淆，用户易将「ACTIVE」理解为代理正在运行
2. **说明文本过载**：长段配置接管说明常驻展示，信息密度过高

#### 3.4.2 左侧面板问题
1. **Profile 卡片选中态过重**：粗橙色边框，视觉冲击力强，易误认为异常
2. **卡片信息排版乱**：名称、地址、模型信息多行挤在一起，层级不清
3. **按钮无分组**：新建 Profile、导入、新建片段全部堆在面板最底部，不按模块就近分布

#### 3.4.3 右侧详情面板问题
1. **Tab 样式不统一**：橙色文字激活，与全局规范不一致
2. **模型映射列表**：「1M」含义不明，无 tooltip 解释；列表行无 hover 反馈
3. **底部按钮语义接近**：「启用」与「运行」两个按钮含义相近，用户易混淆
4. **说明文字过长**：按钮下方长段解释文字，阅读负担重

#### 3.4.4 整改方案
| 问题点 | 整改建议 |
| ---- | ---- |
| 状态区分 | 顶部独立展示全局代理状态（运行/停止）；Profile 的 ACTIVE 标签改为「当前选中」，轻量化展示 |
| 说明文本 | 长说明收拢到帮助图标，页面仅保留一句话摘要 |
| Profile 卡片 | 选中态改为左侧竖线+浅背景；信息结构化排版（名称加粗，地址模型灰色小字分行） |
| 按钮分组 | 按模块就近放置按钮：Profile 列表下方对应 Profile 操作；配置片段下方对应片段操作 |
| Tab 组件 | 统一为底部下划线激活样式 |
| 模型列表 | 「1M」增加 tooltip：「上下文窗口 1M tokens」；列表增加 hover 背景 |
| 底部按钮 | 区分「启用配置」与「运行会话」语义，分别增加 tooltip 解释；按钮按主次排序 |

### 3.5 设置页面
#### 3.5.1 布局与分组问题
1. **设置项无清晰分组**：功能模块开关与「供应商余量」混杂，没有分类标题区隔
2. **Tab 间距过大**：顶部 Tab 分散排布，页面顶部留白多
3. **表单基线不统一**：开关与左侧文字基线不对齐，阅读不顺畅

#### 3.5.2 内容与交互问题
1. **专业术语无解释**：「FTSS 全文搜索」「本地代理」等术语用户不易理解
2. **目录区域说明隐晦**：「只读」提示不明确，用户不知道为什么不能修改
3. **缺少生效提示**：用户不确定修改是否即时生效，是否需要保存

#### 3.5.3 整改方案
| 问题点 | 整改建议 |
| ---- | ---- |
| 设置分组 | 增加分组标题：「功能模块」「存储配置」「其他设置」，组间用留白或分割线区隔 |
| Tab 优化 | 收紧 Tab 间距，样式与全局规范统一 |
| 表单对齐 | 固定左侧标签宽度，开关统一右对齐，垂直基线对齐 |
| 术语解释 | 专业术语增加问号图标，hover 显示解释 |
| 目录区域 | 明确说明：「目录暂不支持修改，点击「打开目录」可定位文件」 |
| 生效提示 | 页面顶部或底部增加提示：「所有设置即时生效，自动保存到本地数据库」 |

### 3.6 关于页面
#### 3.6.1 视觉与布局问题
1. **背景装饰喧宾夺主**：大尺寸渐变圆形背景，与整体简约工具风格不符，干扰文字阅读
2. **信息列表排版松散**：两列不对齐，阅读视线跳跃
3. **版权信息隐蔽**：藏在页面最底部，几乎不可见

#### 3.6.2 功能缺失问题
1. **缺少一键复制功能**：开发者提 issue、排查问题时需要复制全部环境信息
2. **缺少检查更新**：关于页标配功能缺失
3. **缺少开源许可说明**：使用大量开源依赖，缺少许可证声明

#### 3.6.3 色彩语义问题
- Git commit、版本号使用红色高亮，与告警语义冲突

#### 3.6.4 整改方案
| 问题点 | 整改建议 |
| ---- | ---- |
| 背景优化 | 移除渐变圆形装饰，改为纯色或极淡纹理背景，突出信息卡片 |
| 排版优化 | 固定左侧标签宽度，内容右对齐，形成整齐基线 |
| 色彩修正 | commit 哈希与版本号改为橙色高亮，增加一键复制按钮 |
| 功能补充 | 增加「复制全部信息」「检查更新」按钮 |
| 许可声明 | 增加开源许可证模块，清晰展示依赖库与协议 |
| 版权信息 | 放入卡片底部，独立展示 |

### 3.7 新建任务弹窗
#### 3.7.1 布局与排版问题
1. **控件排布混乱**：模型槽位、迭代上限、允许破坏性操作挤在同一行，标签与控件对应关系不清晰
2. **说明文字截断**：迭代上限下方的辅助文案被截断，用户无法完整阅读
3. **输入框大小不合理**：迭代上限输入框过窄，与周围控件间距不均

#### 3.7.2 认知与风险问题
1. **专业术语无解释**：迭代上限、模型槽位、system prompt、破坏性操作等术语对普通用户不友好
2. **高危操作无警示**：「允许破坏性操作」属于高危权限，与普通开关样式无差异，无风险提示
3. **按钮主次冲突**：右上角「AI 生成草稿」与底部「保存」同为橙色主按钮，视觉权重冲突

#### 3.7.3 整改方案
| 问题点 | 整改建议 |
| ---- | ---- |
| 布局重构 | 按模块纵向分组：「任务目标」「基础配置」「高级配置」「高危选项」，每组独立标题，控件纵向对齐 |
| 说明文案 | 长说明移入 tooltip，页面只保留简短描述；避免文字截断 |
| 术语解释 | 所有专业术语增加问号帮助图标，hover 显示通俗解释 |
| 高危操作 | 单独成组；开关开启时文字变橙红色，增加 ⚠️ 图标；tooltip 详细说明风险 |
| 按钮层级 | 「AI 生成草稿」改为次按钮样式，「保存」保留橙色主按钮，明确主次 |
| 表单校验 | 任务目标为空时，保存按钮置灰并提示必填 |

## 五、设计体系建设建议

1. **建立基础设计系统**
   - 统一色彩、字体、间距、圆角、阴影基础令牌
   - 沉淀通用组件库（按钮、Tab、开关、卡片、弹窗、列表）
   - 所有新页面严格复用组件，避免碎片化样式

2. **制定交互规范**
   - 统一空状态、加载态、错误态、成功反馈的交互模式
   - 明确 tooltip、弹窗、抽屉的使用场景与规范
   - 建立快捷键体系规范

3. **建立设计走查机制**
   - 功能上线前增加 UI 走查环节
   - 定期进行全产品体验巡检，及时发现不一致问题

4. **以「开发者效率工具」为核心设计原则**
   - 信息优先：减少装饰，突出内容
   - 操作高效：减少路径，增加快捷操作
   - 低干扰：减少常驻提示，避免打断用户专注
   - 专业感：克制的色彩、清晰的层级、一致的规范
