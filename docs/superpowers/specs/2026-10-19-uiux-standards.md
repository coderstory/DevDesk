## 1 总则

### 1.1 设计原则（四条）

1. **信息优先**：减少装饰元素，突出内容与数据；色彩只服务于信息传达与操作反馈。
2. **操作高效**：缩短操作路径，关键操作就近布局；高频功能视觉权重最高。
3. **低干扰**：减少常驻提示与视觉噪音，辅助信息按需出现，不打断用户专注。
4. **专业感**：克制的色彩、清晰的层级、一致的规范，不拟人化、不情绪化。

验收方法：每项设计决策对照四条原则逐条核；任一新页面/组件不合任一条即判违规。

### 1.2 微信基调

整体风格对标微信 PC 端设计语言（出自 v1.0 §1 第 44 行）：浅灰基底（#F7F7F7）、绿色主色（#07C160）、细分割线（#E5E5E5/#EDEDED）、轻量卡片（白底+极淡阴影）、圆角克制（6-8px）、扁平无渐变。

验收方法：任一页面/组件用"与微信 PC 端同功能区域做逐项视觉对照"作为通过判据。

### 1.3 适用范围

本规范覆盖 DevDesk 全部现有页面（首页/笔记/待办/Claude 切换器/智能体/设置/关于）及未来所有新增页面。新增页面开发前必须先读本规范，不符合的 PR 不得合并。

验收方法：新 PR diff 对照本规范逐节核，任一条不合即不得合并。

**语义例外（D-12 校准，demo 真机点击校准 2026-10-19）**：优先级圆点（Todo/任务卡片上的优先级标记）使用 红=高/灰=中/绿=低 三色，其中"绿=低优先级"例外于 §2.2 语义规则"绿=操作+高亮"——优先级圆点是状态指示（与 §8 第 3 项"红/橙色做普通信息高亮"不同语义域），按状态语义而非操作语义着色。本例外仅适用于优先级圆点，不推广至其他绿色用法。

### 2.2 语义规则

| 颜色 | 允许的语义 | 禁止的语义 |
| ---- | ---- | ---- |
| 绿（#07C160） | 操作（主按钮）、高亮（选中/激活/成功） | 无（语义已收敛） |
| 红（#FA5151） | 告警（错误/逾期/危险操作） | 普通选中态、普通信息高亮 |
| 蓝（#576B95） | 链接跳转 | 标题、按钮、选中标识 |
| 中性灰序列 | 分割、hover、辅助文字、背景 | 表达操作、表达状态（操作/状态走绿或红） |

禁止项：大面积渐变背景、装饰性色块、多余底色、暖橙/米色旧色板残留。

验收方法：grep 全量 Color/RGBA 字面量并逐处对色板；新增色值必须引用 token 槽位，禁止裸 hex（出自 D-03 令牌唯一落点）。

## 3 尺寸令牌

### 3.1 间距（8px 网格）

定义在 `src\core\theme.h` 的 `SizeTokens`。

| 场景 | 数值 | 出处 |
| ---- | ---- | ---- |
| 模块间距 | 16px | v1.0 §2.3 |
| 列表项间距 | 8px | v1.0 §2.3 |
| 卡片内边距 | 16px | v1.0 §2.3 |
| 弹窗内边距 | 16px | v1.0 §2.3，D-12 校准（原 24px；demo 真机点击校准 2026-10-19，24px 偏松，16px 更贴合内容紧凑度） |
| 页面外 padding | 12px | v1.0 §2.3，D-12 校准（原 16px；指页面内容区到窗口外缘的留白，与"模块间距"语义不同——模块间距是页面内部块与块之间的间距） |

### 3.2 圆角

**统一圆角 6px（D-12 校准，demo 真机点击校准 2026-10-19，替换 v1.0 §2.2.5 三档 6/8/4）**：原三档圆角（按钮 6 / 卡片 8 / 输入框 4）在 demo 真机点击中视觉碎裂感明显，统一 6px 后整体性更强、与微信 PC 端克制圆角口径一致。

| 元素 | 数值 | 出处 |
| ---- | ---- | ---- |
| 按钮 | 6px | v1.0 §2.2.1，D-12 统一 |
| 卡片 | 6px | v1.0 §2.2.5，D-12 校准（原 8px） |
| 输入框 | 6px | v1.0 §2.2.5，D-12 校准（原 4px） |

### 3.3 字号

| 层级 | 大小 | 使用场景 | 出处 |
| ---- | ---- | ---- | ---- |
| 标题 | 16-18px | 页面大标题 | v1.0 §2.4 |
| 主文字 | 14px | 核心内容、列表主文字 | v1.0 §2.4 |
| 说明文字 | 12px | 次要信息、时间戳、标签 | v1.0 §2.4 |

### 3.4 字体

全局使用系统默认无衬线字体（Windows：微软雅黑；Mac：苹方），对齐微信字体策略（v1.0 §2.4）。

验收方法：截图对照 Windows 端字体为微软雅黑（非宋体/等宽）；Mac 端为苹方。

### 3.5 落地映射

尺寸与颜色令牌唯一落点为 `src\core\theme.h` 的 `ColorTokens` / `SizeTokens` 结构（出自 EUI 审计"样式架构总述"，D-03）。模块层组件通过 `src\core\component_theme.h` 的 `componentTokens()` 桥接到 EUI-NEO 组件主题，禁用 EUI 内置 `light()`/`dark()` 防止色源分裂。19 处（下界，白色字面量未计，出 EUI 审计 L125d）手工色字面量（分布 9 文件）随所属页面工单逐页清理，禁止一次性全量替换（出自 D-03"新旧槽位并存、逐页切换"）。

验收方法：`SizeTokens` 字段值与上表一致；`ColorTokens` 字段值与 §2.1 色板全表一致；`componentTokens()` 映射覆盖全部新增槽位。

### 3.6 布局框架

整体布局采用三栏结构（出自 v1.0 §2.3.1）：侧边栏 200px（图文模式）、中栏 240-280px、右区自适应。具体宽度数值延后至设计文档拍板，W3/W8 核实现状后对齐。

**中栏文件树宽校准（D-12，demo 真机点击校准 2026-10-19）**：Markdown 笔记本的中栏文件树宽固定 **220px**（v1.0 §3.3.3 区间 240-280px 偏松，demo 实测 220px 更贴合文件名长度与中栏视觉重量）；Todo 列宽 240px 在原区间内保持不变。

验收方法：各页面截图对照三栏布局；Markdown 文件树宽 = 220px、Todo 列宽 = 240px（D-12 校准）。

## 4 组件规范

### 4.1 按钮（四级体系）

| 级别 | 视觉定义 | 使用场景 | 禁止项 |
| ---- | ---- | ---- | ---- |
| 主按钮 | 微信绿填充（#07C160）+ 白色文字 + 圆角 6px | 核心确认操作：新建、保存、启用、确认 | 同一视口多于 1 个主按钮（操作权重必须唯一，规范自增，签认可删） |
| 次按钮 | 浅灰底（#F2F2F2）+ 深灰文字 + 圆角 6px | 次要操作：取消、编辑、测试、导入 | 与主按钮视觉等权（等宽/等色） |
| 文字按钮 | 纯绿色或灰色文字，无背景 | 辅助操作：复制、查看详情、更多 | 表达核心确认操作 |
| 危险按钮 | 红色填充 + 白色文字 | 删除、高危操作确认 | 表达普通操作 |

通用禁止：按钮阴影、边框（填充按钮）、圆角超过 8px（规范自增，签认可删；出自 v1.0 §2.2.1"按钮无阴影、无边框、填充纯色、圆角小而克制"）。

**统一尺寸（D-12 校准，demo 真机点击校准 2026-10-19，规范 §4.1 新增）**：主按钮/次按钮高度 **32-36px**、左右 padding **8-12px**、字号 **14px**；文字按钮字号同 14px、无背景无 padding 限定（按文字宽度）。四级按钮共用同一高度档，避免同视口内按钮高低错落。本尺寸为页面级 chrome 约束，与 §7.6 1080P 不溢出政策配套。

验收方法：遍历每个页面的每条按钮，检查视觉样式是否落入上表对应级别，并确认同视口主按钮唯一；同视口按钮高度一致（32-36px 区间内同一档位）。

### 4.2 Tab

视觉定义：未激活=灰色文字（#666666），无背景；激活=深灰文字（#1A1A1A）+ 底部 2px 微信绿（#07C160）下划线，下划线长度与文字对齐（出自 v1.0 §2.2.3）。

使用场景：视图切换、设置分页、详情面板分页。

**禁止项**：使用实心填充按钮作为 Tab 切换（出自 v1.0 §3.3"视图切换改为微信式 Tab，移除原橙色实心按钮"）；使用粗边框表达选中；Tab 间距过大（设置页当前问题的纠正，v1.0 §3.6）。

EUI 实现注记：微信式 Tab 为 **W2 自建组件**（基于既有 EUI 基础能力：shapes 三态 states（EUI 审计 L35）/ mouseArea（EUI 审计 L34）/ 显式传值；经 R2a 审计 grep 负结论证实（`audits/2026-10-19-standards-audit-R2a.md` 🔴2；EUI 审计原文无组件级条目））。

验收方法：统计全仓 `<Tabs>`/tab 渲染调用，验证每条符合上表视觉；grep 实心按钮 id 不含 tab/切换语义。

### 4.3 选中态

视觉定义（出自 v1.0 §2.2.2）：深灰背景（#E5E5E5）+ 左侧 2px 微信绿（#07C160）竖线 + 深灰文字（#1A1A1A），无加粗、无多余装饰。

适用：导航条目、列表条目、卡片选中、文件树选中、Profile 选中。

**禁止项**：红色/橙色粗外边框作为普通选中态（出自 v1.0 §3.4"完全移除原红色粗边框"及 D-01"五项冲突"）；小对勾标记（出自 v1.0 §3.1"移除原小对勾标记"）。

EUI 实现注记：SelectionBar 为 ui_kit 新增组件（整改规划 W2），封装 2px 左竖线 + 深灰背景组合。

验收方法：遍历每个区域的选中态渲染路径，检查无粗边框、无对勾、竖线颜色为 #07C160。

### 4.4 开关

视觉定义（出自 v1.0 §2.2.4）：关闭态=灰色轨道 + 白色滑块；开启态=微信绿（#07C160）轨道 + 白色滑块。圆形滑块、圆角轨道。

使用场景：模块开关、功能开关、配置项开关。

EUI 实现注记：微信式开关为 **W2 自建组件**（基于既有 EUI 基础能力：shapes 三态 states（EUI 审计 L35）/ mouseArea（EUI 审计 L34）/ 显式传值；经 R2a 审计 grep 负结论证实（`audits/2026-10-19-standards-audit-R2a.md` 🔴2；EUI 审计原文无组件级条目））。

验收方法：模块开关/功能开关渲染页截图对照；probe 中验证开关开启态轨道色值为 #07C160。

### 4.5 卡片

视觉定义：纯白背景（#FFFFFF）+ 极淡阴影或纯分割线 + 圆角 6px（D-12 校准，原 8px；出自 v1.0 §2.2.5）。卡片之间优先用留白与分割线区分，少用卡片嵌套（v1.0 §2.3）。

使用场景：数据卡片、内容面板、列表项卡片。

**禁止项**：厚重描边（超过 1px）、渐变背景、内阴影、多层嵌套卡片。

验收方法：截图对照卡片样式；检查无渐变、无厚度超过 1px 的描边。

### 4.6 输入框

视觉定义：纯白背景（#FFFFFF）+ 1px 灰色边框 + 圆角 6px（D-12 校准，原 4px）；focus 时边框变微信绿（#07C160）（出自 v1.0 §2.2.5）。

使用场景：搜索框、表单输入、标签输入。

**禁止项**：厚重描边、渐变、内阴影、focus 时边框不变色。

验收方法：截图对照输入框样式；probe 中验证 focus 态边框颜色。

### 4.7 分割线

一级分割线（#E5E5E5）：模块之间、大区域之间。二级分割线（#EDEDED）：列表项之间、卡片内部。

原则：优先用留白区分，分割线用于留白不足时（出自 v1.0 §2.3）。

验收方法：检查每个使用分割线的场景，验证色值与粗细。

### 4.8 导航栏

视觉定义（出自 v1.0 §3.1）：侧边栏背景=浅灰（#F7F7F7）；选中态=深灰背景（#E5E5E5）+ 左侧 2px 微信绿竖线 + 图标同步变绿（图标口径待 P-02 拍板，默认 FA7 Solid 重着色）。分组：上半区（首页/笔记本/Todo/Claude/智能体）+ 下半区（设置/关于），组间细分割线分隔。

**禁止项**：选中态用对勾标记；分组不清；图标彩色底色。

EUI 实现注记：侧边栏选中态换用 SelectionBar（W3 整改规划）；图标按 P-02 口径（默认 FA7 Solid 重着色）。

验收方法：截图对照导航选中/未选中双态；`test_app_sidebar.cpp:232`（文本断言 `label->text == "首页"`）和 `:371`（文本断言 `"智能体"`）——分组不改动这两个标签则不红（出测试影响面审计 L125 所引行号）。

### 4.9 Tooltip

视觉定义：纯白背景 + 灰色文字 + 圆角 + 阴影，hover 触发、移出消失。

使用场景：纯图标按钮功能说明、专业术语解释、文字截断时展示完整内容、缩写说明。纯图标按钮**必须**带 tooltip（出自 v1.1 §2.3.2"纯图标按钮必须带 tooltip 说明功能"）。

**禁止项**：tooltip 内嵌长段文字（建议超过 3 行收帮助浮层；建议值，签认可调）。

EUI 实现注记：EUI-NEO tooltip 机制现成但需逐处 source 绑定，无自动挂载（出自 EUI 审计 L42-L44）。

验收方法：hover 每个纯图标按钮确认 tooltip 出现；hover 专业术语旁问号图标确认解释文字。

### 4.10 轻提示（Toast）

视觉定义：黑色半透明背景 + 白色文字 + 圆角，居中显示，1.5s 自动消失（出自 v1.0 §四 第 3 条）。

使用场景：保存成功、复制成功、操作完成等非阻塞反馈。

EUI 实现注记：EUI 审计自认 toast.h 200 行后布局细节未读（存疑，出 EUI 审计 L125c）。既有通知式 toast 保留不迁移；微信式黑色半透明居中轻提示为 ui_kit 新增小组件（出自整改规划 W2 与"风险"段）。两种 toast 并存，新反馈点用微信式，旧调用不动。

验收方法：截图对照 toast 样式（黑底+白字+居中）；验证 1.5s 自动消失。

### 4.11 右键菜单

视觉定义（出自 v1.0 §四 第 2 条）：纯白背景 + 灰色分割线 + 黑色文字，hover 浅灰背景。

EUI 实现注记：EUI-NEO contextMenu 机制现成（出自 EUI 审计 L64）。

验收方法：右键触发菜单并截图对照。

### 4.12 空状态

视觉定义（出自 v1.0 §四 第 6 条）：极简文字 + **可选**操作按钮（全场景允许）。无插画、无情绪化表达，保持工具中性。

规则：空状态按钮必须**就近**触发对应场景的创建操作（出自 v1.1 §2.2.3"按钮就近原则"）。Todo 空列「+ 添加任务」为 v1.0 §3.4 明示实例。

**禁止项**：插画式空状态、情绪化文案（如"这里空空如也~"），空状态无操作入口（规范自增，签认可删）。

验收方法：遍历所有空状态场景（空列/空列表/无搜索结果/无数据图表），验证文案极简且按钮就近。

### 4.13 Hover 反馈

视觉定义：所有可点击元素 hover 时背景变浅灰（#EDEDED），无其他动效（出自 v1.0 §四 第 1 条）。卡片 hover 可加极淡阴影（出自 v1.1 §2.3.1，规范自增，签认可删），但不禁用底色变化。

EUI 实现注记：按钮/列表行 hover 已由 EUI-NEO 组件内建支持；VirtualList 行 hover 需自挂 mouseArea（出自 EUI 审计 L39）。

验收方法：鼠标划过每个可点击元素，确认出现背景色变化；检查无多余的放大/抖动/颜色跳变动效。

### 4.14 面板/列底灰底（D-12 校准，规范 §4 卡片强化）

视觉定义（D-12 校准，demo 真机点击校准 2026-10-19）：内容区/列底用浅灰底 `#F7F7F7`（或二级分割线色 `#EDEDED`），白卡浮起于其上——Todo 列底、Markdown 右区等。v1.0 §3.4.2（Todo 列底浅灰）与 §3.3.1（Markdown 右区浅灰）已有该视觉定义，D-12 加"强制"语气：内容区/列底**必须**用浅灰底（非白底），白卡靠 `#FFFFFF` 与底色对比浮起，不允许整页纯白底嵌套白卡（白卡浮起效果丧失）。

使用场景：Todo 看板的列底、Markdown 编辑器外的右区底、其他内容列表/网格的区底。

EUI 实现注记：直接复用 §2.1 已有 `pageBg`/`dividerSecondary` 令牌，无新组件。

验收方法：截图对照内容区/列底为浅灰底（非白底），白卡浮起效果可见；grep 确认对应元素底色引用 `pageBg`/`dividerSecondary` 令牌而非 `surfaceWechat`。

### 4.15 表单栅格（D-12 校准，规范 §4 表单强化）

视觉定义（D-12 校准，demo 真机点击校准 2026-10-19）：表单控件按栅格排列——label 定宽 **100-120px**（或占比 25-30%），control 填满剩余宽度。v1.1 §2.1.3 已有 120px 定宽，D-12 强化进规范并扩为区间。

使用场景：设置页设置项、弹窗分组表单、详情面板字段表单。

EUI 实现注记：在 ui_kit 层提供 FormRow helper（label 定宽 + control 填满），随 W2 落地。

验收方法：截图对照表单 label 宽度落入 100-120px（或占比 25-30%），control 填满剩余宽度；同表单内 label 宽度一致。

## 5 交互标准

### 5.1 表单校验

校验反馈：输入为空时保存按钮置灰（禁点击）；校验不通过时字段下方出现红色小字提示。对齐微信表单反馈方式（出自 v1.0 §3.8"输入为空时保存按钮置灰，表单校验提示用红色小字"）。

验收方法：空输入、格式错误输入各测一次，验证按钮置灰和红字提示。

### 5.2 高危操作警示

高危选项（如"允许破坏性操作"）：单独分组展示；开关开启时文字变红；增加警告图标；tooltip 详述风险（此半句出自 v1.1 §3.7.3；v1.0 §3.8 第 314 行含高危选项设计但无 tooltip）。所有涉及数据删除、不可逆操作的地方均适用此规范（规范自增，签认可删）。

验收方法：开关切换时文字变色截图；hover tooltip 内容含风险详述。

### 5.3 术语问号解释

所有专业术语（迭代上限、模型槽位、system prompt、1M tokens、FTS5 等）旁增加问号图标，hover 显示通俗解释（出自 v1.0 §3.5 第 245 行"'1M'增加 hover 提示：上下文窗口 1M tokens"）。问号图标本身需先验证字形渲染（出自 P-02 存疑项）。

验收方法：hover 每个问号图标，验证解释内容通俗易懂且正确。

### 5.4 帮助体系

全局统一「？」帮助入口：将快捷键说明、功能解释、专业术语一览统一收纳至悬浮弹窗，默认隐藏。页面仅保留一句话核心提示，长文本全部收拢到 tooltip 或帮助面板（出自 v1.1 §2.2.1"全局统一增加帮助入口"及 v1.0 §3.3"快捷键说明移入右上角帮助图标"）。

验收方法：检查各页面无长段常驻说明文本；帮助图标可触发悬浮弹窗。

### 5.5 拖拽反馈

拖拽时卡片半透明，目标位置显示绿色（#07C160）占位线（出自 v1.0 §3.4"拖拽时卡片半透明，目标位置显示绿色占位线"）。

EUI 实现注记：Todo 卡片拖拽已完整实现（出自 EUI 审计 L92），整改仅视觉重制（换绿色占位线颜色）。

验收方法：实跑拖拽操作并截图，验证拖拽中卡片半透明 + 目标位绿色占位线。

### 5.6 空状态触发

空状态"新建/添加"按钮必须就近放置，按钮直接触发对应场景的创建操作，用户无需另行寻找入口（出自 v1.1 §2.2.3"按钮就近原则"）。

验收方法：每个空状态场景点击按钮，确认触发正确的创建操作。

## 6 文案标准

### 6.1 一句话原则

页面仅保留一句话核心提示；长段说明文字、快捷键一览、功能解释全部收纳到帮助入口（出自 v1.1 §2.2.1）。

### 6.4 全中文

所有 UI 文案使用简体中文，技术专有名词例外（API、SQLite、Git 等保留英文）。（规范自增，签认可删）

验收方法：grep UI 文本字符串，确认无非 ASCII 英文文案（技术名词除外）。

## 7 验收方法学

### 7.1 测试三层形态

现有 UI 测试断言分三层（出自测试影响面审计 §任务三第 129 行）：(1) 元素 id 存在性与 onClick/onTextInput 接线（headless compose 后 `ui.find`，数量最多）；(2) 文本内容断言（`->text == / contains`，少数且集中）；(3) 几何数值断言（frame 恒值、不重叠、屏内、z 序）与颜色断言（theme token 或 hex 字面量）。无截图像素对比测试；截图仅作人工审阅证据（probe `--screenshot` 进程内 glReadPixels 落 PNG，不进断言）。

### 7.2 探针机制

真窗口探针已存在 6 个可执行文件：`home_probes` / `screenshot_probe` / `settings_dropdown_z_probe` / `module_toggle_sidebar_probe` / `agent_dialog_probe` / `agent_e2e_probe`（出自测试影响面审计第 131 行）。注册进 `ctest -L probe`，需单独执行（`build-test-run.sh` 与 CI 均不跑 probe；CI 设 `DEVDESK_BUILD_PROBES=0` 不编 probe）。Todo / Markdown / Claude / About 四区暂无专用探针（出自整改规划第 28 行），W0.1 补齐。

### 7.3 逐项验收清单模板

每项规范的验收由以下四步组成：

1. **截图对照**：改后截图与 v1.0 描述逐项对照，色值/间距/圆角/字号逐项标 Pass/Fail。
2. **关键交互实跑**：每页 3-5 条关键交互（点击/拖拽/输入/hover/右键）实际执行并记录结果。
3. **断言同步**：测试断言只许换期望值，不许删覆盖；删装饰类用例必须改写为"无装饰"反证断言（出自闸门 4，整改规划第 37 行）。
4. **diff 零业务逻辑审查**：独立审阅代理核 diff，确认无业务逻辑改动（出自铁律 1，整改规划第 16 行）。

### 7.4 验收写法示例

规范写法（可执行）："首页标题栏左侧文字必须为'工作台'，16px 深灰（#1A1A1A），验收方法：headless compose 后 `ui.find('home.h1')->text == '工作台'`。"

禁止写法（不可执行）："首页标题应该大气美观。"

### 7.5 交付口径

交付时报三行（出自全局纪律"测试数字不是交付证明"）：(1) 哪些业务场景实际跑起来了（真窗口/真网/真机）；(2) 结果如何；(3) 哪些没跑到（明写"未验证"）。**不报 Total/Passed 数字**。

### 7.6 1080P 约束与内滚动政策（D-12 校准，规范 §7 验收新增）

**页面级 chrome 不溢出 1080P**（D-12 校准，demo 真机点击校准 2026-10-19）：在 **1920×1080** 逻辑分辨率下，每页的页面级 chrome（标题栏、Tab 条、底部按钮栏、侧边栏等结构性元素）不允许溢出可视区，不允许页面级滚动条出现。

**内容区内滚动允许**：内容区（列表、日志、表格、调用记录、Markdown 文件树等长内容区域）允许内部滚动，对齐微信 PC 端长列表模式——内容区内部可滚、页面外壳不滚。**不加滚动条分页器**（不分页加载、不分页导航，长列表用纯内滚动消化）。

验收方法：在 1920×1080 逻辑分辨率下截图对照，页面级 chrome 完整可见无溢出；内容区滚动条出现位置限定在内容区内部（不出现页面级滚动条）；分页器元件不存在于本规范任何页面。

## 11 EUI 能力边界注记

以下结论出自 EUI 能力审计（EUI 审计 L9-L23 总矩阵 13 项），是组件实现注记的唯一来源。13 项中本次整改所需能力全部有实现路径；骨架屏无现成组件（已被 v1.0 空状态哲学排除，不需要）；FA 问号字形可用性存疑（W2 闭环验证）。

### 11.1 13 项能力状态摘要

| 序号 | 能力 | 状态 | 备注 |
| ---- | ---- | ---- | ---- |
| 1 | 主题/设计令牌 | 现成 | 双侧均有；DevDesk `theme.h` 为唯一色源（EUI 审计 L11） |

| 3 | tooltip | 现成 | 需逐处 source 绑定，无自动挂载（EUI 审计 L13+L44） |
| 4 | toast | 现成 | 自动消失有，多实例队列无；EUI 审计自认 toast.h 200 行后布局细节未读（存疑，EUI 审计 L14+L125c） |
| 5 | 弹出层 | 有机制、无通用组件 | stack+zIndex/dialog/styledMenu/多窗可承载帮助面板（EUI 审计 L15）；整改不依赖通用组件 |
| 6 | 下拉/菜单 | 现成 | dropdown/contextMenu/styledMenu；可搜索 combo 无（EUI 审计 L16） |
| 7 | 骨架屏 | 无组件 | 自绘基础齐备且有官方自绘先例（EUI 审计 L17）；**整改不依赖**（已被 v1.0 空状态哲学排除） |

### 11.2 三处现实缺口

| 缺口 | 影响 | 处置 |
| ---- | ---- | ---- |
