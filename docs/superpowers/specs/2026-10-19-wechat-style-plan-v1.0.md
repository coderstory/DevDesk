## 一、改造核心思路
本次改造**保留原有产品功能架构与信息逻辑**，全面替换视觉语言为微信PC端原生设计风格，核心目标：
1. **降低学习成本**：用户对微信界面有原生熟悉感，无需重新学习交互与视觉逻辑
2. **强化办公属性**：微信风格克制、低干扰、中性商务，适配开发者日常办公场景
3. **解决原有问题**：从根源解决原设计色彩语义混乱、组件不统一、视觉噪音大等问题
4. **保持工具效率**：不牺牲信息密度与操作效率，在极简风格下保留开发工具的专业性

整体风格对标：微信PC端 3.x 版本设计语言 —— 浅灰基底、绿色主色、细分割线、轻量卡片、圆角克制、扁平无渐变。

## 二、全局设计规范（微信风格）

### 2.1 色彩体系
完全替换原暖橙+米色体系，采用微信标准色板，语义清晰、视觉中性。

| 色彩类型 | 色值 | 使用场景 |
| ---- | ---- | ---- |
| 主色（微信绿） | `#07C160` | 主按钮、选中态标识、Tab激活、开关开启、成功提示 |
| 警示红 | `#FA5151` | 错误提示、逾期任务、危险操作、删除按钮 |
| 链接蓝 | `#576B95` | 文字链接、可跳转文本 |
| 页面背景 | `#F7F7F7` | 全局页面底色、侧边栏底色 |
| 卡片/内容区背景 | `#FFFFFF` | 内容卡片、输入框、弹窗、列表底色 |
| 一级分割线 | `#E5E5E5` | 模块分割、大区域分隔 |
| 二级分割线 | `#EDEDED` | 列表项分割、卡片内分隔 |
| 一级文字 | `#1A1A1A` | 标题、核心内容、列表主文字 |
| 二级文字 | `#666666` | 次要信息、说明文字、标签 |
| 三级文字 | `#999999` | 辅助信息、时间戳、置灰内容 |
| hover背景 | `#EDEDED` | 列表项、按钮、导航项鼠标悬浮 |
| 选中背景 | `#E5E5E5` | 导航选中、列表选中、卡片选中 |

> 色彩原则：全页面**无大面积渐变、无装饰性色块、无多余底色**，所有色彩只服务于信息传达与操作反馈。

### 2.2 核心组件规范
#### 2.2.1 按钮体系
| 按钮类型 | 视觉样式 | 使用场景 |
| ---- | ---- | ---- |
| 主按钮 | 微信绿填充 + 白色文字 + 圆角6px | 核心确认操作：新建、保存、启用、确认 |
| 次按钮 | 浅灰底(`#F2F2F2`) + 深灰文字 + 圆角6px | 次要操作：取消、编辑、测试、导入 |
| 文字按钮 | 纯绿色/灰色文字，无背景 | 辅助操作：复制、查看详情、更多 |
| 危险按钮 | 红色填充 + 白色文字 | 删除、高危操作确认 |

> 微信风格特点：按钮无阴影、无边框、填充纯色，圆角小而克制，视觉重量轻。

#### 2.2.2 导航与选中态
- 侧边导航：默认灰底灰字，**选中态深灰背景(`#E5E5E5`) + 左侧2px微信绿竖线 + 深灰文字**，无加粗、无多余装饰
- 列表选中：浅灰背景 + 左侧绿色细竖线，**全程取消粗边框选中样式**
- 选中逻辑：用「背景深浅变化 + 细侧边线」表达选中，替代原有的粗边框，视觉更克制

#### 2.2.3 Tab 标签
- 未激活：灰色文字(`#666666`)
- 激活：深灰文字 + 底部2px微信绿短下划线（长度与文字对齐）
- 无背景填充、无边框，完全对齐微信PC端Tab样式

#### 2.2.4 开关控件
- 关闭态：灰色轨道 + 白色滑块
- 开启态：微信绿轨道 + 白色滑块
- 圆形滑块、圆角轨道，完全对齐微信原生开关样式，替代原橙色开关

#### 2.2.5 卡片与输入框
- 卡片：纯白背景 + 极淡阴影或纯分割线 + 圆角8px
- 输入框：纯白背景 + 1px灰色边框 + 圆角4px，focus时边框变绿色
- 无厚重描边、无渐变、无内阴影

### 2.3 布局与间距
1. **整体框架**：沿用微信PC端三栏/两栏结构
   - 左侧导航栏：固定宽度60px（图标模式）/ 180px（图文模式），建议保留图文模式，宽度200px
   - 中间列表/文件树：固定宽度240-280px，白底，右侧细分割线
   - 右侧主内容区：自适应宽度，浅灰背景
2. **间距规范**：采用微信8px基础网格
   - 模块间距：16px
   - 列表项间距：8px
   - 卡片内边距：16px
   - 弹窗内边距：24px
3. **分割原则**：优先用留白和分割线区分模块，少用卡片嵌套，保持页面通透

### 2.4 字体与文字层级
- 标题：16px / 18px，一级字重，用于页面大标题
- 副标题/列表主文字：14px，常规字重，核心内容
- 说明/次要文字：12px，二级/三级文字色
- 全局使用系统默认无衬线字体（Windows：微软雅黑；Mac：苹方），对齐微信字体策略

## 三、分页面改造方案

### 3.1 左侧全局导航栏
**对标：微信PC端左侧侧边栏**

#### 原有问题
- 选中态辨识度低，样式不统一
- 功能平级，无分组
- 暖米色风格与办公场景匹配度低

#### 微信化改造点
1. **底色**：侧边栏背景改为浅灰(`#F7F7F7`)，与微信侧边栏一致
2. **选中态**：选中项深灰背景(`#E5E5E5`) + 左侧2px微信绿竖线，图标同步变绿，移除原小对勾标记
3. **导航分组**：
   - 上半区：首页、Markdown笔记本、Todo看板、Claude切换器、智能体（工作功能）
   - 下半区：设置、关于（系统功能）
   - 组间用细分割线分隔，对齐微信导航分组逻辑
4. **图标**：线性图标，选中时填充绿色，默认灰色，保持与微信图标一致的轻量化风格
5. **Logo区**：左上角DevDesk Logo简化，深色文字，无多余装饰

### 3.2 首页（工作台）
**对标：微信PC端「收藏」「文件传输助手」概览页**

#### 原有问题
- 背景装饰重，卡片风格不统一
- 按钮主次不分，功能入口重复
- 数据卡片信息密度低

#### 微信化改造点
1. **页面底色**：全局浅灰背景(`#F7F7F7`)，移除原渐变圆形装饰
2. **顶部标题栏**：
   - 左侧标题「工作台」，16px深灰字
   - 右侧仅保留「刷新」文字按钮，移除重复的「设置」入口
   - 移除「欢迎回来～」生活化文案，风格克制中性
3. **数据卡片**：
   - 纯白背景 + 极淡阴影 + 圆角8px，横向均匀排布
   - 指标数字18px深灰，说明文字12px浅灰，层级清晰
   - 无数据时显示灰色占位「--」，保持卡片完整
4. **图表区域**：
   - 纯白卡片包裹，标题左对齐
   - 空状态显示浅灰文字「今日暂无API调用」，居中，无多余引导
5. **底部操作按钮**：
   - 「+新建笔记」：微信绿主按钮，视觉权重最高
   - 「+新建任务」：浅灰次按钮
   - 「切换Claude Profile」：浅灰次按钮
   - 三个按钮不等宽，主按钮更宽，对齐微信按钮主次逻辑

### 3.3 Markdown 笔记本页面
**对标：微信PC端聊天列表 + 聊天内容区结构**

#### 原有问题
- 视图切换Tab误用按钮样式
- 快捷键说明常驻，视觉噪音大
- 文件树缺少层级区分

#### 微信化改造点
1. **三栏结构对齐微信**：
   - 左：全局导航
   - 中：笔记本目录/文件树（白底，右侧分割线）
   - 右：编辑器主内容区（浅灰底，编辑器卡片纯白）
2. **顶部工具栏**：
   - 视图切换（编辑/实时/双栏/预览）改为微信式Tab，绿色下划线激活，移除原橙色实心按钮
   - 快捷键说明移入右上角「？」帮助图标，hover弹出，默认隐藏
   - 「+新建笔记」主按钮绿色填充，放在右上角
3. **中间文件树**：
   - 搜索框：灰色边框 + 圆角4px，内置搜索图标
   - 列表项：文件夹📁、文件📄图标区分，14px深灰文字
   - 选中态：浅灰背景 + 左侧绿色竖线，和微信聊天列表选中逻辑一致
   - 「+笔记」「+文件夹」按钮放在搜索框右侧，图标按钮，hover显示文字
4. **编辑器区域**：
   - 编辑器纯白背景，浅灰分割线区分标题区与内容区
   - 标签输入框：浅灰底，圆角4px，标签绿色小字
   - 底部状态栏：12px浅灰文字，右对齐，显示字数、保存状态

### 3.4 Todo 看板页面
**对标：微信待办 + 微信会话卡片风格**

#### 原有问题
- 选中卡片红/橙粗边框，语义冲突
- 顶部控件混杂，筛选能力弱
- 归档卡片与活跃卡片无区别

#### 微信化改造点
1. **顶部工具栏**：
   - 左侧：搜索框（灰色边框，圆角4px）
   - 中间：「逾期」筛选标签，默认灰色，点击后绿色高亮
   - 右侧：「+列」文字按钮（灰色） + 「+新建任务」绿色主按钮
   - 操作层级清晰，区分看板结构操作与任务新建操作
2. **看板列**：
   - 列头：14px深灰标题 + 数字角标，右侧编辑、添加图标按钮
   - 列背景：浅灰底色，与页面底色接近，卡片浮于其上
   - 空列：居中浅灰文字「暂无任务」，下方小字「+ 添加任务」绿色文字按钮
3. **任务卡片**：
   - 纯白背景 + 圆角6px + 极淡阴影，对齐微信消息卡片
   - 选中态：浅灰背景 + 左侧2px绿色竖线，**完全移除原红色粗边框**
   - 逾期卡片：左侧2px红色竖线，标题红色，语义明确
   - 已归档卡片：文字降为三级灰，透明度0.7，视觉弱化
   - 卡片信息：标题 + 优先级标签 + 截止时间，信息精简
4. **交互**：拖拽时卡片半透明，目标位置显示绿色占位线，对齐微信拖拽反馈

### 3.5 Claude 切换器页面
**对标：微信设置页 + 会话详情结构**

#### 原有问题
- 两套状态混淆，用户易误解
- 按钮无分组，排版混乱
- 专业术语无解释

#### 微信化改造点
1. **顶部状态区**：
   - 左侧标题「Claude切换器」
   - 右侧独立展示代理状态：灰色圆点+「已停止」/ 绿色圆点+「运行中」
   - 「启动代理」按钮绿色主按钮，放在状态旁，明确是全局操作
2. **左右分栏**：
   - 左：Profile列表（白底，右侧分割线）
   - 右：Profile详情（浅灰底，详情卡片纯白）
3. **左侧Profile列表**：
   - 卡片改为列表项，头像/图标 + 名称 + 地址小字
   - 选中态：浅灰背景 + 左侧绿色竖线，移除原橙色粗边框
   - 「当前选中」标签改为绿色小圆角标签，放在列表项右侧
   - 列表底部：「+新建Profile」「导入」按钮，浅灰次按钮
4. **右侧详情区**：
   - Tab标签：基础信息/模型映射/环境变量，绿色下划线激活
   - 模型映射列表：每行左对齐模型名，右侧开关 + 说明文字
   - 「1M」增加hover提示：「上下文窗口1M tokens」
   - 底部操作按钮：
     - 主按钮：「启用」绿色填充
     - 次按钮：「测试连通」「编辑」浅灰底
     - 「运行」独立为文字按钮，区分语义
5. **共享配置片段**：独立成下方模块，列表式展示，空状态引导新建

### 3.6 设置页面
**对标：微信PC端「设置」页面**

#### 原有问题
- 设置项无分组，排版松散
- 术语无解释，基线不统一
- Tab间距过大

#### 微信化改造点
1. **顶部Tab**：通用/模块/日志/同步，绿色下划线激活，间距收紧
2. **设置分组**：
   - 每组有分组标题（14px深灰，加粗）
   - 组内设置项纵向排列，左对齐标签，右对齐开关/按钮
   - 组间用留白+分割线区隔，完全对齐微信设置页排版
3. **功能模块开关组**：
   - 每个开关项：功能名称 + 下方小字说明
   - 开关统一右对齐，微信绿开启样式
   - 「供应商余量」单独分组，标注「实验功能」
4. **存储目录区域**：
   - 分组标题「Markdown笔记目录」
   - 路径输入框：只读灰底，右侧「打开目录」浅灰按钮
   - 下方小字说明：「目录暂不支持修改，打开后可手动迁移文件」
5. **全局提示**：页面底部小字「所有设置即时生效，自动保存到本地数据库」

### 3.7 关于页面
**对标：微信「关于微信」极简信息页**

#### 原有问题
- 背景装饰重，色彩语义混乱
- 排版松散，缺少功能
- 版权信息隐蔽

#### 微信化改造点
1. **页面结构**：居中卡片，纯白背景，圆角8px，浅灰页面底色，移除所有渐变装饰
2. **卡片内容**：
   - 顶部：DevDesk图标 + 应用名称，居中
   - 信息列表：两列对齐，左标签右内容，分割线分隔每行
   - Git commit、版本号：绿色文字，hover显示复制图标，移除原红色高亮
3. **操作按钮**：
   - 「检查更新」绿色主按钮
   - 「复制全部信息」浅灰次按钮
   - 按钮居中排列在卡片底部
4. **底部**：版权与开源声明，12px浅灰文字，居中在页面最底部
5. **风格原则**：极简、信息优先，无多余装饰，完全对齐微信关于页的克制感

### 3.8 新建任务弹窗
**对标：微信PC端新建/编辑弹窗**

#### 原有问题
- 控件排布混乱，说明文字截断
- 高危操作无警示，按钮主次冲突
- 专业术语无解释

#### 微信化改造点
1. **弹窗结构**：
   - 顶部标题栏：「新建任务」居中，右上角关闭按钮
   - 中间表单区域：纵向分组排列
   - 底部按钮区：「取消」「保存」左右排列
2. **表单分组**：
   - 任务目标：大输入框，占满宽度，必填项标红
   - 基础配置：触发方式、模型槽位，下拉选择框
   - 高级配置：迭代上限、执行记忆，输入框+说明
   - 高危选项：「允许破坏性操作」单独分组，开关开启时文字变红，增加⚠️提示
3. **控件样式**：
   - 输入框、下拉框：灰色边框，圆角4px，focus变绿
   - 开关：微信样式，开启绿色
   - 专业术语后加「？」图标，hover显示解释
4. **按钮区**：
   - 右下角：「取消」浅灰按钮 + 「保存」绿色主按钮
   - 右上角「AI生成草稿」改为绿色文字按钮，不抢占主按钮视觉权重
5. **交互**：输入为空时保存按钮置灰，表单校验提示用红色小字，对齐微信表单反馈

---

## 四、交互体验微信化适配
1. **hover反馈统一**：所有可点击元素，hover时背景变浅灰，无其他夸张动效
2. **右键菜单**：对齐微信右键菜单样式，纯白背景、灰色分割线、黑色文字，hover浅灰背景
3. **toast提示**：黑色半透明圆角提示，居中显示，1.5s自动消失，对齐微信轻提示
4. **快捷键体系**：保留原有快捷键，增加微信常用快捷键支持（Ctrl+F搜索、Ctrl+N新建等）
5. **拖拽交互**：轻量半透明拖拽，占位线提示，无厚重阴影
6. **空状态**：极简文字+可选操作按钮，无插画、无情绪化表达，保持工具中性

---

## 五、改造价值总结
| 维度 | 改造前 | 改造后（微信风格） |
| ---- | ---- | ---- |
| 视觉风格 | 暖米色工具风，装饰元素多，个性强 | 冷灰极简办公风，克制中性，普适性强 |
| 色彩语义 | 橙/红色语义混乱，选中与告警冲突 | 绿/灰/红语义清晰，符合用户固有认知 |
| 组件规范 | 各页面组件不统一，学习成本高 | 完全对齐微信原生组件，用户零学习成本 |
| 视觉噪音 | 说明文字常驻，装饰元素多，干扰强 | 信息优先，辅助内容收拢，专注度高 |
| 场景适配 | 偏向个人工具风格 | 适配办公场景，专业感更强 |
| 交互体验 | 反馈样式多，逻辑不统一 | 交互逻辑与微信一致，操作自然顺手 |

本次改造**不改动产品功能与信息架构**，仅通过视觉语言与交互规范的替换，实现产品体验的整体升级，同时解决原有设计的核心问题，最终打造出开发者熟悉、低干扰、高效率的桌面工具体验。
