# DevDesk 上线模块设计（Release）

> **创建日期**：2026-10-27
> **模块**：`module_release`（新）
> **状态**：设计定稿，待拆任务

---

## 1. 定位与边界

把「一个人负责的、多环境多服务的发布流程」变成一份可留痕的清单式执行台。

**做什么**：配置管理、完整性校验、按时间点提醒、按步骤逐条确认、全程留痕。

**明确不做**（第一版）——

| 不做 | 原因 |
|------|------|
| 触发 GitLab 流水线 | 工具是记录台不是执行器；上线不可逆，不经工具的手更安全 |
| 调用 nacos / 数据库 / 网关 API | 同上，且需要各系统凭据 |
| 校验分支是否真实存在 | 需要 GitLab 凭据与网络；写错分支在执行那一步自然会撞上 |
| 多人协作 / 远端同步 | 本地 sqlite，单机使用 |

后续若要接外部系统，以扩展的形式挂在既有模型上，不改核心数据。

---

## 2. 领域模型

```
上线任务（一天一个，提前建）
├── 任务级前置项：提测单 · CAB 单 · 工单（nacos/数据库）· 上线公告
└── 环境（可多个）
    └── 服务（按 服务 × 环境 展开）
        ├── 合并分支
        ├── 配置项（仅后端：nacos · 数据库 · 定时任务 · 菜单 · 网关）
        ├── 部署
        └── 验证完成
```

环境与服务的定义放在**基础配置**里长期维护；任务引用它们时**做快照**，此后互不影响。

---

## 3. 基础配置

### 3.1 服务

| 字段 | 说明 |
|------|------|
| 名称 | 唯一 |
| 类型 | 后端 / PC 前端 / 移动前端 |
| 默认分支 | 新建任务时预填到每个环境，可改 |

**配置项由类型决定，不是逐服务勾选**：后端固定 5 项（nacos、数据库、定时任务、菜单、网关）；两类前端一项都没有。

### 3.2 环境

| 字段 | 说明 |
|------|------|
| 名称 | EM / EU / AM / US 等 |
| 包含的服务 | 从服务目录里选 |
| 上线时间窗 | 开始 + 结束；允许跨零点（结束 ≤ 开始视为次日） |

环境定义全局共用；一个任务里同一环境只出现一次。

## 4. 任务

### 4.1 创建

- **计划上线日期**必填，默认只允许**周二、周四**；选其他日子弹二次确认「非常规发布日，确定要建吗？」。
- 「一天一个」按**计划日期**算：同一天已有任务时，点「新建」直接打开已有那个，不新建。
- 任务提前建，挂未来的发布日；跨到凌晨完成不算超期。

### 4.2 内容

| 部分 | 说明 |
|------|------|
| 加入环境 | 从基础配置挑，可加多个；加入即快照（环境名称、时间窗、服务清单、服务类型与默认分支） |
| 移除环境 | 整个环境从任务里拿掉，二次确认 |
| 移除服务 | 服务级「跳过」= 从任务移除，二次确认；不占进度、不提醒、不出现在执行清单 |
| 分支 | 每个「服务 × 环境」各填一个，默认带服务定义的默认分支；纯手填，不校验真伪 |
| 配置内容 | 仅后端；5 项都是文本，粘贴填写 |
| 配置项跳过 | 某项本次没有 → 勾跳过；该步显示「已跳过」并划掉，校验时不报缺 |
| 工单卡 | 任务级；任务里有任何服务填了 nacos 内容 → 出一张 nacos 工单卡；有数据库内容 → 出一张数据库工单卡 |
| 公告 | 任务级唯一；内容用户填；时间自动取当天**最早环境的开始时间** |

### 4.3 校验

- 触发：点「校验」按钮随时跑；点「提交」时自动跑一次，不过不放行。
- 规则：
  - 本次未移除的服务，分支不能为空
  - 未勾跳过的配置项，内容不能为空
  - 内容为空又没勾跳过 → 报错
- 不校验：分支真伪、配置内容对错、工单号、各类前置单（这些在执行期卡）。
- 呈现：不合格项标红，并列出「哪儿不完整」清单。

### 4.4 修改

- 提交后仍可改配置；改完自动重新校验。
- **改配置内容或改分支 → 自动撤回该步的已确认状态**，并记一条日志（内容变了，旧确认不作数）。

## 5. 执行

### 5.1 步骤

**任务级前置**（可提前完成，有到期时间）

| 步骤 | 形式 | 到期时间 |
|------|------|----------|
| 提测单 | 填单号 + 勾「已通过」 | 时间基准 − 1h |
| CAB 单 | 填单号 + 勾「已通过」 | 时间基准 − 1h |
| nacos 工单 | 填工单号 + 勾「已审批」 | 时间基准 − 1h |
| 数据库工单 | 填工单号 + 勾「已审批」 | 时间基准 − 1h |
| 上线公告 | 填内容 + 勾「已发」 | 时间基准（最早环境开始时间） |

> **时间基准** = 任务里所有环境开始时间的最小值。

**服务级清单**（每个 服务 × 环境 各一套）

| 顺序 | 步骤 | 何时可做 |
|------|------|----------|
| 1 | 合并分支 | 随时（建单后即可勾） |
| 2~6 | 5 项配置（顺序可拖拽） | 时间窗开始后 |
| 7 | 部署 | 时间窗开始后 |
| 8 | 验证完成 | 时间窗开始后 |

前端服务的清单只有 `合并分支 → 部署 → 验证完成`。

### 5.2 推进方式

- **自由推进 + 引导**：任意服务的任意可做步骤都能点，同时给一个「下一步」默认路径。
- **服务顺序可拖拽**，调整结果记进任务。
- **配置项顺序可拖拽**，但只在「配置中 / 待执行」阶段可调，进入执行后锁定。
- 过了时间窗仍可继续做，列表标红「已超时」。

### 5.3 撤回

- 任务未进入「已完成」前，**任何一步都能撤回**，弹二次确认；撤回后该服务退回未完成。
- 撤回记日志（哪一步、何时撤的）。
- 任务已完成 → 整单只读，不能撤回；要改只能作废重建。

### 5.4 完成判定

- **环境完成** = 该环境里所有未移除的服务都走完（含验证完成）。
- **任务完成** = 所有环境完成 **且** 任务级前置全部完成。
- 环境里服务被全部移除 → 该环境直接算完成（没服务可做 = 不欠账）。

## 6. 提醒引擎

### 6.1 模型

每一项待办都带一个**到期时间**。引擎只做一件事：

> 任何时刻，把「**已经到期但还没完成**」的项收集起来，弹**一个**窗。

这样天然解决时间重叠——同一时刻该发的公告、该做的部署，列在同一个窗里，按环境分组；四个环境撞在一起也还是一个窗。

### 6.2 分级

| 颜色 | 含义 |
|------|------|
| 红 | 已到环境上线时间，部署未完成；或任务已到期仍停在「配置中」（这任务根本没准备好） |
| 橙 | 已到「时间基准 − 1h」，前置项未完成 |
| 黄 | 已到公告时间，公告未发 |

一个窗里混着多档时，**窗取最高优先级的色**，各条目自带色标。

### 6.3 行为

- **独立全屏窗**（新开窗口，不是应用内遮罩）。
- 窗里**只列、只跳转**，不能直接勾选；点某条 → 关窗跳到执行框对应位置，在那里操作。
- 关闭后 **5 分钟**再弹，直到该项完成。
- 全部做完了就不弹。
- 应用关着期间到期的，**重开时补弹**，不因错过而吞掉。
- 应用完全退出时无法提醒（不装后台服务、不开机自启）——已知边界。
- 任务处于「配置中」且未到时间基准 → 不弹任何提醒。

## 7. 状态

```
配置中 ──提交──▶ 待执行 ──时间窗到──▶ 执行中 ──全部完成──▶ 已完成
   │                │                  │
   └────────────────┴──────────────────┴──▶ 已作废
```

- **状态只跟时间走**：提前勾前置不算「执行中」，只体现在进度上。
- **超时**是标记不是状态。
- **已作废**：停止提醒、进度冻结但保留；**可恢复**（按当前进度与时间自动回到对应状态）；**不占当天名额**，所以作废后当天可再建一个。

## 8. 边界约定

| # | 约定 |
|---|------|
| 1 | 任务引用环境/服务一律**快照**，基础配置后续改动不影响已建任务 |
| 2 | 基础配置删服务/环境不影响历史任务；环境仍引用被删服务时，删服务要二次确认并自动从环境摘掉 |
| 3 | 时间窗允许跨零点，结束 ≤ 开始视为次日 |
| 4 | 提醒只在应用运行时生效；关闭期间到期的重开补弹 |
| 5 | 一个窗里多档颜色时窗取最高优先级，条目各自标色 |
| 6 | 配置项顺序只在配置/待执行阶段可拖，执行后锁定 |

## 9. 数据表（草案）

沿用 `core/schema.h` 单库单表集，无版本化迁移链——建表语句一次写对，后续改动走 `migrate` 补列。

| 表 | 关键列 |
|----|--------|
| `release_service` | id, name, kind(backend/pc_web/mobile_web), default_branch, sort |
| `release_env` | id, name, start_minute, end_minute, sort |
| `release_env_service` | env_id, service_id |
| `release_task` | id, plan_date, status, announce_text, announce_sent_at, pretest_no, pretest_ok, cab_no, cab_ok, ticket_nacos_no, ticket_nacos_ok, ticket_db_no, ticket_db_ok |
| `release_task_env` | id, task_id, env_name, start_minute, end_minute, removed |
| `release_task_service` | id, task_env_id, service_name, service_kind, default_branch, branch, removed |
| `release_task_config` | id, task_service_id, kind(nacos/db/cron/menu/gateway), content, skipped, conf_order, done_at |
| `release_task_step` | id, task_service_id, kind(branch/deploy/verify), done_at |
| `release_task_log` | id, task_id, scope, step, action(confirm/revoke), at, note |

`start_minute/end_minute` 存当天的分钟数（0~1439），跨零点由比较规则处理。

## 11. UI 要点与 EUI-NEO 缺口

**可用**：多行文本（`InputBuilder.multiline()` + `.scrollbar()`）、模态 Dialog（`.screen()` 可接近全屏）、原生文件对话框、复选框、日期/时间选择、Tabs、虚拟列表、拖拽排序。

**缺口**：**折叠面板（Accordion）缺失**。任务详情页的环境分组若用折叠，需要上游补组件，或改用 Tab / 自绘面板。

**全屏编辑配置内容**：用 DialogBuilder 的 `.screen()` 撑到整屏，或 `eui::app::openWindow` 开独立大窗——二选一，实现阶段定。
