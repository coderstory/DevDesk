## 1. 现状速写（给产品方：现在是什么样）

打开智能体页 → 点「新建任务」（或点任务卡片的「编辑」），弹出 **760×500** 的模态弹窗，从上到下是：

| 区域 | y 坐标 | 内容 |
|------|--------|------|
| 标题行 | y=24 | 「新建任务」/「编辑任务」+ 右上「AI 生成草稿」橘色小按钮 + ✕ |
| 任务目标 | y=64 | 标签「任务目标」+ 多行输入框（高 96） |
| 触发行 | y=172 | 标签「触发方式」+ 下拉（手动/定时/常驻/事件/每天/闹钟）；定时分支同一行扩展出 cron 输入+模板下拉；事件分支扩展出三个开关；闹钟分支扩展出时间输入 |
| 触发提示 | y=212 | 一行小灰字说明当前触发方式怎么用（高 12，与预览行互斥） |
| 元信息行 | y=224 | 标签「模型槽位」+ 下拉 + 标签「迭代上限」+ 数字输入 +「允许破坏性操作」开关 +（定时/事件时）「只跑一次」开关 —— **全挤在同一行** |
| 元信息提示 | y=264 | 一行小灰字：「迭代=单次运行的最多轮数，跑满以『受限』结束、不再重试；破坏性操作=允许删除文件等高危工具，不勾则被拒」 |
| 执行记忆 | y=276 | 标签「执行记忆」+ 多行输入（高 72）+ 下方「结束后自动记录回复」开关 |
| 错误行 | y=408 | 校验不通过时显示红字 |
| 按钮行 | 底 60 |「取消」（白底灰边）+「保存」（橘底白字），各占一半宽 |

**核心问题对应**：

1. **文字截断**：元信息提示那行小字（y=264）只有 12px 高、lineHeight=12——中文 11px 在这个高度被截断不可读。触发提示行同理。
2. **混排无边界**：触发方式/模型槽位/迭代上限/破坏性开关四组语义全挤在一起，没有分组间隔或区域分隔。
3. **术语无解释**：「迭代上限」「模型槽位」「system prompt」「破坏性操作」没有内联帮助。
4. **破坏性开关归属混淆**：紧贴迭代输入框右侧，与「只跑一次」开关同排——用户不清楚「危险」到底跟谁有关。
5. **输入框尺寸不合理**：迭代数字输入 100px 宽但只能输入 1-2 位数；任务目标固定 96px 高写长目标不便。
6. **按钮主次不清**：「AI 生成草稿」与「保存」同橘色，两个操作不应同权重；说明文字 11px 太小。

## 2. EUI-NEO 能力前置裁定

读自 `docs/EUI-NEO-CAPABILITIES.md`（2026-09-20 调研，2026-09-27 M0 spike 补充）：

| 需要的 UI 能力 | 框架支持 | 结论 |
|---------------|---------|------|
| tooltip（悬浮提示） | ✅ `components::tooltip` | 直接用于 `?` 图标 |
| 多行 input | ✅ `.multiline(true).scrollbar(true)` | 任务目标/执行记忆已在使用 |
| 开关组件 | ✅ `components::toggleSwitch` | 破坏性/自动记录/只跑一次已在使用 |
| 下拉组件 | ✅ `components::dropdown` | 触发方式/模型槽位已在使用 |
| 绝对定位 | ✅ `.x().y().ignoreLayout()` | AI 生成草稿 chip 已在使用 |
| 弹窗组件 | ✅ `components::dialog` / `dialog_form.h` | 当前即用此 |
| **折叠/展开面板（Accordion/Collapse）** | **❌ 不支持** | 见 §3「折叠面板」裁决 |
| font-weight 真切换 | ❌ 只打包 Bold 一份字重 | 不依赖字重区分层级 |

### 3.1 砍案详细论证：折叠面板

用户建议"高级配置折叠面板（默认收起）"的意图是把不常用的字段（模型槽位、迭代上限、破坏性操作）收起来减少视觉噪音。这个意图是合理的，但落地方式在当前框架下不可行。

**为什么不可行**：
- EUI-NEO 无 Collapse/Accordion 组件（`docs/EUI-NEO-CAPABILITIES.md` §10 核对表已记）。
- 用 state 控制区域高度（`expanded ? h : 0` + transition）可以"看起来像"折叠，但：
  - 需自管理展开/收起状态、动画时长、easing
  - 收起时子元素仍参与布局测量（EUI-NEO 的 flex layout 不跳过高度 0 的子节点）
  - 两个平台（Windows/macOS）的渲染差异会加倍 bug 面
  - 探针/单测的"面板高=500"断言需配套更新

**替代方案**：默认全展开 + 用间距和视觉层级让"高级"字段**看起来**是独立的一组（组间空行 + 小标题「高级」），但不改变可见性。产品方可在 EUI-NEO 支持原生 Collapse 后追加本特性。

### 5.3 触发提示互斥耦合的拆除

**现状问题**：`trigger.hint`（触发方式说明）与 `cron.preview` / `once.preview`（预览行）共用同一个 y=212 位置，`skipIfEmpty` 控制谁显示。这导致：
- 触发提示被截断（12px 高不折行）
- 定时/闹钟用户看预览，看不到触发说明；切回手动才看到触发说明——信息时有时无

**本次改为**：
- 触发说明文字固定渲染（不限高、可折行），始终显示
- cron/闹钟预览行另占独立位置（不再与说明互斥）
- 删除 `trigger.hint` 的 12px 缝打法

### 5.4 文字系统修复

**问题 1**：`meta.hint`（y=264）12px 高不折行 → 70+ 汉字一行塞不下，被框架裁剪

**修法**：删除 `meta.hint`，内容拆到各字段的 tooltip（见 §6.2）和破坏性开关的独立说明行。所有说明文字最小行高 **18px**（`fontSizeSmall - 1 = 12px` 文字 + 3px 上下留白 + 折行余量）。

**问题 2**：执行记忆 placeholder 过长不折行

**修法**：placeholder 文案本身不进布局测量系统（它是 input 内部绘制），但提示文字改为独立 text 行后不受 input 内部机制限制。

**双平台兼容策略**：
- 所有文本区使用 `.wrap(true)` + 显式 `maxWidth`（等于内容区宽）
- 行高 `lineHeight` 取 `max(平台默认行高, 声明值)`；声明值一律用框架的 auto（`0`）或 ≥18
- 兜底：`clip(true)` 保几何不被文字溢出破坏

## 6. 视觉方案（P-B）

### 6.1 按钮层级

| 按钮 | 样式 | 实现方式 |
|------|------|---------|
| 保存 | 橘底白字 | `components::button` + `.theme(themeTokens, true)`（现状不变） |

### 6.2 tooltip 文案（技术名词解释）

| 术语 | tooltip 内容 |
|------|-------------|
| 模型槽位 | 「选择执行任务使用的 AI 模型——主 slot 为默认日常模型，pro slot 适合复杂推理任务。具体可选模型取决于当前 profile 的后端配置。」 |
| 迭代上限 | 「单次运行最多对话轮数；跑满后任务以『受限』状态结束，不再自动重试。设为较大值（如 50）适合复杂多步任务，较小值（如 5）适合简单问答。」 |

- 破坏性开关**关闭态**：track 用默认 surface 色，无特殊标记

- 开关文字前加 `⚠️ ` 前缀（Unicode U+26A0）
- 破坏性开关下方说明文字（新增 `agent.dialog.task.destructive.desc`）始终显示，色 = `textTertiary`，开启时不变（不额外标红，信息在 tooltip 里）
